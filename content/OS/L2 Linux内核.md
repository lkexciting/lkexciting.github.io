# L2 Linux内核

> 来源：`L2 Linux内核.pdf`，38 页。对应 [[OS/第 2 章 · 操作系统服务与结构|Chapter 2]]；模块见 [[OS/L3 Linux内核模块|L3 Linux内核模块]]。课件混合旧 x86 启动及不同版本构建示例，下文按历史教学流程解释，不将其当成当前机器直接执行清单。

## 1. 内核子系统（Kernel Subsystems）

课件 1–13 页。Linux 是支持动态模块的**宏内核（Monolithic Kernel）**：调度、内存、文件系统、网络与驱动等大量服务在内核态协作；能加载模块不等于微内核（Microkernel）。

| 源码目录 | 常见职责 |
| --- | --- |
| `arch` | 特定体系结构支持 |
| `kernel` | 核心管理及相关基础机制 |
| `mm` | 内存管理 |
| `fs` | 文件系统 |
| `drivers` | 设备驱动 |
| `net` | 网络 |
| `include` | 头文件与接口声明 |
| `init` | 启动初始化 |
| `ipc` | 进程间通信 |

![课件源码目录示意](OS/pictures/L2%20Linux%E5%86%85%E6%A0%B8/%E5%AD%A3%E8%80%81%E5%B8%88-p011.png)

读源码先从问题定位子系统，再追踪入口、数据结构、调用关系。课件行号与字段是版本证据，不是跨版本固定地址。

## 2. 内核代码的约束（Kernel Programming Constraints）

课件第 14 页：不能直接使用用户态 libc 接口；内核栈较小，不宜放巨大局部数组或深递归；中断、抢占、多核会产生并发；失败可能影响整个系统。

`printf` 与 `printk` 属于不同运行环境。用户指针也不能直接当作可信内核指针。持有自旋锁或在不可睡眠上下文时，不能调用可能睡眠的路径。

课件“必须 GNU C”等句子描述的是所展示工具链背景，不将它扩展为所有版本对编译器和语言的永久唯一要求。

## 3. 配置与构建产物（Configuration and Build Artifacts）

课件 15–25 页。

- **Kconfig** 描述配置项、依赖与可选择条件。
- **`.config`** 记录本次具体配置结果。
- **Kbuild / Makefile** 根据配置与依赖构建目标。
- `y`：编入内核；`m`：编成可加载模块；`n`：不构建。并非每个选项都允许三者。
- **vmlinux**：带相应 ELF 结构的内核链接产物。
- **bzImage / vmlinuz**：课件 x86 启动映像或发行系统安装命名，不能与所有架构产物混同。
- **initramfs**：启动早期使用的临时根文件系统内容，与内核镜像不是同一文件。

![课件内核构建过程](OS/pictures/L2%20Linux%E5%86%85%E6%A0%B8/%E5%AD%A3%E8%80%81%E5%B8%88-p019.png)

理解流程：确认目标架构与工具链 → 配置 → 编译链接内核和模块 → 按实验环境部署 → 启动并验证。`ARCH`决定目标架构，`CROSS_COMPILE`指定交叉工具链前缀，二者不是任选一个即可。

课件命令 `make mrproper` 会清理配置等构建状态；不能把它当成不影响工作的普通查看命令。课程资料中的安装、引导修改和重启仅作为流程说明，本次未执行。

## 4. 启动过程（Boot Process）

课件 26–37 页。

```text
固件初始化（Firmware）
  引导加载程序（Bootloader）
    加载内核及早期根文件系统
      内核初始化硬件、内存、调度与驱动
        启动第一个用户空间进程
          初始化服务、终端和登录环境
```

![课件启动过程，具有历史版本背景](OS/pictures/L2%20Linux%E5%86%85%E6%A0%B8/%E5%AD%A3%E8%80%81%E5%B8%88-p028.png)

课件的 BIOS、bootsect/setup/head.S、`/etc/inittab`、运行级别（Runlevel）是特定启动体系与传统 init 示例。理解每一层的职责，不假定所有 UEFI、架构或发行版都使用这套文件。

`inittab` 的典型记录含 `id:runlevel:action:process`：标识、运行级、处理方式、启动命令。它属于相应 init 机制的配置，不是内核亲自逐行解释的通用脚本。

## 5. 验证与自测（Verification and Review）

课程实验构建完成后，成功标准不仅是“make 没报错”：应检查目标产物、架构与配置，部署路径是否匹配，启动是否确实进入该内核，模块是否与运行内核对应。

1. 源码目录修改了驱动，为什么不代表运行中的内核已经改变？
2. 将配置选 m 与选 y 的差别？
3. 内核初始化结束与用户登录，是同一个阶段吗？

> [!success]- 答案
> 1. 修改源文件后还需构建、部署并加载/启动新产物。
> 2. m 形成模块，y 链入内核；是否可动态卸载还取决于实现与使用状态。
> 3. 不是，用户空间初始化和登录服务在之后继续工作。

术语：内核镜像（Kernel Image）、交叉编译（Cross Compilation）、引导加载器（Bootloader）、初始化（Initialization）、运行级别（Runlevel）。
