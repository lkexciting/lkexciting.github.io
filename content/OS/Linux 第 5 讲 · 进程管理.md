# Linux 第 5 讲 · 进程管理

> 来源：`L5 Linux进程管理.pdf`，89 页。对应 [[OS/第 3 章 · 进程|Chapter 3]]、[[OS/第 4 章 · 线程|Chapter 4]]、[[OS/第 5 章 · CPU 调度|Chapter 5]]；调度补充见 [[OS/第 5-1 章 · Windows 与 Linux 调度实现|Chapter 5-1]]。课件并列 Linux 2.4、2.6 和 5.9.x 的材料，字段和实现必须按对应版本阅读。

## 1. 执行实体与状态（Task and State）

课件 3–12 页。Linux 用 **task** 表示可调度执行实体，维护对应 `task_struct`。进程与线程的关键差别在资源共享关系，不是“线程完全没有自己的管理结构”。

| 课件状态 | 含义 |
| --- | --- |
| TASK_RUNNING | 包括正在执行，以及已经就绪、等待 CPU 的实体 |
| TASK_INTERRUPTIBLE | 可被相应信号等事件唤醒的睡眠 |
| TASK_UNINTERRUPTIBLE | 不因普通信号立即结束该等待的睡眠 |
| 停止/跟踪状态 | 执行被停止或由调试机制控制 |
| 僵尸相关退出状态 | 运行已结束，退出信息尚待父进程等回收 |

具体常量及状态字段划分随版本变化。`TASK_RUNNING` 不能只翻译成“此刻占着一个 CPU”。

## 2. task_struct、栈与队列（PCB, Stacks and Queues）

课件 13–33 页。

`task_struct` 对应进程控制块（Process Control Block，PCB）职责：保存标识、状态、调度、亲属关系、时间、文件、信号、内存等管理信息。很多资源由指针关联的独立对象描述，不能说 PCB 内嵌所有文件和所有页面内容。

线程有自己的执行寄存器上下文、用户栈和相应内核栈；同进程线程通常共享地址空间、代码和堆，但每个线程的栈空间并不因此失去独立用途。

![课件比较内核栈及 task_struct 的版本变化](OS/pictures/L5%20Linux%E8%BF%9B%E7%A8%8B%E7%AE%A1%E7%90%86/%E5%AD%A3%E8%80%81%E5%B8%88-p027.png)

- 进程链表（Task List）：组织和遍历执行实体。
- 运行队列（Runqueue）：组织可调度实体。
- 等待队列（Wait Queue）：组织等待某事件的睡眠者。

一个结构可通过不同链接同时参与不同逻辑集合；不能把“在进程链表”理解为“就绪可运行”。等待队列中的睡眠/唤醒还要避免 [[OS/第 6 章 · 进程同步|Chapter 6]] 的唤醒丢失。

## 3. 创建、执行与终止（Creation, Execution and Exit）

课件 34–56 页。

### 3.1 fork 的返回值

- 失败：父进程中返回 -1，不产生成功创建的子进程。
- 成功：父进程返回子 PID，子进程返回 0。
- 父子继续执行 fork 后面的代码；谁先执行不由源码行位置保证。

课件 38–39 页的打印顺序会变化，因为创建后存在两个可独立调度的执行实体，不能假设 PID 小者先输出。fork 前的用户态输出缓冲也可能被复制，所以分析打印次数需说明缓冲是否已刷新。

### 3.2 资源复制与共享

`fork` 创建逻辑独立地址空间，物理页可通过写时复制（Copy-on-Write）暂时共享；`clone` 类机制通过标志控制共享关系。文件描述符表副本中的项也可能引用同一打开文件描述对象，因此“表不同”不意味着文件偏移一定独立。

课件以 `do_fork` / `copy_process` 展示：检查限制 → 建立子实体与状态 → 按规则复制/共享资源 → 分配标识并建立关系 → 放入可运行状态 → 返回。函数名称和源码行号按该版本理解。

![课件 copy_process 流程](OS/pictures/L5%20Linux%E8%BF%9B%E7%A8%8B%E7%AE%A1%E7%90%86/%E5%AD%A3%E8%80%81%E5%B8%88-p047.png)

### 3.3 exec 与 wait

`exec` 替换当前进程的程序映像，成功后从新入口执行，不会正常返回到旧程序下一行；它不是又创建一个新 PID 的普通函数。`wait` 类操作回收子进程退出信息，避免已结束子进程长期保留僵尸记录。

课件把内核线程创建与用户态 clone 示例并置，应区分：内核线程执行内核函数，不能仅凭“共享地址空间标志”就把用户线程称作内核线程。

## 4. Linux 调度的历史版本（Historical Schedulers）

课件 57–88 页。

| 材料 | 核心机制 | 不能混淆的地方 |
| --- | --- | --- |
| 2.4 示例 | 扫描可运行实体、按 goodness 等选取 | 扫描与 O(1) 位图不是同一算法 |
| 早期 2.6 O(1) | 每 CPU 队列、优先级数组与位图、active/expired | 不是所有“2.6”版本的唯一实现 |
| 2.6.23 引入的 CFS | 公平调度思想与虚拟运行时间 | 不等于之前的 active/expired 交换 |

![课件优先级数组示意](OS/pictures/L5%20Linux%E8%BF%9B%E7%A8%8B%E7%AE%A1%E7%90%86/%E5%AD%A3%E8%80%81%E5%B8%88-p075.png)

**O(1)** 说的是其特定选择路径不随可运行进程数量线性扫描；不表示调度、迁移、锁和全部系统开销均为零或常量。

课件按旧内部编号把优先级分为实时区和普通区，较小内部编号可能更高；不能和 Windows 中数字越大通常优先级越高的编号体系混用。

**主动让出（Voluntary Switch）**：等待资源、睡眠等；** 被动切换（Involuntary Switch）**：时间配额耗尽或更高优先级实体就绪等。`need_resched` 表示需要重新调度，不等于在任意指令位置立即安全切换。

## 5. 自测与术语（Review）

1. 一个进程含 4 个线程，是否只需要一个执行上下文？
2. fork 后父子输出谁先谁后？
3. exec 成功后旧程序的下一行会继续吗？
4. O(1) 说明所有 Linux 版本都采用同一个调度器吗？

> [!success]- 答案
> 1. 否，每个线程有自己的寄存器、栈及调度执行状态。
> 2. 无额外同步时不能保证。
> 3. 不会正常继续，已经替换成新程序映像。
> 4. 否，是具体历史调度器的复杂度名称。

术语：执行实体（Task）、运行队列（Runqueue）、等待队列（Wait Queue）、进程控制块（PCB）、写时复制（COW）、虚拟运行时间（Virtual Runtime）、处理器亲和性（Processor Affinity）。
