# Chapter 2 红黑树与 B+树（Red-Black Trees & B+ Trees）

> **课件来源**：`ADS02BTree_Stu.ppt`（13 页）
> **本章主线**：AVL 树用「高度差 ≤ 1」强制平衡，旋转次数虽少但删除时可能一路旋到根 → **红黑树（Red-Black Tree, RB Tree）** 用「颜色约束」实现更松的平衡，插入 ≤ 2 次旋转、删除 ≤ 3 次旋转 → **B+ 树（B+ Tree）** 把同样的平衡思想推广到「多路（multiway）」情形，专为**磁盘 I/O** 设计。

---

## 0. 本章速览

| 项目 | 红黑树（RB Tree） | B+ 树（order $M$） |
|---|---|---|
| 平衡方式 | 颜色 + 黑高（black-height） | 结点孩子数在 $[\lceil M/2\rceil, M]$ 之间，所有叶子同深度 |
| 高度 | $\le 2\log_2(N+1)$ | $O(\log_{\lceil M/2\rceil} N)$ |
| 查找 | $O(\log N)$ | $O(\log N)$（结点内二分） |
| 插入旋转 | $\le 2$ | 分裂（split）沿路径上传 |
| 删除旋转 | $\le 3$ | 借（borrow）/ 合并（merge） |
| 典型用途 | `std::map`、`TreeMap`、Linux CFS 调度器 | 数据库索引、文件系统（B+ 树叶存数据、叶间有链） |

**AVL 与红黑树的旋转次数对比（课件结论）**

| 旋转次数 | AVL | Red-Black Tree |
|---|---|---|
| Insertion | $\le 2$ | $\le 2$ |
| Deletion | $O(\log N)$ | $\le 3$ |

![图 2-1 AVL 与红黑树的旋转次数对比：插入均 ≤2，删除 AVL 为 O(log N)、红黑树 ≤3](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig06_slide08.webp)

> 这正是红黑树在工业界更流行的原因：**删除时旋转次数是常数**，而 AVL 可能 $O(\log N)$ 次。

## 1. 红黑树的定义与性质

**目标**：一棵**平衡的二叉搜索树**，但用「颜色」而非「高度」来记账，使得维护代价（旋转次数）更小。

每个结点字段：`key, color, left, right, parent`，空指针统一视为 `NIL`（外部结点，黑色）。

**【定义】红黑树（red-black tree）** 是满足以下 5 条性质（red-black properties）的 BST：

1. **每个结点非红即黑**（every node is either red or black）；
2. **根是黑的**（the root is black）；
3. **每个叶子（NIL）是黑的**（every leaf is black）；
4. **红结点的两个孩子都是黑的**（if a node is red, both children are black）——即**不能有连续两个红结点**；
5. **对每个结点，从它到所有后代叶子的简单路径上黑结点数相同**（all simple paths contain the same number of black nodes）。

![图 2-2 红黑树的结构与 5 条性质（结点含 key/color/left/right/parent，NIL 为外部黑结点）](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig01_slide02.webp)

**直观理解**：性质 5 保证「黑高相等」，性质 4 保证「红结点不能连成串」，于是最长路径（红黑交替）最多是最短路径（全黑）的 **2 倍** → 树高被限制在对数级。

### 1.1 黑高（black-height）

**【定义】** 结点 $x$ 的黑高 $bh(x)$ = 从 $x$（**不含 $x$ 自身**）到任一后代叶子的简单路径上的黑结点数。整棵树的 $bh(\text{Tree}) = bh(\text{root})$。

> $bh$ 是良定义的：由性质 5，任意路径黑结点数相同，取哪条都一样。

### 1.2 高度上界（重要引理）

**【引理】** 有 $N$ 个内部结点的红黑树，高度至多 $2\ln(N+1)$。

（严格写法应为 $2\log_2(N+1)$；课件用 $\ln$ 表示对数，量级不变。）

**证明分两步：**

**① 对任意结点 $x$，其子树内部结点数 $\text{sizeof}(x) \ge 2^{bh(x)} - 1$（对高度归纳）。**

- 基础：$h(x)=0$（$x$ 为 NIL），$\text{sizeof}(x)=2^0-1=0$，成立。
- 归纳：设对所有 $h(x)\le k$ 成立。对 $h(x)=k+1$ 的结点，其孩子 $y$ 满足 $bh(y) = bh(x)$ 或 $bh(x)-1$：
  - 若 $y$ 是红，则 $bh(y)=bh(x)$；若 $y$ 是黑，则 $bh(y)=bh(x)-1$。故 $bh(y) \ge bh(x)-1$。
  - 由归纳假设 $\text{sizeof}(y) \ge 2^{bh(y)}-1 \ge 2^{bh(x)-1}-1$。
  - 于是 $\text{sizeof}(x) = 1 + 2\,\text{sizeof}(y) \ge 1 + 2\left(2^{bh(x)-1}-1\right) = 2^{bh(x)}-1$。∎

**② $bh(\text{Tree}) \ge h(\text{Tree})/2$。** —— 因为由性质 4，任一路径上红结点数不超过黑结点数，故 $h \le 2\,bh$。于是

$$N \ge 2^{h/2}-1 \ \Longrightarrow\ h \le 2\log_2(N+1).$$

> **考点**：这条引理把「红黑」翻译成「高度」，从而所有基于高度的结论（查找 $O(\log N)$）自动成立。

## 2. 插入（Insert）

**基本思路（sketch）**：按 BST 插入新结点 $z$，**先染红**（这样性质 5 一定不被破坏，只有可能违反性质 4「红—红」或性质 2「根为黑」）。然后沿路径向上修复。

设 $z$ 为当前「出问题的红结点」（红-红冲突的下方结点），$p$ 为父，$g$ 为祖父，$y$ 为叔结点（uncle，$g$ 的另一个孩子）。

| 情形 | 条件 | 处理 | 是否结束 |
|---|---|---|---|
| **Case 1** | 叔结点 $y$ 是**红** | $p$、$y$ 染黑，$g$ 染红，令 $z \leftarrow g$ 继续向上 | 否（上移两层） |
| **Case 2** | $y$ 是黑，且 $z$ 是「内侧」孩子（zig-zag） | 对 $p$ 旋转，转成 Case 3 | 否（转成 Case 3） |
| **Case 3** | $y$ 是黑，且 $z$ 是「外侧」孩子（zig-zig） | 对 $g$ 旋转，$p$ 染黑、$g$ 染红 | **是**（结束） |

**要点**：
- Case 1 只是「把问题上移两层」，染色即可，最坏爬到根（此时把根染黑即可，树高增加 1，黑高整体 +1）；
- Case 2 → Case 3：最多 2 次旋转；
- 整个修复过程可以**迭代（iteratively）**实现（不需要递归），时间 $T=O(h)=O(\log N)$。

![图 2-3 红黑树插入的三种情形 Case 1/2/3（叔结点红→染色上移；内侧→双旋；外侧→单旋）](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig02_slide04.webp)

> 记忆法：**「叔红变色上移，叔黑看内外；内侧先转成外侧，外侧单旋收工」**。

## 3. 删除（Delete）

先按普通 BST 删除，再修复颜色。分三种结构情形：

1. **删叶结点（degree 0）**：把父指针置 NIL；
2. **删度为 1 的结点**：用其唯一孩子替代；
3. **删度为 2 的结点**：用**左子树最大**（前驱）或**右子树最小**（后继）替代，问题转化为删除那个替代结点。

**关键**：只有当被删除的结点是**黑色**时才需要调整（若是红色，性质 5 不变）。删除黑结点会使该路径上黑高少 1 —— 于是把替代结点 $x$ 视为带有一层「额外的黑」（**double black**，双黑），目标是把这个多余的黑「还」回去。

设 $x$ 为双黑结点（$x$ 本身可能是 NIL），$w$ 为其兄弟（sibling）：

| 情形 | 条件 | 处理 | 后续 |
|---|---|---|---|
| **Case 1** | $w$ 是**红** | 旋转 $w$ 与父，$w$ 染黑、原父染红 | 兄弟变黑，转 Case 2/3/4，**问题未解决** |
| **Case 2** | $w$ 黑，且 $w$ 的**两个孩子都黑** | $w$ 染红，$x \leftarrow$ 父（把多余的黑上移） | 若到根则结束，否则继续 |
| **Case 3** | $w$ 黑，$w$ 的**近侧孩子红、远侧孩子黑** | 旋转 $w$ 与近侧孩子，交换颜色 | 转 Case 4 |
| **Case 4** | $w$ 黑，$w$ 的**远侧孩子红** | 旋转父与 $w$，$w$ 取父色、父染黑、远侧孩子染黑 | **结束** |

![图 2-4 删除的四种情形 Case 1–4（w 为兄弟结点，x 为双黑结点）](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig03_slide05.webp)

![图 2-5 Case 2 会「继续上移」多余的黑；Case 3 转成 Case 4 后一次旋转结束](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig04_slide06.webp)

课件的完整删除示例（结点 10,5,15,3,7,6,8,11,17）：删除 5 → 用 6 替代（Case 1/2.1/2.2/3/4 依次出现），可以清楚看到「Case 1 → Case 2 → Case 3 → Case 4」的链条。

![图 2-6 完整删除示例：同一棵树中依次触发 Case 1、Case 2.1、Case 2.2、Case 3、Case 4](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig05_slide07.webp)

**旋转次数**：删除最多 **3 次旋转**（Case 1 一次、Case 3 一次、Case 4 一次），其余是染色 —— 这就是红黑树相对 AVL 的优势。

## 4. 红黑树 ↔ 2-3-4 树（理解型考点）

把每个**黑结点与它的红孩子「合并」成一个多关键字结点**，红黑树就变成一棵 **2-3-4 树**（order 4 的 B 树）：

- 一个黑结点 + 0 个红孩子 → 2-结点（1 key, 2 children）；
- 一个黑结点 + 1 个红孩子 → 3-结点（2 keys, 3 children）；
- 一个黑结点 + 2 个红孩子 → 4-结点（3 keys, 4 children）。

于是：
- 插入 Case 1（叔红→染色上移）= 2-3-4 树的**结点分裂（split）上传**；
- 插入 Case 3（单旋）= 3-结点内部**换位**；
- 红黑树「插入 ≤ 2 次旋转」对应 2-3-4 树「分裂只影响常数个结点」。

**这条对应关系能解释所有 case 的动机**，考试中常要求「画出红黑树对应的 2-3-4 树」。

## 5. B+ 树（B+ Tree）

### 5.1 为什么需要多路树

磁盘（disk）访问以「块（block / page）」为单位，一次 I/O 的代价远大于 CPU 计算。二叉树的 $O(\log N)$ 次结点访问 = $O(\log N)$ 次磁盘 I/O，太贵。**把结点做大（一个结点存几百个 key），让树高降到 3~4 层**，就能把 I/O 次数压到常数级 —— 这就是 B 树 / B+ 树的核心动机。

### 5.2 定义

**【定义】阶为 $M$ 的 B+ 树（B+ tree of order $M$）**：

1. **根**要么是叶子，要么有 $2 \sim M$ 个孩子；
2. **除根以外的所有非叶结点**有 $\lceil M/2\rceil \sim M$ 个孩子；
3. **所有叶子在同一深度**（all leaves are at the same depth）；
4. 假设每个非根**叶子**也含 $\lceil M/2\rceil \sim M$ 个数据项（key）；
5. **所有真实数据（actual data）都存在叶子上**；内部结点只存「索引」；
6. 每个内部结点含 $M$ 个指向孩子的指针，以及 $M-1$ 个「子树中的最小关键字」（第一个子树的最小值不存，因为可由前一个推出）—— 即内部结点的 key 是**对应子树的最小值**。

![图 2-7 一棵 order 4 的 B+ 树（即 2-3-4 树）：数据全在叶，内部结点存各子树最小关键字](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig07_slide09.webp)

**B+ 树 vs B 树**：
- B 树的内部结点也存数据；**B+ 树所有数据只在叶子**，内部结点纯索引 → 同样大小的结点能容纳更多 key → 扇出（fanout）更大 → 树更矮；
- B+ 树的叶子通常用**链表串起来**，支持高效**范围查询（range query）**与顺序扫描 —— 这是数据库索引偏爱 B+ 树的原因；
- 查找在 B+ 树中**一定走到叶子**（即使内部结点命中也要继续往下），代价稳定；B 树可能提前命中。

### 5.3 查找（Find）

从根开始，在结点内找到第一个 $> x$ 的 key 的左邻指针，逐层下降，直到叶子。

课件例子（order 3，即 2-3 树）：Find 52 → 根 `16 | 41`，$52 > 41$ 走第三个孩子 `41,52 | 58,59,61` → 在叶子中找到 52。

### 5.4 插入（Insert）与分裂

**课件算法（通用 order M）**：

```
Btree Insert( ElementType X, Btree T )
{
    从根到叶搜索 X，找到合适的叶结点;
    把 X 插入该叶子;
    while ( 该结点有 M+1 个 key ) {          /* 上溢 overflow */
        把它分裂成两个结点，分别含 ⌈(M+1)/2⌉ 和 ⌊(M+1)/2⌋ 个 key;
        if ( 该结点是根 )
            新建一个根，含两个孩子;          /* 树高 +1 */
        检查其父结点（把分裂出的最小 key 上移）;
    }
}
```

**课件 order 3（2-3 树）的插入序列演示**（初始叶子：`8,11,12` `16,17` `22,23,31` `41,52` `58,59,61`）：

| 操作 | 结果与说明 |
|---|---|
| Insert 18 | `16,17` → `16,17,18`，3 个 key 已满但合法（阶 3 的叶子最多 3 个 key） |
| Insert 1 | `8,11,12` 满 → 分裂为 `1,8` 与 `11,12`，`11` 上移到父结点；若父也溢出则继续上传 |
| Insert 19 | `16,17,18` 分裂 → `16,17` 与 `18,19`，`18` 上移 |
| Insert 28 | `22,23,31` → `22,23` / `28,31`，`28` 上移 |
| Insert 70 | `58,59,61` → `58,59` / `61,70`，`61` 上移 |

![图 2-8 order 3 的 B+ 树插入演示（Find 52，Insert 18/1/19/28），可见分裂与上移](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig08_slide10.webp)

**要点**：
- B+ 树是**「从下往上长」**的：分裂只沿根路径上传，最多 $O(\log_M N)$ 层；
- 与红黑树不同，**B+ 树的分裂把「高度增长」推迟到根分裂**，因此所有叶子始终同深度。

### 5.5 删除（Delete）与借/合并

删除时若叶子 key 数低于 $\lceil M/2\rceil$ 就**下溢（underflow）**：

1. **先向兄弟借（borrow）**：先找**有富余 key（多于下限）的兄弟**，通过父结点「旋转」一个 key 过来（课件：「First find a sibling with 2 keys and adjust. Keep more nodes full.」）；
2. **兄弟也穷则合并（merge）**：把两个结点 + 父结点中的分隔 key 合并成一个结点；
3. 合并可能导致父结点下溢 → **继续向上**；
4. **删除与插入类似，区别只在于：当根失去两个孩子（只剩一个孩子）时要把根删除**，树高 −1。

![图 2-9 删除时的「先借后并」：先找有 2 个 key 的兄弟调整，保持结点尽量满](ADS/pictures/Chapter%202%20%E7%BA%A2%E9%BB%91%E6%A0%91%E4%B8%8EB%2B%E6%A0%91%20AI%E7%B2%BE%E8%AE%B2/fig09_slide11.webp)

> 「Keep more nodes full」是 B 树实现的经典优化：**优先借、避免合并**，可减少结点数、提升后续查询与空间利用率。

### 5.6 复杂度分析

- **树高（depth）**：每个内部结点至少 $\lceil M/2\rceil$ 个孩子，故

$$\text{Depth}(M,N) = O\left(\log_{\lceil M/2\rceil} N\right)$$

- **单结点内查找**：顺序扫描 $O(M)$；若结点内用二分，则 $O(\log M)$。
- 因此总查找时间：

$$T(M,N) = O\left(\frac{M}{\log M}\log N\right) \quad(\text{顺序扫描时}) \qquad T_{\text{Find}}(M,N) = O(\log N)$$

- **最优的 $M$ 是 3 或 4**（课件结论）：$M$ 太小退化成二叉树，$M$ 太大则结点内比较开销与结点尺寸（一次 I/O 传输量）不划算。实际系统中 $M$ 常取「一个磁盘页能装下的最大值」（如 4KB / 8KB 页对应数百阶）。

## 6. 易错点与考点清单

1. **5 条红黑性质**要能背；特别注意**叶子 NIL 是黑的**、**根是黑的**、**黑高不含自身**。
2. 高度引理：$N \ge 2^{bh}-1$ 且 $h \le 2bh$ ⟹ $h \le 2\log_2(N+1)$；证明靠**对高度归纳 + 红结点不能相邻**。
3. **插入先染红**（保性质 5），只在「红-红」时修复；**插入 Case 1 可能一路上移**，Case 2→3 最多 2 旋。
4. **删除只有删黑结点才修复**；双黑（double black）的本质是「这条路径少了一个黑」。
5. 删除 **Case 1 不解决问题**（只是把兄弟变黑），**Case 2 会把问题交给父结点**（可能一直传到根），**Case 3 转 Case 4**，**Case 4 一定结束**。区分「近侧/远侧孩子」是常见失分点。
6. **红黑树 ↔ 2-3-4 树**的合并规则要会画（黑结点 + 红孩子合并）。
7. B+ 树**数据只在叶子**，内部结点 key = 子树最小关键字（第一个子树不存）；**所有叶子同深度**。
8. B+ 树插入分裂成 $\lceil (M+1)/2\rceil$ 与 $\lfloor (M+1)/2\rfloor$；删除**先借后并**，根只剩一个孩子时删根。
9. **$M$ 的最优值是 3 或 4**；B+ 树高度 $O(\log_{\lceil M/2\rceil}N)$，不要错写成 $O(\log_M N)$。
