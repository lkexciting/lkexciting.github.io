## §2.1 引言：什么是指令集

- **指令集**（instruction set）：一台计算机**全部指令的集合**（repertoire of instructions）
- 不同计算机的指令集不同，但**本质相通**（many aspects in common）
- 早期计算机的指令集很简单 —— 为了**简化实现**（simplified implementation）
- 现代计算机（RISC 阵营）重新回到简单指令集
- 核心思想：**存储程序**（stored program）——指令和数据一样以二进制存在存储器里，因此"程序可以处理程序"（编译器、链接器就是这样的程序）

### RISC-V 简介

- 全书统一使用的示例 ISA；由 **UC Berkeley** 开发，**开放 ISA**（open ISA）
- 现由 **RISC-V Foundation**（riscv.org）管理
- 设计理念：**简洁（simple）、模块化（modular）、可扩展（extensible）**
- 与现代主流 ISA 同类（RISC 风格），在嵌入式核市场占有很大份额（消费电子、网络/存储设备、相机、打印机等）
- 与 MIPS 的关系：MIPS 是 RISC-V 的"商业前身"，二者指令集高度相似（§2.16）

> 为什么学 RISC-V 而不是 x86？因为它**规整**：32 位定长指令、少量格式、load/store 架构。规整性使第 4 章的硬件实现（尤其是译码）变得简单，这正是"简单源于规整"的回报。

## §2.2 计算机硬件的操作（Arithmetic Operations）

### 2.2.1 三操作数形式

RISC-V 算术指令一律是**三操作数**：两个源（source）、一个目的（destination）。

```
add a, b, c        // a gets b + c
sub a, b, c        // a gets b - c
```

### 2.2.2 设计原则 1：简单源于规整（Simplicity favors regularity）

- **规整**（regularity）使实现更简单
- 简单 → 更低的成本实现更高的性能（simplicity enables higher performance at lower cost）
- 反面教材：x86 的 `add` 可以是"寄存器+寄存器""寄存器+内存""内存+立即数"…… 译码器极其复杂（§2.17）

### 2.2.3 编译示例

```c
f = (g + h) - (i + j);
```

```asm
add t0, g, h      # t0 = g + h
add t1, i, j      # t1 = i + j
sub f, t0, t1     # f = t0 - t1
```

> 注意最后一条是 `sub` 而不是 `add`（讲义 P8 此处有笔误）。RISC-V **没有**"三操作数 + 一个内存操作数"的形式，每个操作数都必须是寄存器或立即数。

## §2.3 计算机硬件的操作数（Operands）

### 2.3.1 寄存器操作数

- 算术指令的操作数放在**寄存器**（register）里
- RISC-V 有 **32 × 64 位**的**寄存器堆**（register file）
	- 64 位数据称为**双字**（doubleword）
	- 32 位数据称为**字**（word）
- 用途：存放**频繁访问**的数据

**设计原则 2：越小越快（Smaller is faster）**

> 对比主存：主存有数百万个位置，访问要几十上百个周期；寄存器只有 32 个，访问在 1 个周期内完成。**"寄存器少"是优点不是缺点**——地址译码简单、连线短、访问快。

### 2.3.2 RISC-V 寄存器约定（必背）

| 寄存器 | ABI 名 | 用途 | 保存者（Saver） |
|---|---|---|---|
| x0 | zero | 常量 0（**不可写**） | n.a. |
| x1 | ra | 返回地址（return address） | caller |
| x2 | sp | 栈指针（stack pointer） | callee |
| x3 | gp | 全局指针（global pointer） | —— |
| x4 | tp | 线程指针（thread pointer） | —— |
| x5–x7 | t0–t2 | 临时寄存器（temporary） | caller |
| x8 | s0 / fp | 保存寄存器 / 帧指针（frame pointer） | callee |
| x9 | s1 | 保存寄存器 | callee |
| x10–x11 | a0–a1 | 参数 / 返回值 | caller |
| x12–x17 | a2–a7 | 参数 | caller |
| x18–x27 | s2–s11 | 保存寄存器 | callee |
| x28–x31 | t3–t6 | 临时寄存器 | caller |
| f0–f31 | ft0–ft11, fs0–fs11, fa0–fa7 | 浮点寄存器 | 见 ABI |

> 口诀：**a 传参、ra 返回、sp 指栈、s 要保、t 随便用**。
> "Saver = caller" 意思是：**调用者**若想在调用返回后还用到这些寄存器，就自己先存起来；"callee" 意思是**被调用者**必须保证返回时这些寄存器的值不变。

### 2.3.3 寄存器操作数示例

```c
f = (g + h) - (i + j);   // f..j 分别在 x19..x23
```
```asm
add x5, x20, x21     # x5 = g + h
add x6, x22, x23     # x6 = i + j
sub x19, x5, x6      # f = x5 - x6
```

### 2.3.4 存储器操作数

- 主存用于存放**复合数据**（composite data）：数组（array）、结构体（structure）、动态数据
- 要对内存数据做算术，必须先**装入寄存器**（load），算完再**存回内存**（store）
- 这就是 **load-store 架构**：只有 `ld/sd/lw/sw…` 能访问存储器

**关键约定**：

| 约定 | RISC-V 的做法 |
|---|---|
| 编址单位 | **按字节编址**（byte addressed），每个地址对应一个 8 位字节 |
| 字节序 | **小端**（little endian）：最低有效字节放在最低地址 |
| 对齐 | RISC-V **不要求**字对齐（unlike some other ISAs），但硬件上非对齐访问可能更慢 |

### 2.3.5 大端 vs 小端（Endian-ness）

```
内存地址:   100   101   102   103
内容:       45    7b    87    7f
```

| 解释方式 | 32 位值 |
|---|---|
| Big-endian | `45 7b 87 7f`（最高有效字节在最低地址） |
| Little-endian | `7f 87 7b 45`（最低有效字节在最低地址） |

RISC-V 采用 **little endian**。网络字节序（network byte order）传统上是 big endian —— 这是"字节序转换函数"存在的原因。

### 2.3.6 内存操作数示例

```c
A[12] = h + A[8];    // h in x21, base address of A in x22
```
```asm
ld  x9, 64(x22)      # x9 = A[8]   （8 个元素 × 8 字节 = 64）
add x9, x21, x9      # x9 = h + A[8]
sd  x9, 96(x22)      # A[12] = x9  （12 × 8 = 96）
```

- 语法：`ld rd, offset(rs1)` → 有效地址 = `rs1 + offset`（**基址+偏移** base + displacement 寻址）
- **下标要乘元素大小**：`long long` 占 8 字节 → 下标 i 的偏移是 8i（用 `slli rd, rs, 3` 实现）

### 2.3.7 寄存器 vs 存储器

| | 寄存器 | 存储器 |
|---|---|---|
| 速度 | 极快（1 周期） | 慢（几十~上百周期） |
| 数量 | 32 个 | 数百万位置 |
| 访问方式 | 任何指令 | **只能** load/store |

因此**编译器要尽可能把变量放在寄存器里**，只把"不常用"的变量**溢出**（spill）到内存。寄存器分配（register allocation）是编译器优化的核心问题之一。

### 2.3.8 立即数操作数（Immediate Operands）

```
addi x22, x22, 4      # x22 = x22 + 4
```

- **没有** `subi` 指令 —— 直接用负常数：`addi x22, x22, -4`
- 立即数在指令里**直接编码**，不需要额外一条 load

**设计原则 3：让常见情况变快（Make the common case fast）**

> 程序中大量出现 `i++`、`p+4` 这类小常数运算。给立即数一个位置，就省掉了一次访存/一次额外指令——这就是"常见情况快"。

### 2.3.9 常量 0：寄存器 x0

- `x0` 恒为 0，**不可被改写**
- 常用技巧：
	- 寄存器间传送：`add x22, x23, x0`（等价伪指令 `mv x22, x23`）
	- 无条件跳转：`beq x0, x0, Label`（等价 `j Label`）
	- 清零：`add x5, x0, x0`

## §2.4 有符号数与无符号数（Signed and Unsigned Numbers）

### 2.4.1 无符号二进制整数

x=x_(n-1)2^(n-1)+x_(n-2)2^(n-2)+⋯+x_1 2¹+x_0 2⁰

- 范围：0∼+2ⁿ-1
- 64 位：0∼18446774073709551615
- LSB（least significant bit，最低有效位）在右，MSB（most significant bit）在左

**例**：`0000 ... 0000 1011₂` =1×2³+0×2²+1×2¹+1×2⁰=8+2+1=11₁₀

### 2.4.2 进制表示与转换

- 十进制 3510=3×10³+5×10²+1×10¹+0（按"权"展开）
- 二进制 `0010 0011₂` =1×2⁵+1×2¹+1×2⁰=35
- 十六进制（hexadecimal）：每 4 位一组，`0x23` =2×16¹+3×16⁰

| Dec | Bin | Hex | Dec | Bin | Hex | Dec | Bin | Hex | Dec | Bin | Hex |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 0 | 0000 | 0 | 4 | 0100 | 4 | 8 | 1000 | 8 | 12 | 1100 | c |
| 1 | 0001 | 1 | 5 | 0101 | 5 | 9 | 1001 | 9 | 13 | 1101 | d |
| 2 | 0010 | 2 | 6 | 0110 | 6 | 10 | 1010 | a | 14 | 1110 | e |
| 3 | 0011 | 3 | 7 | 0111 | 7 | 11 | 1011 | b | 15 | 1111 | f |

**八/十六进制 ↔ 二进制**（直接分组）：

- 13.724_8=001011.111010100_2=1011.1110101_2
- 2b.5e₁₆=00101011.01011110_2=101011.0101111_2
- 0.10101_2=000.101010_2=0.52_8
- 11001.11_2=00011001.1100_2=19.c₁₆

**R 进制 → 十进制**（按权展开）：

- 10101.01_2=1×2⁴+1×2²+1×2⁰+1×2^(-2)=21.25₁₀
- 307.6_8=3×8²+7×8⁰+6×8^(-1)=199.75₁₀
- 3a.1₁₆=3×16¹+10×16⁰+1×16^(-1)=58.0625₁₀

**十进制 → 二进制**：

- 整数部分："**除基取余，上右下左**"
- 小数部分："**乘基取整，上左下右**"
- ⚠️ 小数部分可能**永远乘不到 0**（如 0.1），此时只能得到近似值
- 实用技巧：整数拆成 2^k 之和，小数拆成 0.5,0.25,0.125,… 之和
	- 4123.25=4096+16+8+2+1+0.25=1000000011011.01_2=101b.4₁₆
	- 4023=(4096-1)-64-8=111111111111_2-1000000_2-1000_2=111110110111_2=fb7₁₆

### 2.4.3 补码（2's Complement）

**位模式含义**（n 位）：

x=-x_(n-1)2^(n-1)+x_(n-2)2^(n-2)+⋯+x_0 2⁰

- 第 63 位是**符号位**（sign bit）：1 表示负数，0 表示非负
- 非负数的补码表示与无符号表示**完全相同**
- 范围：-2^(n-1)∼+2^(n-1)-1（64 位：-9223372036854775808∼9223372036854775807）

**例**：`1111 ... 1111 1100₂` =-1×2^(31)+1×2^(30)+⋯=-2147483648+2147483644=-4

**几个特殊值**：

```
0            : 0000 0000 ... 0000
-1           : 1111 1111 ... 1111
最负（most-negative）: 1000 0000 ... 0000
最正（most-positive）: 0111 1111 ... 1111
```

> 注意：**负数比正数多一个**（-2^(n-1) 有表示，+2^(n-1) 没有）。2^(n-1) 无法表示 —— 这是第 3 章"溢出"的根源。

### 2.4.4 补码的本质：模运算（Modular Arithmetic）

**核心定义**（n 位定点整数）：

[X]_(补)=2ⁿ+X (-2ⁿ≤X<2ⁿ, mod 2ⁿ)

> （定点小数 [X]_补=2+X 在计算机中**不使用**，无需掌握。）

**钟表比喻**：模 12 系统中，-4≡8(mod 12)。时针从 10 点拨到 6 点：
- 倒拨 4 格：10-4=6
- 顺拨 8 格：10+8=18≡6(mod 12)

⇒ -4 的模 12 补码=8

**关键结论**：

1. **一个负数的补码 = 模 − 该负数的绝对值**
2. 对确定的模，x 减 y 总可以用 x 加 -y 的补码代替 → **加法和减法统一为加法**（硬件只需一个加法器！）

**现实例子**：

- 算盘只有 4 档且只能加：9828-1928=9828+(10⁴-1928)=9828+8072=17900→7900（高位 1 被丢弃）
- 8 位加法器：01111111-01000000=01111111+(2⁸-01000000)=01111111+11000000=100111111→00111111

**推论（求补码的实用方法）**：负数的补码 = 对应正数**各位取反、末位加 1**。

[-123]_(补)=128-01111011_2=11111111_2-01111011_2+1=10000100_2+1=10000101_2

### 2.4.5 取负（Signed Negation）

x̄+x=1111…111_2=-1 ⇒ x̄+1=-x

**例**：+2=0000…0010_2 → -2=1111…1101_2+1=1111…1110_2

### 2.4.6 符号扩展（Sign Extension）

用更多位表示同一个数：**把符号位向左复制**（无符号数则补 0）。

```
+2: 0000 0010  =>  0000 0000 0000 0010
-2: 1111 1110  =>  1111 1111 1111 1110
```

RISC-V 中发生符号扩展的地方（考点）：

| 指令 | 扩展方式 |
|---|---|
| `lb`（load byte） | **符号**扩展到 64 位 |
| `lbu` | **零**扩展 |
| `lh` / `lhu` | 符号 / 零扩展 |
| `lw` / `lwu` | 符号 / 零扩展 |
| `addi` 等 I 型 | 立即数**符号扩展** |
| `beq, bne` | 位移量**符号扩展** |
| 逻辑运算与立即数 | 高位**补 0**（零扩展，见 P58） |

> ⚠️ 易错：**逻辑指令的立即数补 0，算术指令的立即数符号扩展**。因为逻辑运算关心的是位模式，不是数值。

### 2.4.7 其他编码：原码、反码、移码

| 编码 | 规则 | 缺点/用途 |
|---|---|---|
| **原码**（sign and magnitude） | 最高位符号 + 其余为幅值 | 0 有两种表示（+0/-0）；加减不统一；需额外处理符号位；a<b 时做 a-b 困难。**现仅用于浮点数尾数** |
| **反码**（1's complement） | 各位取反，x 的相反数为 2ⁿ-x-1 | 保留两个 0（全 0 与全 1）；加法后需"减 1"修正 |
| **移码**（biased / excess-N） | 数值 + 偏置 2^(n-1) | 最小负数 `00...0`，最大正数 `11...1`，0 为 `10...0`；**用于浮点数的阶码** |

**移码的作用**：让**比较大小等同于无符号比较**，便于浮点加减时的**对阶**操作。

```
例：1.01×2^(-1) + 1.11×2^3
补码比较阶码：111(-1) < 011(3)   ← 需要判符号
移码比较阶码：011(3)  < 111(7)   ← 直接当无符号比
```

n=4 时 bias =2³=8：-8→0000，-7→0001，…，0→1000，…，+7→1111。

## §2.5 计算机中指令的表示（Representing Instructions）

### 2.5.1 机器码与规整性

- 指令被编码为**二进制**，称为**机器码**（machine code）
- RISC-V 指令编码为 **32 位指令字**（32-bit instruction word）
- 用**少量格式**（format）编码操作码（opcode）、寄存器号等
- 关键词：**规整性（Regularity）**

### 2.5.2 六种基本格式

#### R 型（register-register）

![[Ch2-P44-R型指令格式.webp]]

| funct7 | rs2 | rs1 | funct3 | rd | opcode |
|---|---|---|---|---|---|
| 7 位 [31:25] | 5 位 [24:20] | 5 位 [19:15] | 3 位 [14:12] | 5 位 [11:7] | 7 位 [6:0] |

- 用于：**所有操作数都在寄存器**的算术、逻辑、移位指令
- 字段含义：
	- `opcode`：操作码（主操作）
	- `rd`：目的寄存器号（destination）
	- `funct3`：3 位功能码（附加操作码）
	- `rs1`：第一个源寄存器号
	- `rs2`：第二个源寄存器号
	- `funct7`：7 位功能码（附加操作码）
- opcode = `0110011`（0x33）；`0111011`（0x3B，用于 W 后缀的 32 位版本）

**编码示例**：`add x9, x20, x21`

![[Ch2-P45-R型指令编码示例.webp]]

```
funct7=0000000  rs2=10101(=21)  rs1=10100(=20)  funct3=000  rd=01001(=9)  opcode=0110011(=51)
→ 0000 0001 0101 1010 0000 0100 1011 0011₂ = 0x015A04B3
```

#### I 型（immediate）

![[Ch2-P46-I型指令格式.webp]]

| immediate | rs1 | funct3 | rd | opcode |
|---|---|---|---|---|
| 12 位 [31:20] | 5 位 | 3 位 | 5 位 | 7 位 |

- 用于：**立即数算术**（`addi`）与**取数**（`ld/lw/lb…`）、`jalr`
- `rs1`：源寄存器号 **或基地址寄存器号**
- `immediate`：常数操作数，**或加到基地址上的偏移**；**补码表示、符号扩展**
- opcode：`addi` 等 = `0010011`（0x13）；load = `0000011`（0x03）；`jalr` = `1100111`（0x67）

**设计原则 4：好的设计需要好的折中（Good design demands good compromises）**

> 不同格式让译码变复杂，但能保证"**所有指令都是 32 位**"，从而使取指、PC 递增统一。教材强调：把格式**尽量做得相似**（rs1、rs2、rd 尽量固定在相同位置），这就是折中的智慧。

#### S 型（store）

![[Ch2-P47-S型指令格式.webp]]

| imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode |
|---|---|---|---|---|---|
| 7 位 [31:25] | 5 位 | 5 位 | 3 位 | 5 位 [11:7] | 7 位 |

- store 指令需要**两个源**（基址 + 要存的值），**没有 rd**
- 为了**让 rs1、rs2 始终位于相同的位位置**（与 R 型一致），立即数被**劈成两半**：高 7 位放 [31:25]，低 5 位放 [11:7]
- opcode = `0100011`（0x23）

> 这就是"折中"的直接体现：**牺牲"立即数连续"换取"寄存器字段固定"**，因为译码器最常做的是"读两个寄存器"，让它们在固定位置能省硬件。

#### B 型（branch，SB 格式）

| imm[12] | imm[10:5] | rs2 | rs1 | funct3 | imm[4:1] | imm[11] | opcode |
|---|---|---|---|---|---|---|---|
| [31] | [30:25] | 5 位 | 5 位 | 3 位 | [11:8] | [7] | 7 位 |

- **PC 相对寻址**（PC-relative addressing）：目标地址 = PC + 立即数
- 立即数的最低位**恒为 0**（指令按 2 字节对齐），故不编码 imm[0]，相当于免费获得 1 位范围
- 范围：±4 KiB；opcode = `1100011`（0x63）

#### U 型（upper immediate）

| imm[31:12] | rd | opcode |
|---|---|---|
| 20 位 [31:12] | 5 位 | 7 位 |

- `lui rd, imm`：把 20 位常数放到 rd 的 [31:12]，**低 12 位清 0**，并把 bit31 符号扩展到 [63:32]
- `auipc rd, imm`：rd = (imm<<12) + PC
- opcode：`lui` = `0110111`（0x37）；`auipc` = `0010111`（0x17）

#### J 型（jal，UJ 格式）

| imm[20] | imm[10:1] | imm[11] | imm[19:12] | rd | opcode |
|---|---|---|---|---|---|
| [31] | [30:21] | [20] | [19:12] | 5 位 | 7 位 |

- 20 位立即数（编码 21 位，最低位隐含 0）→ 范围 **±1 MiB**
- PC 相对；opcode = `1101111`（0x6F）

### 2.5.3 机器码综合示例

```c
A[30] = h + A[30] + 1;      // h in x21, base of A in x10
```

```asm
ld   x9, 240(x10)     # load A[30]  (30×8=240)
add  x9, x21, x9
addi x9, x9, 1
sd   x9, 240(x10)     # store A[30]
```

![[Ch2-P50-机器码示例.webp]]

| 指令 | 格式 | 十六进制机器码 |
|---|---|---|
| `ld x9, 240(x10)` | I | `0f05 3483` |
| `add x9, x21, x9` | R | `009a 84b3` |
| `addi x9, x9, 1` | I | `0014 8493` |
| `sd x9, 240(x10)` | S | `0e95 3823` |

**手算 `add x9, x21, x9`**：funct7=0，rs2=9，rs1=21，funct3=0，rd=9，opcode=0x33
`0000000 01001 10101 000 01001 0110011` → `0000 0000 1001 1010 1000 0100 1011 0011` = **0x009A84B3** ✓

**手算 `sd x9, 240(x10)`**：imm=240=0x0F0=0000 1111 0000
- imm[11:5]=0000111，rs2=9，rs1=10，funct3=011，imm[4:0]=10000，opcode=0100011
- `0000111 01001 01010 011 10000 0100011` = **0x0E953823** ✓

### 2.5.4 反向解码（考试常见）

**例**：`0x00578833` 是什么指令？

```
0x00578833 → 0000 0000 0101 0111 1000 1000 0011 0011
opcode = 0110011 → R 型
funct7=0000000  rs2=00101(5)  rs1=01111(15)  funct3=000  rd=10000(16)
→ add x16, x15, x5
```

> 解码步骤固定：**① 取低 7 位定格式 → ② 按格式切字段 → ③ 查 funct3/funct7 定操作**。

### 2.5.5 存储程序的意义

![[Ch2-P106-翻译与启动流程.webp]]

- 指令以二进制表示，**与数据无异**
- 指令和数据都存在存储器中
- 因此**程序可以操作程序**（编译器、链接器就是这样的程序）
- **二进制兼容**（binary compatibility）使得编译好的程序能在不同机器上运行（前提：标准化的 ISA）

## §2.6 逻辑运算（Logical Operations）

### 2.6.1 六组操作

| 操作 | C | Java | RISC-V（寄存器） | RISC-V（立即数） |
|---|---|---|---|---|
| 左移 shift left | `<<` | `<<` | `sll` | `slli` |
| 逻辑右移 shift right logical | `>>`（无符号） | `>>>` | `srl` | `srli` |
| 算术右移 shift right arithmetic | `>>`（有符号） | `>>` | `sra` | `srai` |
| 按位与 AND | `&` | `&` | `and` | `andi` |
| 按位或 OR | `\|` | `\|` | `or` | `ori` |
| 按位异或 XOR | `^` | `^` | `xor` | `xori` |
| 按位取反 NOT | `~` | `~` | —— | `xori rd, rs, -1` |

> RISC-V **没有** `not` 指令，用 `xori rd, rs, -1` 实现（与全 1 异或 = 取反）。同理**没有** `mov`，用 `add rd, rs, x0`。

### 2.6.2 移位（Shift）

- `slli`（shift left logical immediate）：左移补 0；**左移 i 位 = 乘 2ⁱ**
- `srli`：右移补 0；**右移 i 位 = 除 2ⁱ**（仅无符号）
- `srai`：右移补**符号位**；用于有符号除法（向负无穷取整）

> ⚠️ 有符号除法与算术右移的区别：C 的 `/` 是**向 0 取整**（-7/2 = -3），而 `srai` 是**向下取整**（-7>>1 = -4）。编译器需要额外的修正指令。

**I 型移位指令格式**（RV64 变体）：

| funct6 | immed | rs1 | funct3 | rd | opcode |
|---|---|---|---|---|---|
| 6 位 | 6 位 | 5 位 | 3 位 | 5 位 | 7 位 |

（RV32 中移位量只需 5 位，故为 funct7 + shamt[4:0]）

### 2.6.3 掩码操作（Masking）

**AND 用于"选位"**（某些位置 1，其余清 0）：

```
x10 = ... 0000 1101 1100 0000
x11 = ... 0000 0011 1100 0000   ← 掩码
x9  = ... 0000 0000 1100 0000   ← and x9,x10,x11（只保留掩码为 1 的位）
```

**OR 用于"置位"**（某些位设为 1，其余不变）：

```
x9 = ... 0000 0011 1101 1100
```

**XOR 用于"取反/求差"**：

```
x12 = 1111 ... 1111           ← 全 1
x9  = ~x10                    ← xor x9,x10,x12
```

### 2.6.4 立即数扩展的差异（易错）

- 与立即数做**逻辑**运算：立即数高位**补 0**（零扩展）后形成 64 位常数
- 与立即数做**加法**运算：立即数**符号扩展**

## §2.7 决策指令（Instructions for Making Decisions）

程序根据输入数据与计算结果选择不同的执行路径 —— 这靠**条件分支**（conditional branch）与**无条件跳转**（unconditional jump）实现。

### 2.7.1 基本分支指令

| 指令 | 含义 | 依据 |
|---|---|---|
| `beq rs1, rs2, L1` | if (rs1 == rs2) goto L1 | 相等 |
| `bne rs1, rs2, L1` | if (rs1 != rs2) goto L1 | 不等 |
| `blt rs1, rs2, L1` | if (rs1 < rs2) goto L1 | 有符号小于 |
| `bge rs1, rs2, L1` | if (rs1 >= rs2) goto L1 | 有符号大于等于 |
| `bltu` / `bgeu` | 同上，但按**无符号**比较 | |
| `jal` / `jalr` | 无条件跳转 | |

- 条件为真则跳到**标号**（label）处，否则**顺序执行**（continue sequentially）
- `beq` 采用 **PC 相对寻址**：`PC = PC + (L1_offset)`

### 2.7.2 编译 if-else

```c
if (i == j) f = g + h;
else        f = g - h;      // f..j in x19..x23
```

```asm
      bne x22, x23, Else     # i != j → Else
      add x19, x20, x21      # f = g + h
      beq x0, x0, Exit       # 无条件跳转（x0==x0 恒真）
Else: sub x19, x20, x21      # f = g - h
Exit: ...
```

> 技巧：**把条件"反过来写"**（`==` 用 `bne` 跳走），让"then 分支"顺序执行——因为 then 分支通常更常见，跳转更少（"让常见情况变快"）。

### 2.7.3 编译 while 循环

```c
while (save[i] == k) i += 1;   // i in x22, k in x24, &save in x25
```

```asm
Loop: slli x10, x22, 3        # x10 = i * 8
      add  x10, x10, x25      # x10 = &save[i]
      ld   x9, 0(x10)         # x9 = save[i]
      bne  x9, x24, Exit      # 若不等于 k，退出
      addi x22, x22, 1        # i++
      beq  x0, x0, Loop       # 无条件回到循环头
Exit: ...
```

> 骨架记忆：**"测试在头、跳回在尾"**。C 的 `for` 也可以编译成同样结构（初始化 → 测试 → 体 → 步进 → 跳回）。

### 2.7.4 基本块（Basic Block）

- 定义：一段指令序列，满足
	- **没有内嵌分支**（除末尾）
	- **没有分支目标**（除开头）
- 用途：编译器以基本块为单位做优化；高级处理器可以**加速基本块的执行**（分支预测、指令预取）
- 这是第 4 章"分支预测"和第 5 章"指令 Cache"的天然单位

### 2.7.5 更多条件：blt / bge

```c
if (a > b) a += 1;     // a in x22, b in x23
```
```asm
      bge x23, x22, Exit    # if (b >= a) skip
      addi x22, x22, 1
Exit:
```

> 注意"取反"：`a > b` 的补集是 `a <= b`，即 `b >= a` → 用 `bge`。**RISC-V 没有 `bgt`/`ble`**，用交换操作数 + `blt/bge` 实现。

### 2.7.6 有符号 vs 无符号（重点）

```
x22 = 1111 1111 1111 1111 1111 1111 1111 1111
x23 = 0000 0000 0000 0000 0000 0000 0000 0001
```

- 按**有符号**解释：x22 = −1 < x23 = +1 → `blt` 成立
- 按**无符号**解释：x22 = 4 294 967 295 > x23 = 1 → `bltu` 不成立

> 同一组位模式，**比较结果完全相反**。选错指令是经典 bug。

### 2.7.7 边界检查技巧（Bound Checking）

要把"数组下标越界"检查写成**一条指令**：

```c
if (0 <= x && x < y) ...   // 常规写法需要两次比较
```

技巧：**把有符号数当无符号数比较**

```asm
bgeu x20, x11, IndexOutOfBounds   # if (x >= y) 越界
```

- 若 x 是负数，其无符号值巨大 → `bgeu` 必然成立 → 被判越界
- 因此 **一个无符号比较同时检查了 "x<0" 和 "x≥y"**
- 常用于 `array[i]` 的越界检查（C 语言标准库/内核大量使用）

### 2.7.8 课堂练习（含答案）

**(1) 汇编 → 机器码**

```asm
LOOP: beq  x6, x0, DONE
      addi x6, x6, -1
      addi x5, x5, 2
      jal  x0, LOOP
DONE:
```

设 LOOP 地址为 0：

| 指令 | 机器码 | 计算要点 |
|---|---|---|
| `beq x6,x0,DONE`（offset=12） | `0x00030663` | imm[4:1]=0110 → bits[11:8]；rs1=6 → bits[19:15] |
| `addi x6,x6,-1` | `0xFFF30313` | imm=−1=0xFFF |
| `addi x5,x5,2` | `0x00228293` | imm=2 |
| `jal x0,LOOP`（offset=−12） | `0xFF5FF06F` | imm[20:1]=−6 → 0b1111111010 |

**(2) 循环编译（讲义 P70 例题，注意此处用 2ⁱ 左移 2 位即 ×4）**

```c
for (i=0;i<n;i++) g = g + A[i];   // n→x5, g→x6, A→x7
```
```asm
      add  x10, x0, x0      # i = 0
L1:   sll  x11, x10, 2      # x11 = i * 4   ← 讲义写法（若元素为 8 字节应用 slli 3）
      add  x11, x11, x7     # x11 = &A[i]
      ld   x12, 0(x11)      # x12 = A[i]
      add  x6, x6, x12      # g = g + A[i]
      addi x10, x10, 1      # i++
      bne  x10, x5, L1      # i != n 继续
```

> ⚠️ 讲义此处用 `sll x11,x10,2`（×4），但题目声明 `sizeof(long long int)=8`。严格应为 `slli x11,x10,3`。**考试按元素大小 8 字节 → 左移 3 位**。

## §2.8 支持计算机硬件中的过程（Procedures）

### 2.8.1 过程调用的六步

1. 把**参数**放到 `x10–x17`（a0–a7）
2. **转移控制**到过程（procedure）
3. 为过程**分配存储空间**（栈帧）
4. 执行过程的**操作**
5. 把**结果**放到调用者可见的寄存器（`x10–x11`）
6. **返回**到调用点（地址在 `x1`）

### 2.8.2 调用与返回指令

| 指令 | 语义 |
|---|---|
| `jal x1, ProcedureLabel` | **jump and link**：把下一条指令地址（PC+4）存入 x1，跳到目标 |
| `jalr x0, 0(x1)` | **jump and link register**：跳到 `x1 + 0`，返回值丢弃（rd=x0） |
| `jalr x0, 100(x5)` | 计算跳转（computed jump），如 `switch/case`、函数指针 |

> `jalr` 的 rd 用 x0 是因为**返回值不可写**，同时表示"不需要链接"。

### 2.8.3 叶过程（Leaf Procedure）

叶过程 = **不调用其他过程**的过程。

```c
long long int leaf_example(long long int g, long long int h,
                           long long int i, long long int j) {
  long long int f;
  f = (g + h) - (i + j);
  return f;
}
```
（g..j 在 x10..x13，f 用 x20，中间量用 x5、x6 → 需保存 x5、x6、x20）

```asm
      addi sp, sp, -24      # 栈帧 3 个字（24 字节）
      sd   x5, 16(sp)       # 保存 x5
      sd   x6, 8(sp)        # 保存 x6
      sd   x20, 0(sp)       # 保存 x20
      add  x5, x10, x11     # x5 = g + h
      add  x6, x12, x13     # x6 = i + j    ← 讲义此处误写 x1，应为 x13
      sub  x20, x5, x6      # f = x5 - x6
      addi x10, x20, 0      # 返回值放到 x10
      ld   x20, 0(sp)       # 恢复
      ld   x6, 8(sp)
      ld   x5, 16(sp)
      addi sp, sp, 24       # 弹出栈帧
      jalr x0, 0(x1)        # 返回
```

**栈帧（stack frame / activation record）的三个要点**：

1. **分配**：`addi sp, sp, -N`（栈向**低地址**增长）
2. **保存/恢复**：`sd` / `ld` 配对，顺序**相反**
3. **释放**：`addi sp, sp, +N`

> ⚠️ 栈帧大小应为 16 的倍数（ABI 对齐要求），例题用 24 是教材简化；实际 RV64 要求 `sp` 16 字节对齐。

### 2.8.4 非叶过程（Non-Leaf Procedure）

非叶过程要**递归调用**自己或别人，因此调用前必须保存：

- **返回地址 x1**（`jal` 会覆盖它！）
- 调用后仍需要的**参数**与**临时寄存器**

```c
long long int fact(long long int n) {
  if (n < 1) return 1;
  else return n * fact(n - 1);
}
```

```asm
fact: addi sp, sp, -16
      sd   x1, 8(sp)        # 保存返回地址
      sd   x10, 0(sp)       # 保存 n
      addi x5, x10, -1      # x5 = n - 1
      bge  x5, x0, L1       # if n >= 1 goto L1
      addi x10, x0, 1       # 否则返回 1
      addi sp, sp, 16
      jalr x0, 0(x1)
L1:   addi x10, x10, -1     # n = n - 1
      jal  x1, fact         # 递归调用
      addi x6, x10, 0       # x6 = 返回值
      ld   x10, 0(sp)       # 恢复 n
      ld   x1, 8(sp)        # 恢复返回地址
      addi sp, sp, 16
      mul  x10, x10, x6     # 返回 n * fact(n-1)
      jalr x0, 0(x1)
```

> 这就是**递归的机器级真相**：每一层调用在栈上压一个帧，`sp` 一路下移；返回时逐层弹出。栈溢出（stack overflow）就是这条链太长。

### 2.8.5 栈（The Stack）

![[Ch2-P80-栈的增长方向.webp]]

- 过程的寄存器值"看起来是易失的"——每次切换过程就消失了
- 因此把值**备份到内存中的栈**里
- 栈从**高地址向低地址**增长（stack grows this way ↓）
- `sp`（x2）指向**栈顶**（最低地址）

### 2.8.6 调用/返回时的存储管理

1. 新过程必须在栈上为自己的所有变量**创建空间**
2. 执行 `jal` 前，调用者必须把 `x1, x5–x7, x10–x17, x28–x31` 中**还要用**的值存到自己的栈空间
3. 参数复制到 `x10–x17`，然后执行 `jal`
4. 被调用者创建栈空间后**更新 x2(sp)**
5. 被调用者结束时把返回值放到 `x10/x11`，**释放栈空间**，`sp` 增加
6. 返回后，调用者可从栈中**恢复**自己的值

### 2.8.7 谁保存什么（Caller-saved vs Callee-saved）

| 类别 | 寄存器 | 规则 |
|---|---|---|
| **Caller saved**（调用者保存） | `x1`（ra）、`x5–x7`、`x10–x17`、`x28–x31` | 调用者若在返回后还要用，**自己先存** |
| **Callee saved**（被调用者保存） | `x8–x9`、`x18–x27` | 被调用者若要用，**必须先保存再恢复** |

细节：

- `x10–x17`：旧参数在设置新参数前必须保存
- `x1`：`jal` 会覆盖，故调用前必须保存
- `x5–x7, x28–x31`：如果返回后还要用临时值，保存它们（被调用者可以随意使用）
- 不必保存 `x8–x9, x18–x27`：被调用者会负责

> 记忆：**"t 和 a 是公共草稿纸（caller 自己收拾），s 是受保护席位（callee 负责复原）"**。

### 2.8.8 内存布局（Memory Layout）

![[Ch2-P84-内存布局.webp]]

| 段 | 内容 | 指针 |
|---|---|---|
| **Text** | 程序代码 | PC |
| **Static data**（静态数据段） | 全局变量、`static` 变量、常量数组/字符串 | `x3`（gp，global pointer），初始化为可 ±偏移访问该段的地址 |
| **Dynamic data**（堆 heap） | `malloc` / `new` 分配 | 向上（高地址）增长 |
| **Stack** | 自动存储（automatic storage） | `sp` 向下（低地址）增长 |

```
高地址
┌──────────────┐
│    Stack     │ ↓ 向下增长
├──────────────┤
│      ↓       │
│      ↑       │
├──────────────┤
│  Dynamic data│ ↑ 向上增长
├──────────────┤
│ Static data  │  (gp)
├──────────────┤
│    Text      │
└──────────────┘
低地址
```

> 堆与栈**相向增长**，中间的空隙就是"可用内存"；两者相遇即"内存耗尽"。

### 2.8.9 帧指针（Frame Pointer, x8/fp）

- 过程在栈上分配的空间叫**活动记录**（activation record）
- **帧指针 fp** 指向记录**起始处**，`sp` 指向**末尾**
- 为什么需要 fp：`sp` 在过程执行中可能变化（如 `alloca`、变长数组），而变量地址需要**稳定**的参照 → 用 `fp` 相对寻址
- `x3(gp)` 指向保存全局变量的区域；`malloc()` 的动态存储在堆上

> 现代编译器在 `-O2` 下常**省略 fp**（用 `sp` 相对寻址，省一个寄存器）——这解释了为什么"优化后的栈帧更难调试"。

## §2.9 与人沟通：字符数据（Character Data）

### 2.9.1 字符集

| 字符集 | 大小 | 说明 |
|---|---|---|
| **ASCII** | 128 个字符 | 95 个可打印（graphic）+ 33 个控制（control） |
| **Latin-1** | 256 个字符 | ASCII + 96 个附加图形字符 |
| **Unicode** | 世界大多数字母表 + 符号 | Java、C++ 宽字符使用 |
| **UTF-16 / UTF-32** | 定长 | |
| **UTF-8** | **变长**（variable-length） | 兼容 ASCII，Web 主流 |

### 2.9.2 字节/半字/字操作指令

| 指令 | 语义 | 扩展方式 |
|---|---|---|
| `lb rd, off(rs1)` | 取**字节**（8 位） | **符号扩展**到 64 位 |
| `lh rd, off(rs1)` | 取**半字**（16 位） | 符号扩展 |
| `lw rd, off(rs1)` | 取**字**（32 位） | 符号扩展 |
| `lbu / lhu / lwu` | 同上 | **零扩展** |
| `sb rs2, off(rs1)` | 存**最低 8 位** | —— |
| `sh rs2, off(rs1)` | 存**最低 16 位** | —— |
| `sw rs2, off(rs1)` | 存**最低 32 位** | —— |
| `ld / sd` | 取/存**双字**（64 位） | —— |

### 2.9.3 字符串复制（strcpy）

```c
void strcpy(char x[], char y[]) {   // 以 '\0' 结尾（null-terminated）
  size_t i = 0;
  while ((x[i] = y[i]) != '\0') i += 1;
}
```
（x 在 x11，y 在 x10）

```asm
strcpy: addi sp, sp, -8
        sd   x19, 0(sp)        # 保存 x19（callee-saved）
        add  x19, x0, x0       # i = 0
L1:     add  x5, x19, x10      # x5 = &y[i]
        lbu  x6, 0(x5)         # x6 = y[i]（无符号字节）
        add  x7, x19, x11      # x7 = &x[i]
        sb   x6, 0(x7)         # x[i] = y[i]
        beq  x6, x0, L2        # 若为 '\0' 结束
        addi x19, x19, 1       # i++
        jal  x0, L1
L2:     ld   x19, 0(sp)
        addi sp, sp, 8
        jalr x0, 0(x1)
```

> 这里用 `lbu`（零扩展）而非 `lb`（符号扩展），因为字符应按无符号处理——否则高位为 1 的字节会被解释成负数。这类细节是**编码规范影响正确性**的典型例子。

## §2.10 大立即数与地址的寻址（Wide Immediates and Addresses）

### 2.10.1 32 位常数怎么装进寄存器

- 大部分常数很小，12 位立即数足够
- 偶尔需要 32 位常数 → 用 `lui` + `addi` 两条指令拼出来：

```
lui  rd, constant       # 20 位常数 → rd[31:12]；bit31 符号扩展到 [63:32]；[11:0] 清 0
```

**例**：构造 `0x003D0500`

```asm
lui  x19, 976        # 976 = 0x3D0 → x19 = 0x003D0000
addi x19, x19, 1280  # 1280 = 0x500 → x19 = 0x003D0500
```

> 为什么 `addi` 能加 1280？因为 1280 < 2048，在 12 位**有符号**正数范围内。若低 12 位的最高位为 1（即 ≥ 0x800），`addi` 会因符号扩展而"多减 4096"，此时需要把 `lui` 的常数**加 1** 补偿——这是经典考点。

### 2.10.2 各类跳转的寻址范围

| 指令 | 格式 | 立即数 | 范围 | 基准 |
|---|---|---|---|---|
| 条件分支 `beq/bne/blt/bge` | SB | 12 位（实为 13 位） | ±4 KiB | **PC 相对** |
| `jalr` | I | 12 位 | ±2 KiB | 寄存器相对 |
| `jal` | UJ | 20 位（实为 21 位） | ±1 MiB | PC 相对 |
| `lui` | U | 20 位 | 高 20 位 | —— |
| `auipc` | U | 20 位 | 高 20 位 + PC | PC 相对 |

**远跳转（long jump）到 32 位绝对地址**：`lui` 装高 20 位 → `jalr` 加低 12 位并跳转。

### 2.10.3 分支寻址（Branch Addressing）

![[Ch2-P95-SB型与PC相对寻址.webp]]

- 分支需要指定：opcode、两个寄存器、目标地址
- 大多数分支目标**在附近**（向前或向后）
- 采用 **PC 相对寻址**：`目标地址 = PC + 立即数 × 2`
- 立即数按"半字"（2 字节）为单位编码，最低位恒 0

### 2.10.4 跳转寻址（Jump Addressing）

- `jal` 用 **20 位**立即数（范围更大：±1 MiB）
- UJ 格式把 20 位立即数**打散**到 4 个位置（与 SB 类似，都是为了与其它格式共享字段位置）

### 2.10.5 寻址方式总结与编码总结

![[Ch2-P97-寻址方式总结.webp]]

![[Ch2-P98-指令编码总结.webp]]

记忆要点：

- **立即数寻址**：`addi x5, x6, 20`（操作数就在指令里）
- **寄存器寻址**：`add x5, x6, x7`
- **基址/偏移寻址**：`ld x5, 40(x6)`（40 是偏移，x6 是基址）
- **PC 相对寻址**：`beq/bne/jal`
- **寄存器间接**：`jalr`

### 2.10.6 目标地址计算实例

假设 `Loop` 位于地址 80000：

| 指令 | 地址 | 机器码（分字段） |
|---|---|---|
| `slli x10,x22,3` | 80000 | `0000000 00011 10110 001 01010 0010011` |
| `add x10,x10,x25` | 80004 | `0000000 11001 01010 000 01010 0110011` |
| `ld x9,0(x10)` | 80008 | `0000000 00000 01010 011 01001 0000011` |
| `bne x9,x24,Exit` | 80012 | `0000000 11000 01001 001 01100 1100011` |
| `addi x22,x22,1` | 80016 | `0000000 00001 10110 000 10110 0010011` |
| `beq x0,x0,Loop` | 80020 | `1111111 00000 00000 000 01101 1100011` |
| `Exit:` | 80024 | |

> 观察最后一个 `beq` 的立即数字段：`1111111 ... 01101` → 位移为负（向后跳），且 imm[12]=1、imm[11]=1。**负偏移的编码**是考试高频陷阱：要把补码正确拆分到 imm[12]、imm[11]、imm[10:5]、imm[4:1] 四个片段。

## §2.11 并行与指令：同步（Synchronization）

### 2.11.1 为什么需要原子操作

- 两个处理器共享一块内存：P1 写、P2 读
- 若不同步 → **数据竞争**（data race）：结果取决于访问顺序
- 需要硬件支持：
	- **原子的读/写内存操作**（atomic read/write）
	- 读与写之间**不允许**其他访问该地址
- 可以是单条指令（如原子的寄存器↔内存交换），也可以是**一对原子指令**

### 2.11.2 RISC-V 的做法：lr / sc

| 指令 | 语义 |
|---|---|
| `lr.d rd, (rs1)` | **load reserved**：从 rs1 的地址读到 rd，并在该地址上**设置保留标记**（reservation） |
| `sc.d rd, rs2, (rs1)` | **store conditional**：若该地址自 `lr.d` 后**未被改动**，把 rs2 存入；**成功返回 0**，**失败返回非 0** |

**例 1：原子交换（atomic swap，用于 test-and-set 锁变量）**

```asm
again: lr.d x10, (x20)
       sc.d x11, x23, (x20)    # x11 = 状态（0 成功）
       bne  x11, x0, again     # 失败则重试
       addi x23, x10, 0        # 把读到的旧值给 x23
```

**例 2：加锁（lock）**

```asm
       addi x12, x0, 1         # x12 = 1（锁定值）
again: lr.d x10, (x20)         # 读锁
       bne  x10, x0, again     # 若锁已被占（非 0）则自旋
       sc.d x11, x12, (x20)    # 尝试写入 1
       bne  x11, x0, again     # 失败则重试
```

**解锁**：

```asm
       sd x0, 0(x20)           # 写 0，释放锁
```

> 这是后面操作系统"自旋锁（spinlock）"的硬件基础。`lr/sc` 的思想与 x86 的 `lock cmpxchg`、ARM 的 `LDXR/STXR` 一致。

## §2.12 翻译并启动程序（Translating and Starting a Program）

### 2.12.1 完整流程

![[Ch2-P106-翻译与启动流程.webp]]

```
源程序 ──编译器──> 汇编程序 ──汇编器──> 目标模块(.o) ──链接器──> 可执行文件 ──加载器──> 内存中运行
                                                          ↑
                                                    库目标模块
```

（许多编译器直接产生目标模块）

### 2.12.2 伪指令（Pseudo-instruction）

- 伪指令**不必由硬件实现**，但在汇编语言中出现可以**简化翻译与编程**
- ⚠️ **考虑性能时应只数"真实指令"**

| 伪指令 | 实际展开 |
|---|---|
| `mv x10, x11` | `add x10, x11, x0` |
| `li x9, 123` | `addi x9, x0, 123`（超范围时展开为 `lui`+`addi`，可能多条） |
| `j Label` | `jal x0, Label` |
| `add x9, x10, 15` | `addi x9, x10, 15`（汇编器自动选立即数版本） |
| `nop` | `addi x0, x0, 0` |
| `not x9, x10` | `xori x9, x10, -1` |

> RISC-V 汇编器**不要求**程序员区分"寄存器版/立即数版"，它会生成正确的操作码。

### 2.12.3 远距离分支（Branching Far Away）

若分支目标太远，12 位偏移装不下，**汇编器重写代码**：

```asm
beq x5, x6, L1
        ↓
bne x5, x6, L2     # 跳过
jal x0, L1         # 用 20 位立即数跳远
L2: ...
```

> 这是"**指令集限制由工具链弥补**"的经典例子：ISA 只提供有限范围，编译器/汇编器生成"跳板"。

### 2.12.4 目标模块（Object Module）的内容

| 部分 | 作用 |
|---|---|
| **Header**（头） | 描述目标模块的内容（段大小、位置） |
| **Text segment** | 翻译后的指令 |
| **Static data segment** | 生存期与程序相同的静态数据 |
| **Relocation info**（重定位信息） | 依赖程序绝对位置的内容 |
| **Symbol table**（符号表） | 全局定义与外部引用 |
| **Debug info** | 与源代码的关联信息 |

### 2.12.5 链接（Linking）

把多个目标模块合成**可执行映像**（executable image），三步：

1. **合并段**（merges segments）
2. **解析标号**（resolve labels）—— 确定它们的地址
3. **修补位置相关引用和外部引用**（patch location-dependent and external references）

> 有**虚拟存储**后，程序可以被装到虚拟地址空间的**绝对位置**，因此不再需要"重定位加载器"在加载时改地址（第 5 章虚拟内存）。

### 2.12.6 加载（Loading）

从磁盘上的映像文件装入内存：

1. 读 header，确定各段大小
2. 创建**虚拟地址空间**
3. 把 text 和已初始化数据拷入内存（或设置页表项，等缺页时再调入——**demand paging**）
4. 在栈上设置**参数**（argv、argc）
5. 初始化寄存器（`sp`、`fp`、`gp`）
6. 跳到**启动例程**（startup routine）：把参数复制到 `x10…`，调用 `main`；`main` 返回后执行 `exit` 系统调用

### 2.12.7 动态链接（Dynamic Linking）

![[Ch2-P114-动态链接与惰性绑定.webp]]

- 只在**库过程被调用时**才链接/加载
- 要求过程代码**可重定位**（relocatable）
- 优点：
	- 避免"静态链接所有（传递依赖的）库"造成的**映像膨胀**（image bloat）
	- 自动获得库的**新版本**
- 实现：**间接跳转表**（indirection table）+ **桩代码**（stub：装入例程 ID，跳转到链接器/加载器）
- **惰性绑定**（lazy linkage）：首次调用才解析真实地址，之后直接走表

### 2.12.8 Java 的启动方式

```
Java 源码 → javac → 字节码（bytecode，JVM 的可移植指令集）
                        ↓
        ┌───────────────┴────────────────┐
   解释器（interprets bytecodes）      JIT 编译器
                                     把"热点"方法编译成本机代码
```

> 这正好对应第 1 章"编译 vs 解释"的性能差异，也是 §2.13 中 Java/JIT 性能接近优化 C 的原因。

## §2.13 C 排序程序综合实例（A C Sort Example）

### 2.13.1 swap（叶过程）

```c
void swap(long long int v[], long long int k) {
  long long int temp;
  temp = v[k];
  v[k] = v[k+1];
  v[k+1] = temp;
}
```
（v→x10，k→x11，temp→x5）

```asm
swap: slli x6, x11, 3     # x6 = k * 8
      add  x6, x10, x6    # x6 = &v[k]
      ld   x5, 0(x6)      # temp = v[k]
      ld   x7, 8(x6)      # x7 = v[k+1]
      sd   x7, 0(x6)      # v[k] = x7
      sd   x5, 8(x6)      # v[k+1] = temp
      jalr x0, 0(x1)
```

### 2.13.2 sort（非叶过程）骨架

```c
void sort(long long int v[], size_t n) {
  size_t i, j;
  for (i = 0; i < n; i += 1)
    for (j = i - 1; j >= 0 && v[j] > v[j+1]; j -= 1)
      swap(v, j);
}
```
（v→x10，n→x11，i→x19，j→x20）

**外层循环骨架**

```asm
      li   x19, 0           # i = 0
for1tst:
      bge  x19, x11, exit1  # i >= n 退出
      ...（内层循环）...
      addi x19, x19, 1      # i++
      j    for1tst
exit1:
```

**内层循环骨架**

```asm
      addi x20, x19, -1     # j = i - 1
for2tst:
      blt  x20, x0, exit2   # j < 0 退出
      slli x5, x20, 3       # x5 = j * 8
      add  x5, x10, x5      # x5 = &v[j]
      ld   x6, 0(x5)        # x6 = v[j]
      ld   x7, 8(x5)        # x7 = v[j+1]
      ble  x6, x7, exit2    # v[j] <= v[j+1] 退出（伪指令 → bge x7,x6,exit2）
      mv   x21, x10         # 备份 v（x10 将被覆盖）
      mv   x22, x11         # 备份 n
      mv   x10, x21         # 参数 1：v
      mv   x11, x20         # 参数 2：j
      jal  x1, swap
```

**保存/恢复寄存器（5 个）**

```asm
      addi sp, sp, -40
      sd   x1, 32(sp)
      sd   x22, 24(sp)
      sd   x21, 16(sp)
      sd   x20, 8(sp)
      sd   x19, 0(sp)
      ...
exit1:
      ld   x19, 0(sp)
      ld   x20, 8(sp)
      ld   x21, 16(sp)
      ld   x22, 24(sp)
      ld   x1, 32(sp)
      addi sp, sp, 40
      jalr x0, 0(x1)
```

> 注意：`s` 系列（x19–x22）是 **callee-saved**，所以 sort 必须自己保存它们；x1 也必须保存，因为 `jal` 会覆盖。

### 2.13.3 编译器优化的效果（重要结论）

| 现象 | 数据/结论 |
|---|---|
| `-O1/-O2/-O3` 后**指令数大幅下降**，但 **CPI 上升** | 指令变少变"复杂"，周期数不一定同比例降 |
| **相对性能**提升 2~3 倍 | 优化有效，但不是线性 |
| **Java 解释执行**很慢，**Java/JIT** 显著提速，某些情况接近优化 C | JIT 把热点编译为本机码 |
| Quicksort vs Bubblesort：算法差异带来的加速比高达 **数百~数千倍** | **算法决定上限** |

**教训（Lessons Learnt）**

1. **指令数（IC）和 CPI 单独都不是好的性能指标**
2. **编译器优化对算法敏感**
3. **Java/JIT 远快于 JVM 解释执行**，有时可与优化 C 相比
4. **再好的编译器也救不了糟糕的算法**（Nothing can fix a dumb algorithm!）

## §2.14 数组 vs 指针（Arrays versus Pointers）

```c
clear1(int array[], int size) {      clear2(int *array, int size) {
  int i;                               int *p;
  for (i = 0; i < size; i += 1)        for (p = &array[0]; p < &array[size]; p++)
    array[i] = 0;                          *p = 0;
}                                     }
```

| | 数组版 | 指针版 |
|---|---|---|
| 地址计算 | 循环内**每次**都要 `i*8 + base` | 指针**自增**即可（`p = p + 1`） |
| 指令 | `slli` + `add` 在循环体内 | 循环内只有 `addi` |
| 效率 | 多一条移位 | 少一条 |

- **强度削弱**（strength reduction）：乘法被移位代替（`×8` → `slli 3`）
- 数组版**移位在循环内**（下标递增要重算）；指针版把地址计算提到了循环外

**但：编译器可以自动完成同样的优化**

- **归纳变量消除**（induction variable elimination）：编译器把 `i*8` 变成"每次加 8"
- 结论：**让程序更清晰、更安全**比手工用指针更好——可读性优先，优化交给编译器

## §2.15 真实机器：MIPS / ARM / x86

### 2.15.1 MIPS

- MIPS 是 RISC-V 的**商业前身**，指令集高度相似：
	- 32 位指令
	- 32 个通用寄存器（0 号恒为 0）
	- 32 个浮点寄存器
	- 只有 load/store 访问内存（各数据宽度寻址方式一致）
- **主要差异在条件分支**：
	- RISC-V：`blt, bge, bltu, bgeu` 直接比较
	- MIPS：`slt, sltu`（set less than，结果 0/1）+ `beq/bne` 两条完成一次比较

> 例子：MIPS 实现 `if (a < b) goto L` 需要 `slt $t0,$a,$b; bne $t0,$zero,L`。

### 2.15.2 ARM v8

- 转向 64 位时**彻底重构**，风格**很像 MIPS**
- 相对 v7 的变化：
	- 取消条件执行字段（conditional execution field）
	- 立即数为 12 位常数
	- 取消 load/store multiple
	- PC 不再是通用寄存器
	- 通用寄存器扩展到 32 个
	- 寻址方式适用于所有字长
	- 增加除法指令
	- 增加 `beq/bne` 指令

### 2.15.3 x86 的演进（CISC 的活化石）

| 年份 | 型号 | 关键特性 |
|---|---|---|
| 1974 | 8080 | 8 位微处理器，累加器 + 3 对索引寄存器 |
| 1978 | 8086 | 16 位扩展，**复杂指令集（CISC）** |
| 1980 | 8087 | 浮点协处理器，FP 指令 + 寄存器栈 |
| 1982 | 80286 | 24 位地址、**MMU**（分段存储映射与保护） |
| 1985 | 80386 | 32 位扩展（IA-32），更多寻址方式，**分页** |
| 1989 | i486 | 流水线、片上 Cache、FPU |
| 1993 | Pentium | **超标量**（superscalar）、64 位数据通路；MMX；著名的 FDIV bug |
| 1995/1997 | Pentium Pro / II | 新微架构 |
| 1999 | Pentium III | **SSE**（Streaming SIMD Extensions） |
| 2001 | Pentium 4 | 新微架构；SSE2 |
| 2003 | AMD64 | 扩展到 64 位 |
| 2004 | EM64T | Intel 采纳 AMD64（+SSE3） |
| 2006 | Intel Core | SSE4、虚拟机支持 |
| 2008 | AVX | 更长的 SSE 寄存器、更多指令 |

**关键洞察**：`If Intel didn't extend with compatibility, its competitors would!` → **技术优雅 ≠ 市场成功**（Technical elegance ≠ market success）。

### 2.15.4 x86 的基本特征

- **每指令两个操作数**（source/dest + second source）

| 目的/源操作数 | 第二源操作数 |
|---|---|
| 寄存器 | 寄存器 |
| 寄存器 | 立即数 |
| 寄存器 | 内存 |
| 内存 | 寄存器 |
| 内存 | 立即数 |

- 内存寻址方式：
	- 地址在寄存器中
	- 地址 = `Rbase + displacement`
	- 地址 = `Rbase + 2^scale × Rindex`（scale = 0,1,2,3）
	- 地址 = `Rbase + 2^scale × Rindex + displacement`
- **变长编码**（variable length）：后缀字节说明寻址方式，前缀字节修改操作（操作数长度、重复、加锁……）

### 2.15.5 如何实现 CISC

- 复杂指令集使实现困难 → 硬件把指令**翻译成更简单的微操作**（microoperations）
	- 简单指令：1 → 1
	- 复杂指令：1 → 多条
- **微引擎**（microengine）风格类似 RISC
- 市场份额使这种方案**经济可行**
- 性能可与 RISC 相比：**编译器会避开复杂指令**

### 2.15.6 CISC 与 RISC 之争（讲义中文补充）

**CISC 的缺陷**

- 指令系统日益庞大 → 研制周期变长、难以保证正确性、难以调试维护
- 指令操作复杂 → 增加机器周期 → 降低系统性能
- 实测统计（**20/80 律**）：
	- 最常用的**简单指令**占程序的 **80%**，但只占指令系统的 **20%**
	- 微程序控制的计算机中，占指令总数 **20%** 的复杂指令占用了控制存储器容量的 **80%**

**RISC 的历史**

- 1975 年 IBM 开始研究指令系统合理性问题，John Cocke 提出 **RISC**（Reduced Instruction Set Computer）
- 1982 年：UC Berkeley 的 **RISC I**、Stanford 的 **MIPS**、IBM 的 **IBM801** 相继完成（第一代 RISC）
- MIPS 是典型 RISC；82 年后新指令集大多采用 RISC 体系结构
- x86 因"**兼容**"需要保留 CISC 风格，同时借鉴 RISC 思想（内部翻译成 RISC 微操作）

**RISC 设计风格的主要特点**

1. **简化的指令系统**：指令少、寻址方式少、指令格式少、**指令长度一致**
2. **以 RR 方式工作**：除 Load/Store 外，其余指令只访问寄存器
3. **指令周期短**：流水线工作，除 Load/Store 外多数指令 1 个（或不足 1 个）时钟周期完成
4. **大量通用寄存器**：减少访存次数
5. **组合逻辑控制**：不用或少用微程序控制
6. **优化的编译系统**：有效支持高级语言

> 第 4 章的"单周期 → 流水线"设计之所以能成立，正是因为 RISC 的这 6 条特征——**定长指令、规整格式、只有 load/store 访存**。

### 2.15.7 RISC-V 的其余指令

**RV64I 基础整数指令**（除前面讲的之外）：

| 指令 | 含义 |
|---|---|
| `auipc rd, immed` | rd = (imm<<12) + PC；后接 `jalr`（加 12 位立即数）实现远跳 |
| `slt, sltu, slti, sltui` | set less than（结果为 0/1） |
| `addw, subw, addiw` | **32 位**加/减（结果符号扩展到 64 位） |
| `sllw, srlw, sraw, slliw, srliw, sraiw` | 32 位移位 |

**RV32I**：寄存器 32 位宽、32 位运算。

**扩展（Extensions）**：

| 扩展 | 内容 |
|---|---|
| **M** | 整数乘、除、取余 |
| **A** | 原子内存操作 |
| **F** | 单精度浮点 |
| **D** | 双精度浮点 |
| **C** | **压缩指令**（16 位编码，用于常用指令，减小代码体积） |

> 命名如 `RV64GC` = RV64I + M/A/F/D + C。

## §2.16 谬误与陷阱（Fallacies and Pitfalls）

### 谬误（Fallacies）

**1. "强大的指令 → 更高的性能"**

- 看似：指令更强 → 需要的指令更少
- 实则：
	- 复杂指令**难以实现**
	- 可能**拖慢所有指令**（包括简单指令），因为时钟周期要迁就最慢的指令
	- **编译器很擅长用简单指令生成快代码**

**2. "用汇编代码可以获得高性能"**

- 现代编译器更懂现代处理器（调度、寄存器分配、流水线）
- 汇编代码行数多 → **错误更多、生产率更低**
- 只在极少数场景（启动代码、驱动、SIMD 内核）才手写汇编

**3. "向后兼容 → 指令集不会变"**

- 事实：指令集**不断累积新指令**（看 x86 的指令数增长曲线）
- 这是"兼容性包袱"（compatibility baggage）

### 陷阱（Pitfalls）

**1. 顺序的字并不在顺序的地址上**

> 地址要**加 4**（RV32 指令）或 **加 8**（双字数据），**不是加 1**！

**2. 过程返回后仍保留指向自动变量的指针**

```c
int *danger() { int x = 5; return &x; }   // x 在栈上，返回后失效
```

- 栈弹出后指针**悬空**（dangling pointer）
- 通过参数把栈上变量的地址传回去也是同样错误

## §2.17 结论（Concluding Remarks）

**四条设计原则**（贯穿全书）：

1. **简单源于规整**（Simplicity favors regularity）
2. **越小越快**（Smaller is faster）
3. **让常见情况变快**（Make the common case fast）
4. **好的设计需要好的折中**（Good design demands good compromises）

**软硬件的层次**：编译器（compiler）→ 汇编器（assembler）→ 硬件（hardware）

**RISC-V 是典型的 RISC ISA**（对比 x86 的 CISC）

## §2.19 易错点清单

1. **`add` 与 `sub` 别写错**（`f=(g+h)-(i+j)` 最后一步是 `sub`）
2. **数组下标要乘元素大小**（8 字节 → 左移 3）
3. **`bgt/ble` 不存在**：用交换操作数 + `blt/bge`，或"条件取反 + 跳走"
4. **有符号 vs 无符号分支**：`blt` 与 `bltu` 结果可能相反
5. **S 型立即数被劈成两半**，不是连续的 12 位
6. **B/J 型立即数的最低位隐含为 0**（不编码）
7. **B/J 型立即数是"字节偏移"**，不是指令条数
8. **`jal` 会覆盖 `x1`**：非叶过程必须先保存 ra
9. **栈帧大小与 `sp` 的加减必须对称**
10. **`lbu` vs `lb`**：字符/无符号数据用 `lbu`
11. **逻辑立即数零扩展，算术立即数符号扩展**
12. **`x0` 不可写**：所有"丢弃结果"的场合都用 `rd = x0`
13. **顺序字地址加 4/8，不是加 1**
14. **伪指令不是真实指令**，算 CPI/IC 时要展开
15. **`srai` 向下取整，C 的 `/` 向 0 取整**
