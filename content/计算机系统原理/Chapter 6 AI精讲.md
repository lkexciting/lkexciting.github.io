# Chapter 6 AI 精讲：输入输出系统（Input/Output System）

> 对应课件：第六章 输入输出系统
> 本讲目标：掌握 I/O 的**硬件层**（外设模型、总线、I/O 接口、编址）与**控制层**（程序查询、中断、DMA 三种数据交换方式），并理解**软件层**（设备无关层、驱动程序、中断服务程序）的分工。核心是能定量比较"**中断 vs DMA** 的 CPU 开销"。

---

## 0. 本章逻辑主线

```
外设（通用模型：控制/状态/数据 + 缓冲器 + 变换器）
   ↓ 通过电缆
I/O 接口（I/O 控制器）：I/O 端口 = 数据/状态/控制寄存器
   ↓ 挂在
总线（数据线 / 地址线 / 控制线）
   ↓ 由 CPU 用不同方式驱动
┌──────────────┬──────────────┬──────────────┐
│ 程序直接控制  │   中断方式    │    DMA 方式   │
│ (轮询 polling)│ (中断驱动)   │ (直接存储器存取)│
└──────────────┴──────────────┴──────────────┘
   ↓ 上层
I/O 软件层次：用户 I/O 库 → 设备无关层 → 驱动程序 → 中断服务程序
```

**一句话总结**：I/O 系统的全部演化，都是在回答同一个问题——**如何让"慢且多样"的外设，不拖慢"快且单一"的 CPU**。

## §6.1 外设的发展与分类

### 6.1.1 按交互方式分类

| 类别 | 定义 | 例子 |
|---|---|---|
| **人-机交互设备** | 输入/输出的信息**人可读** | 键盘、鼠标、扫描仪、打印机、显示器 |
| **机器可读设备** | 信息**机器可读**，人无法直接读取 | 网络、Modem、D/A、A/D、磁盘、声音输入设备 |

### 6.1.2 按功能行为分类

| 类别 | 特点 | 例子 |
|---|---|---|
| **输入/输出设备** | 大部分为**字符型设备**（character device），用于信息输入输出 | 输入：键盘、鼠标、扫描仪；输出：打印机、显示器 |
| **外部存储设备** | 大部分为**成块传送设备**（block device），信息机器可读 | 磁盘、磁带、光盘 |

> **字符设备 vs 块设备**是 OS 里最重要的设备分类：前者按**字节流**访问（不可定位），后者按**块**访问（可随机定位）。这个区别直接决定了驱动程序与缓冲策略（§6.8）。

### 6.1.3 设备的数据率差异（惊人的跨度）

| 设备 | 行为 | 伙伴 | 数据率（KB/s） |
|---|---|---|---|
| 键盘 Keyboard | 输入 | 人 | **0.01** |
| 鼠标 Mouse | 输入 | 人 | 0.02 |
| 行式打印机 Line Printer | 输出 | 人 | 1.00 |
| 激光打印机 Laser Printer | 输出 | 人 | 100.00 |
| 图形显示器 Graphics Display | 输出 | 人 | **30 000.00** |
| 网络 LAN | 输入或输出 | 机器 | 200.00 |
| 软盘 Floppy disk | 存储 | 机器 | 50.00 |
| 光盘 Optical Disk | 存储 | 机器 | 500.00 |
| 磁盘 Magnetic Disk | 存储 | 机器 | 2 000.00 |

> **键盘 0.01 KB/s 与显卡 30 000 KB/s 相差 300 万倍**！这个巨大差异解释了为什么**不存在一种"通用最优"的 I/O 方式**：慢设备适合轮询/中断，快设备必须用 DMA。

## §6.2 外部设备的通用模型

![[Ch6-P04-外设通用模型.webp]]

**所有设备都可以抽象成同一个模型**（这是本节的精髓）：

| 部件 | 作用 |
|---|---|
| **I/O 接口（电缆）** | 通过电缆与计算机内部的 I/O 接口传送**数据、状态、控制**信息 |
| **控制逻辑** | 根据**控制信息**控制设备操作，并**检测设备状态** |
| **缓冲器**（buffer） | 保存交换的**数据信息**（速度匹配） |
| **变换器**（transducer） | 在**电信号形式（内部数据）**与**其他形式的设备数据**之间转换 |

**电缆中的三类信号线**：

1. **控制信号**（control）
2. **状态信号**（status）
3. **数据信号**（data）

> 这三类信号正好对应 I/O 接口中的三类寄存器：**控制寄存器、状态寄存器、数据寄存器**。抽象模型与硬件实现一一对应——这就是"抽象"的力量。

### 6.2.1 键盘（Keyboard）

![[Ch6-P05-键盘与主机连接.webp]]

- 与主机的连接：早期通过 **5 芯 PS/2 接口电缆**（时钟、数据、复位、地、+5V），现在多为 **USB**
- 通过键盘输入字符并在显示器上显示
- **信息交换的基本单位是字符**

**ASCII 码**（American Standard Code for Information Interchange）：

- 共 **128 个元素**：**32 个通用控制字符** + **10 个十进制数码** + **52 个英文字母** + **34 个专用符号**
- 除 32 个控制字符外，其余 **96 个全部是可打印字符**
- 通常在 **7 位代码后跟 1 位奇偶校验位**，组成一个字节

### 6.2.2 键盘输入信息的过程

1. **按下一个键**
2. **查出按下的是哪个键**
	- ① **行扫描法**（微机系统中应用最广）
	- ② **线反转法**
3. 把按键**位置信息**转换为对应的 **ASCII 码**，保存到计算机中

**按功能分类**：

| 类型 | 功能 |
|---|---|
| **编码键盘**（encoded keyboard） | 检测被按键，**直接提供 ASCII 码**送 CPU |
| **非编码键盘**（non-encoded keyboard） | 只提供键盘的**行列矩阵**，识别按键**位置**，提供**位置码**送 CPU |

![[Ch6-P09-行扫描法.webp]]

**行扫描法**（基本做法：**按行扫描、接地检查**）：

- 键盘排列成 **8 行 × 16 列** 的矩阵
- 逐行输出低电平（扫描），读列线：某列读到低电平 → 该行该列的键被按下
- 优点：**用少量 I/O 线支持大量按键**（24 根线支持 128 键）

> 为什么键盘不采用"一键一线"？因为 128 个键要 128 根线。**矩阵扫描**把线数从 O(n) 降到 O(√n) —— 这是典型的"用时间（扫描）换空间（引脚）"。

## §6.3 I/O 总线、I/O 控制器与 I/O 设备的关系

![[Ch6-P10-IO总线与南北桥.webp]]

**典型的 PC 结构**：

```
CPU ──(CPU 前端总线/FSB)── 北桥（North Bridge）── 存储器总线 ── 主存储器
                              │
                          (I/O 总线)
                              │
                            南桥（South Bridge）
                              │
        ┌────────┬────────┬───┴────┬────────┬────────┐
     USB 控制器  以太网卡  磁盘控制器  声卡   视频卡   PCI 插槽
        │          │        │
      鼠标/键盘   网线    光驱/disk
```

> **北桥**连接"高速"部件（CPU、内存、显卡），**南桥**连接"低速"外设。这个"分层的总线结构"体现了存储层次同样的思想：**把不同速度的东西分开，避免慢的拖累快的**。
> 现代 CPU 已把北桥功能集成进芯片（内存控制器、PCIe 控制器直接进 CPU），南桥演变为 **PCH**（Platform Controller Hub）。

### 6.3.1 系统总线的组成

系统总线通常由**一组控制线、一组数据线和一组地址线**构成。

> 有些总线**没有单独的地址线**，地址信息通过数据线传送 → 称为**数据/地址复用**。

| 线组 | 作用 | 宽度含义 |
|---|---|---|
| **数据线**（Data Bus） | 承载源与目的部件之间传输的**信息** | 宽度反映**一次能传送的数据位数** |
| **地址线**（Address Bus） | 给出源/目的数据所在的**主存单元或 I/O 端口地址** | 宽度反映**最大寻址空间** |
| **控制线**（Control Bus） | **控制**对数据线和地址线的访问与使用；传输**定时信号和命令** | —— |

**典型的控制信号**：

| 信号 | 含义 |
|---|---|
| **时钟**（Clock） | 用于总线**同步** |
| **复位**（Reset） | **初始化**所有设备 |
| **总线请求**（Bus Request） | 该设备**要使用总线** |
| **总线允许**（Bus Grant） | 收到该信号的设备**可以使用总线** |
| **中断请求**（Interrupt Request） | 某个**中断正在请求** |
| **中断回答**（Interrupt Acknowledge） | 某个中断请求**已被接受** |
| **存储器读**（Memory Read） | 从指定主存单元读数据到数据总线 |
| **存储器写**（Memory Write） | 把数据总线上的数据写到指定主存单元 |
| **I/O 读**（I/O Read） | 从指定 I/O 端口读数据到数据总线 |
| **I/O 写**（I/O Write） | 把数据总线上的数据写到指定 I/O 端口 |
| **传输确认**（Transmission Acknowledge） | 数据**已被接收**或**已送总线** |

> 现在总线设计的趋势：**点对点、异步、串行**。
> （对比早期的"共享并行总线"：点对点避免争用，串行减少引脚、提高频率，异步避免全局时钟同步难题——PCIe、SATA、USB 都是这个方向。）

### 6.3.2 总线的性能指标

| 指标 | 定义 |
|---|---|
| **总线宽度** | 数据线的**条数**，决定每次能同时传输的信息位数 |
| **总线工作频率** | 早期一个时钟周期传一次数据（工作频率 = 时钟频率）；现在有些总线一个时钟传 **2 次或 4 次**（DDR/QDR），工作频率是时钟频率的 **2 倍或 4 倍** |
| **总线传送方式** | **非突发**：每个总线事务都传地址，一个地址对应一次数据传送；**突发**（burst）：先传**一个地址**，后传**多次数据**，后续地址**自动增量** |
| **总线带宽**（bandwidth） | 总线的**最大数据传输率** |

**同步总线的带宽公式**：

B=W×F/N

- W：总线宽度（字节）
- F：总线时钟频率
- N：完成**一次数据传送**所用**时钟周期数**
- F/N 实际上就是**总线工作频率**

**例**：W=8 字节（64 位），F=200 MHz，N=2（DDR 相当于每周期传 2 次）

B=8×(200×10⁶)/2=800 MB/s

> 注意：若 N 表示"每传一次数据需要 2 个时钟"，则 F/N 就是**有效工作频率**。**突发传送**能显著提高 B，因为它把"送地址"的开销**摊薄**到多个数据上。

## §6.4 I/O 接口（I/O 控制器）

### 6.4.1 I/O 接口的五大功能

| 功能 | 实现 |
|---|---|
| **数据缓冲** | 提供**数据缓冲寄存器**，达到主机与外设**工作速度的匹配** |
| **错误或状态检测** | 提供**状态寄存器**，保存各种错误或状态信息供 CPU 查用 |
| **控制和定时** | 提供**控制和定时逻辑**，接受从系统总线来的控制定时信号 |
| **数据格式转换** | 提供**数据格式转换部件**，使外部接口的数据转换为内部接口需要的格式（或反向） |
| **与主机和设备通信** | 上述功能通过 I/O 接口与主机、I/O 接口与设备之间的通信完成 |

### 6.4.2 I/O 接口的结构与 I/O 端口

![[Ch6-P19-IO接口结构.webp]]

**三类 I/O 端口**（CPU 可访问的寄存器）：

| 端口 | 作用 | 访问方式 |
|---|---|---|
| **数据端口**（数据缓冲寄存器） | 暂存交换的数据 | 读/写数据 |
| **状态端口**（状态寄存器） | 保存外设/控制器的状态 | **读状态字** |
| **控制端口**（控制寄存器） | 接收 CPU 的命令 | **发命令字** |

**一句话**：

- 通过**发送命令字**到 I/O 控制寄存器 → **向设备发命令**
- 通过**读状态寄存器** → 获取外设或 I/O 控制器的**状态**
- 通过**发送或读取数据** → 与外设进行**数据交换**

> **对外设的访问 = 向 I/O 端口发命令、读状态、读/写数据**。
> 不同 I/O 模块在**复杂性**和**控制外设的数量**上相差很大（从简单的串口控制器到复杂的 RAID 控制器）。

### 6.4.3 I/O 设备的寻址方式（重点）

**I/O 端口必须编号后 CPU 才能访问**；一个 I/O 控制器可能占有多个端口地址。**寻址方式 = I/O 端口的编号方式**。

| 方式 | 做法 | 特点 | 采用者 |
|---|---|---|---|
| **统一编址**（memory-mapped I/O） | 与主存空间**统一编址**，从主存空间分出一部分地址给 I/O 端口 → 即把 I/O 端口**映射到某主存区域** | **无需专门 I/O 指令**，可用普通 load/store 访问；但**占用主存地址空间** | **RISC 架构**（MIPS、**RISC-V**）、Motorola |
| **独立编址**（isolated I/O / port-mapped） | **不和主存单元一起编号**，单独成为一个 **I/O 地址空间** | 需**专门的 I/O 指令**（IN/OUT），故称"特殊 I/O 指令方式"；**不占用主存空间** | **Intel**（x86）、Zilog |

> 这解释了一个日常现象：写驱动时，ARM/RISC-V 平台上访问外设就是**读写某个内存地址**（`*(volatile uint32_t*)0x40000000`），而 x86 上要用 `in`/`out` 指令。
> **统一编址的最大好处**：可以用**全部**访存指令与寻址方式操作外设（包括 DMA、Cache 一致性机制），编程模型统一。

## §6.5 I/O 设备与主机数据交换的三种基本方式

### 6.5.1 方式一：程序直接控制方式（Programmed I/O）

**最简单的 I/O 方式**，分两种：

| 类型 | 做法 |
|---|---|
| **无条件传送**（unconditional） | 对**简单外设****定时（同步）** 进行数据传送（假定外设总准备好） |
| **条件传送 / 轮询**（polling / 程序查询方式） | OS **主动查询**：① I/O 设备（含接口）把状态放到**状态寄存器**；② OS **阶段性地查询**状态寄存器中的特定状态，以决定下一步动作 |

![[Ch6-P23-程序查询方式打印流程.webp]]

**打印输出的流程**（以启动打印为例）：

```
开始 → 启动打印机
     → 读接口状态（读打印机状态）
     → 就绪？ ──否──> 继续读（循环等待，"踏步"）
        │是
     → 输出一个字符
     → 读打印机状态
     → 忙？ ──是──> 继续读（等待）
        │否
     → 完成？ ──否──> 回到"启动打印"
        │是
      结束
```

**"就绪"的含义**：打印控制器的**数据缓冲中内容已被取走**，现为"**空**"，可接受新的打印字符。

> **致命缺陷："踏步"（busy-wait）**。CPU 在循环里空转，**CPU 与外设完全串行**，效率极低。这直接催生了中断方式。

### 6.5.2 方式二：中断 I/O 方式（Interrupt-driven I/O）

![[Ch6-P24-中断IO方式.webp]]

**基本思想**：

- 外设准备好时，**主动向 CPU 发中断请求**
- CPU 响应后，**中止现行程序**，转入"**中断服务程序**"进行输入/输出操作，实现主机与外设接口之间的数据传送，并启动外设工作
- 中断服务程序执行完，**返回原程序断点**继续执行
- 此时**外设与 CPU 并行工作**

> **关键区别**：轮询是 **CPU 主动问**，中断是 **外设主动喊**。CPU 从"等待者"变成"被通知者"，这就是并行的来源。
> 课件强调：**程序切换（响应中断过程）由硬件完成**，即执行"**中断隐指令**"（不是程序员写的指令，是硬件自动完成的动作序列）。

**几乎所有系统都支持中断 I/O 方式。**

### 6.5.3 方式三：DMA 方式（Direct Memory Access）

- **磁盘等高速外设特有**的 I/O 方式
- 高速外设**成批地直接与主存**交换数据
- 需要专门的 **DMA 控制器**控制总线完成传送
- 外设准备好数据 → 向 DMA 控制器发 **DMA 请求** → DMA 控制器向 CPU 发**总线请求** → CPU 让出总线 → **DMA 控制器控制总线传输，无需 CPU 干涉**

（详见 §6.7）

## §6.6 中断机制详解

### 6.6.1 处理器响应中断的基本处理（"中断隐指令"）

异常/中断发生时，处理器依次做**三件事**：

**① 关中断（禁止中断）**

- 将**中断允许触发器**标志**清 0**
- 目的：保证接下来的"保护断点"等关键动作**不被打断**（否则现场会乱）

**② 保护断点和程序状态**

- 将返回原程序的**断点**和**程序状态**保存到**堆栈或特殊寄存器**
- 即 `PC → 堆栈` 或 `PC → EPC`（RISC-V 中是 **SEPC**，第 4 章讲过）

**③ 识别异常事件并转到具体处理程序**，有两种方式：

| 方式 | 做法 | 采用者 |
|---|---|---|
| **软件识别** | 设一个**异常状态寄存器**（MIPS 中为 **Cause** 寄存器）记录异常原因；OS 用**统一的异常处理程序**（MIPS 入口 `0x8000 0180`），该程序**按优先级顺序查询**状态寄存器识别事件 | **MIPS** |
| **硬件识别（向量中断）** | 用专门的**硬件查询电路**按优先级识别，得到一个"**中断类型号**"；据此到**中断向量表**中读取对应的**中断服务程序入口地址** | **80x86** |

> **软件识别 vs 硬件识别的权衡**：
> - 软件识别：**硬件简单**，但识别慢（要逐位查询），且入口统一（再多一次跳转）
> - 硬件识别：**快**（一次得到向量号），但需要**优先级排队电路**
> 这正是第 1 章"让常见情况变快"与"好的设计需要好的折中"的又一次体现。

### 6.6.2 多重中断（中断嵌套）

**定义**：在一个中断处理（执行中断服务程序）过程中，若又有新的中断请求发生，且**新中断优先级高于**正在执行的中断，则**立即中止**当前中断服务程序，转去处理新中断。

**两种"优先级"要分清**（考点）：

| 概念 | 由谁决定 | 反映什么 |
|---|---|---|
| **中断响应优先级** | **查询程序**或**硬联排队线路** | 多个中断**同时请求**时**先响应哪个** |
| **中断处理优先级** | 各自的**中断屏蔽字**（可动态设定） | 本中断与其他中断的**处理关系**（能否嵌套） |

![[Ch6-P27-多重中断嵌套.webp]]

**例**（课件图）：中断优先级顺序为 **3# > 2# > 1#**，且

- **1# 对 2# 开放**（不屏蔽 2#）
- **2# 对 3# 开放**（不屏蔽 3#）

执行过程：

```
主程序 ──> 1# 中断服务 ──(2# 请求，未被屏蔽)──> 2# 中断服务
                                                    │
                                          (3# 请求，未被屏蔽)
                                                    ↓
                                              3# 中断服务
                                                    │ 返回
                                              2# 继续
                                                    │ 返回
                                              1# 继续
                                                    │ 返回
                                                主程序
```

> **屏蔽字（mask）** 是实现"处理优先级"的手段：每个中断服务程序有一个屏蔽字，决定"我现在允许哪些中断打断我"。**响应优先级**决定"同时来的时候先理谁"，**处理优先级**决定"正在处理时谁能插队"。

### 6.6.3 与第 4 章的对应

| 第 4 章（RISC-V） | 本章（通用/中文教材） |
|---|---|
| **SEPC** 保存出错指令 PC | 保护**断点**（PC → 堆栈/EPC） |
| **SCAUSE** 保存原因 | **异常状态寄存器**（MIPS 的 Cause） |
| 统一入口（假设 `0x1C090000`） | **软件识别**（统一入口） |
| **向量中断**（handler 地址由原因决定） | **硬件识别**（中断向量表） |
| 冲刷流水线 | 关中断 + 保存现场 |

> 两章讲的是同一件事的两种表述：**"保存现场 → 识别原因 → 转处理程序 → 恢复现场"**。

## §6.7 DMA 方式详解

### 6.7.1 为什么要引入 DMA

**程序直接控制方式**：受"**踏步**"现象限制，效率低下，**不适合高速设备**与主机间的数据传送。

**中断控制方式**虽比程序直接控制有效，CPU 与外设有一定并行度，但由于以下原因**也不适合高速设备**：

1. **对 I/O 请求响应慢**：每传送**一个数据**都要等外设的中断请求，并增加许多**中断响应**和**中断处理前后**的附加开销（保护断点、现场等），不能及时响应
2. **数据传送速度慢**：数据传送**由软件完成**（CPU 执行中断服务程序），速度慢

> 算一笔账：磁盘 4 MB/s、每次中断传 16 B → 每秒 **25 万次中断**，每次 500 周期 → 每秒 1.25 亿周期。若 CPU 500 MHz，**光服务中断就占 25%**！这就是 DMA 的必要性。

### 6.7.2 DMA 的基本要点

**基本思想**：

- 在**高速外设与主存之间直接传送**数据
- 由**专门硬件（DMA 接口/DMA 控制器）控制总线**进行传输

**适用场合**：

- **高速设备**（磁盘、光盘等）
- **成批数据交换**，且**数据间间隔时间短**，一旦启动，数据**连续读写**

**采用"请求-响应"方式**：

- 每当高速设备**准备好数据**，就进行一次 **DMA 请求**
- DMA 控制器接受请求后，**申请总线使用权**
- **DMA 控制器的总线优先级比 CPU 高** —— 因为不马上响应，高速设备可能**数据丢失**（磁盘转过去了就没了）

**与中断控制方式结合使用**：

- DMA 传送**前**：**寻道、旋转**等操作结束时，通过**中断**告知 CPU
- DMA 传送**中**：DMA 控制器控制总线传数据，**CPU 执行其他程序**
- DMA 传送**结束**：通过 **"DMA 结束中断"** 告知 CPU

> 所以 DMA **不是"取代"中断，而是"分工"**：
> **中断负责"开始/结束"这类低频事件，DMA 负责"大量数据搬运"这类高频动作。**

### 6.7.3 DMA 的三种数据传送方式（重点、必考）

由于 **DMA 接口与 CPU 共享主存**，会出现**争用主存**的现象。为协调两者，有三种方式：

#### ① CPU 停止法（成组传送 / block transfer）

![[Ch6-P32-CPU停止法.webp]]

- DMA 传输时，**CPU 脱离总线**，停止访问主存，直到 DMA 传送**一块数据结束**

| 优点 | 缺点 |
|---|---|
| **控制简单**；适用于**传输率很高**的外设做**成组**数据传送 | **CPU 工作受影响**：DMA 访存时 CPU 基本**停止**；**主存周期没有被充分利用** |

> 课件补充：即使 I/O 设备高速运行，**两个数据之间的准备间隔时间也总大于一个存储周期** → 可在 DMA 接口中引入**缓冲器**弥补。

#### ② 周期挪用（窃取）法（cycle stealing / 单字传送）

![[Ch6-P33-周期挪用法.webp]]

- DMA 传输时，CPU **让出一个总线事务周期**，由 DMA 控制总线访问主存，**传送完一个数据后立即释放总线**

| 优点 | 缺点 |
|---|---|
| 既能**及时响应** I/O 请求，又能较好发挥 **CPU 与主存**的效率；在下一数据的**准备阶段**，主存周期被 **CPU 充分利用**；适合 **I/O 设备的读写周期大于主存周期**的情况 | 每次 DMA 访存都要**申请总线控制权、占用总线、释放总线** → **增加传输开销** |

> 名字很形象：DMA"**偷**"走一个存储周期。适用于"**偶尔来一个字**"的设备（如网络卡、声卡）。

#### ③ 交替分时访问法（time-sharing / 交替访问）

- 每个**存储周期分成两个时间片**，**一个给 CPU，一个给 DMA**
- 这样在**每个存储周期内**，CPU 和 DMA **都可访问存储器**

> 优点：CPU 与 DMA **都不必等待**，主存利用率最高。
> 代价：要求**存储器速度足够快**（周期被切成两半，各片仍要满足访问时间），硬件最复杂。

**三种方式对比**：

| 方式 | CPU 受影响 | 主存利用率 | 适用 |
|---|---|---|---|
| CPU 停止法 | **大** | 低 | 超高速成批传输 |
| 周期挪用 | 小 | 较高 | 一般高速设备（最常用） |
| 交替分时 | **几乎无** | **最高** | 存储器很快的场合 |

### 6.7.4 DMA 的系统逻辑结构

![[Ch6-P34-DMA系统逻辑结构.webp]]

典型部件：

| 部件 | 作用 |
|---|---|
| **地址寄存器**（AR） | 存放主存地址，每传一个字**自动加 1** |
| **字计数器**（WC） | 记录还要传多少个字，减到 0 表示完成 |
| **数据缓冲寄存器**（DR） | 暂存数据 |
| **DMA 请求触发器** | 记录外设的 DMA 请求 |
| **控制/状态逻辑** | 产生总线请求、控制传送时序 |
| **中断机构** | 传送结束时发"**DMA 结束中断**" |

**传送流程**：

```
外设就绪 → 发 DMA 请求 → DMA 控制器向 CPU 发总线请求
   → CPU 响应（让出总线）→ DMA 控制器占用总线
   → 主存 ⇄ 外设 直接传送一个字
   → 地址 +1，计数器 −1 → 未完成则继续
   → 完成 → 发 DMA 结束中断 → CPU 处理善后
```

## §6.8 例题：中断与 DMA 方式下 CPU 的开销（核心计算题）

### 6.8.1 题目

- 处理器频率 **500 MHz**
- 硬盘控制器中有一个 **16 B** 的数据缓存器
- 磁盘传输速率 **4 MB/s**
- 传输过程中**要求没有任何数据被错过**
- 假定 **CPU 访存与 DMA 访存没有冲突**

**问 1**：若用**中断驱动 I/O**，每次传送的开销（含中断响应与处理）是 **500 个时钟周期**。如果硬盘**仅用 5% 的时间**进行传送，处理器用在硬盘 I/O 上的时间百分比（**主机占用率**）为多少？

**问 2**：若用 **DMA**，处理器花 **1000 个时钟**做 DMA 初始化设置，DMA 完成后的中断处理需 **500 个时钟**。如果每次 DMA 传送 **8000 B** 的数据块，那么当硬盘**一直进行读写（100% 时间传送）**时，处理器用在硬盘 I/O 上的时间百分比为多少？

### 6.8.2 解答（附逐步推理）

**（1）中断方式**

- 硬盘每次中断只能传 **16 字节**（缓存器大小）
- 若"不漏数据"，必须达到的中断频率：

(4 MB/s)/(16 B)=(4×10⁶)/16=250000 次/秒=250 k 次/秒

- 每秒用于中断的时钟周期数：

250 k×500=1.25×10⁸

- 若硬盘**一直**在传，占用率：

(1.25×10⁸)/(500×10⁶)=25%

- 但硬盘**仅用 5% 的时间**传送 → 实际占用率：

25%×5%=1.25%

**（2）DMA 方式**

- 每次 DMA 传送耗时：

(8000 B)/(4 MB/s)=2×10^(-3)s=2 ms

- 每秒 DMA 传送次数：

1/(2×10^(-3))=500 次/秒

- 每次 DMA 的 CPU 开销 = 初始化 1000 + 结束中断 500 = **1500 周期**
- 每秒 CPU 花在硬盘 I/O 上的周期：

(1000+500)×500=750000=7.5×10⁵

- 占用率：

(7.5×10⁵)/(500×10⁶)=1.5×10^(-3)=0.15%

### 6.8.3 结论与"仓库比喻"

| 方式 | 主机占用率 | 备注 |
|---|---|---|
| 中断（5% 负载） | **1.25%** | 已假设"不漏数据"（极苛刻） |
| DMA（100% 负载） | **0.15%** | **负载高 20 倍，开销却只有 1/8** |

> **课件中的仓库比喻**（帮助理解）：
> 大仓库门口有一个可放 **16 个零件**的箱子，要把零件运到小仓库。
> - **中断方式**：**每装满一箱**就喊车床上的技工来搬到车间，再从车间搬到小仓库 —— 技工（CPU）**频繁被叫走**
> - **DMA 方式**：技工一次告诉搬运工"**把 8000 个零件放到小仓库固定位置**"，然后回去干活；搬运工**分两组**（一组从大仓库搬到箱子，一组把箱子直接运到小仓库），8000 个运完后技工才来检查一次
>
> 显然是 DMA 的"生产效率"更高 —— 因为**批量化把"每次搬运的固定开销"摊薄了**。

## §6.9 I/O 软件层次与操作系统的角色

### 6.9.1 为什么 I/O 需要层次结构

所有高级语言的**运行时（runtime）** 都提供了执行 I/O 的机制：

- C：`printf()`、`scanf()` 等**标准 I/O 库函数**
- C++：`<<`、`>>` **重载操作符**

从高级语言提出 I/O 请求，到设备响应并完成，涉及**多层次 I/O 软件与 I/O 硬件的协作**。

> **从用户 I/O 软件切换到内核 I/O 软件的唯一办法是"异常"机制：系统调用（自陷 trap / `ecall`）。**

### 6.9.2 操作系统的职责由 I/O 系统的三个特性决定

| 特性 | 含义 | 后果 |
|---|---|---|
| **共享性**（sharing） | I/O 系统被多个程序共享 | 需 OS **统一调度管理** |
| **复杂性**（complexity） | 设备控制细节复杂 | 不能由上层用户程序实现，需 OS 提供**驱动程序** |
| **采用中断 I/O 方式** | 通常用**外部中断**要求处理器执行专门程序；中断导致**向内核态转移** | **必须由 OS 处理** |

**OS 在 I/O 中的四大职能**：

1. 保证用户程序**只能访问自己有权访问**的那部分 I/O 设备
2. 为用户程序提供**设备驱动程序**，以**屏蔽设备控制细节**
3. **处理外部 I/O 中断**，提供**中断服务程序**
4. 对共享的 I/O 资源提供**合理的调度管理**，使系统**吞吐率达到最佳**

### 6.9.3 I/O 软件的四个层次

```
┌─────────────────────────────────────┐
│ 用户 I/O 软件（库函数 printf/fread） │  用户态
├─────────────────────────────────────┤
│ 设备无关 I/O 软件（缓冲、命名、保护）│
├─────────────────────────────────────┤
│ 设备驱动程序（与设备相关）           │  内核态
├─────────────────────────────────────┤
│ 中断服务程序                         │
└─────────────────────────────────────┘
              ↓
           I/O 硬件
```

![[Ch6-P41-用户程序到内核.webp]]

### 6.9.4 实例：Linux 中 `printf()` 的执行过程

![[Ch6-P42-printf执行过程.webp]]

```
用户空间（用户态）                                 内核空间（内核态）
main() → printf() → write() ──ecall──> system_call() → sys_write()
  用户程序   I/O 标准库函数  系统调用封装函数   系统调用处理程序   系统调用服务例程
```

**逐步说明**：

1. 某函数调用 `printf()`，执行到该语句时转到 C 语言 I/O 标准库函数 `printf()`
2. `printf()` 通过一系列函数调用，最终调用 `write()`
3. 调用 `write()` 时，通过一系列步骤在**内核空间**中找到 `write` 对应的**系统调用服务例程 `sys_write`** 来执行

> **"`system_call` 中如何知道要转到 `sys_write` 执行呢？"**
> **答案：根据系统调用号（syscall number）！**
> 用户态把系统调用号放在约定寄存器（RISC-V 为 `a7`，x86-64 为 `rax`），`ecall`/`syscall` 陷入内核后，内核用该号**查表**（系统调用表）得到服务例程地址。

### 6.9.5 设备无关 I/O 软件层的四项工作

| 工作 | 内容 |
|---|---|
| **设备驱动程序统一接口** | OS 为所有外设驱动规定**统一接口** → 新设备驱动只要按规范编制，就可在**不修改 OS** 的情况下添加新设备；**所有设备都抽象成文件**，设备名与文件名**形式上无差别**，统一接口，不同名字映射到对应驱动 |
| **缓冲处理** | 每个设备的 I/O 都需用**内核缓冲区**，缓冲区的申请与管理是**所有设备公共的** → 放在设备无关层 |
| **错误报告** | I/O 在内核态执行时的错误信息，都通过设备无关层返回用户进程 → **错误处理框架与设备无关** |
| **打开与关闭文件** | `open`/`close` 等系统调用**不涉及具体 I/O 操作**，只需修改主存中的一些数据结构 → 由设备无关层处理 |
| **逻辑块大小处理** | 为所有**块设备**和所有**字符设备**分别提供**统一的抽象视图**；对块设备，不管磁盘/光盘扇区多大，**所有逻辑数据块大小相同** → 高层软件只处理简化的抽象设备 |

**错误的两类来源**：

- **直接返回编程错误**（无需驱动处理）：请求了不可能的 I/O 操作、写信息到输入设备或从输出设备读信息、无效缓冲区地址/参数、指定了不存在的设备
- **由驱动检测并处理**，驱动无法处理时**上报**：写一个已被破坏的磁盘扇区、打印机缺纸、读一个已关闭的设备

### 6.9.6 设备驱动程序（与设备相关）

- 每个外设**具体的 I/O 操作**都通过执行**设备驱动程序**完成
- 外设种类繁多、控制接口不一 → 不同外设的驱动**千差万别** → **驱动程序与设备相关**
- 每个（类）外设都有一个**设备控制器**，其中包含各种 **I/O 端口**；CPU 通过执行驱动中的 **I/O 指令**访问各种 I/O 端口

**不同 I/O 控制方式下，驱动的实现方式不同**（重要对比）：

| 控制方式 | 驱动程序行为 | 用户进程状态 |
|---|---|---|
| **程序直接控制** | 驱动**完成**用户程序的 I/O 请求后才结束 | **不被阻塞**；内核 I/O 软件一直代表用户进程在内核态处理 |
| **中断控制** | 驱动**启动第一次** I/O 操作后，**调出其他进程**执行 | **被阻塞**；CPU 与外设并行；外设完成时发中断 → 中断服务程序中**再次启动** I/O |
| **DMA 控制** | 驱动对 DMA 控制器**初始化**后，发"**启动 DMA 传送**"命令；外设开始 I/O 并在外设与主存间传数据。同时 CPU **执行处理器调度程序，转其他进程** | **被阻塞**；DMA 完成所有任务后向 CPU 发"**DMA 完成**"中断 |

### 6.9.7 中断服务程序

- **中断控制**和 **DMA 控制**两种方式下**都需中断处理**
- **中断控制方式**：中断服务程序主要**从数据缓冲器取数**或**写数据到缓冲器**，然后**启动外设工作**
- **DMA 控制方式**：中断服务程序进行**数据校验等后处理**工作
- 内核 I/O 软件中用到的 **I/O 指令**、"**开中断**"和"**关中断**"等指令都是**特权指令**，**只能在 OS 内核程序中使用**

> 这最后一句话解释了**为什么 I/O 必须由 OS 垄断**：如果用户程序能随意关中断或直接操作设备端口，系统就没法保证公平与安全。

## §6.10 三种 I/O 方式的完整对比（总结表）

| 维度 | 程序直接控制（轮询） | 中断方式 | DMA 方式 |
|---|---|---|---|
| **CPU 参与程度** | **全程参与**（踏步等待） | 每个数据**参与一次**（中断处理） | 只在**开始/结束**参与 |
| **CPU 与外设** | **串行** | **并行** | **并行**（程度最高） |
| **数据传送者** | CPU（用 load/store） | CPU（执行中断服务程序） | **DMA 控制器**（硬件） |
| **传送单位** | 字/字节 | 字/字节 | **数据块** |
| **适用设备** | 极慢设备（LED、开关） | 中低速字符设备（键盘、串口） | **高速块设备**（磁盘、网卡、显卡） |
| **硬件复杂度** | 最低 | 中（需中断控制器） | 高（需 DMA 控制器） |
| **CPU 开销（示例）** | 极高 | 1.25%（5% 负载时） | **0.15%**（100% 负载时） |
| **关键问题** | "踏步"浪费 CPU | 每次传送都有中断开销 | 与 CPU **争用主存/总线** |

## §6.11 易错点清单

1. **统一编址 vs 独立编址**：RISC-V/MIPS 用**统一编址**（memory-mapped），x86 用**独立编址**（IN/OUT）
2. **中断隐指令**是**硬件自动完成**的，不是程序指令
3. 响应中断的**第一步是关中断**（否则保护现场会被打断）
4. **响应优先级**（谁先被响应）≠ **处理优先级**（谁能嵌套），后者由**屏蔽字**决定
5. **软件识别**（统一入口 + 查 Cause）vs **硬件识别**（向量表），别记反（MIPS=软件，x86=硬件）
6. **DMA 的总线优先级高于 CPU**（否则高速设备会丢数据）
7. DMA **不是取代中断**：开始/结束仍靠中断
8. **CPU 停止法**：CPU 停、简单、主存利用率低
9. **周期挪用**：偷一个存储周期、开销在"申请/释放总线"
10. **交替分时**：存储周期切两半、主存利用率最高、要求存储器快
11. 中断开销题：**中断频率 = 传输率 / 每次传送字节数**，别忘了乘**负载百分比**
12. DMA 开销题：**每次 DMA 开销 = 初始化 + 结束中断**，且**传输时间 = 块大小 / 传输率**
13. **块设备 vs 字符设备**：逻辑块大小统一处理只针对块设备
14. **驱动与设备相关**，**设备无关层**负责缓冲、命名、错误框架、逻辑块大小
15. **开关中断、I/O 指令是特权指令**
