## §3.1 引言：计算机要处理哪些算术

- **整数运算**（operations on integers）
	- 加法与减法（addition and subtraction）
	- 乘法与除法（multiplication and division）
	- **溢出处理**（dealing with overflow）
- **浮点实数**（floating-point real numbers）
	- 表示与运算（representation and operations）

> 贯穿全章的一句话（结论章会重申）：**位没有固有含义（bits have no inherent meaning）**，其解释完全取决于所施加的**指令**。同一串 `1111 1111` 可以是有符号 −1、无符号 255、或浮点 NaN 的一部分。

## §3.2 加法与减法（Addition and Subtraction）

### 3.2.1 整数加法与溢出判断

**例**：7+6

```
  0000 ... 0000 0111   (+7)
+ 0000 ... 0000 0110   (+6)
= 0000 ... 0000 1101   (+13)
```

**溢出的判定规则**（有符号补码加法）：

| 操作数符号 | 是否可能溢出 | 判据 |
|---|---|---|
| 一正一负 | **绝不溢出** | —— |
| 两个正数 | 可能 | **结果符号为 1** → 溢出 |
| 两个负数 | 可能 | **结果符号为 0** → 溢出 |

> 本质：正+正的结果本应更大，若"变成负数"，说明数值已经从正方向绕到负方向（模运算的"回绕"）。

### 3.2.2 整数减法

- 减法 = 加上第二个操作数的**相反数**：7-6=7+(-6)

```
+7:  0000 ... 0000 0111
-6:  1111 ... 1111 1010    ← −6 的补码
+1:  0000 ... 0000 0001    ← 结果
```

**减法溢出规则**：

| 情形 | 判据 |
|---|---|
| 两个正数相减 / 两个负数相减 | **不会溢出** |
| 负数 − 正数 | 结果符号为 **0** → 溢出 |
| 正数 − 负数 | 结果符号为 **1** → 溢出 |

> 讲师补充：本质是"**借位占用了符号位**"。

### 3.2.3 全加器（Full Adder, FA）

![[Ch3-P05-全加器.webp]]

- 输入：加数 A_i、被加数 B_i、低位进位 C_in
- 输出：和 F_i、进位 C_out

F_i=A_i⊕B_i⊕C_in
C_out=A_iB_i+A_iC_in+B_iC_in

> 门延迟基准（教材设定）：**异或门 = 3 级门延迟**，与/或门 = 1 级。
> → **Sum 延迟 = 6 级**（两个异或串联），**Carry out 延迟 = 2 级**（与或两级）。
> 这两个数字是后面所有延迟计算的"原子单位"。

### 3.2.4 串行进位（行波）加法器

![[Ch3-P06-串行进位加法器.webp]]

- n 位串行加法器 = n 个 FA 把进位**逐级串联**（C_0→C_1→⋯→C_n）
- **缺点**：进位串行传递，**速度慢**

**延迟计算（必考）**：

| 量 | 延迟 |
|---|---|
| 从 C_0 到 C_n（最终进位） | 2n 级门延迟 |
| 最后一位的和 F_(n-1) | 2n+1 级门延迟 |

> 推导：每一位的进位要经过"与-或"2 级；最后一位的和还要再异或一次（但只算"最后一级"的额外延迟，故 2n+1）。
> 结论：**延迟与位数成正比** → 32 位要 64 级，太慢。

### 3.2.5 先行进位加法器（Carry Lookahead Adder, CLA）

![[Ch3-P10-四位全先行进位加法器.webp]]

**为什么**：串行进位延迟与位数成正比，现代计算机必须打破这种线性依赖。

**怎么做**：定义两个辅助函数

G_i=A_iB_i （进位生成函数 generate）
P_i=A_i+B_i （进位传递函数 propagate）

（有的教材用 P_i=A_i⊕B_i，两者在 CLA 中都可推导出一致结果）

则全加逻辑方程变为：

F_i=A_i⊕B_i⊕C_i
C_(i+1)=G_i+P_iC_i

**递推展开（n=4）**：

C_1=G_0+P_0C_0
C_2=G_1+P_1G_0+P_1P_0C_0
C_3=G_2+P_2G_1+P_2P_1G_0+P_2P_1P_0C_0
C_4=G_3+P_3G_2+P_3P_2G_1+P_3P_2P_1G_0+P_3P_2P_1P_0C_0

**核心洞察**：每个进位只依赖 G_i,P_i（**当拍就能算出**）和 C_0，**彼此之间没有等待**，可以**同时产生**。实现这组逻辑的电路称为 **4 位先行进位部件（4 位 CLU）**。

**门延迟**：4 位全先行进位加法器产生所有和数需要 1+2+3=6 级门延迟（G/P 1 级 + 进位逻辑 2 级 + 求和异或 3 级）。

### 3.2.6 局部（单级）先行进位加法器

![[Ch3-P11-局部先行进位.webp]]

- **全先行进位的成本太高**：想象 C₃₁ 的逻辑公式有多长（32 项乘积之和）
- 工程折中：把若干 N 位 CLA **级联**成大加法器
	- 例：4 个 **8 位** CLA 拼成 **32 位**局部先行进位加法器
- 关键路径：(A_(7:0),B_(7:0),C_0)→C_8→C₁₆→C₂₄
- **延迟 = 3 + 2 + 2 + 5 = 12 级**门延迟

> 对比：纯串行 32 位要 ~64 级；局部 CLA 只要 12 级。这就是"**好的设计需要好的折中**"（第 2 章原则 4）在电路层的体现。

### 3.2.7 带标志的加法器（Flag Adder）

![[Ch3-P12-带标志加法器.webp]]

两个 n 位**有符号**整数（补码）相加时，必须判断是否溢出；程序中经常需要**比较大小**，而比较是靠减法得到的**标志信息**来判断的。

| 标志 | 名称 | 定义 |
|---|---|---|
| **OF** | 溢出标志（overflow） | OF=C_n⊕C_(n-1) |
| **SF** | 符号标志（sign） | SF=F_(n-1)（结果的最高位） |
| **ZF** | 零标志（zero） | ZF=1 当且仅当 F=0 |
| **CF** | 进位/借位标志（carry） | CF=C_out⊕C_in（减法时表示借位） |

> **OF 的本质**：最高位进位与次高位进位**不一致** → 符号位"被破坏" → 溢出。
> **CF 的本质**：无符号运算的"进/借位"。

**比较大小的实现**（关键考点）：

| 比较 | 指令 | 依据 |
|---|---|---|
| 有符号 a<b | `blt` | SF⊕OF=1（结果符号与溢出"异或"） |
| 无符号 a<b | `bltu` | CF=1（减法产生借位） |
| a=b | `beq` | ZF=1 |

> 为什么有符号比较要**异或 OF**？因为当减法溢出时，结果的符号位是"反的"，必须用 OF 修正回来。

### 3.2.8 整数加/减运算器

![[Ch3-P13-整数加减运算器.webp]]

**补码加减公式**：

[A+B]_(补)=[A]_(补)+[B]_(补)(mod 2ⁿ)
[A-B]_(补)=[A]_(补)+[-B]_(补)(mod 2ⁿ)

**关键问题**：如何求 [-B]_(补)？

[-B]_(补)=[B]_(补)+1

**硬件实现**：在 B 的输入端加一排**异或门**，用控制信号 **Sub** 控制：

- `Sub = 0`（加法）：B 原样进入加法器，C_in=0
- `Sub = 1`（减法）：B **按位取反**（与 1 异或），且 C_in=1 → 实现"取反加 1"

> 一个加法器 + 一排异或门 + 一个控制信号 = **加/减运算器**。这是第 4 章 ALU 的最核心部件。

### 3.2.9 溢出的处理策略

- **有符号数与无符号数的溢出判断不一样**
	- 有符号：看符号位是否异常（OF）→ 产生**溢出异常**（overflow exception）
	- 无符号：看最高位是否有进位（CF）→ **通常不判**，也不产生"溢出异常"（地址计算等场景就是希望它"回绕"）

| 语言/场景 | 溢出行为 |
|---|---|
| C（有符号） | **未定义行为**（UB），编译器可假设不发生 |
| C（无符号） | 定义良好的模 2ⁿ 回绕 |
| Java | 抛异常 / 或用 `Math.addExact` |
| RISC-V `add` | **不**产生异常，只是结果回绕 |
| MIPS `add` | 溢出产生异常；`addu` 不产生 |

> RISC-V 的选择：**默认不检查溢出**（`add`），需要时用软件判断或用 `addw` 等。理由是"让常见情况快"——绝大多数加法不会溢出。

### 3.2.10 多媒体算术（Arithmetic for Multimedia）

- 图形与媒体处理面向 **8 位、16 位数据的向量**
- 用 **64 位加法器 + 分段进位链**（partitioned carry chain）
	- 可做 **8×8 位**、**4×16 位**、**2×32 位**的并行运算
	- 这就是 **SIMD**（single-instruction, multiple-data，单指令多数据）
- **饱和运算**（saturating operations）：溢出时结果取**可表示的最大/最小值**
	- 对比补码的模运算（会"回绕"）
	- 应用：音频的**削波**（clipping）、视频的**饱和度**（saturation）

> 例：像素值 250 + 10 用饱和运算得 255（而不是回绕成 4）——因为"白色再亮还是白色"。

## §3.3 乘法（Multiplication）

### 3.3.1 无符号乘法：手算即算法

![[Ch3-P16-无符号乘法手算.webp]]

```
      1000    (8, multiplicand 被乘数)
   ×  1001    (9, multiplier 乘数)
   --------
      1000    ← 乘数最低位为 1，抄下被乘数
     0000     ← 该位为 0，写 0
    0000
   1000
   --------
   1001000    (72, product 积)
```

**两个关键事实**：

1. 整个过程只用到两种操作：**加法 + 左移** → 可以用 **ALU + 移位器**实现
2. **积的长度 = 两个操作数长度之和**（n 位 × n 位 = 2n 位）

### 3.3.2 乘法硬件（第一版）

![[Ch3-P17-乘法硬件.webp]]

结构：

- **64 位被乘数寄存器**（multiplicand），配一个 **128 位 ALU**
- **64 位乘数寄存器**（multiplier），**64 位积寄存器**（product）
- 每步：
	1. 若乘数最低位为 1，把被乘数加到积的高 64 位
	2. 被乘数**左移** 1 位
	3. 乘数**右移** 1 位
	4. 重复 64 次

> 缺点：被乘数要 128 位宽（要能左移到最高），ALU 也要 128 位——**硬件浪费**。

### 3.3.3 优化乘法器（Optimized Multiplier）

![[Ch3-P19-优化乘法器.webp]]

**优化思路**：把"积左移"改成"**积右移**"，这样被乘数**不动**，只需 64 位 ALU。

| 部件 | 作用 |
|---|---|
| **被乘数寄存器 X** | 存放被乘数（64 位，固定不动） |
| **乘积寄存器 P** | 初始为 0；结束时存放 128 位积的**高 64 位** |
| **乘数寄存器 Y** | 初始放乘数；结束时存放 128 位积的**低 64 位** |
| **进位触发器 C** | 保存加法器的进位信号 |
| **循环计数器 C_n** | 初值 64，每循环一次减 1，C_n=0 结束 |
| **64 位 ALU** | 在控制逻辑下对 P 和 X 做加/减 |

**每周期动作（并行完成）**：

1. 若 Y 的最低位为 1：P ← P + X（否则加 0）
2. {C, P, Y} **整体右移一位**（C 移入 P 的最高位，P 的最低位移入 Y 的最高位，Y 的最低位丢弃）

> **"加"与"移"可以并行**（perform steps in parallel: add/shift），因此**每个部分积只需 1 个时钟周期**。
> 代价：频率不能太高（组合逻辑路径长）。教材评论："That's ok, if frequency of multiplications is low"。

### 3.3.4 快速乘法器

**为什么需要**：ALU 迭代法要 n 次"加+右移"（一位乘法约 n 次；两位乘法约 n/2 次），**时间随位数线性增长**，由时钟和控制电路限制。而程序中**约 1/3 是乘法运算**。

**两条实现路线**：

1. **流水线方式**（pipelined）
2. **硬件叠加方式**（如**阵列乘法器** array multiplier）

**流水线快速乘法器（32 位）**：

- 为乘数的**每一位**配一个 n 位加法器
- 每个加法器的两个输入：
	- 本次乘数对应位与被乘数相乘的结果（0 或被乘数）
	- 上次的**部分积**
- 每个加法器的输出分两部分：
	- 和的**最低有效位（LSB）**作为本位的**乘积位**
	- **进位 + 高 31 位的和**组成 32 位数，作为本次部分积
- 全是**组合逻辑电路**，**无需控制器**控制

### 3.3.5 阵列乘法器（Array Multiplier）

![[Ch3-P24-阵列乘法器.webp]]

- 用 n×n 个全加器构成二维阵列，部分积在阵列中"斜向"传播
- 每个 FA 有三个输入：部分积输入、进位输入、被乘数位（A_i 与 B_j 相与后的结果）
- **速度仅取决于逻辑门和加法器的传输延迟**（与时钟无关）
- 属于**无符号阵列乘法器**；有符号（补码）乘法需用 **Booth 编码**或先转绝对值

**成本/性能折中**（Faster Multiplier）：

- 用多个加法器 → **面积换速度**
- 可以**流水线化** → 多个乘法并行执行

### 3.3.6 RISC-V 乘法指令

| 指令 | 结果 |
|---|---|
| `mul rd, rs1, rs2` | 积的**低 64 位** |
| `mulh` | 积的**高 64 位**（操作数按**有符号**） |
| `mulhu` | 积的高 64 位（操作数按**无符号**） |
| `mulhsu` | 积的高 64 位（一**有符号**一**无符号**） |

> **用 `mulh` 的结果判断 64 位乘法是否溢出**：若高 64 位不等于低 64 位的符号扩展，则溢出。
> 注意：`mul` 单独无法判断溢出——必须配合 `mulh`。

## §3.4 除法（Division）

### 3.4.1 手算除法

```
            1001   (quotient 商)
        ---------
 1000 ) 1001010   (dividend 被除数)
       -1000
       -----
          101
          1010
         -1000
         -----
            10   (remainder 余数)
```

- **n 位操作数产生 n 位商和 n 位余数**
- 长除法（long division）规则：
	- 若**除数 ≤ 当前被除位段** → 商该位为 **1**，做**减法**
	- 否则 → 商该位为 **0**，**落下**下一位被除数

### 3.4.2 三类除法算法

| 算法 | 做法 |
|---|---|
| **恢复余数法**（restoring division） | 先做减法；若余数 < 0，**把除数加回来**（恢复） |
| **不恢复余数法**（non-restoring） | 余数为负时不恢复，下一步改做加法（加减交替） |
| **有符号除法**（signed division） | 用**绝对值**相除，再按规则调整商与余数的符号 |

**必须先检查除数是否为 0**。

### 3.4.3 除法硬件与优化除法器

![[Ch3-P30-优化除法器.webp]]

| 部件 | 作用 |
|---|---|
| **除数寄存器 Y** | 存放除数 |
| **余数寄存器 R** | 初始为**高 64 位**被除数；结束时是**余数** |
| **余数/商寄存器 Q** | 初始为**低 64 位**被除数；结束时是 **64 位商** |
| **循环计数器 C_n** | 初值 **65**（教材写 33，是按 32 位/含符号位处理），每循环减 1 |
| **ALU** | 对 R 和 Y 做"加/减" |

**优化要点**：

- **移位与减法同时进行**（一个周期处理一个部分余数）
- "**Looks a lot like a multiplier!**" → **同一套硬件可兼作乘法和除法**（same hardware can be used for both）

### 3.4.4 为什么除法不能像乘法那样并行

- **乘法**：每一步"加不加"只取决于**乘数位**（事先已知）→ 可以并行展开
- **除法**：每一步"减不减"取决于**上一步余数的符号**（数据相关）→ **无法并行**

**更快的除法器**：**SRT 除法**（Sweeney-Robertson-Tocher）每步产生**多位商**，但**仍需多步**。

### 3.4.5 RISC-V 除法指令

| 指令 | 含义 |
|---|---|
| `div rd, rs1, rs2` | 有符号除法的**商** |
| `rem` | 有符号除法的**余数** |
| `divu` / `remu` | 无符号的商 / 余数 |

**重要特性**：**溢出和除零不产生错误（不陷入异常），只返回定义好的结果**

- 除零：`div` 返回 −1，`rem` 返回被除数（按 RISC-V 规范）
- 这样"常见情况（无错误）"更快 —— 又是"让常见情况变快"

### 3.4.6 有符号除法的符号规则（易错）

必须满足：**被除数 = 商 × 除数 + 余数**

以 (-7)/2 为例：

| 方案 | 商 | 余数 | 是否可取 |
|---|---|---|---|
| A | −3 | −1 | ✅ 取这个 |
| B | −4 | +1 | ❌ 虽然等式成立，但商的绝对值会随符号改变 |

**规则**：

1. 源操作数**符号相反**时，**商为负**
2. **非零余数的符号与被除数相同**（(-7)/2 余 -1；7/(-2) 余 +1）

> 与 C 语言一致（C99 起规定"向零取整"）。这也是第 2 章"`srai` 与 `/` 不同"的根源：`srai` 是向下取整。

## §3.5 浮点（Floating Point）

### 3.5.1 为什么需要浮点

- 表示**非整数**，且要覆盖**极大和极小**的数
- 类似**科学计数法**（scientific notation）：

| 例子 | 是否规格化（normalized） |
|---|---|
| -2.34×10^(56) | ✅ |
| +0.002×10^(-4) | ❌ |
| +987.02×10⁹ | ❌ |

- 二进制形式：±1.xxxxxxx_2×2^(yyyy)

### 3.5.2 IEEE 754 标准

- 由 **IEEE Std 754-1985** 定义
- 制定原因：各家浮点表示**各行其是**，导致科学计算代码**不可移植**（portability issues）
- 现在几乎**全世界统一采用**
- 两种主要表示：
	- **单精度**（single precision，32 位）
	- **双精度**（double precision，64 位）

### 3.5.3 IEEE 浮点格式

![[Ch3-P37-IEEE754格式.webp]]

```
单精度:  S(1)  Exponent(8)   Fraction(23)
双精度:  S(1)  Exponent(11)  Fraction(52)
```

x=(-1)^S×(1+Fraction)×2^(Exponent-Bias)

**三个字段**：

| 字段 | 含义 |
|---|---|
| **S**（sign） | 符号位：0 非负，1 负 |
| **Exponent** | 阶码，**移码**（excess/bias）表示：实际指数 + Bias |
| **Fraction** | 尾数小数部分（**不含**隐含的 1.） |

**两条关键设计**：

1. **规格化尾数**（normalize significand）：1.0≤|significand|<2.0
	- 因为二进制规格化后**整数部分恒为 1**，所以**不必存**（**隐藏位 hidden bit**）
	- 尾数的真实值是 "`1.` + Fraction"
2. **阶码用移码**（excess representation）：实际指数 + **Bias**
	- 保证阶码是**无符号**数（便于比较）
	- 单精度 **Bias = 127**；双精度 **Bias = 1023**

### 3.5.4 单精度可表示范围

- 阶码 `00000000` 与 `11111111` **保留**（特殊用途）

| 极值 | 阶码 | 实际指数 | 尾数 | 值 |
|---|---|---|---|---|
| 最小正规格化数 | 00000001 | 1-127=-126 | 0…0 → 1.0 | ±1.0×2^(-126)≈±1.2×10^(-38) |
| 最大正规格化数 | 11111110 | 254-127=+127 | 1…1 → ≈2.0 | ±2.0×2^(+127)≈±3.4×10^(+38) |

**双精度**：最小 ±1.0×2^(-1022)≈±2.2×10^(-308)；最大 ±2.0×2^(+1023)≈±1.8×10^(+308)。

![[Ch3-P40-浮点数轴与上下溢.webp]]

**数轴结构**（重要观念）：

```
← 负上溢 | 可表示的负数 | 负下溢 | 零 | 正下溢 | 可表示的正数 | 正上溢 →
        -2×2^127    -2^-126   0   2^-126            2×2^127
```

- **机器 0**：尾数为 0，或落在下溢区中间的数
- **浮点数范围比定点数大，但数的个数没变多** → 因此**数之间更稀疏，且不均匀**（越靠近 0 越密）

> 这解释了浮点运算的两个特性：**① 加法不满足结合律**；**② 大数吃小数**（10^(20)+1=10^(20)）。

### 3.5.5 浮点精度（Precision）

- **相对精度**（relative precision）：所有小数位都是有效位
	- 单精度：约 2^(-23)，相当于 23×log₁₀2≈23×0.3≈ **7 位十进制有效数字**
	- 双精度：约 2^(-52)，相当于 52×0.3≈ **16 位十进制有效数字**

> 记忆：**单 7 双 16**。

### 3.5.6 编解码示例

**例 1：表示 -0.75**

-0.75=(-1)¹×1.1_2×2^(-1)

- S=1
- Fraction =1000…00_2（去掉隐含的 `1.`）
- Exponent：
	- 单精度：-1+127=126=0111 1110_2
	- 双精度：-1+1023=1022=011 1111 1110_2

```
单精度：1 01111110 1000...00
双精度：1 01111111110 1000...00
```

**例 2：解码单精度 `1100 0000 1010 0000...`**

- S=1
- Fraction =01000…_2 → 尾数 =1.01_2=1.25
- Exponent =10000001_2=129
- x=(-1)¹×(1+0.01_2)×2^(129-127)=-1×1.25×2²=-5.0

**例 3：十进制 → 浮点（-12.75）**

1. 整数部分：12=8+4=1100_2
2. 小数部分：.75=.5+.25=.11_2
3. 拼接并规格化：1100.11=1.10011×2³
4. 阶码：127+3=130=1000 0010_2
5. 结果：`1 10000010 1001100 0000 0000 0000 0000` = **0xC14C0000**

> 手算技巧：**先写二进制，再规格化，最后加 Bias**；反过来解码时**先减 Bias**。

### 3.5.7 非规格化数（Denormal Numbers）

当 **Exponent = 000…0** 时：

x=(-1)^S×(0+Fraction)×2^(-Bias)

- 比规格化数**更小**
- 作用：允许**渐进下溢**（gradual underflow），精度**逐渐降低**而不是突然变成 0
- **Fraction = 000…0** 时：x=(-1)^S×0×2^(-Bias)=±0.0
	- → **0.0 有两种表示**（+0 和 −0）！

> 为什么需要 denormal？若没有它，最小正数（2^(-126)）与 0 之间有个"突然的悬崖"，减法结果会突然归零，误差巨大。denormal 让这段区间"平滑下降"。

### 3.5.8 无穷大与 NaN

| Exponent | Fraction | 含义 |
|---|---|---|
| 111…1 | 000…0 | **±Infinity**（无穷大） |
| 111…1 | ≠ 000…0 | **NaN**（Not-a-Number，非数） |

**Infinity**：

```
+∞: 0 11111111 00000000000000000000000
-∞: 1 11111111 00000000000000000000000
```

- 可以参与后续计算，**避免每次都要做溢出检查**
- 例：`X/0 > Y` 可作为有效比较（结果确定）

**NaN**：

- 表示**非法或未定义**的结果，如 0.0/0.0、√-1、∞-∞
- 可以继续参与计算（结果仍是 NaN）
- **有助于调试**（NaN 会"传染"，最终暴露出来）

### 3.5.9 浮点加法：四步法

以十进制 4 位有效数字为例：9.999×10¹+1.610×10^(-1)

| 步骤 | 操作 | 结果 |
|---|---|---|
| **1. 对阶**（align） | 移动**指数较小**的数 | 9.999×10¹+0.016×10¹ |
| **2. 尾数相加**（add significands） | | 10.015×10¹ |
| **3. 规格化并检查上/下溢** | | 1.0015×10² |
| **4. 舍入并再次规格化** | | 1.002×10² |

**二进制例子**：1.000_2×2^(-1)+(-1.110_2×2^(-2))，即 0.5+(-0.4375)

| 步骤 | 结果 |
|---|---|
| 1. 对阶 | 1.000_2×2^(-1)+(-0.111_2×2^(-1)) |
| 2. 尾数相加 | 0.001_2×2^(-1) |
| 3. 规格化 | 1.000_2×2^(-4)（无上/下溢） |
| 4. 舍入 | 1.000_2×2^(-4)=0.0625 |

> ⚠️ 对阶时**小阶向大阶看齐**，被移动的尾数低位会**丢失**——这是浮点加法误差的主要来源。
> ⚠️ 注意第 2 步得到 0.001_2 后要**左移规格化**，同时**阶码减小**（-1→-4）。

### 3.5.10 浮点加法器硬件

![[Ch3-P52-浮点加法器步骤.webp]]

- 比整数加法器**复杂得多**
- **一个时钟周期做完太久**：远长于整数运算；若为了它降低时钟频率，会**惩罚所有指令**
- 因此 FP 加法器通常**需要多个周期**，并且**可以流水线化**

### 3.5.11 浮点乘法：五步法

以 1.110×10^(10)×9.200×10^(-5) 为例：

| 步骤 | 操作 | 结果 |
|---|---|---|
| **1. 阶码相加**（add exponents） | 偏置阶码相加后**要减去一个 Bias** | 新阶码 =10+(-5)=5 |
| **2. 尾数相乘** | | 1.110×9.200=10.212 |
| **3. 规格化并检查上/下溢** | | 1.0212×10⁶ |
| **4. 舍入并再次规格化** | | 1.021×10⁶ |
| **5. 确定符号** | 由两操作数符号决定 | +1.021×10⁶ |

**二进制例子**：1.000_2×2^(-1)×(-1.110_2×2^(-2))=0.5×(-0.4375)

1. 阶码相加：无偏 -1+(-2)=-3；带偏 (−1+127)+(−2+127)-127=-3+127
2. 尾数相乘：1.000_2×1.110_2=1.110_2
3. 规格化：1.110_2×2^(-3)（无需调整）
4. 舍入：不变
5. 符号：正 × 负 → 负 → -1.110_2×2^(-3)=-0.21875

> **偏置阶码相加为什么要减一个 Bias**？因为 (E_1+B)+(E_2+B)=E_1+E_2+2B，要得到 E_1+E_2+B，必须减去 B。

### 3.5.12 浮点运算硬件

- FP 乘法器复杂度与 FP 加法器**相当**，只是把尾数加法器换成**乘法器**
- 典型 FP 硬件支持：加、减、乘、除、**倒数**（reciprocal）、**开方**（square-root），以及**浮点↔整数转换**
- 通常需要**多个周期**，**可流水线化**

### 3.5.13 RISC-V 浮点指令

| 类别 | 指令 |
|---|---|
| 独立的 FP 寄存器 | `f0`–`f31`（双精度；单精度值存在低 32 位） |
| 取/存 | `flw, fld, fsw, fsd`（例：`fld f0, 20(x5)`） |
| 单精度算术 | `fadd.s, fsub.s, fmul.s, fdiv.s, fsqrt.s` |
| 双精度算术 | `fadd.d, fsub.d, fmul.d, fdiv.d, fsqrt.d` |
| 比较 | `feq.s/flt.s/fle.s`（及 `.d` 版本） |

**关键规则**：

- FP 指令**只对 FP 寄存器**操作（整数与浮点不混用，代码尺寸影响最小）
- 比较指令的结果是**整数寄存器中的 0 或 1**：`flt.d x5, f0, f1`，然后用 `beq/bne` 分支

**例：华氏转摄氏**

```c
float f2c(float fahr) { return ((5.0/9.0)*(fahr - 32.0)); }
```
（fahr→f10，结果→f10，常量在全局存储区，gp = x3）

```asm
f2c:  flw    f0, const5(x3)     # f0 = 5.0f
      flw    f1, const9(x3)     # f1 = 9.0f
      fdiv.s f0, f0, f1         # f0 = 5.0/9.0
      flw    f1, const32(x3)    # f1 = 32.0f
      fsub.s f10, f10, f1       # f10 = fahr - 32.0
      fmul.s f10, f0, f10       # f10 = (5/9)*(fahr-32)
      jalr   x0, 0(x1)
```

> 注意 `fdiv.s f0,f0,f1` 在**每次调用时都重算** 5.0/9.0——这是编译器的"保守"；优化编译器可能把它提到循环外（循环不变式外提）。

**例：矩阵乘 C=C+A×B（32×32，双精度）**

```asm
mm:   li   x28, 32            # 行大小 / 循环上界
      li   x5, 0              # i = 0
L1:   li   x6, 0              # j = 0
L2:   li   x7, 0              # k = 0
      slli x30, x5, 5         # x30 = i * 32
      add  x30, x30, x6       # x30 = i*32 + j
      slli x30, x30, 3        # ×8 → 字节偏移
      add  x30, x10, x30      # &c[i][j]
      fld  f0, 0(x30)         # f0 = c[i][j]
L3:   slli x29, x7, 5         # x29 = k * 32
      add  x29, x29, x6
      slli x29, x29, 3
      add  x29, x12, x29      # &b[k][j]
      fld  f1, 0(x29)         # f1 = b[k][j]
      slli x29, x5, 5
      add  x29, x29, x7
      slli x29, x29, 3
      add  x29, x11, x29      # &a[i][k]
      fld  f2, 0(x29)         # f2 = a[i][k]
      fmul.d f1, f2, f1       # f1 = a[i][k] * b[k][j]
      fadd.d f0, f0, f1       # f0 += ...
      addi x7, x7, 1
      bltu x7, x28, L3
      fsd  f0, 0(x30)         # c[i][j] = f0
      addi x6, x6, 1
      bltu x6, x28, L2
      addi x5, x5, 1
      bltu x5, x28, L1
```

> 观察：**最内层循环每次都要重算三个地址**（大量整数运算），而浮点运算只有 2 条。这解释了第 3.8 节"优化矩阵乘"的动机，也说明**内存访问才是真正的瓶颈**（第 5 章）。

### 3.5.14 精确算术：保护位与舍入

**IEEE 754 规定额外的舍入控制**：

- **附加精度位**：**保护位（guard）、舍入位（round）、粘滞位（sticky）**
- **四种舍入模式**（rounding modes）：
	1. 向上舍入（toward +∞）
	2. 向下舍入（toward -∞）
	3. 截断（truncate，toward 0）
	4. **就近舍入到偶数**（round to nearest even）—— **默认**

- 允许程序员**微调数值行为**
- 并非所有 FP 部件都实现全部选项；多数语言与库只使用**默认**模式
- 这是**硬件复杂度、性能与市场需求之间的折中**

**保护位示例**：把 2.56₁₀×10⁰ 加到 2.34₁₀×10²，假设只有 3 位有效数字，就近舍入：

| 做法 | 过程 | 结果 |
|---|---|---|
| **有**保护位/舍入位 | 0.025610×10²（保护位=5，舍入位=6）；和为 2.365610×10²；舍入 | 2.37₁₀×10² |
| **无**保护位/舍入位 | 0.02₁₀×10²+2.34₁₀×10²=2.36₁₀×10² | **末位差 1** |

> 结论：**保护位能显著减少"对阶丢失"造成的误差**。没有它，小数的低位在移位时被直接丢弃。

### 3.5.15 浮点比较的真假判断（经典题）

对下列关系式判断是否**永真**（假定 d、f 都不是 NaN）：

| 表达式 | 是否永真 | 理由 |
|---|---|---|
| `x == (int)(float) x` | ❌ | float 只有 24 位有效位，大整数会丢精度 |
| `x == (int)(double) x` | ✅ | double 尾数 52 位，可精确表示 32 位 int |
| `f == (float)(double) f` | ✅ | 由低精度向高精度再回低精度，无损 |
| `d == (float) d` | ❌ | 双→单会丢精度 |
| `f == -(-f)` | ✅ | 取负只是改符号位，两次还原 |
| `2/3 == 2/3.0` | ❌ | 左边整数除法 = 0，右边 ≈ 0.6667 |
| `d < 0.0 ⇒ ((d*2) < 0.0)` | ✅ | 乘 2 只改阶码，不改符号 |
| `d > f ⇒ -f > -d` | ✅ | 取负反转序（严格单调） |
| `d * d >= 0.0` | ✅ | 平方非负（除非溢出为 ∞ 或 NaN） |
| `x * x >= 0` | ❌ | **int 溢出**可能得负（如 46341²） |
| `(d+f) - d == f` | ❌ | 结合律/消去律在浮点下不成立（大数吃小数） |

> 这类题考的是"**整数溢出 + 浮点精度 + 舍入**"三件事的综合直觉。建议自己写程序验证一遍。

### 3.5.16 两个真实事故（务必记住）

**① Ariane 5 火箭爆炸（1996-06-04）**

- 首次飞行 **37 秒**后偏离航线解体，损失约 **5 亿美元**的通信卫星
- 原因：把一个 **64 位浮点数转换为 16 位带符号整数**时**溢出异常**
- 溢出的值是火箭的**水平速率**，比 Ariane 4 高出 **5 倍**
- 设计 Ariane 4 软件时确认过"水平速率不会超过 16 位整数"，但 Ariane 5 **直接复用了这段代码**，没有重新检查
- 教训：**不同数据类型之间的转换往往隐藏着难以察觉的错误**

**② 爱国者导弹定位失败（1991-02-25）**

- 海湾战争中拦截飞毛腿失败，击中军营，**28 名美军死亡**
- 原因：系统时钟的**浮点精度问题**
- 系统用计数器每 0.1 秒计一次，用 **0.1 的 24 位定点二进制小数** x 乘以计数值得到秒数
- 0.1 的二进制是无限循环：0.000110011001100…_2
- x=0.00011001100110011001100_2，误差

0.1-x=0.000000000000000000000001100[1100]…_2=2^(-20)×0.1≈9.54×10^(-8)

- 连续工作 100 小时 → 计数 100×60×60×10=36×10⁵ 次
- 时钟偏差 =9.54×10^(-8)×36×10⁵≈0.343 秒
- 飞毛腿速度约 2000 m/s → 距离误差 ≈2000×0.343≈ **687 米**（足以错过拦截窗口）

**后续三个追问（讲义的三层递进）**：

| 表示方式 | 误差 | 100 小时后距离偏差 |
|---|---|---|
| 24 位定点小数 | 2^(-20)×0.1≈9.54×10^(-8) | **687 m** |
| `float`（24 位有效位） | 2^(-24)×0.1≈5.96×10^(-9) | **43 m**（精确约 16 倍） |
| 32 位定点小数 | 2^(-30)×0.1≈9.31×10^(-11) | **0.67 m**（精确约 64 倍） |

**启示**：

1. 程序员应对**底层机器级数据的表示和运算**有深刻理解
2. 计算机世界里"**差之毫厘，失之千里**"
3. **不能遇到小数就用浮点数**：若只是"整数 × 一个确定的小数常量"，可以先用**定点整数**相乘，再**移位**确定小数点位置 —— 这样既**更精确**又**更快**（无需转 IEEE 754 再乘）

## §3.7 真实机器：x86 的 SSE 与 AVX

### 3.7.1 早期 x86 浮点架构（8087 遗产）

- 基于 **8087 浮点协处理器**
	- **8 个 80 位扩展精度寄存器**
	- 用作**下压栈**（push-down stack），寄存器从栈顶编号 `ST(0), ST(1), …`
- 内存中的 FP 值是 32 位或 64 位，在 load/store 时转换
- **极难生成与优化代码** → 结果：**浮点性能很差**

**x86 FP 指令的四类**：数据传送（`FILD/FISTP/FLDPI/FLD1/FLDZ`）、算术（`FIADDP/FIMULP/FIDIVRP/FSQRT/FABS/FRNDINT`）、比较（`FICOMP/FSTSW`）、超越函数（`FPATAN/FCOS/FPTAN/FPSIN/FYL2X`）

- 可选变体：`I`（整数操作数）、`P`（弹出栈顶）、`R`（反序）
- **但不是所有组合都允许** → 编码极其混乱

### 3.7.2 SSE2 / AVX

- **SSE2** 增加 **4 个 128 位寄存器**（AMD64/EM64T 扩展到 8 个）
- 可用于多个 FP 操作数同时运算：
	- **2 × 64 位**双精度
	- **4 × 32 位**单精度
- 指令**同时**作用于它们 → 这就是 SIMD
- 后续 **AVX** 进一步扩展到 **256 位**（`ymm`）、**AVX-512** 到 **512 位**（`zmm`）

## §3.8 更快：子字并行与矩阵乘

**未优化的 C 代码**（C=C+A×B）：

```c
for (int i = 0; i < n; ++i)
  for (int j = 0; j < n; ++j) {
    double cij = C[i+j*n];
    for (int k = 0; k < n; k++)
      cij += A[i+k*n] * B[k+j*n];
    C[i+j*n] = cij;
  }
```

**优化后（AVX-512 intrinsic，i 步进 8）**：

```c
#include <x86intrin.h>
void dgemm(int n, double* A, double* B, double* C) {
  for (int i = 0; i < n; i += 8)
    for (int j = 0; j < n; ++j) {
      __m512d c0 = _mm512_load_pd(C+i+j*n);
      for (int k = 0; k < n; k++) {
        __m512d bb = _mm512_broadcastsd_pd(_mm_load_sd(B+j*n+k));
        c0 = _mm512_fmadd_pd(_mm512_load_pd(A+n*k+i), bb, c0);  // 融合乘加
      }
      _mm512_store_pd(C+i+j*n, c0);
    }
}
```

**对应的 x86 汇编关键指令**：

```asm
vmovapd       (%r11), %zmm1          # 一次装入 8 个 C 元素
vbroadcastsd  (%rax,%r8,8), %zmm0    # 把 B 的一个元素复制 8 份
vfmadd231pd   (%rcx), %zmm0, %zmm1   # 并行 乘+加（FMA）
vmovapd       %zmm1, (%r11)          # 一次写回 8 个 C 元素
```

> 三个优化点：
> 1. **SIMD**：一条指令算 8 个 double（8 倍理论加速）
> 2. **FMA**（fused multiply-add）：乘加一条指令完成，且只有一次舍入（更准更快）
> 3. **循环顺序调整 + 广播**：把 B 的标量"铺开"，让 A 的连续 8 个元素与 C 的 8 个元素同时更新
>
> 这一段是"**硬件并行如何被程序员利用**"的最佳示例，也是第 4 章 ILP、第 5 章 Cache 分块（blocking）的引子。

## §3.9 谬误与陷阱（Fallacies and Pitfalls）

### 陷阱 1：右移等于除法吗？

- **左移 i 位 = 乘 2ⁱ** ✅（对整数总是成立，除非溢出）
- **右移 i 位 = 除 2ⁱ**？**只对无符号整数成立**

有符号整数必须用**算术右移**（复制符号位）：

```
-5 / 4:
-5 = 1111 1011₂
1111 1011₂ >> 2 (算术) = 1111 1110₂ = -2      ← 向 −∞ 取整
1111 1011₂ >>> 2 (逻辑) = 0011 1110₂ = +62    ← 若误用逻辑右移，结果荒谬
```

> **算术右移向 -∞ 取整，而 C 的 `/` 向 0 取整**。(-5)/4 在 C 中是 -1，而 `-5>>2` 是 -2。编译器处理有符号除法时要额外插入修正指令（如"加 2^k-1 再右移"）。

### 陷阱 2：结合律在浮点下不成立

并行程序可能以**意想不到的顺序**交错执行，从而破坏结合律假设：

| | (x+y)+z | x+(y+z) |
|---|---|---|
| x=-1.50×10^(38) | | |
| y=+1.50×10^(38) | | |
| z=1.0 | **1.00** | **0.00** |

- 左式：x+y=0，0+z=1 → **1.00**
- 右式：y+z 因 1.0 太小被"吃掉"仍为 1.50×10^(38)，再加 x → **0.00**

> 教训：**并行程序必须在不同并行度下验证**。这也是为什么科学计算要关心"归约顺序"和"确定性"。

### 谬误：谁会关心浮点精度？

- 对科学计算当然重要
- 对日常消费应用呢？"我的银行余额差了 0.0002 分！" —— 看似无所谓
- **但 Intel Pentium FDIV bug 说明：市场期待准确**
	- 1994 年 Pentium 除法表错误，导致某些除法结果偏差，Intel 最终召回，损失约 4.75 亿美元
	- 参见 Colwell, *The Pentium Chronicles*

## §3.10 结论（Concluding Remarks）

- **位没有固有含义**，其解释取决于所施加的**指令**
- 计算机对数的表示是**有限范围、有限精度**的，程序中必须考虑这一点
- ISA 支持算术运算：
	- 有符号与无符号整数
	- 浮点（对实数的**近似**）
- 范围与精度都是**有界**的 → 运算可能**溢出（overflow）**与**下溢（underflow）**

|---|---|
| 全加器 | F_i=A_i⊕B_i⊕C_in；C_out=A_iB_i+A_iC_in+B_iC_in |

| 求相反数 | [-B]_(补)=[B]_(补)+1 |

| 浮点值 | (-1)^S(1+Frac)2^(E-Bias) |

## §3.12 易错点清单

1. **溢出只看符号**：同号相加才可能溢出，异号相加绝不溢出
2. **OF 与 CF 不要混用**：OF 管有符号，CF 管无符号
3. **有符号比较要 SF⊕OF**，不是只看 SF
4. **减法靠"取反加 1"**：Sub=1 时同时取反并置 C_in=1
5. **串行加法器延迟 2n/2n+1** 与 **CLA 6 级/12 级** 要能背
6. **积是 2n 位**；`mul` 只给低 64 位，判溢出必须 `mulh`
7. **除法不能并行**：减法依赖余数符号（数据相关）
8. **有符号除法余数符号跟随被除数**（-7/2 余 -1）
9. **浮点尾数有隐藏的 1.**，编码时要去掉
10. **阶码是移码**，编码时加 Bias，解码时减 Bias
11. **FP 乘法中偏置阶码相加要减一个 Bias**
12. **对阶时小阶向大阶看齐**，被移出的低位会丢失
13. **denormal 时隐藏位是 0**（不是 1）
14. **±0 两种表示**
15. **右移代替除法只对无符号成立**；算术右移向 -∞ 取整
16. **浮点不满足结合律**，并行归约要小心
