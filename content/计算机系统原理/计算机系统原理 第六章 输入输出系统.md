# 输入输出系统：CPU 怎样与外部设备协作

## 1. I/O 设备为什么不能像寄存器一样直接使用

处理器、内存和外设在速度、数据单位、出错方式上差异很大。CPU 通过设备控制器提供的寄存器或接口交换数据，而不直接控制磁盘电机或传感器模拟电路。控制器负责把设备行为转换成可供系统使用的状态、命令与数据。

## 2. 两种不同的设备分类

| 分类维度 | 类别 | 例子与含义 |
|---|---|---|
| 面向谁 | 人机交互设备 | 键盘、显示器、打印机，服务人类输入输出 |
| 面向谁 | 机器交互设备 | 网络接口、采集卡，在机器之间交换信息 |
| 操作单位 | 字符或字节流设备 | 按连续数据流使用，通常不支持任意块寻址 |
| 操作单位 | 块设备 | 按固定大小块访问，可按块号定位，例如磁盘 |

这两个维度不能混为一谈：网络接口面向机器通信，却不因此变成磁盘式块设备；设备在操作系统中的接口还取决于驱动与抽象。

## 3. 设备控制器的三个基本寄存器

- 数据寄存器：保存待发送或刚接收的数据。
- 状态寄存器：报告就绪、忙碌、完成、错误等状态。
- 控制寄存器：接收启动、方向、模式、中断使能等命令。

以接收一个字节为例：设备到达数据 → 控制器置就绪位 → CPU 或 DMA 读取数据 → 控制器更新状态。必须按设备协议处理就绪与确认，不能只反复读取某个地址而忽略状态。

内存映射 I/O 把这些寄存器放到处理器地址空间中；独立编址 I/O 使用专门的访问机制。I/O 地址看起来像内存地址，并不意味着它具有普通 RAM 的缓存和重排语义。

## 4. 三种数据传送方式

| 方式 | CPU 的工作 | 优点 | 代价 |
|---|---|---|---|
| 程序查询／轮询 | 不断检查就绪并搬运数据 | 简单、可控 | 设备慢时浪费 CPU |
| 中断驱动 | 先执行其他任务，设备就绪后进入处理程序 | 减少持续等待 | 高频小传输会产生处理中断的开销 |
| DMA | 设置源、目的、长度等，由控制器搬运 | 适合批量数据，减轻 CPU 搬运负担 | 仍有初始化、完成通知与一致性管理 |

DMA 不是“CPU 完全不参与”。CPU 或驱动通常要配置传输、安排缓冲区、处理结束和错误。DMA 与 CPU 共享内存和互连带宽，还要避免双方同时无序访问同一缓冲区。

## 5. 用数量级分析选择机制

假设设备每秒产生 10⁶ 字节，每次中断只搬一个字节，处理中断固定花费 1μs，仅固定开销就需要每秒 1 秒 CPU 时间，尚未计算真正的数据处理。

若每次集中处理 1000 字节，中断频率约降为每秒 1000 次，同样的固定开销约为 1 ms/s。批处理降低开销，但必须等待数据积累，增加延迟，并需要更大的缓冲区。

设计时比较：数据率、允许延迟、每次通知的固定成本、缓冲区大小与总线带宽。不存在对所有设备都最好的同一种方式。

## 6. 缓冲与吞吐量

设输入平均速率为 R_in，处理速率为 R_out。短时间内输入更快，可以用缓冲吸收突发；若长期 R_in>R_out，任何有限缓冲最终都会溢出，需要限流、丢弃、降采样或提高服务能力。

若在最长 T 秒内不能及时服务设备，至少要容纳约 R_inT 的新数据，还应留出协议和突发余量。注意速率是 bit/s 还是 B/s。

## 7. 一次磁盘或网络读取的逻辑路径

应用提出读取请求 → 系统调用进入内核 → 驱动安排请求和缓冲区 → 控制器执行 → 中断或轮询确认完成 → 检查错误与实际长度 → 唤醒等待任务或返回结果。

缓存命中时，不一定真正访问设备；异步接口下，提交请求与取得结果也可能是分开的两个时刻。

## 8. 易错点与自测

- 中断表示需要处理事件，不保证数据已经全部读完。
- 更高设备标称速率不等于更高应用吞吐量，路径上仍有总线、内存、协议和 CPU 瓶颈。
- 字符／块是接口与访问特征，输入／输出是数据方向，二者不是同一分类。
- 轮询在等待很短、处理要求确定或通知成本很高时仍有价值，不应一概视为错误方案。

自测：一个低速键盘和一个高速网卡，为什么可能使用不同的数据搬运与通知策略？——二者的数据率、延迟要求和批处理收益不同，应按上面的预算分析，而不是只看设备名称。
