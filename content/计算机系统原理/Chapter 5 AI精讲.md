# Chapter 5 AI 精讲：大容量和高速度——开发存储器层次结构（Large and Fast: Exploiting Memory Hierarchy）

> 教材：Computer Organization and Design — RISC-V Edition, Chapter 5
> 本讲目标：用**局部性原理（principle of locality）**把"又大又快"这个矛盾变成现实。掌握 Cache 的四种映射方式、三种缺失、两类写策略、AMAT 计算，以及虚拟存储（页表、TLB、缺页）的完整机制。

---

## 0. 一句话主线

> **快的存储器小，大的存储器慢**——我们想要"又大又快"，靠 **Cache（缓存）** 制造这个假象。
> 而 Cache 之所以有效，是因为程序具有**局部性**。

本章的所有细节（映射方式、替换策略、写策略、多级 Cache、虚拟存储）都是这条主线的推论。

## §5.1 引言：局部性原理（Principle of Locality）

### 5.1.1 两条局部性

程序在**任何时刻**只访问其地址空间中**很小的一部分**。

| 类型 | 定义 | 例子 |
|---|---|---|
| **时间局部性**（temporal locality） | **最近访问过**的项很可能**很快再被访问** | 循环中的指令、归纳变量（induction variable，如 `i`） |
| **空间局部性**（spatial locality） | **最近访问项附近**的项很可能**很快被访问** | 顺序取指、数组元素 |

> 这两条是整个存储层次存在的**唯一理由**。若程序完全随机访问内存，任何 Cache 都无效。

### 5.1.2 如何利用局部性

**存储层次**（memory hierarchy）：

```
全部数据放在磁盘
  ↓ 把"最近访问过（及附近）"的项复制到较小的 DRAM   → 主存（main memory）
  ↓ 把"更近访问过（及附近）"的项复制到更小的 SRAM   → 附在 CPU 上的 Cache
```

### 5.1.3 层次结构的基本术语

| 术语 | 定义 |
|---|---|
| **块/行**（block / line） | **复制的单位**，可能包含多个字（word） |
| **命中**（hit） | 访问的数据在**上层**存在，访问由上层满足 |
| **命中率**（hit ratio） | hits / accesses |
| **缺失**（miss） | 数据不在上层 → 从下层**复制块**上来 |
| **缺失代价**（miss penalty） | 复制块所花的时间 |
| **缺失率**（miss ratio） | misses / accesses = **1 − 命中率** |

> 关键设计问题（贯穿全章）：
> **① 块放在哪？② 怎么找到它？③ 缺失时替换谁？④ 写的时候怎么办？**

## §5.2 存储器技术（Memory Technologies）

### 5.2.1 四种技术的对比（性价比）

| 技术 | 访问时间 | 价格（$/GiB） |
|---|---|---|
| **SRAM**（Static RAM，静态 RAM） | 0.5 – 2.5 ns | $500 – $1000 |
| **DRAM**（Dynamic RAM，动态 RAM） | 50 – 70 ns | $3 – $6 |
| **磁磁盘**（magnetic disk） | 5 – 20 ms | $0.01 – $0.02 |

**理想存储器**（ideal memory）：SRAM 的访问时间 + 磁盘的容量与每 GB 成本 —— **现实中不存在**，只能用层次结构逼近。

> 注意数量级：SRAM 比 DRAM 快约 **30~100 倍**，贵约 **100~300 倍**；DRAM 比磁盘快约 **10⁵ 倍**，贵约 **300 倍**。这个"**每层差 10~100 倍**"的规律是层次结构能工作的关键。

### 5.2.2 DRAM 技术

- 数据以**电荷**形式存储在**电容**中
- 用**单个晶体管**访问该电荷（所以密度高、便宜）
- **必须周期性刷新**（refresh）：读出内容再写回
	- 刷新以 DRAM 的"**行**"（row）为单位进行

### 5.2.3 高级 DRAM 组织

| 技术 | 作用 |
|---|---|
| **行缓冲**（row buffer） | 允许一行中的多个字**并行**读出与刷新 |
| **突发模式**（burst mode） | 从同一行**连续供字**，减少延迟 |
| **DDR**（Double Data Rate） | 在时钟**上升沿和下降沿**都传输 |
| **QDR**（Quad Data Rate） | 分离的 DDR 输入与输出（等效 4 倍） |
| **同步 DRAM**（SDRAM） | 连续突发访问**不必每次送地址**，提高带宽 |
| **DRAM banking** | 允许多个 DRAM **同时**访问，提高带宽 |

![[Ch5-P07-DRAM组织结构.webp]]

### 5.2.4 主存的主要性能指标（讲义补充）

- 按**字节**连续编址，每个存储单元 1 字节（8 位）
- **存储容量**：所包含存储单元的总数（MiB / GiB）
- **存取时间 T_A**：从 CPU 送出地址开始，到主存读出数据送到 CPU（或把 CPU 数据写入主存）所需的时间，单位 ns。分**读取时间**与**写入时间**
- **存储周期 T_MC**：**连续两次访问**存储器所需的**最小时间间隔**

T_MC=T_A+（下一次存取开始前所需的附加时间）

> 因此 T_MC>T_A：因为**读出放大器、驱动电路**都需要一段**稳定恢复时间**，读出后不能立即进行下一次访问。

### 5.2.5 CPU 与存储器的通信方式

| 方式 | 过程 | 特点 |
|---|---|---|
| **异步方式**（asynchronous） | 需**握手信号**：CPU 送地址 → 主存译码 → CPU 发读命令 → 等"完成"信号 → CPU 取数 | 灵活，但协议开销大 |
| **同步方式**（synchronous） | CPU 与主存由**统一时钟**控制，**无需应答信号**；主存总在确定时间内准备好数据 | 快，但**存储器芯片必须支持同步** |

> 现代 SDRAM 就是同步的：CPU 送地址与命令后，**在确定的时钟数后**取数据（如 CL=16 表示 16 个时钟后数据到达）。

### 5.2.6 Flash 存储（闪存）

- **非易失**（nonvolatile）半导体存储
- 比磁盘快 **100~1000 倍**；更小、更低功耗、更坚固（robust）
- 但每 GiB 价格更贵（介于磁盘与 DRAM 之间）

| 类型 | 特点 | 用途 |
|---|---|---|
| **NOR flash** | 随机读写；位单元像 NOR 门 | 嵌入式系统的**指令存储器** |
| **NAND flash** | 更密（bits/area）、**按块访问**、每 GB 更便宜 | U 盘、媒体存储、SSD |

- **写寿命**：Flash 位在约 **100 000 次**访问后**磨损**（wear out）
	- 不适合直接替代 RAM 或磁盘
	- **磨损均衡**（wear leveling）：把数据**重映射**到用得少的块

### 5.2.7 磁盘（Disk Storage）

- **非易失、旋转式磁存储**

![[Ch5-P15-磁盘的磁道与扇区.webp]]

**几何结构**：

- 盘面被分为许多**同心圆**，每个同心圆是一个**磁道**（track），有编号（最外为 0 磁道）
- 每个磁道划分为若干**扇区**（sector），传统每扇区 **512 字节**，现代迁移到 **4096 字节（4K 扇区）**，IDEMA 称之为"高级格式化"
- 现代磁盘**磁道上的位密度相同**，因此**外道扇区数比内道多**，从而提高整盘容量（**区域位记录** ZBR）

**每个扇区记录**：

| 内容 | 说明 |
|---|---|
| **Sector ID** | 扇区标识 |
| **数据** | 512 字节（4096 字节为提案） |
| **ECC**（Error Correcting Code） | 用于**掩盖缺陷与记录错误** |

**访问一个扇区包含**：

1. **排队延迟**（queuing delay，若有其他访问在等待）
2. **寻道**（seek）：移动磁头
3. **旋转延迟**（rotational latency）
4. **数据传输**（data transfer）
5. **控制器开销**（controller overhead）

**例（教材）**：512 B 扇区、15 000 rpm、平均寻道 4 ms、传输率 100 MB/s、控制器开销 0.2 ms、磁盘空闲。

平均读取时间=4 ms+underbrace1/2·60/15000 s_(2 ms)+underbrace512/(100×10⁶)s_(0.005 ms)+0.2 ms=6.2 ms

若实际平均寻道为 1 ms → 3.2 ms。

> 观察：**寻道与旋转延迟占了 6.2 ms 中的 6 ms（97%）**，真正的数据传输只有 0.005 ms。这就是为什么磁盘的性能几乎完全由**机械运动**决定，也是 SSD 的革命性所在。

![[Ch5-P18-磁盘连接与DMA.webp]]

**连接方式**：磁盘控制器接在 **I/O 总线**上，I/O 总线与其他总线（系统总线、存储器总线）之间用**桥接器**（bridge）连接。

- 磁盘最小读写单位是**扇区**，按**成批数据**方式交换
- 采用 **DMA**（Direct Memory Access，直接存储器存取）方式：由专门的 **DMA 控制器**控制外设与主存间直接数据交换，**数据不通过 CPU**

**磁盘性能问题**：

- 厂商给出的平均寻道时间基于**所有可能寻道**；由于**局部性**与 **OS 调度**，**实际**平均寻道更小
- 智能磁盘控制器**在物理扇区上重新分配**，对外呈现**逻辑扇区**接口（SCSI、ATA、SATA）
- 磁盘自带 **Cache**：**预取**（prefetch）扇区以避免寻道与旋转延迟

## §5.3 Cache 基础（The Basics of Caches）

**Cache**：存储层次中**最靠近 CPU** 的那一层。

面对访问序列 X_1,…,X_(n-1),X_n，两个核心问题：

1. **怎么知道数据在不在？**
2. **到哪里去找？**

### 5.3.1 直接映射（Direct Mapped）

![[Ch5-P21-直接映射Cache.webp]]

- **位置由地址决定**
- **直接映射**：只有**一个**候选位置

（块地址）mod（Cache 中的块数）

- 块数是 **2 的幂** → 用**低位地址位**作索引（index）

### 5.3.2 标记与有效位（Tags and Valid Bits）

![[Ch5-P22-标记与有效位.webp]]

**问题 1：怎么知道这个位置存的是哪一块？**

- 把**块地址**也存起来
- 实际上**只需高位**（低位已被索引用掉）→ 称为**标记**（tag）

**问题 2：位置里根本没数据怎么办？**

- **有效位**（valid bit）：1 = 存在，0 = 不存在
- **初始为 0**

### 5.3.3 完整示例（8 块、每块 1 字、直接映射）

初始状态全部 `V=N`。访问序列：

| 字地址 | 二进制地址 | 命中/缺失 | Cache 块（index） |
|---|---|---|---|
| 22 | `10 110` | Miss | 110 |
| 26 | `11 010` | Miss | 010 |
| 22 | `10 110` | **Hit** | 110 |
| 26 | `11 010` | **Hit** | 010 |
| 16 | `10 000` | Miss | 000 |
| 3 | `00 011` | Miss | 011 |
| 16 | `10 000` | **Hit** | 000 |
| 18 | `10 010` | Miss | 010（**替换**掉 26） |

以地址 22（`10110`）为例：**低 3 位 `110` 是 index，高 2 位 `10` 是 tag**。

| Index | V | Tag | Data |
|---|---|---|---|
| 110 | Y | 10 | Mem[10110] |

> 注意最后一步：地址 18（`10010`）的 index 也是 `010`，**与 26 冲突** → 直接映射**只能**替换，把 26 挤出去。这就是后面"冲突缺失"的来源。

### 5.3.4 地址划分（Address Subdivision）

![[Ch5-P29-地址划分.webp]]

```
| Tag | Index | Block offset | Byte offset |
```

- **Index**：选中 Cache 中的哪一块
- **Block offset**（字偏移）：选中块中的哪个字
- **Byte offset**：选中字中的哪个字节（2 位，因为 1 字 = 4 字节）
- **Tag**：剩下的高位，用于确认"是不是我要的那一块"

### 5.3.5 Cache 容量的计算（考点）

**设定**：

- Cache 有 2ⁿ 块 → **n 位 index**
- 块大小 2^m 个字（2^(m+2) 字节）→ **m 位字偏移 + 2 位字节偏移**
- 32 位地址

**则**：

标记字段大小=32-(n+m+2)

直接映射 Cache 总位数=2ⁿ×(underbrace32·2^m_(数据)+underbrace(32-n-m-2)_(标记)+underbrace1_(有效位))

**例**：n=10、m=0（1 字/块，4 字节）→ 数据占 **4 KiB**；标记与有效位占 2^(10)×21=2.625 KiB。
→ **通常仍称其为"4 KiB Cache"**（只算数据部分）。

> 这说明：**Cache 的实际晶体管开销比"容量"大得多**（本例多出 65%）。这也解释了为什么相联度越高越贵（标记位数 × 比较器数都增加）。

### 5.3.6 块大小的权衡

**例**：64 块、每块 16 字节，地址 1200 映射到哪一块？

块地址=⌊1200/16⌋=75, 块号=75mod64=11

地址划分：Tag **52 位** | Index **6 位** | Offset **4 位**

**块大小的影响**（重要权衡）：

| 增大块大小 | 效果 |
|---|---|
| ✅ 减少**缺失率** | 因为**空间局部性** |
| ❌ 固定容量下**块数变少** | 竞争加剧 → 缺失率**上升** |
| ❌ 造成**污染**（pollution） | 大块挤掉有用数据 |
| ❌ **缺失代价增大** | 可能**抵消**缺失率下降的收益 |

**缓解手段**：

- **尽早重启**（early restart）：块中所需字一到就恢复执行
- **关键字段优先**（critical-word-first）：**先传**引起缺失的那个字

### 5.3.7 Cache 缺失的处理

- **命中**：CPU 正常继续
- **缺失**：
	1. **暂停 CPU 流水线**（stall）
	2. 从下一层取块
	3. **指令 Cache 缺失** → **重新开始取指**
	4. **数据 Cache 缺失** → **完成数据访问**

> 第 4 章的"停顿"在这里有了具体来源：Cache 缺失是流水线停顿最主要的成因。

### 5.3.8 写策略（Write Policy）

#### 写直达（Write-Through）

- 写命中时**同时更新 Cache 和内存**
- 否则 Cache 与内存**不一致**
- **缺点**：写变慢。例：base CPI = 1，10% 指令是 store，写内存需 100 周期

Effective CPI=1+0.1×100=11

- **解决：写缓冲（write buffer）**
	- 保存等待写入内存的数据
	- CPU **立即继续**执行
	- **只在写缓冲已满时**才停顿

#### 写回（Write-Back）

- 写命中时**只更新 Cache 中的块**
- 用**脏位**（dirty bit）记录每块是否被改过
- 当**脏块被替换**时，才写回内存
- 可用写缓冲：让被替换的块先被读出

#### 写缺失（Write Miss）时的分配策略

| 策略 | 做法 | 适用 |
|---|---|---|
| **写分配**（write allocate） | **取块**到 Cache 再写 | 写回法**通常**如此（因为之后可能还要写同一块） |
| **非写分配**（no write allocate） | **不取块**，直接写到内存 | 写直达法常用；因为程序常**先写满整块**再读（如初始化） |

### 5.3.9 实例：Intrinsity FastMATH

- 嵌入式 MIPS 处理器，**12 级流水线**，每周期都要取指与访数据
- **分离 Cache**（split cache）：独立的 I-Cache 与 D-Cache，各 **16 KB**（256 块 × 16 字/块）
- D-Cache 可配置写直达或写回
- SPEC2000 缺失率：**I-Cache 0.4%**、**D-Cache 11.4%**、加权平均 **3.2%**

> **为什么 I-Cache 缺失率远低于 D-Cache？** 因为**指令访问具有极强的空间局部性**（顺序执行），而数据访问模式（数组、指针、结构体）更分散。这也是"分离 Cache"的理由：**两者的局部性特征不同，应分别优化**。

### 5.3.10 主存如何支撑 Cache

- 用 DRAM 作主存，**固定宽度**（如 1 字），通过**固定宽度同步总线**连接
- **总线时钟通常比 CPU 时钟慢**

**例（1 字宽 DRAM、4 字块）**：

- 地址传输 1 个总线周期
- 每次 DRAM 访问 15 个总线周期
- 每次数据传输 1 个总线周期

Miss penalty=1+4×15+4×1=65 总线周期
Bandwidth=(16 B)/(65 周期)=0.25 B/周期

**三种存储器组织的对比**（传输 4 个字）：

| 组织方式 | 代价 | 说明 |
|---|---|---|
| **一字宽**（one-word-wide） | 1+4×15+4×1=65 | 串行传 4 次 |
| **四字宽**（4-word wide） | 1+15+1=17 | 一次并行传 4 字（贵） |
| **四体交叉**（4-bank interleaved） | 1+15+4×1=20 | 4 个体并行访问，再逐字传 |

> 交叉存储（interleaving）是"**用并行换带宽**"的经典手法，与第 3 章的 SIMD、第 4 章的多发射同源。

## §5.4 度量与改进 Cache 性能

### 5.4.1 CPU 时间的组成

CPU Time=underbrace 程序执行周期_(含 Cache 命中时间)+underbrace 存储器停顿周期_(主要来自 Cache 缺失)

**简化假设下**：

Memory stall cycles=(Memory accesses)/Program×Miss rate×Miss penalty

=Instructions/Program×Misses/Instruction×Miss penalty

> 注意第二种写法：把"每次访问的缺失率"换成"**每条指令的缺失数**"（misses per instruction），对指令/数据 Cache 分开算更方便。

### 5.4.2 综合例题（必掌握）

**已知**：

- I-Cache 缺失率 = 2%
- D-Cache 缺失率 = 4%
- 缺失代价 = 100 周期
- base CPI（理想 Cache）= 2
- load/store 占指令的 **36%**

**求**：实际 CPI

**解**：

I-Cache 每条指令缺失周期=0.02×100=2
D-Cache 每条指令缺失周期=0.36×0.04×100=1.44
Actual CPI=2+2+1.44=5.44

理想 CPU 快 5.44/2=2.72 倍

> 关键点：**D-Cache 的缺失率要乘以"访存指令比例 36%"**，因为它不是每条指令都访存；而 **I-Cache 每条指令都要取指**，所以直接乘缺失率。

### 5.4.3 平均访存时间（AMAT）

AMAT=Hit time+Miss rate×Miss penalty

**例**：CPU 时钟 1 ns，命中时间 1 周期，缺失代价 20 周期，缺失率 5%

AMAT=1+0.05×20=2 ns=2 个周期/指令

### 5.4.4 性能总结（重要的趋势）

| 变化 | 后果 |
|---|---|
| **CPU 性能提升** | **缺失代价变得更显著**（相对而言） |
| **base CPI 降低** | 存储器停顿占时间的**比例更大** |
| **时钟频率提高** | 存储器停顿占**更多 CPU 周期** |

> 结论：**评估系统性能时不能忽略 Cache 的行为**。这也是"存储墙"（memory wall）的定量表述。

### 5.4.5 相联 Cache（Associative Caches）

| 类型 | 放置规则 | 查找代价 |
|---|---|---|
| **全相联**（fully associative） | 块可放在**任意**位置 | **所有表项同时搜索**；每个表项一个比较器（**昂贵**） |
| **n 路组相联**（n-way set associative） | 每组 n 个表项；块号决定组号：(块号)mod(组数) | **只搜索该组**的 n 个表项；**n 个比较器** |

![[Ch5-P47-相联度谱.webp]]

![[Ch5-P52-组相联Cache组织.webp]]

> **相联度谱**：直接映射 = 1 路组相联；全相联 = 只有 1 组。**它们不是三种东西，而是同一参数（每组表项数）的三个取值**。

### 5.4.6 相联度对比示例（经典题）

4 块 Cache，访问块序列 **0, 8, 0, 6, 8**：

**直接映射**（index = 块号 mod 4）

| 块地址 | index | 命中/缺失 | 访问后 Cache 内容（块 0/1/2/3） |
|---|---|---|---|
| 0 | 0 | miss | Mem[0] |
| 8 | 0 | miss | Mem[8] |
| 0 | 0 | **miss** | Mem[0] |
| 6 | 2 | miss | Mem[0] · · Mem[6] |
| 8 | 0 | **miss** | Mem[8] · · Mem[6] |

→ **5 次全缺失（0 命中）**

**2 路组相联**（2 组，每组 2 块）

| 块地址 | index（组） | 命中/缺失 | Set 0 / Set 1 |
|---|---|---|---|
| 0 | 0 | miss | Mem[0] |
| 8 | 0 | miss | Mem[0] Mem[8] |
| 0 | 0 | **hit** | Mem[0] Mem[8] |
| 6 | 0 | miss | Mem[0] Mem[6] |
| 8 | 0 | **miss** | Mem[8] Mem[6] |

→ **4 缺失 / 1 命中**

**全相联**

| 块地址 | 命中/缺失 | 内容 |
|---|---|---|
| 0 | miss | Mem[0] |
| 8 | miss | Mem[0] Mem[8] |
| 0 | **hit** | Mem[0] Mem[8] |
| 6 | miss | Mem[0] Mem[8] Mem[6] |
| 8 | **hit** | Mem[0] Mem[8] Mem[6] |

→ **3 缺失 / 2 命中**

> 结论：**相联度提高 → 冲突缺失减少 → 缺失率下降**，但**比较器与标记位数增加** → 成本与命中时间上升。

### 5.4.7 相联度取多少？

**64 KB D-Cache、16 字块、SPEC2000 的模拟结果**：

| 相联度 | 缺失率 |
|---|---|
| 1 路 | 10.3% |
| 2 路 | 8.6% |
| 4 路 | 8.3% |
| 8 路 | 8.1% |

> **收益递减**（diminishing returns）：2 路就把 10.3% 降到 8.6%，而 8 路只再降 0.5%。

经验：

- **2 路或 4 路组相联较常用**
- 大容量 **L2/L3** 可用 **4 路以上**
- ⚠️ **关联度越高，总标记位数越多，额外空间开销越大**

### 5.4.8 标记位数计算例题（考点）

**已知**：4096 块、4 字块、32 位地址。求直接映射、2 路、4 路、全相联的总标记位数。

**先算**：每块 16 字节（=2⁴）→ 地址中 **4 位是字节偏移**，剩下 **28 位**用于 index + tag。

| 结构 | 组数 | index 位数 | tag 位数 | 总标记位数 |
|---|---|---|---|---|
| **直接映射** | 4096 | 12 | 28-12=16 | 16×4096=64 Kib |
| **2 路** | 2048 | 11 | 28-11=17 | 17×2×2048=68 Kib |
| **4 路** | 1024 | 10 | 28-10=18 | 18×4×1024=72 Kib |
| **全相联** | 1 | 0 | 28 | 28×4096=112 Kib |

**规律**：**相联度每翻一倍，组数减半 → index 少 1 位 → tag 多 1 位**（总标记位数随之增加）。

### 5.4.9 替换策略（Replacement Policy）

| 策略 | 说明 |
|---|---|
| **直接映射** | **无可选择**（只能替换那一个） |
| **组相联** | 优先选**无效**（V=0）的表项；否则在组内选 |
| **LRU**（Least-Recently Used，最近最少使用） | 选**最久未用**的：2 路简单，4 路可管理，**更高相联度太难** |
| **随机**（Random） | 高相联度时性能**接近 LRU**，且实现简单 |

### 5.4.10 多级 Cache（Multilevel Caches）

```
CPU → L1（一级，小但快）→ L2（更大更慢）→ 主存 → 磁盘
                    （部分高端系统还有 L3）
```

**例（多级 Cache 的价值）**：

**已知**：CPU base CPI = 1，时钟 4 GHz，缺失率 2%/指令，主存访问 100 ns。

**只有一级 Cache**：

Miss penalty=(100 ns)/(0.25 ns)=400 周期
Effective CPI=1+0.02×400=9

**加 L2**：访问时间 5 ns，**全局缺失率**（到主存）0.5%

- 一级缺失但 L2 命中：罚 5/0.25=20 周期
- 一级缺失且 L2 缺失：额外罚 400 周期

CPI=1+0.02×20+0.005×400=1+0.4+2=3.4

性能比=9/3.4=2.6

> 注意"**全局缺失率**"（global miss rate，相对所有访问）与"**局部缺失率**"（local miss rate，相对到达该级的访问）的区别。计算到主存的代价时用**全局**缺失率。

**多级 Cache 的设计哲学**：

| 层次 | 优化目标 |
|---|---|
| **L1** | **最小命中时间**（hit time）—— 它在关键路径上 |
| **L2** | **低缺失率**（避免访问主存）；命中时间影响较小 |

**结果**：

- L1 通常**比 L2 小**
- L1 的**块比 L2 的块小**

### 5.4.11 与高级 CPU 的交互

- **乱序 CPU 可在 Cache 缺失期间继续执行**其他指令
	- 未完成的访存留在 **load/store 单元**
	- **依赖**指令在**保留站**等待
	- **独立**指令继续执行
- 缺失的**实际影响取决于程序的数据流**
	- 极难解析 → 用**系统仿真**（simulation）

### 5.4.12 与软件的交互：分块（Blocking）

- 缺失取决于**访存模式**：算法行为 + 编译器的访存优化
- **目标**：让数据在被替换前被**尽可能多地访问**

**DGEMM 的内层循环**：

```c
for (int j = 0; j < n; ++j) {
  double cij = C[i+j*n];
  for (int k = 0; k < n; k++)
    cij += A[i+k*n] * B[k+j*n];
  C[i+j*n] = cij;
}
```

**问题**：B 按**列**访问（`B[k+j*n]`，步长 n），每次都跳到新的一行 → **空间局部性极差**，每次访问都可能缺失。

**分块（blocking）**：

```c
#define BLOCKSIZE 32
void do_block(int n, int si, int sj, int sk, double *A, double *B, double *C) {
  for (int i = si; i < si+BLOCKSIZE; ++i)
    for (int j = sj; j < sj+BLOCKSIZE; ++j) {
      double cij = C[i+j*n];
      for (int k = sk; k < sk+BLOCKSIZE; k++)
        cij += A[i+k*n] * B[k+j*n];
      C[i+j*n] = cij;
    }
}
void dgemm(int n, double* A, double* B, double* C) {
  for (int sj = 0; sj < n; sj += BLOCKSIZE)
    for (int si = 0; si < n; si += BLOCKSIZE)
      for (int sk = 0; sk < n; sk += BLOCKSIZE)
        do_block(n, si, sj, sk, A, B, C);
}
```

> **原理**：把大矩阵切成 32×32 的小块，使**三个小块能同时装进 Cache**，从而在块内反复使用 —— 把"每次都要访存"变成"只在块边界访存"。
> 效果：**性能提升约 2 倍到 10 倍以上**（取决于机器与矩阵规模）。

## §5.5 可信赖的存储层次（Dependable Memory Hierarchy）

### 5.5.1 可靠性基本概念

```
        服务完成（service accomplishment）
              ↑ 恢复（restoration）      ↓ 失效（failure）
        服务中断（service interruption）
```

- **故障**（fault）：**部件**失效
	- **不一定**导致系统失效（容错的意义所在）

### 5.5.2 可靠性度量

| 指标 | 定义 |
|---|---|
| **MTTF**（mean time to failure） | 平均无故障时间 → 度量**可靠性** |
| **MTTR**（mean time to repair） | 平均修复时间 |
| **MTBF**（mean time between failures） | =MTTF+MTTR |
| **AFR**（annual failure rate） | 一年内**预期失效设备百分比** |

> 教材强调：**MTTF 很大时容易误导**，而 **AFR 更直观**。

**例**：某磁盘 MTTF = 1 000 000 小时

- 1000000/(365×24)=114 年 → 好像"永不失效"
- 但一个 WSC 有 50 000 台服务器、每台 2 块盘 = 100 000 块盘
- AFR=8760/1000000=0.876%
- 每年预期失效 100000×0.876%=876 块 → **平均每天 2 块以上！**

> 这就是"大规模系统里，**小概率事件变成常态**"。

### 5.5.3 可用性（Availability）

Availability=MTTF/(MTTF+MTTR)

**提升可用性的两条路**：

1. **增大 MTTF**：故障避免（fault avoidance）、**容错**（fault tolerance）、故障预测（fault forecasting）
2. **减小 MTTR**：更好的诊断与修复工具/流程

**"几个 9"的口诀**：

| 可用性 | 含义 | 每年停机 |
|---|---|---|
| 1 个 9 | 90% | > 36.5 天 |
| 2 个 9 | 99% | > 3.65 天 |
| 3 个 9 | 99.9% | > 526 分钟 |
| 4 个 9 | 99.99% | > 52.6 分钟 |
| 5 个 9 | 99.999% | > 5.26 分钟 |

### 5.5.4 汉明码（Hamming SEC Code）

- **汉明距离**（Hamming distance）：两个位模式之间**不同位的个数**
- **最小距离 = 2** → 可**检测** 1 位错（如**奇偶校验** parity code）
- **最小距离 = 3** → 可**纠正** 1 位错、**检测** 2 位错

**奇偶校验的特点**（讲义总结）：

- 汉明距离 d=2
	- 两个数若有**奇数位**不同 → 校验位不同；若**偶数位**不同 → 校验位相同但**至少两位数据位**不同
- **只能发现奇数位错**，不能发现偶数位错
- **不能定位错误位置，没有纠错能力**
- **开销小**，适合校验**1 字节**长的代码 → 常用于存储器读写检查或按字节传输
	- 因为 1 字节出错时，"1 位出错"概率最大，"2 位以上出错"很少

### 5.5.5 编码 SEC（汉明码构造）

**规则**：

1. 位从 **1** 开始**从左**编号
2. **所有 2 的幂次位置**（1, 2, 4, 8, …）是**校验位**
3. 每个校验位负责检查**特定的一组数据位**

| 校验位 | 检查的位 | 规律 |
|---|---|---|
| **位 1**（0001_2） | 1, 3, 5, 7, 9, 11, … | 地址**最右位为 1** 的位 |
| **位 2**（0010_2） | 2, 3, 6, 7, 10, 11, 14, 15, … | 地址**右起第 2 位为 1** 的位 |
| **位 4**（0100_2） | 4–7, 12–15, 20–23, … | 地址**右起第 3 位为 1** 的位 |
| **位 8**（1000_2） | 8–15, 24–31, 40–47, … | 地址**右起第 4 位为 1** 的位 |

> 注意：**每个数据位至少被两个校验位覆盖**——这是能"定位"错误的原因。

**例**：数据字节 `1001 1010`，求汉明码并使**位 10 出错**能被纠正。

1. 留出校验位位置，12 位模式为 `_ _ 1 _ 0 0 1 _ 1 0 1 0`
2. 计算校验位后得到码字 **`011100101010`**
3. 把位 10 取反 → `011100101110`
4. 检查发现**校验位 2 和 8 不正确**；2+8=10 → **位 10 出错**

> 纠错原理：出错位的编号 = **所有校验失败的校验位编号之和**。这是汉明码最优雅的地方。

### 5.5.6 SEC/DED（纠正 1 位 + 检测 2 位）

- 把最小汉明距离做到 **4** → 可**纠正 1 位、检测 2 位**
- 做法：**再加一个覆盖整个字的校验位**（P）
- 算法：既有 ECC 分组的校验（H），又有整体校验（P）。**四种情况**：

| H | P | 结论 |
|---|---|---|
| 偶 | 偶 | **无错** |
| 奇 | 奇 | **可纠正的单错** |
| 偶 | 奇 | **P 位本身出错**（单错） |
| 奇 | 偶 | **双错**（只能检测，不能纠正） |

### 5.5.7 校验位的位数（公式）

设数据位 d、校验位 p。p 位校验码最多表示 2^p 种状态，每种状态说明一种出错情况：

- 数据中某一位错：d 种
- 校验码中某一位错：p 种
- 无错：1 种

⇒ 2^p≥1+d+p

| 数据位数 d | 校验位数 p |
|---|---|
| 8 | **4** |
| 16 | 5 |
| 32 | 6 |
| 64 | 7 |

> **应用**：8 字节（64 位）数据块加 **1 字节** 的 SEC/DED 刚好 → 这就是为什么很多 **DIMM 是 72 位宽**（64 数据 + 8 校验）。

## §5.6 虚拟机（Virtual Machines）

- **宿主机**（host）**仿真**客户机（guest）操作系统与机器资源
	- 改善多客户机之间的**隔离**（isolation）
	- 避免安全与可靠性问题
	- 有助于**资源共享**
- 虚拟化有**性能影响**，但在现代高性能计算机上**可行**
- 例子：IBM VM/370（1970 年代！）、VMWare、Microsoft Virtual PC

### 5.6.1 虚拟机监视器（VMM, Virtual Machine Monitor）

- 把**虚拟资源**映射到**物理资源**（内存、I/O 设备、CPU）
- 客户机代码在**用户态**直接运行在本机
	- 遇到**特权指令**或访问受保护资源时**陷入**（trap）VMM
- 客户机 OS 可以与宿主机 OS **不同**
- VMM 处理真实 I/O 设备：为客户机**仿真通用的虚拟 I/O 设备**

**例：定时器虚拟化**

| 场景 | 行为 |
|---|---|
| 本机 | 定时器中断 → OS 挂起当前进程、处理中断、选择并恢复下一个进程 |
| 有 VMM | VMM 挂起当前 **VM**、处理中断、选择并恢复下一个 **VM** |
| 若 VM 需要定时器中断 | VMM 仿真一个**虚拟定时器**，在物理定时器中断发生时向 VM 仿真中断 |

### 5.6.2 ISA 对虚拟化的支持

- **用户态与系统态**（user / system mode）
- **特权指令**只在系统态可用；在用户态执行则**陷入**系统
- **所有物理资源**只能通过特权指令访问（**页表、中断控制、I/O 寄存器**）
- 虚拟化支持正在"**复兴**"：现代 ISA（如 x86）都在**改造**以支持虚拟化（VT-x、AMD-V）

## §5.7 虚拟存储（Virtual Memory）

### 5.7.1 基本思想

- **把主存当作二级存储（磁盘）的"Cache"**
- 由 **CPU 硬件与操作系统共同管理**
- 程序**共享主存**：
	- 每个程序得到**私有的虚拟地址空间**，存放它常用的代码与数据
	- **受保护**，不被其他程序访问
- CPU 与 OS 把**虚拟地址**翻译为**物理地址**
	- VM 的"块"叫**页**（page）
	- VM 的"缺失"叫**缺页**（page fault）

![[Ch5-P84-虚拟存储与页表.webp]]

> **核心洞见**：虚拟存储不是为了"扩大内存"这么简单，它同时提供了 ①**保护**（protection）、②**共享**（sharing）、③**按需装入**（demand paging）、④**地址空间抽象**。

### 5.7.2 RISC-V 程序与数据的存储器分配

```
高地址
┌──────────────┐ 0xFFFF FFFF FFFF FFFF
│   Stack      │ ↓
├──────────────┤
│      ↓       │
│      ↑       │
├──────────────┤
│ Dynamic data │ ↑ (heap)
├──────────────┤
│ Static data  │ (gp)
├──────────────┤
│  Reserved    │
├──────────────┤
│    Text      │ PC
└──────────────┘ 0x0000 0000 0000 0000
```

**关键问题**：一个程序在"编辑、编译、汇编、链接、装入"过程中，**哪个环节**确定了每条指令及其操作数的**虚拟地址**？

> **答案：链接时确定虚拟地址；装入时生成页表**，建立虚拟地址与物理地址之间的映射！
> 这就是每个进程的**虚拟（逻辑）地址空间**。

> 这个问题的意义：它把第 2 章的"链接/加载"与本章的"虚拟存储"串起来了——**链接器输出的是虚拟地址，加载器负责建立映射**。

### 5.7.3 地址转换（Address Translation）

![[Ch5-P86-地址转换.webp]]

- **固定大小的页**（如 4 KiB）
- 虚拟地址划分为：**虚拟页号（VPN） + 页内偏移（page offset）**
- 物理地址划分为：**物理页号（PPN） + 页内偏移**
- **偏移不变**（这是"页"对齐的结果）

### 5.7.4 缺页代价（Page Fault Penalty）

- 缺页时页必须**从磁盘取出**
	- **需数百万个时钟周期**（对比 Cache 缺失的几百个）
	- 由 **OS 代码**处理（不是硬件）

**因此要极力降低缺页率**：

1. **全相联放置**（fully associative placement）—— 任何页可放在任何物理页框
2. **聪明的替换算法**（smart replacement）

> 为什么虚拟存储可以做到全相联？因为页表的**查找本身就是"全表查询"**，用巨大的表换取"零冲突缺失"。这里"时间"换"空间"的权衡彻底倒向"降低缺失率"——因为缺页代价太大。

### 5.7.5 页表（Page Tables）

- 存放**放置信息**：**页表项（PTE）数组**，用**虚拟页号**索引
- CPU 中的**页表寄存器**（page table register）指向物理内存中的页表
- 若页**在内存中**：
	- PTE 存放**物理页号**
	- 以及状态位（**referenced 访问位、dirty 脏位** 等）
- 若页**不在内存中**：
	- PTE 可指向**磁盘交换区**（swap space）的位置

![[Ch5-P89-用页表转换.webp]]

![[Ch5-P90-页到存储器的映射.webp]]

### 5.7.6 替换与写

**替换**（减少缺页率，倾向 LRU）：

- PTE 中的**访问位/使用位**（reference bit / use bit）在被访问时置 1
- OS **周期性清零**
- 访问位 = 0 表示该页**最近未被使用**

**写**（磁盘写要数百万周期）：

- **成块写**，不写单个位置
- **写直达不可行**
- **必须用写回**（write-back）
- PTE 中的**脏位**（dirty bit）在页被写时置 1

### 5.7.7 页表的大小（惊人的开销）

**例**：32 位虚拟地址、4 KiB 页、每 PTE 4 字节

2^(20)个表项×4 B=4 MiB

若运行**数百个进程**，每个都有自己的页表 → 内存被页表吃掉。

**减少页表内存的五种方法**：

1. **界限寄存器**（limit register）：限制某进程页表的大小
2. **两个页表 + 两个界限寄存器**：页表**从最高地址向下**和**从最低地址向上**双向增长（栈与堆分别管理）
3. **反置页表**（inverted page table）：对虚拟地址做**哈希**，使页表只需**物理页数**那么大
4. **多级页表**（multiple levels of page tables）
5. **允许页表被分页**（page the page tables）

> 现实中（RISC-V/x86-64）用**多级页表**：只为**实际用到的**虚拟地址区域分配页表页，稀疏地址空间的开销从 O(2^(32)) 降到 O(使用量)。

### 5.7.8 用 TLB 加速转换（Translation Look-aside Buffer）

![[Ch5-P95-用TLB快速转换.webp]]

**问题**：地址转换似乎需要**额外的访存**（一次读 PTE，一次真正的访问）→ 每条指令访存次数翻倍！

**但页表的访问有很好的局部性** → 在 CPU 内做一个 **PTE 的快 Cache**：

| TLB 参数 | 典型值 |
|---|---|
| 表项数 | **16 – 512** 个 PTE |
| 命中代价 | **0.5 – 1 个周期** |
| 缺失代价 | **10 – 100 个周期** |
| 缺失率 | **0.01% – 1%** |

- TLB 缺失可由**硬件**或**软件**处理

### 5.7.9 TLB 缺失的处理

| 情形 | 处理 |
|---|---|
| **页在内存中**（只是 PTE 不在 TLB） | 从内存**装入 PTE** 并重试；可由**硬件**处理（页表结构复杂时硬件会变复杂），也可由**软件**处理（**特殊异常 + 优化过的 handler**） |
| **页不在内存中**（缺页 page fault） | **OS** 负责取页、更新页表，然后**重启出错指令** |

**TLB 缺失处理程序要点**：

- TLB 缺失表明两种情况：**页在但 PTE 不在 TLB**、或**页不在**
- **必须在目的寄存器被覆盖之前识别出 TLB 缺失** → **抛出异常**
- handler 把 PTE 从内存**复制到 TLB**，然后**重启指令**
- 若页不在 → 随后会发生**缺页**

**缺页处理程序（Page Fault Handler）**：

1. 用出错的**虚拟地址**找到 PTE
2. 在磁盘上**定位该页**
3. **选择要替换的页**（若脏 → **先写回磁盘**）
4. 把页**读入内存**并**更新页表**
5. 让进程**重新可运行**（从出错指令**重启**）

### 5.7.10 三种缺失的组合（重要考点）

![[Ch5-P102-三种缺失的组合.webp]]

| TLB | 页表 | Cache | 说明 | 可能的访存次数 |
|---|---|---|---|---|
| hit | hit | hit | **最好情况**，不需访问主存 | 0 |
| hit | hit | miss | 信息在主存但不在 Cache | **1** |
| miss | hit | hit | TLB 缺失但页表命中，信息在主存且**在 Cache** | **1** |
| miss | hit | miss | TLB 缺失、页表命中，信息在主存但**不在 Cache** | **≥2** |
| miss | **miss** | — | 页表缺失 → 信息**不在主存** → **一定也不在 Cache** | **≥2 + 1 次磁盘** |
| hit | **miss** | — | **不可能**（页表缺失则信息不在主存，TLB 中不可能有该页表项） | — |

> **不可能组合的推理**：TLB 里存的正是 PTE 的缓存，**页表缺失说明 PTE 都不存在**，TLB 不可能命中。

### 5.7.11 TLB 与 Cache 的协同

![[Ch5-P101-TLB与Cache的协同.webp]]

| Cache 标记用哪种地址 | 后果 |
|---|---|
| **物理地址**（physically indexed） | **必须先转换**再做 Cache 查找（串行，慢但简单、无别名问题） |
| **虚拟地址**（virtually indexed） | 可与 TLB **并行**查找（快），但有**别名**（aliasing）问题：**同一物理地址对应多个虚拟地址**（共享内存、页共享） |

> 现代 CPU 常用**VIPT**（virtually indexed, physically tagged）：**索引用虚拟地址低位**（因为页内偏移不变），**标记用物理地址**（保证正确性）——两全其美。

### 5.7.12 存储器保护（Memory Protection）

- 不同任务可以**共享**部分虚拟地址空间
- 但需要**防止越权访问**（errant access）→ **需要 OS 协助**
- **硬件对 OS 保护的支持**：
	- **特权监督态**（privileged supervisor mode，即 **kernel mode**）
	- **特权指令**（privileged instructions）
	- **页表及其他状态信息**只在监督态可访问
	- **系统调用异常**（如 RISC-V 的 `ecall`）

### 5.7.13 理解程序性能（两个陷阱）

**① 抖动（thrashing）**

- 程序若**不断在内存与磁盘之间换页**，会运行得**极慢**
- **对策**：重新审视算法与数据结构，改变**局部性**，减少同时使用的页数
- 这组"当前热门的页"非正式地称为**工作集**（working set）

**② TLB 缺失（更常见）**

- TLB 一次只能管 **32~64 个页表项**
- 处理器可直接访问的空间可能**不到 1/4 MiB**：64×4 KiB=0.25 MiB
- **对策**：现代体系结构支持**可变页大小**
	- MIPS 除标准 4 KiB 外，还支持 16 KiB、64 KiB、256 KiB、1 MiB、4 MiB、16 MiB、64 MiB、256 MiB 的页
	- 用**大页**可以让程序直接访问更多内存而**不产生 TLB 缺失**

## §5.8 存储层次的统一框架（A Common Framework）

**四个问题在每一层都成立**：

1. **块放置**（block placement）
2. **查找块**（finding a block）
3. **缺失时替换**（replacement on a miss）
4. **写策略**（write policy）

### 5.8.1 块放置

| 相联度 | 放置选择 |
|---|---|
| **直接映射**（1 路） | **一个**位置 |
| **n 路组相联** | 组内 **n** 个选择 |
| **全相联** | **任意**位置 |

- 相联度越高 → 缺失率越低
- 但**复杂度、成本、访问时间**增加

### 5.8.2 查找块

| 相联度 | 定位方法 | 标记比较次数 |
|---|---|---|
| 直接映射 | **索引**（index） | **1** |
| n 路组相联 | 先索引到组，再在组内搜索 | **n** |
| 全相联 | **搜索所有表项** | **#entries** |
| （虚拟存储） | **全表查找**（full lookup table） | **0**（用页表直接算） |

- **硬件 Cache**：**减少比较次数**以降低成本
- **虚拟存储**：**全表查找**使**全相联可行**，收益是**更低的缺失率**

### 5.8.3 替换

| 策略 | 说明 |
|---|---|
| **LRU** | 高相联度时硬件**复杂且昂贵** |
| **随机** | 接近 LRU，**更易实现** |
| **虚拟存储** | 用**硬件支持的 LRU 近似**（访问位） |

### 5.8.4 写策略

| 策略 | 做法 | 代价 |
|---|---|---|
| **写直达** | 同时更新上下两层 | 简化替换，但**可能需要写缓冲** |
| **写回** | 只更新上层，**替换时**再写下层 | 需要**更多状态**（脏位） |
| **虚拟存储** | **只能写回**（磁盘写延迟太高） | —— |

### 5.8.5 三类缺失（The Three Cs）

| 类型 | 全称 | 成因 |
|---|---|---|
| **强制缺失** | compulsory miss / **cold start miss** | **第一次**访问某块（无法避免） |
| **容量缺失** | capacity miss | **Cache 容量有限**，被替换的块后来又用到 |
| **冲突缺失** | conflict miss / collision miss | **非全相联**时，因**组内竞争**造成；**同样大小的全相联 Cache 不会有** |

![[Ch5-P112-缺失来源.webp]]

> 图中说明：**强制缺失只占 0.006%**，几乎看不见；**8 路与 4 路的差别小到难以在图上分辨**。
> **优化对应关系**：增大容量 → 减少容量缺失；增大相联度 → 减少冲突缺失；增大块 → 减少强制缺失。

### 5.8.6 设计权衡总表

| 设计改动 | 对缺失率的影响 | 负面性能影响 |
|---|---|---|
| **增大 Cache 容量** | 减少**容量缺失** | 可能**增加访问时间** |
| **增大相联度** | 减少**冲突缺失** | 可能**增加访问时间** |
| **增大块大小** | 减少**强制缺失** | **增加缺失代价**；块太大时因**污染**可能**增加缺失率** |

## §5.9 用有限状态机控制简单 Cache（FSM）

### 5.9.1 示例 Cache 的规格

| 参数 | 值 |
|---|---|
| 映射 | **直接映射** |
| 写策略 | **写回 + 写分配**（write-back, write allocate） |
| 块大小 | 4 字（16 字节） |
| Cache 容量 | 16 KB（1024 块） |
| 地址 | 32 位**字节地址** |
| 每块状态 | **有效位 + 脏位** |
| 类型 | **阻塞式**（blocking）—— CPU 等到访问完成 |

**地址划分**：Tag **18 位** | Index **10 位** | Offset **4 位**

### 5.9.2 接口信号

| 侧 | 信号 |
|---|---|
| CPU ↔ Cache | Read/Write、Valid、Address（32）、Write Data（32）、Read Data（32）、Ready |
| Cache ↔ Memory | Read/Write、Valid、Address（32）、Write Data（**128**）、Read Data（**128**）、Ready |

> 注意：**CPU 侧是 32 位（一个字）**，**内存侧是 128 位（一整块 4 字）**——因为 Cache 缺失时按**块**与内存交换。

### 5.9.3 有限状态机（FSM）

![[Ch5-P117-Cache控制器状态机.webp]]

**FSM 三要素**：

- 一组**状态**，每个时钟沿**转移**
	- 状态值用**二进制编码**，当前状态存在**寄存器**中
	- **次态 = f（当前状态，当前输入）**
- **控制输出信号 = f（当前状态）**

**控制步骤（典型流程）**：

1. **Idle**（空闲）→ 收到 CPU 请求 → 比较标记
2. **Compare Tag** → 命中则直接返回数据；缺失则进入下一步
3. 若**脏** → **Write-Back**（把整块写回内存）
4. **Allocate**（分配）：从内存读块到 Cache
5. **Write-Back to Cache**（若原请求是写）
6. 返回 **Ready**

> 讲义注：可以把某些步骤**拆成独立的多个状态**以**缩短时钟周期**（因为每个状态的组合逻辑更简单）——这与第 4 章"加深流水线"是同一思路。

## §5.10 并行与存储层次：Cache 一致性（Cache Coherence）

### 5.10.1 一致性问题

两个 CPU 核共享物理地址空间（假设写直达 Cache）：

| 时间步 | 事件 | CPU A 的 Cache | CPU B 的 Cache | 内存 |
|---|---|---|---|---|
| 0 | | | | 0 |
| 1 | CPU A 读 X | **0** | | 0 |
| 2 | CPU B 读 X | 0 | **0** | 0 |
| 3 | CPU A 写 1 到 X | **1** | **0**（陈旧！） | 1 |

> **问题**：CPU B 的 Cache 里是**过期值**。若 B 再读 X，会读到 0 —— 错误。

### 5.10.2 一致性的定义

- **非正式**：**读返回最近写入的值**
- **正式**（三条）：
	1. **P 写 X，P 读 X**（中间无其他写）→ 读返回所写的值
	2. **P1 写 X，P2 读 X**（足够晚）→ 读返回所写的值
	3. **P1 写 X，P2 写 X** → **所有处理器看到相同的写顺序**（最终 X 的值相同）

### 5.10.3 一致性协议（Cache Coherence Protocols）

**协议的目的**：

- **数据迁移**（migration）到本地 Cache → **减少共享内存带宽**
- **只读数据的复制**（replication）→ **减少访问竞争**

**两类协议**：

| 协议 | 机制 |
|---|---|
| **监听协议**（snooping） | 每个 Cache **监视总线**上的读/写 |
| **目录协议**（directory-based） | Cache 与内存在**目录**中记录块的**共享状态** |

### 5.10.4 失效式监听协议（Invalidating Snooping）

- Cache 要写某块时，先取得**独占访问权**（exclusive access）
- 在总线上**广播失效消息**（invalidate）
- 其他 Cache 中该块的后续**读会缺失** → **拥有者提供更新后的值**

| CPU 活动 | 总线活动 | A 的 Cache | B 的 Cache | 内存 |
|---|---|---|---|---|
| CPU A 读 X | Cache miss for X | **0** | | 0 |
| CPU B 读 X | Cache miss for X | 0 | **0** | 0 |
| CPU A 写 1 到 X | **Invalidate for X** | **1** | **（失效）** | 0 |
| CPU B 读 X | Cache miss for X | **1**（提供） | **1** | 1 |

> 对比 §5.10.1 的表格：多了一条"**总线失效广播**"，B 的陈旧副本被作废，因此 B 再读会缺失并获得新值。

### 5.10.5 存储一致性（Memory Consistency）

**问题**：写**什么时候**被其他处理器"看到"？（"看到"= 读返回所写的值）

- **不可能瞬时可见**
- **假设**：
	- 一个写**只有在所有处理器都看到它之后**才算完成
	- 一个处理器**不会把写与其他访问重排**
- **推论**：
	- P **先写 X 再写 Y** → **所有看到新 Y 的处理器也看到新 X**
	- 处理器**可以重排读，但不能重排写**

> 这是 `fence` / 内存屏障指令存在的理由（也是第 2 章 `lr/sc` 同步的语义基础）。

## §5.11 冗余磁盘阵列（RAID）

**RAID**（Redundant Arrays of Inexpensive Disk，廉价磁盘冗余阵列）：

- 把多个独立操作的磁盘按某种方式组织成**磁盘阵列**以**增加容量**
- 利用类似主存中**多体交叉**的技术，把数据分布在多盘上，通过**并行工作**提高**数据传输速度**
- 用**冗余**技术进行**错误检测与恢复**，提高**可靠性**

**级别**：0–7 级，以及 RAID10（0+1）、RAID30（0+3）、RAID50（0+5）。

### RAID 0（条带化，无冗余）

- **无冗余**，适用于**容量与速度要求高、非关键**的数据
- 比单个大容量磁盘有更快的 **I/O 响应**
	- **连续分布**：两个 I/O 请求访问不同盘 → **并行发送**，减少排队时间
	- **交叉分布**：同一 I/O 请求的不同数据块**并行传送** → 高传输率（如视频编辑/播放）

### RAID 1（镜像）

- **镜像盘**实现 **1 对 1 冗余**
	- **读**：可由**定位时间更少**的那个盘提供数据
	- **写**：两个盘**并行更新**，写性能由**较慢**的一次决定
	- **检错**：恢复简单，一个盘坏仍可从另一个读
- 特点：**可靠性高，但价格昂贵**
- 常用于可靠性要求极高的场合（系统软件存储、金融证券系统）

### RAID 5（分布式奇偶校验）

- **奇偶校验块分布在各盘**中，所有盘**地位等价**
	- 提高**容错性**
	- 避免专门校验盘的**I/O 瓶颈**
- 采用**独立存取**技术，**I/O 响应速度高**
- **成本不高但效率高** → 被**广泛使用**

## §5.14 谬误与陷阱（Fallacies and Pitfalls）

### 陷阱 1：字节地址 vs 字地址

**例**：32 字节直接映射 Cache，4 字节块

| 地址 | 块号 |
|---|---|
| **字节** 36 | 36/4=9，9mod8= **1** |
| **字** 36 | 第 36 个字 = 字节 144，144/4=36，36mod8= **4** |

> 差之毫厘，谬以千里。**题目给的是字节地址还是字地址，一定要看清**。

### 陷阱 2：写代码时忽略存储系统的影响

**例**：按**行**遍历 vs 按**列**遍历数组

```c
for (i=0;i<n;i++) for (j=0;j<n;j++) sum += a[i][j];  // 好：行优先，连续访问
for (j=0;j<n;j++) for (i=0;i<n;i++) sum += a[i][j];  // 坏：列优先，大跨步
```

- **大跨步（large stride）导致局部性极差**，每次访问都可能缺失
- 对 n=1024 的二维数组，性能可差 **10 倍以上**

### 陷阱 3：多处理器共享 L2/L3 时的相联度

- **相联度小于核数** → 导致**冲突缺失**
- **核越多，越需要提高相联度**

### 陷阱 4：用 AMAT 评估乱序处理器

- AMAT **忽略了"非阻塞访问"**的效果（乱序 CPU 在缺失期间继续执行）
- 应改用**仿真**评估

### 陷阱 5：用段（segment）扩展地址范围

- 如 Intel 80286
- **段不一定够大**
- **使地址运算复杂化**

### 陷阱 6：在不为虚拟化设计的 ISA 上实现 VMM

- 如"非特权指令也能访问硬件资源"
- 要么**扩展 ISA**，要么**要求客户机 OS 不使用有问题的指令**（半虚拟化 paravirtualization）

## §5.15 结论（Concluding Remarks）

- **快的存储器小，大的存储器慢**
	- 我们真正想要"又快又大" → **Cache 制造这个假象**
- **局部性原理**：程序频繁使用其存储空间的**一小部分**
- **存储层次**：L1 Cache → L2 Cache → … → DRAM → 磁盘
- **存储系统设计对多处理器至关重要**（一致性、一致性模型）

| 可用性 | MTTF/(MTTF+MTTR) |
| MTBF | MTTF+MTTR |
| AFR | 8760/MTTF（MTTF 以小时计） |
| 校验位数 | 2^p≥1+d+p |
| SRAM | 0.5–2.5 ns，$500–1000/GiB |
| DRAM | 50–70 ns，$3–6/GiB |
| 磁盘 | 5–20 ms，$0.01–0.02/GiB |
| TLB 典型 | 16–512 项，命中 0.5–1 周期，缺失 10–100 周期 |

## §5.17 易错点清单

1. **字节地址 vs 字地址**别搞混（陷阱 1）
2. **index 用块地址低位**，不是字节地址低位（要先除以块大小）
3. **D-Cache 缺失率要乘访存指令比例**，I-Cache 不用
4. **全局缺失率 vs 局部缺失率**：算到主存的代价用**全局**
5. **块变大：缺失率可能先降后升**（污染），且**缺失代价一定上升**
6. **写直达需要写缓冲**，否则 CPI 爆炸（例：1→11）
7. **写回需要脏位**；**虚拟存储只能写回**
8. **全相联没有冲突缺失**；直接映射冲突缺失最严重
9. **相联度翻倍 → index 少 1 位 → tag 多 1 位**，**总标记位数增加**
10. **TLB 命中但页表缺失不可能**（页表缺失则 PTE 不存在）
11. **缺页由 OS 处理，Cache 缺失由硬件处理，TLB 缺失两者皆可**
12. **LRU 在高相联度下太贵**，用随机近似
13. **汉明码纠错位置 = 失败校验位编号之和**
14. **AFR 比 MTTF 更直观**（MTTF=100 万小时仍可能每天坏 2 块盘）
15. **跨步访问（按列遍历）会毁掉空间局部性**
16. **AMAT 不适用于乱序处理器**
