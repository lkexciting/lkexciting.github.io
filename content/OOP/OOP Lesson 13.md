# Exceptions：错误传播、栈展开与资源安全

## 1. 异常适合表达什么

当函数无法完成它承诺的操作、又不能在当前层恢复时，可以抛出异常，把处理交给有足够上下文的调用者。正常的循环终止、常见分支或简单输入校验不必一律改用异常。

`throw` 创建并抛出异常对象；`try` 定义处理范围；`catch` 按类型匹配处理器。没有匹配处理器时，程序最终调用 `std::terminate`，不能期待自动恢复。

```cpp
#include <stdexcept>
#include <iostream>

double divide(double a, double b) {
    if (b == 0) throw std::invalid_argument("zero divisor");
    return a / b;
}
int main() {
    try {
        std::cout << divide(1, 0);
    } catch (const std::invalid_argument& e) {
        std::cerr << e.what();
    }
}
```

## 2. 栈展开到底清理什么

从抛出点向匹配的处理器传播时，离开的作用域中已经成功构造的自动对象按构造完成的逆序析构。原生指针变量析构并不会自动 delete 指向的堆对象，所以“异常会清理栈”不等于“所有堆资源都不会泄漏”。

```cpp
#include <memory>
#include <stdexcept>

void work() {
    auto data = std::make_unique<int[]>(100);
    throw std::runtime_error("processing failed");
} // 异常传播时 data 析构，数组被释放
```

若改成裸 `new`，而在到达 `delete[]` 前就抛出异常，资源可能泄漏。RAII 把释放动作绑定到对象析构，不需要每个错误分支都复制一遍清理代码。

## 3. 捕获类型与处理顺序

一般按值抛出、按 `const` 引用捕获，避免不必要复制和派生对象切片。派生类型处理器放在基类前，否则前面的基类处理器已经匹配，后面的细分处理没有机会执行。

```cpp
try {
    // 可能抛出的操作
} catch (const std::out_of_range& e) {
    // 处理更具体的范围错误
} catch (const std::exception& e) {
    // 处理其他标准异常
} catch (...) {
    throw; // 重新抛出当前异常，保留原来的动态类型
}
```

处理器内部的 `throw;` 与 `throw e;` 不同：后者重新按表达式的静态类型抛出，可能切片。不能在没有正在处理的异常时随意执行裸 `throw;`。

## 4. 构造失败时的对象边界

对象的构造函数抛出异常，表示这个对象没有构造成功，因此不会调用这个完整对象的析构函数。但是，已经构造完成的基类和成员对象会被析构。把资源放进 `vector`、`string`、智能指针等成员，通常比在构造函数中手工维护多个裸资源更安全。

不需要机械遵守“两阶段初始化、构造函数绝不申请资源”。RAII 正是鼓励构造成功就建立有效状态；无法完成时抛出异常，并由已构造的资源成员回收资源。分开的 `init()` 适用于有特定约束的设计，但会引入“对象存在却尚未可用”的额外状态。

## 5. 析构函数与 noexcept

不要让异常逃离析构函数，尤其是在另一个异常的栈展开过程中，否则可能触发 `std::terminate`。释放失败若必须报告，应在显式的 `close()`、`commit()` 等操作中表达，并为析构路径安排不抛异常的兜底。

`noexcept` 是“不允许异常逃离”的承诺，不是编译器替你修复异常。异常逃出 `noexcept` 函数会终止程序。旧式 `throw(Type)` 动态异常说明不适合现代 C++ 新代码。

## 6. 异常安全的三个层次

| 保证 | 发生异常后承诺什么 | 设计方法 |
|---|---|---|
| 基本保证 | 不泄漏资源，对象不变量仍成立 | RAII、明确所有权 |
| 强保证 | 操作失败时外部可见状态不变 | 先准备临时结果，最后提交或交换 |
| 不抛保证 | 指定操作不传播异常 | 选择不会失败的操作，或在内部处理 |

例：更新配置时先把新配置解析到临时对象，全部成功再交换进正式配置，可避免解析到一半就破坏旧配置。复制赋值中的 copy-and-swap 也是同一思路。

## 7. 自测

1. 构造失败后，完整对象和成功构造的成员是否都不析构？——不是，完整对象不析构，已完成的成员仍会清理。
2. 把 `new` 得到的地址放入原生指针局部变量，是否已经获得 RAII？——没有。
3. 为什么库通常不应直接退出整个程序？——调用者才知道错误是否可恢复，以及应该怎样报告或重试。
4. catch 后没有处理能力该怎么办？——可补充必要上下文、记录合适信息，再重新抛出，不能默默吞掉错误。
