# **拷贝构造函数**

- **拷贝是通过 `拷贝构造函数` 实现的**
    
- **具有唯一的签名：`T::T(const T&);`**
    
    - 显式参数使用 **常量引用** 传递
        
- **如果你没有提供拷贝构造函数，C++ 会自动为你生成一个！**
    
    - 它会 **拷贝每个成员变量**
        
        - 对于基本类型（数字）、其他对象、对象数组，这是可行的。
            
    - 它会 **拷贝每个指针**
        
        - **问题：** 新旧对象的指针成员将指向 **同一块内存**，数据因此被共享！

# **选择**

## **方案一：仅拷贝指针（浅拷贝）**

- **行为：** 只复制指针本身的值（内存地址），而不复制指针所指向的内存块。
    
- **后果：**
    
    - 多个对象中的指针成员指向 **同一块动态分配的内存**。
        
    - 当一个对象被析构并释放了这块内存后，其他对象的指针就变成了 **悬空指针**。
        
    - 当第二个对象也被析构并再次尝试释放同一块内存时，会导致 **未定义行为**，通常是程序崩溃。

## **方案二：拷贝整个数据块（深拷贝）**

- **行为：** 为新对象的指针成员 **重新分配** 一块新的、大小足够的内存，然后将原对象指针所指向的 **所有数据** 复制到这块新内存中。
    
- **后果：**
    
    - 每个对象都拥有自己独立的、完整的数据副本。
        
    - 对象之间互不影响，析构时也能安全地释放各自的内存，避免了重复释放的问题。

# **标准 C 库字符串函数**

**（声明在 `<cstring>` 头文件中）**

- `size_t strlen(const char *s);`
    
    - `s` 是一个以空字符结尾的字符串。
        
    - **返回值：** 字符串 `s` 的长度。
        
    - **注意：** 长度 **不包括** 终止符 `\0`！
        
- `char *strcpy(char *dest, const char *src);`
    
    - 将 `src` 指向的字符串 **拷贝** 到 `dest` 指向的内存，直到拷贝完终止空字符 `\0` 后停止。(`src` 必须是以 `\0` 结尾的字符串！)
        
    - **要求：** `dest` 必须已经指向一块 **分配了足够空间** 的内存，以容纳整个 `src` 字符串（包括 `\0`）。
        
    - **返回值：** 返回 `dest`。

# **Person (char*) 的实现**

cpp

#include <cstring> // 等价于 #include <string.h>
using namespace std;

// 构造函数
Person::Person(const char *s) {
    name = new char[strlen(s) + 1]; // 动态分配：字符串长度 + '\0'
    strcpy(name, s); // 将字符串内容拷贝到新分配的内存中
}

// 析构函数
Person::~Person() {
    delete [] name; // 释放动态分配的字符数组
}

# **Person 的拷贝构造函数**

1. **在 Person 类的声明中添加拷贝构造函数的原型：**
    
    cpp
    
    Person(const Person& w); // 拷贝构造函数
    
2. **在 Person.cpp 中添加拷贝构造函数的定义：**
    
    cpp
    
    Person::Person(const Person& w) {

        strcpy(name, w.name); // 拷贝字符串内容

- **注意：**
    
    - 拷贝构造函数 **没有返回值**。
        
    - 它可以直接访问参数 `w` 的私有成员 `w.name`，因为它是类的成员函数。
        
    - 拷贝构造函数用于 **初始化一个尚未初始化的新对象**。

# **拷贝与性能开销**

- 不必要的对象拷贝会带来性能开销。
    
- 编译器在保证程序行为不变的前提下，可以 **"优化掉"** 某些拷贝操作（如返回值优化 RVO, NRVO）。
    
- 程序员需要：
    
    - 按照 **"笨"编译器** 的逻辑来编写代码（即假设拷贝会发生），以保证正确性。
        
    - 同时，也要准备好识别并优化那些可能成为性能瓶颈的不必要拷贝。

# **构造 vs. 赋值**

- **构造：** 每个对象在其生命周期内 **只被构造一次**。
    
- **析构：** 每个对象在其生命周期结束时 **应该只被析构一次**。
    
    - **错误1：** 忘记对 `new` 分配的对象调用 `delete` -> **内存泄漏**。
        
    - **错误2：** 对同一个对象多次调用 `delete` -> **未定义行为**。
        
- **赋值：** 一个对象在 **构造完成后**，可以被 **多次赋值**。

# **拷贝构造函数指南**

- **在大多数情况下，你不需要自己编写拷贝构造函数。**
    
    - 当类成员都是基本类型或具有正确拷贝语义的类（如 `std::string`, `std::vector`）时，编译器生成的默认拷贝构造函数就足够了。
        
- **在需要显式管理资源时，你必须自己编写。**
    
    - 例如，类中包含 **原始指针** 并持有动态分配的内存时，你需要实现 **深拷贝**。
        
- **如果你希望禁止对象的拷贝，可以显式删除拷贝构造函数。**
    
    - 将其声明为 `private`（C++98/03 方式）或在声明后加上 `= delete`（C++11 起推荐）。
        
    - 这会阻止编译器生成默认的拷贝构造函数，任何尝试拷贝该对象的行为都会导致编译错误。
        

cpp

// C++11 起推荐的方式
Person(const Person &rhs) = delete;

# **C++ 中的 static**

- **两个基本含义：**
    
    1. **静态存储期**
        
        - 变量在程序整个生命周期内都存在，在固定的内存地址只分配一次。
            
    2. **名称的链接性**
        
        - 控制变量或函数在多个源文件中的可见性（**内部链接** 意味着其名称仅在当前文件内可见）。
            

===== 第 21 页 =====

# **"static" 在 C++ 中的用法**

|使用场景|含义与作用|
|---|---|
|**静态自由函数**|具有**内部链接**，仅在定义它的源文件内可见。|
|**静态全局变量**|具有**内部链接**，仅在定义它的源文件内可见。|
|**静态局部变量**|具有**静态存储期**，在程序生命周期内只初始化一次，函数调用间保持其值。|
|**静态成员变量**|属于**类本身**，被该类的**所有实例对象共享**。|
|**静态成员函数**|属于**类本身**，被所有实例共享。**没有 `this` 指针**，因此**只能直接访问静态成员变量**。|

===== 第 22 页 =====

# **全局 static：在文件内隐藏**

**File1.cpp**

cpp

int g_global;          // 全局变量，外部链接（其他文件可通过 `extern` 访问）
static int s_local;    // 静态全局变量，内部链接（仅在 File1.cpp 内可见）

void func() { ... }    // 普通函数，默认外部链接

static void hidden() { ... } // 静态函数，内部链接（仅在 File1.cpp 内可见）

**File2.cpp**

cpp

extern int g_global; // 声明，可以访问 File1.cpp 中的 g_global
void func();         // 声明，可以调用 File1.cpp 中的 func()

extern int s_local;  // 错误！s_local 在 File1.cpp 中是 static，File2.cpp 无法访问
int myfunc() {
    g_global += 2;   // 可以，修改的是同一个全局变量
    s_local *= g_global; // 编译错误！s_local 在此处未定义
    func();          // 可以，调用的是同一个函数
}

# **函数内的静态局部变量**

- 变量的值在 **程序的整个生命周期内** 都被保持（**静态存储期**）。
    
- **初始化只执行一次**（在第一次执行到其声明时）。
    
- **示例：** 统计函数被调用的次数。
    

cpp

void f() {
    static int num_calls = 0; // 只初始化一次
    // ...
    num_calls++; // 每次调用f()，这个值都会递增并保持
    std::cout << "f() has been called " << num_calls << " times.\n";
}

===== 第 25 页 =====

# **static 应用于对象...**

- **构造时机：**
    
    - 当程序执行流 **第一次** 经过该静态对象的声明时，其构造函数被调用。
        
    - 构造函数 **至多被调用一次**。
        
- **析构时机：**
    
    - 在 `main` 函数结束或调用 `exit` 后，程序退出之前。
        
    - 编译器会确保所有静态对象（包括局部和全局）按其构造的 **相反顺序（LIFO）** 被析构。
        

===== 第 26 页 =====

# **条件构造**

- **示例：** 静态对象的条件构造。
    

cpp

void f(int x) {
    if (x > 10) {
        static X my_X(x, x * 21); // 条件内的静态对象
        // ... 使用 my_X ...
    }
}

- **`my_X` 的行为：**
    
    - 它 **仅在 `f()` 第一次被调用且 `x > 10` 时** 被构造。
        
    - 一旦被构造，它就会一直存在并保持其状态，即使后续 `f(x)` 调用时 `x <= 10`。
        
    - 它 **仅在已被构造的前提下**，才会在程序结束时被析构。
        

===== 第 27 页 =====

# **全局对象**

- 考虑以下全局对象：
    

cpp

#include "X.h"
static X global_x(12, 34);   // 静态全局对象
static X global_x2(8, 16);   // 静态全局对象

- **构造时机：**
    
    - 它们的构造函数在 **`main()` 函数开始执行之前** 就被调用。
        
    - 构造顺序通常由它们在 **文件中的出现顺序** 决定（此例中 `global_x` 先于 `global_x2`）。
        
    - 因此，`main()` 不再是程序执行时第一个被调用的函数。
        
- **析构时机：**
    
    - 在 `main()` 函数执行完毕之后。
        
    - 或当调用 `exit()` 函数时。
        

===== 第 28 页 =====

# **可以对类成员使用 static 吗？**

- **Static 的含义：**
    
    - **隐藏性**：在文件作用域，`static` 控制名称的链接性。
        
    - **持久性**：在局部作用域，`static` 表示静态存储期。
        
- **应用于类成员时：**
    
    - **隐藏性/访问控制：** 静态成员仍然是类的成员，遵守类的访问权限规则（`public`/`private`/`protected`）。
        
    - **持久性/存储：** 静态成员的存在 **不依赖于任何类的实例**。它们在所有实例之间是共享的。
        
- **静态成员是类范围的：**
    
    - 可以是 **变量** -> 静态成员变量
        
    - 可以是 **函数** -> 静态成员函数
        

===== 第 29 页 =====

# **静态成员变量**

- **特性：**
    
    - 它们被该类的 **所有成员函数**（包括非静态函数）共享，就像是全局变量，但作用域在类内。
        
    - 它们在程序开始时初始化（在 `main` 之前），且 **只初始化一次**。
        
    - 必须在 **类外部**（通常在对应的 `.cpp` 实现文件中）**单独进行定义和初始化**。
        
    - 在类外定义时，**不再使用 `static` 关键字**。
        
- **示例：StatMem.cpp**
    

===== 第 30 页 =====

# **静态成员函数**

- **特性：**
    
    - **没有隐式的 `this` 指针。**
        
        - **（为什么？）** 因为它们不依赖于任何特定的类实例。
            
    - 因此，它们 **只能直接访问类的静态成员变量**（或全局变量）。
        
    - 它们 **不能被声明为 `virtual`**，因为虚函数机制依赖于对象实例的 `this` 指针。
        
- **示例：StatFun.cpp**
