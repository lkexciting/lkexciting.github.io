# Appendix A Exam Guide：考试说明与题型精讲

> 对应课件：`About Exams_2025.pdf`（14 页）
> 关键词：题型、考点清单、输出题、程序填空、代码补全、**IDE 不允许使用**

---

## 0. 最重要的三条信息

1. **IDE is NOT allowed**（不能使用 IDE）——意味着你要**手写代码**，不能靠补全和编译报错试错。
2. 题型共五种：判断、单选、文本填空（**写输出**）、程序填空（**单行补全**）、代码补全（主观题：**类设计** + **函数实现**）。
3. 考点清单是**明确的**（见第 2 节），可以按清单逐条自查。

**备考策略**：这门课的考试不考"记忆力"，考"**你脑子里有没有那台编译器**"。所有输出题都依赖你对"构造/析构顺序、拷贝次数、绑定方式"的精确掌握。

## 3. 样题精讲

### 3.1 单选：编译器会自动生成哪个？

> Which function below would **NOT** be automatically generated by a compiler, if the user does not provide one?
> A. Constructor
> B. Destructor
> C. `operator=`
> D. `operator++`

**答案：D**

解析：编译器会为每个类自动生成

- **默认构造函数**（当且仅当没有任何用户声明的构造函数，Ch.5）；
- **析构函数**；
- **拷贝构造函数**；
- **拷贝赋值运算符 `operator=`**；
- （C++11 起还有移动构造、移动赋值）。

但它**不会**生成 `operator++`——自增运算符对任意类型没有"合理默认语义"，必须由程序员定义。

**易错点**：很多人选 A，因为记得"有构造函数就不生成默认构造"。要注意题干说的是"**用户没有提供任何一个**"的默认情形。

### 3.2 文本填空：写输出（构造/析构 + 异常）

```cpp
#include <iostream>
#include <stdexcept>

class A {
public:
    A(int age) : m_age(age) { }
    ~A() { std::cout << m_age; }
public:
    int m_age;
};

void func(A& a) {
    if (a.m_age < 18)
        throw std::logic_error("0");
}

int main() {
    try {
        A a(10), b(18);
        func(b);
        func(a);
        A c(60);
        func(c);
    }
    catch (const std::exception&) {
        std::cout << 0;
    }
    std::cout << std::endl;
    return 0;
}
```

**标准答案：`18100`**

逐行推演（这是必须练熟的能力）：

| 步骤 | 发生什么 | 输出 |
| --- | --- | --- |
| `A a(10), b(18);` | 构造 a（10）、b（18） | — |
| `func(b);` | `18 < 18` 为假，不抛 | — |
| `func(a);` | `10 < 18` 为真 → **抛 `logic_error`** | — |
| 栈展开 | `a`、`b` 被销毁，**析构顺序与构造相反**：先 b 后 a | `18` 然后 `10` |
| `catch` | 捕获 `std::exception&`，输出 | `0` |
| 注意 | `A c(60);` **从未执行**（异常已经跳过了它） | 不输出 60 |
| `endl` | 换行 | — |

合计：`18` + `10` + `0` = **`18100`**。

**三个关键点**：

1. **局部对象的析构顺序是构造的逆序**（`b` 先于 `a`）；
2. **异常抛出点之后的语句不执行**（`A c(60)` 从未构造）；
3. **栈展开会自动调用已构造对象的析构函数**（这是 Ch.13 的核心）。

### 3.3 文本填空：写输出（虚函数 + 默认参数）

```cpp
class Base {
public:
    virtual void fun(int x = 0) {
        cout << "Base::fun(), x = " << x << endl;
    }
};

class Derived : public Base {
public:
    virtual void fun(int x = 10) {      // 注意这里改了默认值
        cout << "Derived::fun(), x = " << x << endl;
    }
};

int main() {
    Derived d1;
    Base* bp = &d1;
    bp->fun();
    return 0;
}
```

**标准答案：`Derived::fun(), x = 0`**

解析（这是最经典的一个"陷阱题"）：

| 部分 | 绑定方式 | 结果 |
| --- | --- | --- |
| **调用哪个函数** | 动态绑定（`virtual`） | `Derived::fun` |
| **默认参数取哪个值** | **静态绑定**（按 `bp` 的静态类型 `Base*`） | `0` |

于是一个荒谬但合规的组合：**执行 `Derived::fun` 的代码，却收到 `Base` 的默认参数 0**。

这正是 Ch.7 那条规则的来源：**"Never redefine an inherited default parameter value"**——默认参数是静态绑定的，与虚函数机制不一致，改了它只会制造困惑。

**如果改成直接调用**：

```cpp
Derived d1;
d1.fun();      // Derived::fun(), x = 10  ← 静态类型是 Derived，用 Derived 的默认值
```

### 3.4 程序填空：单行补全

课件提到一个 "CNY and USD account" 的例子（用两个账户类演示继承/运算符重载），以及一句提示：

> **"It is better to copy directly."**

这句话通常出现在"拷贝构造 vs 赋值"或"传参方式"的填空题里，意思是：**某些情况下直接拷贝比用指针/引用更简单安全**（尤其是小对象，或需要独立副本时）。

**这类题的答题技巧**：

- 先判断"这一行要解决什么问题"（构造子对象？调用基类？返回 `*this`？检查自赋值？）；
- 再回忆"标准骨架"（例如 `operator=` 一定是 `if (this != &rhs) { ... } return *this;`）；
- 注意**分号、`const`、引用符号**这些细节，IDE 不可用意味着没有自动补全帮你。

## 4. 代码补全（主观题）

课件给了两个方向：

### 4.1 类设计（class design）

要求通常是"设计一个类，满足以下功能"，评分点往往是：

| 评分点 | 说明 |
| --- | --- |
| 数据成员是否 `private` | 封装 |
| 是否有构造函数（含参数） | 保证初始化 |
| 是否需要拷贝构造/赋值/析构 | Rule of Three（有指针时） |
| 成员函数是否该 `const` | const-correctness |
| 参数是否用 `const&` | 避免拷贝 |
| 是否需要 `operator<<` | 便于测试 |

### 4.2 函数实现（function implementation）

课件的例子是**复数计算器**（Complex Number Calculator），用**运算符重载**实现加减乘除、输入输出。

一个合格答案的骨架：

```cpp
class Complex {
public:
    Complex(double re = 0, double im = 0) : re_(re), im_(im) {}

    Complex operator+(const Complex& rhs) const {
        return Complex(re_ + rhs.re_, im_ + rhs.im_);
    }
    Complex operator-(const Complex& rhs) const {
        return Complex(re_ - rhs.re_, im_ - rhs.im_);
    }
    Complex operator*(const Complex& rhs) const {
        return Complex(re_ * rhs.re_ - im_ * rhs.im_,
                       re_ * rhs.im_ + im_ * rhs.re_);
    }

    // 复合赋值：返回引用，支持链式
    Complex& operator+=(const Complex& rhs) {
        re_ += rhs.re_; im_ += rhs.im_;
        return *this;
    }

    // 输入输出必须是自由函数
    friend std::ostream& operator<<(std::ostream& os, const Complex& c) {
        os << c.re_ << (c.im_ >= 0 ? "+" : "") << c.im_ << "i";
        return os;
    }
    friend std::istream& operator>>(std::istream& is, Complex& c) {
        is >> c.re_ >> c.im_;
        return is;
    }

private:
    double re_, im_;
};
```

**得分要点**（对应 Ch.9）：

- `operator+` **按值返回新对象**，且成员函数标 `const`；
- `operator+=` **返回 `*this` 的引用**；
- `operator<<` / `operator>>` **必须是自由函数**（左操作数是流），返回 `ostream&` / `istream&`；
- 需要访问私有成员时用 `friend`。

### 4.3 课件的一条格式提醒

> **"It is better to highlight it is C++ code"** —— 提交代码时标注语言（如 Markdown 的 ` ```c++ `），否则排版会乱。

这虽然是小细节，但说明**阅卷是人工的**，可读性会影响印象分。

## 5. 手写代码的注意事项（IDE 不可用）

这是本场考试最实际的一条约束。手写时最容易丢分的地方：

| 类别 | 检查项 |
| --- | --- |
| 语法 | 类定义末尾的 `;`；`#include` 是否写了；`using namespace std;` |
| 声明 | 每个成员函数定义前的 `返回值 类名::`；模板的 `template <class T>` 是否重复 |
| const | 声明与定义是否都写了 `const`；参数是否 `const&` |
| 引用/指针 | `&` 与 `*` 是否漏了；`->` 与 `.` 是否用对 |
| 内存 | `new[]` 配 `delete[]`；拷贝构造/赋值是否成对 |
| 返回 | `operator=` 是否 `return *this;`；链式调用是否返回引用 |
| 异常 | `catch` 是否按引用捕获；顺序是否派生在前 |

**建议的答题节奏**：

1. 先在草稿区写出**类的骨架**（数据成员 + 函数签名）；
2. 再填函数体；
3. 最后**逐行默读一遍**，模拟编译器检查（括号配对、分号、const 一致性）。

## 6. 输出题的通关清单

写输出题（Fill in Blank text）本质是"人工执行编译器 + 运行时"。请按以下清单逐项检查：

1. **构造顺序**：基类 → 成员（按声明顺序）→ 函数体；
2. **析构顺序**：与构造完全相反；
3. **拷贝发生了几次**：按值传参、按值返回、初始化、容器扩容；
4. **绑定方式**：通过指针/引用且函数是 `virtual` → 动态绑定；否则静态；
5. **默认参数**：永远按**静态类型**取；
6. **异常路径**：抛出点之后的语句不执行；栈展开会析构已构造对象；`catch` 后从 try-catch 之后继续；
7. **静态成员/静态局部变量**：跨调用保留，只初始化一次；
8. **`++i` 与 `i++`**：前缀返回引用（无拷贝），后缀返回副本（一次拷贝）；
9. **`endl` 与 `'\n'`**：输出结果相同（都换行），但 `endl` 会 flush；
10. **虚函数在构造/析构中**：不会多态，只到当前层。
