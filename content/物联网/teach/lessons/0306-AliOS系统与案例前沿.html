AliOS 系统与案例前沿

一句话：AliOS Things（Rhino 内核/uMesh/ID²）、HarmonyOS（多内核/分布式软总线）、AntiTheft 防盗案例双平台开发与研究前沿收尾。

本课依据

考试内容以 PPT（课件）为准。本课对应课件《第三章-dw(3)》"典型物联网操作系统"中 AliOS Things 与 HarmonyOS 两节、"案例开发"与"学术研究进展"节【教材 PPT 补充部分会单独标注】。原始课件：D:\学习文件\大三上\物联网技术基础与应用开发\第三章-dw(3).pdf

一、AliOS Things

面向 IoT 领域的轻量级物联网嵌入式操作系统，适用于小型物联网基础设备，可应用在智能家居、智慧城市等领域。

特点课件要点
开发简易支持 C 和 JavaScript；提供 IDE（编译、调试、内存泄漏检测）；支持 GDB/Valgrind/Perf 等 Linux 工具
优异性能小 FootPrint，内核 ROM 占用小于 2KB；内核提供空闲 CPU 模式；多种调度策略保证实时性
服务丰富连接组件支持设备以不同方式接入；支持自组织网络和设备间本地互联；深度定制优化的网络协议栈
更新便捷FOTA（无线固件升级）；支持独立升级及多 bin、差分和乒乓升级；提供 OTA HAL 便于移植

1.1 关键特性表（课件原表）

特性描述
编程模型自主内核 Rhino：模块化、事件和多线程编程模型 + 基于异步事件的框架 Yloop；支持阻塞式 I/O 和分阶段 I/O
任务调度两种模型：基于优先级的抢占式调度和时间片轮转调度
内存分配静态 + 动态都支持
软件更新整个镜像升级、模块化升级和差分升级
网络服务WiFi、LoRa、BLE、蜂窝网络等；支持 LwIP、uMesh、LoRaWAN 协议
AI 支持官方支持，兼容 TensorFlow Lite 库
其他安全：可信执行环境、安全传输协议层、可信身份标识

1.2 Rhino 内核（必背）

  • 内存占用小：为内核对象提供静态和动态两种内存分配方式，专为小内存块管理而设计的内存分配器，可同时支持固定大小块和可变大小块、可有多个内存区域。
  • 低功耗：CPU 空闲时通常执行处理器原生指令（ARM 的 WFI、IA32 的 HLT）进入低功耗；Rhino 提供空闲 CPU 模式——检测到固定时间内系统空闲时，把 CPU 置于 C1（或 C2、C3…）状态（C0 是处理器活跃状态，C1～Cn 都是睡眠状态）并阻止该时段系统时钟中断，空闲结束后再唤醒回 C0。
  • 实时性与多任务：两种调度策略——基于优先级的抢占式调度和循环调度；两种策略下调度首选优先级最高的任务。

1.3 网络服务与安全

组件课件要点
uMesh自组织、自我修复和多跳，适用于大规模部署场景
SAL（套接字抽象层）加速具有不同连接能力的 MCU 通信芯片的开发
LwIP深度定制优化的协议栈：IPv4/IPv6、TCP/UDP、ICMP、ARP 等
LoRaWAN支持 Class A 和 Class C 两种模式的开发
安全系统级 + 芯片级保护；LinkTEE 可信运行环境、Link ID² 可信身份认证（不可篡改、不可伪造、全球唯一，一芯一密），为设备与云提供双向身份认证和链路加密

开发环境：Visual Studio Code、WebIDE（Theia）；组件式开发用 AliOS Cube 工具灵活组合物联网软件栈；支持云端一体在线开发环境。

二、HarmonyOS

华为开发的面向全场景的分布式操作系统。在同一套系统框架内支持 1+8+N 等各类终端：1 指手机，8 代表车机、音箱、耳机、手表/手环、平板、大屏、PC、AR/VR，N 泛指其他 IoT 设备。设计目标三条：面向消费者（能力整合、快速连接、资源共享）、面向应用开发者（开发与终端形态差异无关）、面向设备开发者（组件化、灵活裁剪）。

关键特性表：基于线程的编程模型，实现 POSIX 和 CMSIS-RTOS API；时间片轮转调度；动态内存分配；多种软件更新机制；网络服务含星闪 NearLink；AI 官方支持 TensorFlow Lite、MindSpore Lite；其他：多内核设计、分布式软总线技术。

2.1 多内核设计（必背数字）

系统分为内核层、系统服务层、框架层和应用层，可按需裁剪。手机端设备主要使用 Linux 内核；IoT 领域设备有两个内核：

内核适用设备要点
LiteOS-A标准设备（参考内存 ≥128MB）可支持有 MMU 的设备进行虚拟内存映射；支持大量 POSIX；统一驱动框架 HDF
LiteOS-M微设备（参考内存 ≥1MB）及迷你设备（参考内存 ≥128KB）针对没有 MMU 的设备；分为硬件相关层和硬件无关层，硬件相关层提供统一 HAL 接口；适用于 Cortex-M3/M4/M7、RISC-V 芯片架构

2.2 分布式软总线

参考计算机硬件总线，在 1+8+N 设备间搭建一条"无形"的总线，具备自发现、自组网、高带宽、低时延特点。基于软总线的四大分布式能力：

  • 分布式数据管理：用户数据不再与单一物理设备绑定，业务逻辑与数据存储分离，跨设备运行数据无缝衔接；
  • 分布式任务调度：构建统一分布式服务管理（发现、同步、注册、调用）机制，支持远程启动、远程调用、绑定/解绑、迁移，按设备能力/位置/状态/用户习惯选最合适的设备；
  • 分布式设备虚拟化：资源融合、设备管理、数据处理，把周边设备作为手机能力延伸，共同形成超级虚拟终端；
  • 可完成设备虚拟化、跨设备服务调用、多屏协同、文件分享等分布式业务。

三、案例开发：AntiTheft 防盗应用

功能：基于加速度传感器读数异常检测的节点防盗——每隔 1s 以 100Hz 频率采集加速度读数，检查方差是否超出阈值（默认 4）；超出则判定被盗，点亮红色 LED 并持续一段时间。两个平台版本：Contiki（TelosB+mts300）、RIOT（ESP32+mts300）。

Contiki 版要点

环境：下载源码 + 交叉编译工具链，或用虚拟机 Instant Contiki（用户名 username，密码 user）。代码：两个 protothread——accel_sample_process 采样（etimer 周期 ACCEL_INTERVAL）、antitheft_process 检测（CHECK_INTERVAL 周期调 checkAccelation()）；缓冲区 accelSamples[10]，满则前移 9 个数据、新读数放最后。常数：ACCEL_SAMPLES=10，ACCEL_INTERVAL=CLOCK_SECOND/100（10ms），CHECK_INTERVAL=CLOCK_SECOND；方差 > 4×ACCEL_SAMPLES 则 leds_on(LEDS_RED)。

步骤：② Makefile（CONTIKI_PROJECT = anti-theft-demo） ③ $ make TARGET=sky anti-theft ④ motelist 发现串口 /dev/ttyUSB0 → $ make TARGET=sky MOTES=/dev/ttyUSB0 anti-theft.upload ⑤ 测试：节点放桌面再拿起，观察红灯是否亮

RIOT 版要点

环境（Linux）：git clone RIOT 源码 + apt 安装 gcc-arm-none-eabi 等依赖 + esptools 安装 ESP32 工具链。代码：两个线程 accel_sample_thread 与 antitheft_thread（ztimer_sleep 计时），main 里 thread_create 创建（各配 1024 字节栈、优先级 8、THREAD_CREATE_STACKTEST）；RIOT 版还多一句 else leds_off(LEDS_RED)（未超阈值关灯）。常数：ACCEL_INTERVAL = US_PER_MS * 10，CHECK_INTERVAL = US_PER_SEC。

步骤：② Makefile（APPLICATION = anti-theft-demo； USEMODULE += ztimer） ③ $ make BOARD=esp32-wroom-32 ④ $ make BOARD=esp32-wroom-32 PORT=/dev/ttyUSB0 flash ⑤ 测试：同上，拿起节点观察红灯

四、研究前沿（四个方向 + 四个系统）

方向课件要点
低代码大模型发展为端侧程序开发带来新机遇，LLM as an OS
高安全性节点无人值守、易被俘获；利用新型安全语言特性、新型硬件特性如 TEE。代表 Tock：隔离软件错误、内存保护、有效管理内存；基于类型安全语言 Rust 编写的内核（SOSP17：Multiprogramming a 64 kB Computer Safely and Efficiently）
高拓展性对多种语言、多种协议的支持；课题组工作 WAIT、TinyNet。代表 FireStorm：ARM Cortex M4 低功耗硬件平台 + 基于 TinyOS 的新软件系统，利用 Lua 语言高可拓展特性支持基于 libC 的语言移植、支持多种通信协议（IPSN16）
环境自适应性Intermittent Computing：节点直接从环境采集能量（太阳能、无线电等），电量有限、断电即处理器/内存/寄存器清零 → 需在断电前把状态保存在非易失内存中以便恢复。代表 InK：感知系统能量，在能量用尽之前保存必要信息，确保内存一致性和程序恢复（SenSys18）

课件思考题 3（后四问）与课后习题（本课相关）

问 5：AliOS Things 基于哪种实时操作系统内核？其主要特点是什么？

点开看参考答案

基于 Rhino 实时操作系统内核研发。主要特点：内存占用小（静态+动态两种分配方式、专为小内存块设计的分配器，支持固定/可变大小块和多个内存区域）、低功耗（空闲 CPU 模式，C0 活跃、C1～Cn 睡眠）、实时性与多任务（基于优先级的抢占式调度和循环调度，首选最高优先级任务）。（课件原文）

问 6：AliOS Things 中哪个协议实现自组织网络功能？哪个协议实现轻量级的 TCP/IP 功能？

点开看参考答案

uMesh 实现自组织网络（自组织、自我修复、多跳）；LwIP 实现轻量级 TCP/IP（IPv4/IPv6、TCP/UDP、ICMP、ARP 等）。（课件原文）

问 7：HarmonyOS 中 LiteOS-A、LiteOS-M 分别适用哪些场景？

点开看参考答案

LiteOS-A：标准设备（参考内存 ≥128MB），支持有 MMU 的设备进行虚拟内存映射；LiteOS-M：微设备（参考内存 ≥1MB）及迷你设备（参考内存 ≥128KB）这类没有 MMU 的设备。（课件原文）

问 8：HarmonyOS 分布式软总线是什么意思？

点开看参考答案

参考计算机硬件总线，在 1+8+N 设备间搭建的一条"无形"的总线，具备自发现、自组网、高带宽、低时延特点；全场景设备间可基于软总线完成设备虚拟化、跨设备服务调用、多屏协同、文件分享等分布式业务。（课件原文）

课后习题 12：HarmonyOS 提出的 1+8+N 指代哪些设备？

点开看参考答案

1 指手机为主入口；8 指车机、音箱、耳机、手表/手环、平板、大屏、PC、AR/VR 这 8 个华为自研领域产品；N 是泛 IoT 硬件构成的华为 HiLink 生态。（课后习题答案原文，与课件一致）

课后习题 13：HarmonyOS 的分布式软总线包括哪些模块？各自实现什么功能？

点开看参考答案

四个模块：分布式软总线模块（多设备终端的统一基座，提供统一分布式通信能力，快速发现并连接设备、高效传输任务和数据）、分布式数据管理模块（位于软总线之上，实现应用程序数据和用户数据的分布式管理）、分布式任务调度模块（构建统一的分布式服务管理——发现、同步、注册、调用机制，支持远程启动、远程调用、绑定/解绑、迁移）、分布式设备虚拟化平台（资源融合、设备管理、数据处理，将周边设备作为手机能力的延伸，形成超级虚拟终端）。（课后习题答案原文）
