低功耗 MAC 与链路质量估计

一句话：S-MAC / LPL / RI-MAC 三条技术路线解决"谁和谁同时醒"，RSSI/SNR/LQI/PRR 四个指标量化"链路好不好"，各配一道课件计算思考题。

本课依据

考试内容以 PPT（课件）为准。本课对应课件"基于 IEEE802.15.4 的传感网协议"一节中的"低功耗 MAC"与"链路质量估计"两部分【教材 PPT 补充单独标注】。原始课件：第五章 低功耗无线协议2026.pdf

一、低功耗 MAC：为什么需要、怎么分类

设计目标：尽可能降低传感器节点的通信能耗。无线通信中造成能源浪费的四个原因：

原因说明
空闲侦听能源浪费的主要来源
冲突可能造成接收方无法解码所涉及的任何数据包
偷听节点接收了不是发给自己的数据包
控制开销包头和其他类型数据包的开销

传统 CSMA MAC（802.11）：发数据前先侦听，信道空闲立刻发送，否则退避一段时间。问题：接收者始终需要在线，不适用于无线传感器网络。WSN 的做法是让节点实现低占空比（活动/睡眠交替），核心难题是在收发节点间找到同处活动状态的"汇合点"，两条路线：

  • 基于同步机制的 MAC：节点协同活动/睡眠以对齐活动时间；代价是额外同步开销。
  • 基于异步机制的 MAC：发送方发起（基本技术：前导码采样）；接收方发起（发送方持续监听信道，等待接收方发送信标）。

1.1 同步 MAC：S-MAC

基本模式：节点与邻居同步苏醒和睡眠时间，在苏醒时间内传输数据。冲突避免采用与 802.11 类似的三件套：

  • 虚拟载波侦听：数据包含记录持续时间的字段，节点记入网络分配向量 NAV 并随时间递减；发送前先查 NAV，非零则继续等待。
  • 物理载波侦听：物理层监听信道能量发现正在进行的传输。
  • RTS/CTS 机制：解决隐藏/暴露终端问题，减少空闲侦听。
教材 PPT 补充：多跳延迟与自适应侦听

S-MAC 多跳传输中睡眠造成的延时会逐跳累加；自适应侦听让邻居依据 CTS 包得知下一跳传输结束时间并短暂醒来侦听，可减少延迟。

S-MAC 回顾：比 802.11 CSMA/CA 更节能；但空闲侦听依然开销大（所有人一开始都必须醒着）、网络空闲时有同步开销、发送数据时有 RTS/CTS 开销。

1.2 发送方发起异步 MAC：LPL

LPL（Low Power Listening）：发送方发送足够长的探测包（preamble）列唤醒接收者，直接使用数据包作为探测包；接收方周期性做 CCA（Clear Channel Assessment，对无线信道的简短能量采样），一旦发现能量大于阈值（默认 −77dBm）就进入接收状态。

对比CS（载波侦听）CCA
相同点检测能量是否高于阈值，探测周围是否有人发包
不同点发现则退避发现则进入唤醒收数据
阈值偏高可能无法感知潜在传输，引起冲突可能错过接收
阈值偏小环境噪音引起不必要的退避环境噪音也可能唤醒节点
  • 单播：ACK 包可以缩短数据包列；广播：数据包列持续时间必须 ≥ 接收者睡眠时间（Ttrain ≥ Tsleep）——课件例中广播的开销是单播的两倍。
  • 自适应机制：接收方回完 ACK 后持续监听一段时间（delay after receive），以接收后续连续数据包。
  • 错误唤醒问题：WiFi、蓝牙与 802.15.4 共用 2.4G 频段，节点可能被 WiFi 信号错误唤醒，delay after receive 带来不必要开销。解决：通过 RSSI 特征区分 ZigBee 与其它微波信号——利用广播时间、数据包间隔、峰均比、RSSI 是否可能小于噪声强度四个特征（ZigBee 广播时间 [576,4256]μs、峰均比 ≤1.3；WiFi [194,542]μs、≥1.9；蓝牙 366μs；微波 10ms、峰均比 ≥2.9 且 RSSI 可低于噪声）。
  • LPL 回顾：比同步 MAC 更节能、无需所有节点一开始都醒着；但发送方需持续发探测包直到接收方醒来，持续占用信道，影响发送方通信范围内其他节点。

1.3 接收方发起异步 MAC：RI-MAC

工作机制：接收者周期性醒来并发送探测包（beacon）；发送者有数据时一直处于侦听状态，直到收到接收者的探测包才可以发送数据。数据冲突用冲突避免 + 二进制指数退避处理。对比：发送方发起要持续占用信道，导致其他邻居无法收发；接收方发起只占用很短时间（B-D-A 即完成）。

教材 PPT 补充：EE-RI-MAC 与 A-MAC

EE-RI-MAC：发送者空闲侦听时"时醒时睡"而非持续侦听，减少发送者能耗；A-MAC：RI-MAC 中接收者发 probe 后需等待一段时间，A-MAC 通过 backcast 机制测试网络中是否有潜在 sender，减少接收者等待能耗。

二、链路质量估计（路由协议的基础）

好的路由协议会选择链路质量好的链路通信。评估指标：物理层——RSSI、SNR、LQI；链路层——PRR（衡量链路质量的最终指标）。

指标计算/来源关键数字
RSSI接收信号总能量的度量；8 个 symbol（128μs）周期信号强度平均值；CC2420 记录在 RSSI_VAL 寄存器，P = RSSI_VAL + RSSI_OFFSET（OFFSET≈−45dBm）；Per byte 读寄存器，Per packet 按 SFD 后 8 个 symbol 计算经验值 −95 ~ −55dBm
SNRSNR=10log(S/N)；802.15.4 硬件不支持直接读取，CC2420 用"不收包时 RSSI 读数"作噪声功率（Noise Floor 约 −98dBm）经验值 3~43dB；例：RSSI −75dBm → SNR 23dB
LQISFD 之后 8 个 symbol 的码元错误率（CER）；LQI=(CORR−a)×b，CORR 为平均 correlation value（0~255），a、b 为经验参数经验值 50（最差）~110（最好）；CTP 中 LQI >105 为高质量链路
PRR数据包成功接收率（不考虑重传）；估计：Beacon 包（缺陷：包长不同预测不准）、数据包（receiver feedback / ack 计数）—

RSSI 与 PRR 关系（必背阈值）：RSSI > −87dBm → PRR > 85%，链路质量好；RSSI < −92dBm → PRR < 50%，链路质量差；介于两者进入灰色区域，PRR 非常不稳定、难以预测。RSSI 问题：灰色区域测不准、和接收器灵敏度有关。LQI 与 PRR 关系：单个 LQI 与 PRR 关联性低（LQI 85 对应 PRR 从 10% 到 100% 不等），平均 LQI 与 PRR 关联性高。

2.1 通过 ACK 计数的 PRR 估计（EWMA）

固定时间窗口：PRRcurrent = 收到的 ACK 包数 / 发送的数据包总数 指数加权移动平均：PRR = PRRcurrent × α + (1−α) × PRR（上一时刻估计值） 可调参数：滑动窗口 W 与权重 α；课件示例 W=3，α=0.9 示例：PRRcurrent=0.67 → PRR=0.67×0.9+0.67×0.1=0.67 PRRcurrent=1 → PRR=1×0.9+0.67×0.1=0.967

2.2 基于跨层特征的 4-bit 链路估计

  • 物理层（1 bit）White bit：置 1 表示收到的数据包每个符号误码率很低；若 LQI < 105 则置 0。
  • 链路层（1 bit）Ack bit：置 1 表示收到 L2 层 ACK、上一个包成功发送；置 0 表示发出去的包可能丢了。
  • 网络层（2 bits）：Pin bit——置位后链路估计器不能从路由表删除该链路，直到清零；Compare bit——指示数据包发过来的链路是否优于路由表中一个或多个链路。

课件思考题（本课）

LPL 探测包间隔：CCA 期间采样 400 次，采样平均值超过 −77dBm 才醒来；每次 CCA 长 11ms，探测包长 2ms，接收信号强度 −56dBm，环境噪声 −100dBm。探测包间隔最大为多少？

点开看答案

设 CCA 的 400 次采样中有 n 次采到探测包信号：[n×(−56) + (400−n)×(−100)]/400 > −77，解得 n ≥ 210。即 CCA 期间有数据包在传输的时间至少 (210/400)×11ms = 5.8ms；至少要 3 个数据包落在 CCA 期间，两个间隙合计最大 11−5.8 = 5.2ms，故最大间隔 = 5.2/2 = 2.6ms。（课后习题答案第四章第 4 题）

EWMA 估计：链路上一段时间的数据包/ACK 情况如图，EWMA 窗口 3、权重 α=0.9，求最后两个时刻 t1、t2 的 PRR 估计值。

点开看答案

t1 时刻 PRRcurrent=0.67，上一时刻估计值 0.33：PRR₁ = 0.67×0.9 + 0.33×0.1 = 0.636；t2 时刻 PRRcurrent=0.67，上一时刻估计 0.636：PRR₂ = 0.67×0.9 + 0.636×0.1 = 0.667。（课后习题答案第四章第 5 题）
