一、I/O 操作方式：阻塞式 vs 分阶段

方式课件定义与特点
阻塞式 I/O当程序调用一个 I/O 操作时，直到该 I/O 操作完成，这个调用才会返回；易于编程
分阶段 I/O把 I/O 操作的调用和完成分成了两个独立的阶段；代码冗长，但可以保持系统的高响应性；更灵活、更好控制并发
// 阻塞式 I/O：调用返回即完成 if (send() == SUCCESS) { sendCount++; } // 分阶段 I/O（TinyOS 风格）：call 阶段 + event 阶段 { call SubSend.send(); // call phase …… // other tasks } event void sendDone(error_t err) { if (err == SUCCESS) sendCount++; }

二、内存分配：静态 vs 动态

对比静态内存分配（如 TinyOS）动态内存分配（如 SOS）
确定时间编译时确定运行时确定
构成/方式通常由未初始化数据段（.bss）和初始化数据段（.data）构成；可通过静态数组实现通过 malloc 申请、通过 free 释放
优点效率高、内存池中无碎片可以按需分配
缺点不能按需申请内存池中容易出现碎片、可能造成安全隐患
教材 PPT 补充

教材 PPT 中动态内存分配的举例为 AliOS Things，并强调动态分配"通过 free 释放（否则可能会造成系统安全隐患）"。课件原文举例为 SOS，两者不冲突，答题以课件举例为准、可引用教材补充。

课后习题 6：使用 mmem 内存管理模式，静态数组为 memory[]，可用内存大小为 avial_memory，最大可用空间为 MMEM_SIZE，mmem_alloc() 分配的新内存空间指针指向的地址是？

点开看参考答案

&memory[MMEM_SIZE - avial_memory]（课后习题答案原文）。

三、软件更新

3.1 更新方式与 Bootloader

两种连接方式：有线更新（串口、以太网等）、无线更新（OTA, over the air）（如通过 WiFi）。

Bootloader（名词解释必背）

BootLoader 是设备在加电后执行的第一段代码。它在完成 CPU 和相关硬件的初始化之后，会将操作系统或固化的应用程序装载到内存中，然后跳转到操作系统所在的空间，启动操作系统运行。

具体更新步骤（课件原文四步）：

  1. 在操作系统启动前，通过 BootLoader 查找升级文件；
  2. 找到文件后，擦除 Flash 中存储的旧文件；
  3. 在 Flash 中写入升级的文件；
  4. 检查新写入的文件是否正确——若正确则重启设备加载新文件执行，反之则重新烧写文件，有些设备也可以回滚到原来的版本。

3.2 三种更新方法

方法课件定义适用场景（课后习题答案）
基于整个镜像的更新对软件系统的所有部分进行更新与设备上旧软件无关或差异巨大的新软件更新
基于模块化的更新将软件镜像细分为各个模块，按需选择某些模块更新模块化设计、没有版本管理控制的设备软件更新
基于差分的更新旧版本与新版本代码做差分，得到升级部分的补丁即差分文件；可对整个镜像差分，也可对模块差分版本严格控制、对流量敏感的设备软件更新

3.3 差分计算（必考）

差分文件的两种指令： COPY 指令：COPY1 <n>2 <old addr>2 → 5 Byte ADD 指令：ADD1 <n>2 <BYTE1,…,BYTEm>m → 3+m Byte 课件例题： 旧文件：A B C D E A C B C → 9 Byte 新文件：W A B C D E A C B C → 10 Byte 差分文件：ADD<W> COPY 9 0 = ADD 1 个字节(3+1=4) + COPY(5) = 9 Byte

影响差分文件大小的两个重要因素：差分算法（给定两个文件，计算最小差分文件）与相似性保持技术（保持代码功能前提下，增加新旧代码之间的相似性）。常见的差分算法：bsdiff、xdelta3、HDiffPatch。课件还介绍了课题组工作 MDiffPatch（Exploiting Multiple Similarity Spaces for Efficient and Flexible Incremental Update of Mobile Apps，IEEE INFOCOM 2024）。

课件思考题 2（本课核心）

旧文件：A B C D E A C B C；新文件：W A B C D E A C B C X D E A C B。差分文件大小为多少？具体指令是？

点开看参考答案

课件给出两种等价方案，大小均为 18 字节：
方案一：ADD 1 <W>，COPY 9 0，ADD 1 <X>，COPY 5 3 → 4+5+4+5=18；
方案二：ADD 1 <W>，COPY 9 0，ADD 6 <X D E A C B> → 4+5+9=18。

追问：基于差分的编码方式，在程序头部插入函数和在程序尾部插入函数，哪个差分升级包占用空间比较大？

点开看参考答案

头部插入更大。因为若在头部插入函数，则在此之后的函数跳转地址都需要做相应修改，所需修改的内容更多，整体程序转化后的二进制文件与源文件的差距可能特别大；而在尾部插入函数可能仅仅是后面与源文件有差距，前面二进制文件都一样，差距不大。（课后习题答案原文）
