LoRaWAN 协议详解

一句话：非授权频段的星形单跳广域网——chirp 调制怎么算符号时间（Ts=2^SF/BW）、OTAA 入网、Class A/B/C 三种设备类型，本章收官。

一、LoRa 与 LoRaWAN：定位与拓扑

  • LoRa 芯片：2013 年 8 月 Semtech 发布，基于 chirp 扩频调制（CSS）、超长距低功耗通信；chirp（扫频信号）分线性与指数两种；CSS 凭更优链路预算，在部分牺牲数据率的基础上达到更远通信距离。
  • 显著特性四条：长距离（相同发射功率下距离更远）；低功耗（发送端仅需 100mW（20dBm）即获 162dB 链路预算）；大连接（低数据率低频次场景下网关接入更多设备）；低成本（工作在公用频段）。
  • 拓扑：LoRaWAN 采用星形拓扑，以网关作为中继，终端采用 LoRa 协议与一个或多个网关单跳通信；工作在小于 1GHz 的非授权频段（如 433MHz、868MHz、915MHz 等）。
  • 技术特点：长距离（数公里到数十公里，适合农业监测、智能城市）；低功耗（电池设备长寿命）；抗干扰（CSS 在频繁干扰环境中保持稳定连接）；低成本（部署成本与基础设施需求低）。

二、物理层：信道与 Chirp 调制

信道分配（CN470~510 频段）：上行 96 个（470.3~489.3）；下行 48 个（500.3~509.7，编号 0~47）。LinkADRReq 的 ChMaskCntl：0→信道 0-15，1→16-31，……6→所有信道开启，7→保留。

Chirp 调制关键参数： BW ：带宽，中国取 125KHz，美国可取 125KHz 和 500KHz SF ：spreading factor，一个 chirp 表示 SF 个 bits，取值 7~12 Ts ：一个 chirp 的发送时间，Ts = 2^SF / BW 数据调制：通过起始频率所在纵轴的 offset 调制（频率偏移等价于时间偏移） 课件案例：SF=8，BW=125KHz，发送数据 [0, 0, 50] → 2^8=256 个起始位置，偏移分别为 0/256Ts、0/256Ts、50/256Ts

扩频调制优势：提升传输并发性——同一信道中，6 个用户选择 6 个不同的 SF（7~12），相互正交，可并发传输。包结构：Preamble（up-chirp 信号）→ 同步字（2 个 up-chirp）→ 帧定界符（2.25 个 down-chirp）→ 数据。

三、入网流程（OTAA）

入网激活两种方式：空中激活 OTAA（需要入网流程，与服务器协商获取设备地址和会话密钥）；个性化激活 ABP（事先将必需的通信信息烧录在设备上）。

阶段参数
入网前JoinEUI（8 字节地址，OTAA 中唯一标识入网服务器）、DevEUI（8 字节地址，唯一标识设备）、NwkKey / AppKey（AES-128 密钥，制造时分配）
入网后DevAddr（4 字节设备地址）、FNwkSIntKey（计算上行数据 MIC）、SNwkSIntKey（计算上行 MIC；检查下行 MIC）、NwkSEncKey（加解密上下行 MAC 指令）、AppSKey（加解密上下行应用数据）

四步握手：① 设备用 AppKey 发送 Join-request（MType=000）：JoinEUI、DevEUI、DevNonce（设备端计数入网请求，每发一次加 1）；② 网关返回 AppKey 加密的 Join-accept（MType=001）：DevAddr、Home_NetID、DLSettings（RX1/RX2 数据率）、RxDelay、CFList（上行信道）、JoinNonce（用于生成四个会话密钥）；③ 设备发送确认 ReKeyId；④ 网关回复 RekeyConf，OTAA 激活完成。MType 表：000 入网请求 / 001 入网许可 / 010 不需要确认的上行 / 011 不需要确认的下行 / 100 需要确认的上行 / 101 需要确认的下行。

教材 PPT 补充：重放攻击防护

网关侧：收到的 Join-request 中 DevNonce 不比上一次收到的大，即认为是重放攻击不予接收；设备侧对称地用 JoinNonce 校验 Join-accept。未收到 Join-accept 时，设备随机退避后重发 Join-request。

发送机制：LoRaWAN 标准中设备发送消息采用纯 ALOHA 机制，用 duty-cycle 限制发送频次：1% duty-cycle 下，设备在某信道发送 10ms，则接下来 990ms 内该信道不能再收发。

四、Class A / B / C（必考对比）

类型定位机制要点
Class A（默认）最低功耗，下行时延最大想发即发；每次上行后开两个接收窗口：RXDelay1/RXDelay2 通常默认上行后 1s 和 2s；RX1 信道/数据率与上行相关，RX2 由网关指定；窗口长度至少能检测到 5 个 symbol（无则休眠，有则接收、解调、地址匹配、一致性校验）；RX1 成功接收则 RX2 不打开；网关下行只能等设备上行后的 RX1/RX2。需要确认的上行未收到 ACK 时重传，传输次数 [1,15]；需要确认的下行由设备立刻回复 ACK（负载为空）或上行捎带 ACK。
Class B减小下行时延在 RX1/RX2 基础上增加beacon 同步 + 定时 ping slot 接收窗口；所有网关同时广播 beacon，设备收最强信号获取时间参考；设备先以 Class A 入网，搜到 beacon 后在上行帧中把 Class B 位置 1 通知网关再切换；2 小时内没有再收到 beacon 则切回 Class A；网关可用 RX1、RX2 和 slot 重传确认下行。
Class C最小下行时延供电状态下除发送数据外始终开启接收窗口（RX2 持续开）；RX1 开启时若网关仍在发送，设备停止当前接收；网关不能频繁发请求确认的下行数据——Time_out 后或收到上行确认才能再发。
教材 PPT 补充：Class B 窗口时隙与 FPending

BEACON_PERIOD 128s、BEACON_RESERVED 2.12s、BEACON_GUARD 3s、BEACON_WINDOW 122.88s；slot 长 30ms，共 4096 个 ping slot。FPending=1 表示网关还有更多下行数据：Class A 设备在下次接收窗口后请求；Class B 设备立即发送空白帧开启 RX1/RX2；Class C 网关想发即发，FPending 不触发设备任何行为。

教材 PPT 补充：帧结构与 MAC 指令（速览）

帧 = MHDR（MType 指明消息类型）+ MACPayload + MIC。FPort=0 时 FRMPayload 存放 MAC 指令（如 LinkADRReq），FPort≠0 存应用层数据；FOpts 不为空时存 MAC 指令，此时 FRMPayload 与 FOpts 不能同时存 MAC 指令。Fctrl 关键位：ADR（数据率/功率自适应）、ADRACKReq、ACK、ClassB、FPending。帧计数：上行 FCntUp，下行 MAC 指令帧 NFCntDown（网络服务器管理）、应用数据帧 AFCntDown（应用服务器管理）；OTAA 设备入网清 0，ABP 不重置。

课件思考题（本课）

网关容量倍数：SX1301（8 通道 8 解调器）采用 ADR 机制后网关容量能提高 232.6%，问 SX1301 的容量是单通道单解调器芯片 SX1276/8 的多少倍？

点开看答案

虽然 LoRa 能同时接收正交的 6 个 SF，但受限于解调器数目，SX1301 最多只能同时解调 8 个用户的数据（而非 48 个）；ADR 机制使网关容量提高 232.6%。因此 SX1301 相较 SX1276/8 的容量 = 8 × 232.6% = 18.6 倍。（课后习题答案第五章第 8 题）

chirp 符号计算：设备发送一字节数据 50，SF=10，BW=125KHz，频-时间图上一个符号的时长和起始位置的偏移为多少？

点开看答案

SF=10 → 一个符号表示 10 个比特，带宽被划分为 2¹⁰=1024 份（起始位置传输数据 [0, 2¹⁰−1]）。符号时长 Ts = 2¹⁰×1000/125000 ms = 8.192ms；频移量 = 50×125/2¹⁰ ≈ 6.1035（kHz 口径）。（课后习题答案第五章第 7 题）

系统容量：LoRaWAN 终端每 10 分钟上报 12 字节，SX1301 LoRaWAN 网关的系统容量至少是多少？

点开看答案

最小帧头帧尾共 13 字节；按最小容量计算，设备均用 SF=12 发送（数据率 250bps）。每个节点所需带宽 = (12+13)×8/600 ≈ 0.33bps；可容纳节点 = 250/0.33×8？——按习题解答原式：250/0.33×8×232.6% ≈ 14096（含 ADR 机制 232.6% 扩展）。（课后习题答案第五章第 9 题，建议按原解答口径复述）
