设备模型与命名机制

一句话：三端集成简化靠两招——设备模型（SmartThings 设备档案 vs IoT Studio 物模型）与命名机制（TCP/IP vs NDN），本章思考题也在本节收口。

本课依据

考试内容以 PPT（课件）为准。本课对应课件《第七章》第 2 节【主要功能：三端应用集成简化】+ 思考题页。原始课件：D:\学习文件\大三上\物联网技术基础与应用开发\第七章.pdf

一、三端应用集成简化：为什么与是什么

现状与问题：很多平台可以提供对三端应用开发的支持，但三端应用的集成还较为复杂，如设备端与云端服务交互的数据格式不统一，导致设备端数据无法被云端服务直接解析。两大简化手段：设备模型 + 命名机制。

手段课件定义
设备模型设备的抽象描述，规定设备与云端数据交互规范；解耦设备开发与云服务开发
命名机制物理设备与虚拟 ID 的映射

传统物联网开发方式：应用开发依赖硬件设备，开发流程无法同步进行。设备模型是设备所能提供功能的描述，是设备开发和应用开发的桥梁——基于设备模型，应用开发与设备开发可完全分离。

基于设备模型的开发流程（以智能灯泡为例，两步）：步骤 1 设备模型定义——包括开、关两个功能（可通过云平台控制）、光照、声音强度两个属性、一个属性上报事件；步骤 2 应用开发——硬件开发人员设计电路、编写设备端代码实现开灯关灯；软件开发人员基于设备模型定义，使用虚拟设备模拟真实设备，开发 Web 应用/移动应用。

设备模型：SmartThings VS IoT Studio（对比必背）
设备档案（三星 SmartThings）物模型（IoT Studio）
描述语言JSONJSON
结构设备 > 组件 > 功能 >（属性，命令）功能划分为"属性、事件、服务"三类
功能来源设备所包含的功能必须是平台已有的（如 switch capability 由官方提供，共 73 种）可用平台提供的标准功能，也可由开发者自行定义

智能灯泡示例要点：SmartThings 用 components/capabilities 声明 switch、soundSensor，属性用 enum 枚举 'on'/'off'，命令 'on'/'off' 的 arguments 为空（注：平台无 Light 相关功能定义）；IoT Studio 用 services（turnOn/turnOff，callType async）、properties（SoundValue，float，0.0–100.0 dB，accessMode r）、events（post，method thing.event.property.post，type info，required true）。

二、命名机制：TCP/IP vs NDN（重点）

物联网场景中，内容检索和命令推送是两个基本功能（如"查询现在的室内光线强度"、"打开客厅的灯"）；命名机制是支持这两种操作的基础——需要通过名字找到对应的数据或设备。

基于 TCP/IP 的命名机制

为设备分配 IP 地址，建立从设备到 IP、再到应用层名称的多层映射关系。问题：①关注于建立设备之间的连接，需要实现复杂的协议栈，通过多层映射建立连接；②当用户需要操作多个设备时，需要和多个设备分别建立连接。例子操作过程：查询映射"卧室光强"→光强计 URI → 连接 AlexHome.com → DNS 查询 IP → DHCP 分配 IP → 建立手机到光强计的连接。

基于 NDN 的命名机制

NDN: Name Data Networking，以数据为中心的网络，与位置无关，直接通过名字获取数据。基于两种数据包通信：兴趣包（Interest）——请求的数据名称或希望执行的操作（作为名称的一部分）；数据包（Data）——回复的数据内容，或对操作执行的 ACK。

  • 分层命名机制：按约定规则对数据对象命名，常见规则 /location/fixture-namespace/command/timestamp，例如 /MyHome/Bedroom/Lighting/sensing/Intense/202112311920；数据高度可聚合——收集所有光强读数：/MyHome/Bedroom/Lighting/sensing/Intense/。
  • 新设备的加入：新设备通过兴趣包告诉配置管理器其设备标识和功能，如 "/local/discovery/lighting/serial=123456"；配置管理器进一步配置其属性（ID、NDN 名称前缀、功能集合等）——ID: "/MyHome/Bedroom/_fixtures/123456"，关联事物："/MyHome/Bedroom/Lighting/TableLamp"，功能集合：".../action/ON"、".../action/OFF"。
  • 简单例子："查询现在的室内光强" → INTREST(/MyHome/Bedroom/Lighting/Intense)，回复 DATA(name|data|signature)；"打开卧室的台灯" → INTREST(/MyHome/Bedroom/Lighting/TableLamp/action/ON)，回复 DATA(name|ACK|signature)。（课件原文即拼作 INTREST。）

课件思考题（本章唯一公开思考题）

简述云-端一体开发平台是如何简化物联网应用开发的。

点开看参考答案

物联网应用的开发分为设备端开发、云服务开发、Web 应用/移动应用开发。针对设备端开发，云-端一体开发平台为开发者提供设备开发 SDK、物联网操作系统等内容，简化设备开发与设备入云流程；针对云服务开发，平台提供 IFTTT 规则配置及流式服务编排等方式，通过可视化配置即可完成云服务的开发；针对 Web 应用/移动应用开发，平台同样提供了可视化的开发方式。另外，在三端应用的集成方面，平台通过物模型、命名机制等，对三端应用的集成进行了简化。（出处：教材课后习题答案第 1 题，与课件思考题一致）
