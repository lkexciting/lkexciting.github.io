一、三大典型安全开发框架（对比表）

框架核心机制（课件原文要点）
AWS IoT
（亚马逊）		支持三种类别身份验证：X.509 证书、IAM 用户/组和角色、Amazon Cognito 身份。通常：Web 应用程序和桌面应用程序使用 IAM 或联合身份；移动应用程序使用 Amazon Cognito 身份；IoT 设备使用 X.509 证书。云侧提供身份验证、IAM（Identity and Access Management）角色与策略配置等；在没有验证身份的情况下，AWS IoT 永远不会在设备和云之间交换数据；开发者可将所选角色或策略映射到每个证书，授予或撤销对设备、应用程序的访问权限
阿里云 Link ID2
（IoT Device ID）		专门用于物联网设备身份认证的系统，通过可信计算和密码技术提供设备安全认证、安全连接、业务数据加密等端到端的可信接入能力。四大安全功能：设备身份认证（唯一身份标识、双向身份认证，防篡改仿冒）、安全连接（兼容 TLS 和 DTLS 的轻量级安全协议 iTLS/iDTLS）、业务数据保护（基于设备可信根派生的密钥支持多种加密算法，防护固件、业务数据、应用授权等敏感数据）、密钥管理（集中管理：密钥生成、密钥销毁、端到端的密钥安全分发）。认证方式两种：基于挑战-应答与基于时间戳；挑战-应答机制由三部分组成：设备端、业务服务端、ID² 认证服务端
百度函谷 HISK基于 GP（Global Platform）国际安全标准，提供覆盖设备端、边缘、云端、移动 App 及各链路安全的体系及服务。分为基础服务和 PKI 证书服务：基础服务从证书和密钥保护的角度解决物联网安全问题，赋予设备唯一身份标识，提供设备身份认证服务和敏感数据安全传输服务；PKI 证书服务可为物联网设备签发数字证书，建立 TLS 双向认证

二、开发案例：温度监控（安全版）

目标：物联网节点在 TEE 中用 DHT11 传感器监控温度，数据经非对称加密（RSA）后通过 MQTT 上传云平台；云平台在 TEE 中解密并打印。硬件平台：树莓派 3B（支持 TrustZone，BCM2837、4 核 ARM Cortex A53 @1.2GHz、1GB RAM）；软件平台：Raspberry Pi OS（REE OS）+ OP-TEE（TEE OS）。

  • 角色分工：发布者（树莓派）侧——REE 中 CA 应用负责 MQTT 发布，TEE 中 TA 应用负责加密采集数据，经 TEE Client API / TEE Internal API 交互；DHT11 驱动以 pseudo TA（PTA）形式存在于安全世界，TA 调用 PTA 的方式与 CA 调用 TA 类似（PTA 也有独一无二 uuid）。
  • CA ↔ TA 接口对应表（课件原表，5 组必背）：TEEC_InitializeContext() ↔ TA_CreateEntryPoint()（构造 TA 并初始化上下文，仅一次）；TEEC_OpenSession() ↔ TA_OpenSessionEntryPoint()（建立会话，连接 REE 和 TEE）；TEEC_InvokeCommand() ↔ TA_InvokeCommandEntryPoint()（CA 调用 TA 命令）；TEEC_CloseSession() ↔ TA_CloseSessionEntryPoint()（关闭会话）；TEEC_CloseSession() ↔ TA_DestroyEntryPoint()（销毁 TA）。TA 用 TEEC_UUID 标识，定义于 RFC4122。
  • 参数类型：TEEC_VALUE_INPUT/OUTPUT/INOUT——整数数据，INPUT 从 REE 传至 TEE、OUTPUT 从 TEE 传至 REE、INOUT 双向；TEEC_MEMREF_TEMP_*/PARTIAL_*——数据分配到共享内存，TEMP 为临时内存引用，PARTIAL 为父共享内存块的分区。一次调用只能传 4 个参数，不传的用 TEEC_NONE。
  • 底层机制：CA 调用 TEEC_InvokeCommand() 后，OP-TEE 底层用 SMC 指令将 CPU 从非安全状态切换到安全状态，进入 TA 的 TA_InvokeCommandEntryPoint 按宏定义（如 CMD_RSA_ENC_PKCS1_OPER，CA 与 TA 头文件中定义一致）调用对应安全函数。RSA 加密：N 和 E 两个数组组成 RSA 公钥，用 TEE_AllocateOperation(TEE_ALG_RSAES_PKCS1_V1_5, TEE_MODE_ENCRYPT, …) + TEE_AsymmetricEncrypt() 完成加密（API 由 GlobalPlatform 组织定义，不同 TEE OS 均暴露统一接口）。
  • 传输与云端：CA 用 mosquitto_pub 把加密数据发布到服务器（ip 192.168.31.160，port 8883），带 --cafile ca.crt --cert clientpub.crt --key clientpub.key（TLS 加密传输）；云平台 CA 用 MQTTClient 订阅（SSL 证书 trustStore/privateKey/keyStore），收到消息触发回调 msgarrvd → 调用 RSA 解密 TA（设 RSA 私钥句柄 + TEE_AsymmetricDecrypt 类 API）打印解密数据。每 3 秒采样一次。

三、学术研究前沿（四项，记名字 + 一句话）

方向课件内容
1. 基于 TEE 的端设备安全dTEE：A Declarative Approach to Secure IoT Applications Using TrustZone（基于 TrustZone 的声明式安全物联网应用方法）
2. 基于 WebAssembly 的端设备安全隔离Bring WebAssembly to Resource-constrained IoT Devices、MiTEE
3. 去中心化设备接入认证与全生命周期安全2019：CHIP（connected home over IP），Google、Apple 与 ZigBee 联盟；2021-5：CHIP → Matter，ZigBee 联盟 → CSA（connectivity standards alliance）；2022-10：CSA 正式发布 Matter 1.0 标准。（各版本具体安全机制课件未展开）
4. 智能语音系统安全：海豚音攻击DolphinAttack: Inaudible Voice Commands，CCS 2017（Best Paper Award）。原理：利用人耳听不到的超声波频段（>20kHz 可听上限）注入攻击指令；超声波信号之所以能生效，一是滤波器非完美滤波特性——过渡带内的信号不会被滤掉；二是经 AM（幅度调制）调制的基带信号会经麦克风和放大器的非线性作用还原出来。器件非线性：麦克风、放大器及滤波器等是输入/输出传输特性中具有平方及多次项非线性的组件，线性分量输出同频信号，非线性会产生谐波和叉积、带来新的频率，通过精心设计的输入信号可利用这些新频率恢复出基带信号（攻击指令）。涉及 MEMS 麦克风频率响应（100–10kHz 与 >15kHz）。

课件思考题（本课相关）

1. AWS IoT 设备如何进行身份认证？

点开看参考答案

AWS IoT 在所有连接点处提供相互身份验证和加密。AWS IoT 支持 AWS 身份验证方法（称为 "SigV4"）以及基于身份验证的 X.509 证书。使用 AWS IoT 生成的证书以及由首选证书颁发机构（CA）签署的证书，将所选的角色和/或策略映射到每个证书，以便授予设备或应用程序访问权限，或撤消访问权限。（教材课后习题答案第 7 题原解；课件另指出通常 IoT 设备使用 X.509 证书，移动应用程序使用 Amazon Cognito 身份）

2. 简述 Link ID2 在安全方面的优势。

点开看参考答案

设备身份认证：为每个 IoT 设备提供唯一的身份标识，基于 Link ID2 提供双向身份认证服务，防止设备被篡改或仿冒。安全连接：提供兼容 TLS 和 DTLS 的轻量级安全协议 iTLS/iDTLS，更适合物联网设备，在保障安全性的同时大幅减少 IoT 设备的资源消耗。业务数据保护：基于设备可信根派生的密钥支持多种加密算法，为设备固件、业务数据、应用授权等敏感数据提供安全防护。密钥管理：为 IoT 系统中的设备、应用、业务所使用的密钥提供集中管理，包括密钥生成、密钥销毁、端到端的密钥安全分发。（教材课后习题答案第 8 题原解）

3. 以百度函谷物联系统为例，说明如何从证书和密钥保护角度解决物联网安全问题。

点开看参考答案

函谷物联安全系统 HISK 基于 GP（Global Platform）国际安全标准。通过保护证书和密钥并提供统一的安全接口服务的方式来为上层应用提供安全能力，并赋予设备唯一身份标识，提供设备身份认证服务和敏感数据安全传输服务，进而实现端云一体的安全保障；其 PKI 证书服务还可为物联网设备签发数字证书，建立 TLS 双向认证。（教材课后习题答案第 9 题原解 + 课件原文）
