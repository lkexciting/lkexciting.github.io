BLE 协议架构与链路层

一、组网场景：piconet 星型网络

  • BLE 设备构成星型网络（piconet）：一个 master，多个 slave；master 负责整个 piconet 的通信协调，slave 只能和 master 通信；一个 piconet 中每个 slave 使用不同的通信信道。
  • 一个 BLE 设备可以同时为一个 piconet 的 slave，同时为另一个 piconet 的 slave 或 master。

二、物理层协议

2.1 信道分配与跳频

从 2.4GHz 到 2.480GHz，每个信道 2MHz，总共 40 个信道（0~39）；37、38、39 为广播信道，其他为数据传输信道。为减少数据传输阶段的干扰使用跳频：

  • 基础信道跳频：每一对 master 和 slave 以同一种伪随机序列的方式切换信道；下一次跳频的信道由 gMap、c 和 hop 决定。
  • 自适应跳频：master 和 slave 维护信道质量数组 ChM；gMap 根据 ChM 对每个信道的标记情况更新可用信道。

2.2 GFSK 调制

BLE 调制方式：GFSK（高斯频移键控）——先对原始数据做高斯滤波再进行 FSK 调制；作用：降低不同频率调制之间的干扰（频谱图上 GFSK 旁瓣能量明显小于 FSK）。

2.3 物理帧结构

字段说明
Preamble0、1 交替，首位 bit 与 Access Address 的首位 bit 相同；1Mbps 模式下 8 位 10101010
Access Address（AA）广播包：固定值 0x8E89BED6；数据包：连接建立过程中确定，每一对链路唯一
PDU广播包：最多 37 字节、最少 6 字节；数据包：最多 257 字节、最少 2 字节

三、链路层协议（工作流程，重点）

  • 数据校验：CRC；BLE 的 CRC 生成多项式为 x²⁴+x¹⁰+x⁹+x⁶+x⁴+x³+x¹+x⁰。
  • 数据白化：二进制数据与伪随机序列异或；BLE 用 7bit 长的随机序列。
  • 链路层状态机五状态：扫描 Scanning（对广播信道 37、38、39 轮流扫描）、待机 Standby（可向其他状态切换的中间状态）、广播 Advertising（纯广播或可被连接）、发起 Initiating（监听指定 device 信道，等待发送连接反馈）、连接 Connection（从广播或初始化状态通过发送 CONNECT_REQ 切换）。

3.1 广播包类型与连接建立

PDU type含义与配对
ADV_IND可连接 ↔ CONNECT_REQ（连接请求）
ADV_DIRECT_IND定向可连接 ↔ CONNECT_REQ
ADV_SCAN_IND可扫描 ↔ SCAN_REQ（扫描请求）/ SCAN_RSP（扫描反馈）
ADV_NONCONN_IND不可连接

Header 还含 TxAdd/RxAdd（发送/接收方地址类型：0→厂商分配的静态地址，1→自己生成的随机地址）与 RFU（保留位）。

邻居发现：连接前先扫描发现潜在可连接设备（如设备 A 在扫描信道 38 时发现设备 B，向 B 发送扫描反馈数据包），随后进入连接建立。连接建立：master 发送 CONNECT_REQ → 1.25ms + WinOffset 后向该 slave 发送初始连接事件同步数据包。失败判定两条：slave 没有在 WinSize 时间窗口内收到 master 的初始连接事件数据包；或 master 没有在 Timeout 时延内收到 slave 的反馈。

CONNECT_REQ 结构：initA（发起者地址）、AdvA（接收方地址）、LLData——AA（连接后链路的唯一标记）、WinSize/WinOffset（处理多连接的缓冲时间）、Interval（连接事件间隔）、Latency（slave 隔多少个连接事件再反馈 master）、Timeout（等待反馈的延迟）、ChM（40 bits，每 bit 对应一个信道，与 gMap 对应）、Hop（随机跳频的增量因子）。

3.2 数据信道包与连接事件

Header 关键字段：LLID（数据包或控制包）、NESN（下一个期望的包序号，停等协议，序号 0/1）、SN（包序号，停等协议）、MD（more data，是否还有后续数据包）；另有 MIC（完整性校验）。

  • Connection Interval：7.5ms 到 4s 之间，1.25ms 的倍数；master 发起每次通信事件，slave 反馈。
  • 即使没有实际数据，也周期性发送/反馈空数据包；slave 可设定 latency 节约能量；有 Supervision Timeout（监督超时）；slave 在一个连接事件间隔内可连续发送多个数据包；通信完成立刻进入休眠。
  • 多连接维持：master 采用 TDMA（时分复用）调度；master 和 slave 跳频以 0.625ms 的 slot 为单位同步；master 一个连接事件间隔内处理完所有 slave 通信并执行扫描；piconet 中 slave 越多，连接事件间隔越长；transmitWindowSize（1.25ms 倍数，≤ Interval）、transmitWindowOffset（错开多连接，< Interval）。

四、L2CAP 与 ATT/GATT

4.1 L2CAP：数据包分割和重组

帧格式：Length（数据帧长度）、Channel ID（唯一标识当前通信链路）、L2CAP SDU length（重组后总长度；每个子数据帧最大 251 字节）。课件示例：发送 90 字节数据，CID 为 0x4b，每个子数据帧最大 44 字节（含包头，master/slave 协商达成）；子数据帧没有偏移编号，因为 BLE 使用停等协议。

4.2 ATT 与 GATT

  • ATT（Attribute Protocol）：提供对服务的检索功能；GATT（Generic Attribute Profile）：定义了服务存储的数据结构。
  • 层级：Profile（slave 提供的一系列服务的组合）→ 服务（一系列具体功能的集合，如 SIG 定义的 Battery 0x180F、Heart Rate 0x180D）→ 特征（提供的功能）。
  • 四个属性字段：Handler（句柄，唯一确定，区分不同服务或特征）、UUID（服务/特征标志，可用系统默认或自定义）、Value（对应的值）、Permission（可读、可写等）。每个服务以 UUID=0x2800 表示开始和结束，服务中的 value 包含其特征的 UUID 和 handler。ATT 协议定义了如何解析 GATT 数据结构中的数据。
教材 PPT 补充：SMP

SMP（安全管理协议）负责 BLE 的密钥生成与分发（协议栈顶层）。

课件思考题（本课）

简答题：简述 GFSK 和 FSK 的异同。

点开看答案

GFSK（高斯频移键控）是在调制之前通过一个高斯低通滤波器限制信号的频谱宽度：先对原始数据进行高斯滤波处理，再进行传统 FSK 调制。与 FSK 相比，GFSK 调制信号在非调制信号频率上的能量更少，降低了对其他频率信号的干扰；但不同二进制数据之间的差别更加平滑，使得数据的误解调率提高了。（课后习题答案第四章第 8 题）
