硬件安全机制

一句话：熔断、看门狗、PUF、RoT、Secure Boot、TEE 六大硬件防护——名字 + 原理 + 代表实现，是本章名词解释高发区。

考试内容以 PPT（课件）为准。本课对应课件《第八章-v2(2)》第 2 节"安全机制1：硬件安全机制"【教材 PPT 补充单独标注】。原始课件：第八章-v2(2).pdf

一、熔断机制与看门狗

熔断机制

在 MCU/CPU 等芯片特定引脚外加高电平，电流烧断内部熔丝，使芯片里的程序变为不可读写、只能运行。一般依托芯片内一次性可编程区域（OTP, One-Time Programmable）或 EFUSE。典型实现：ARM Cortex-M 的 FLASH_OPTR.RDP（Read Protection）、ESP32 的 eFuse 模块；STM32 提供三级保护：RDP Level 0（无保护）、Level 1（调试接口锁定）、Level 2（完全不可调试、不可擦除）。

看门狗 / Watchdog Timer

本质是一个电子或软件计时器：系统正常运行时定期重置（喂狗）；若硬件故障或程序错误导致无法重置，达到超时条件时系统重启。分两类：硬件看门狗（HW WDT）由独立时钟驱动，CPU 故障时仍可工作；软件看门狗（SW WDT）由操作系统定期喂狗（如 Zephyr 的 wdt_feed() API）。课件 Zephyr 示例：超时 3 秒（.window = { .max = 3000 }，WDT_FLAG_RESET_SOC 超时自动重启），循环里每 1000ms 喂一次狗。

课件重要结论

熔断机制近年渐渐退出历史舞台——因为测试分析仪器设备的更新换代，使芯片暴力破解的成本越来越低。

二、PUF 与信任根 RoT（易混对比，必考）

物理非克隆函数 PUF信任根 RoT
是什么晶圆制造过程中，芯片等器件内创建的具有独特物理性质的模块，为半导体器件提供唯一身份标识——相当于每个 IC 的"指纹"或数字身份证明建立信任链的来源，SoC 中的安全根基，所有后续组件的可信性都依赖于可信根的初始可信状态
核心特性不可复制性：即使相同工艺和材料重新创建相同 IC，生成的 PUF 也不同；PUF 密钥在系统启动时重新生成，不存储在闪存——天然安全优势常见例子是硬件安全模块（HSM, hardware security module）

三、安全启动 Secure Boot（信任链四层）

Secure Boot 用于在设备启动阶段确保执行代码的完整性与可信性。流程必背：

Root Key（信任根 RoT） → 存储在芯片安全区域（OTP、eFuse 或 HSM），整个信任链的起点 1st Bootloader（一级引导程序） → 存于受保护的只读存储区（ROM），上电后最先执行 → 用 Root Key 验证 2nd Bootloader 的【数字签名】，合法后解密并加载 2nd Bootloader（二级引导程序） → 验证通过后运行，进一步验证【应用镜像（Boot Image）】的签名与完整性 Boot Image（系统固件） → 只有通过层层签名验证的镜像才能被执行，确保启动到运行全链可信

四、可信执行环境 TEE（本章案例开发的基础）

ARM TrustZone 将 SoC 的硬件和软件资源划分为安全世界和非安全世界：需要保密的操作（指纹识别、密码处理等）放在安全世界执行，其他在非安全世界执行。应用流程由 CA 发起，CA 调用 TA，切换为安全世界执行 TA 程序；TA 处理完成后切回非安全世界，通过共享内存把结果返回给 CA。

软件接口遵循 GlobalPlatform（GP）标准，核心组件表（必背）：

组件所在环境作用
Client Application（CA）REEREE 中的应用程序（如支付 APP、指纹识别 APP），发起对 TEE 的安全请求
Trusted Application（TA）TEETEE 中的可信应用，执行具体敏感操作（如密钥生成、指纹比对）
TEE Client APIREEREE 侧接口库，提供 CA 调用 TEE 的函数（连接 TA、传递参数、获取结果）
TEE Internal APITEETEE 侧接口库，提供 TA 与 TEE 系统交互能力（内存管理、加密服务）
TEE ManagerTEETEE 核心管理组件：TA 的加载、生命周期管理、CA 与 TA 的通信路由

TEE 与 REE 交互流程（课件以"手机指纹解锁"为例，五步）：① 发起请求：REE 中指纹解锁 APP（CA）经 TEE Client API 发请求；② 权限校验：TEE Manager 验证 CA 合法性（如签名校验）；③ 安全执行：TEE 加载启动 TA，TA 用 TEE 内部加密算法与安全存储（预存指纹模板）在隔离环境完成指纹采集与比对；④ 结果返回：TA 将比对结果经 TEE Manager 传给 CA，同时销毁临时敏感数据（原始指纹图像）；⑤ 操作完成：CA 据结果执行后续逻辑（解锁屏幕），敏感数据始终不暴露在 REE 中。

教材 PPT 补充

TEE 芯片厂商：国外有高通、三星、LG，国内有展讯、联发科、威盛电子、华为海思等；开源 TEE OS 主要为 OP-TEE（面向移动设备）和 TF-M（面向低端物联网设备）；各家 TEE 内部实现不同，但都提供 GlobalPlatform 规范规定的 API，对开发者接口统一。

课件思考题（本课相关）

1. 简述导致物联网设备出现硬件安全的原因。

点开看参考答案

物联网设备拥有大量传感器和控制器，采集的物联网数据会通过硬件的方式被恶意篡改，而硬件防护难以实施：一方面，不同企业根据产品需求和特性进行定制化的裁剪和开发，造成物联网设备与系统间巨大差异性，硬件安全防护方案很难直接移植至物联网中；另一方面，物联网中大量采用的开源组件或项目缺乏安全防护，却没有有效的对应策略或措施。因此物联网设备的硬件安全问题越来越难以解决。（教材课后习题答案第 1 题原解）

2. 物理非克隆函数是什么？为什么建立物理非克隆函数？它与信任根的区别是什么？

点开看参考答案

是什么：PUF 是在晶圆制造过程中于芯片内创建的具有独特物理性质的模块，为半导体器件提供唯一的身份标识；具有不可复制性——即使使用相同工艺和材料重新创建相同的 IC，生成的 PUF 也不同，因此非常安全并具有防篡改能力。

为什么建立：为物联网设备提供保护，通常 PUF 密钥作为主密钥，对会话密钥、应用口令等进行加密处理，保证数据安全。

与信任根的区别：两者都用于对数据加密、确保设备安全。区别在于：PUF 使用半导体器件的"指纹"作为密钥进行数据加密，信任根使用硬件安全模块来生成密钥；且 PUF 生成的密钥在系统启动时重新生成、不存储在闪存中，而信任根在硬件安全模块中生成密钥，该模块无法在计算机生态系统之外访问。（教材课后习题答案第 3 题原解）
