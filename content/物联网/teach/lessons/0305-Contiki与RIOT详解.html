Contiki 与 RIOT 详解

一、Contiki OS

1.1 简介与发展历程

Contiki OS 是一款开源、高度便携、多任务的操作系统，适用于资源有限的无线传感器网络，专为具有少量内存的微控制器（MCU）而设计。

时间事件
2002瑞典计算机科学研究所的 Adam Dunkels 等人提出最早的 Contiki OS
2004Contiki OS 2.0 诞生，加入网络模拟器 Cooja 和轻量级网络通信元语协议栈 Rime
2011加入丰富网络协议：基于 IPv6 的路由协议 Contiki RPL、低功耗 MAC 协议 Contiki MAC
2012 起瑞典公司 Thingsquare 接受并维护 Contiki OS 项目
2015 年 8 月Contiki OS 3.0 发布

1.2 关键特性表（课件原表）

特性描述
编程模型基于 protothreads 的编程模型，支持多线程编程风格；提供以多堆栈实现的多线程库 mt_thread
任务调度基于优先级的事件驱动、protothreads 调度、基于 mt_thread 的调度
内存分配静态内存分配和动态分配两种机制
软件更新基于模块化的软件更新方式
网络服务路由协议 Contiki RPL、轻量级网络层协议 uIP、IPv6 地址压缩协议 6LowPAN 等
AI 支持官方不支持，开发者自行适配后可使用 TensorFlowLite
其他提供基于 shell 的交互式编程接口

1.3 protothreads（必考）

主要特点三条：基于协作式的调度模式、使用单个堆栈实现、不能使用局部变量（跨阻塞点）。由瑞士计算机学院的 Adam Dunkels 等人于 2006 年提出。五个核心宏：

PROCESS(name, strname); // 所有 Contiki 程序必须以宏 PROCESS() 开头 AUTOSTART_PROCESSES(&name); // 程序启动时自动执行当前进程 PROCESS_THREAD(name, ev, data) { // 定义 protothread 的实现 static struct etimer wtimer; // 变量初始化（须在 BEGIN 之前） PROCESS_BEGIN(); // 必须在初始化的变量之后调用 etimer_set(&wtimer, CLOCK_CONF_SECOND); /* 1s */ while (1) { PROCESS_WAIT_EVENT_UNTIL(etimer_expired(wtimer)); // 未到期: Yield printf("Hello one.\n"); etimer_reset(&wtimer); } PROCESS_END(); // 表示当前线程终止 }

课件例子：两个 protothreads 分别每 1s、2s 输出 Hello one / Hello two，输出序列 Hello one. Hello one. Hello two. Hello one. Hello one. Hello two…

实现机理：宏展开后是一个 switch(process_pt->lc) 状态机——未到期时执行 case 0 / case 9、返回 1（yield）；到期时跳到 case 9 执行 printf。这就是"单堆栈、不能使用局部变量"的根源。

mt_thread 多线程库：protothreads 基于单个堆栈，mt_thread 基于多个堆栈；mt_thread 支持协作式调度（主动 yield）和抢占式调度（系统负责抢占）。主要 API：mt_init() 初始化库、mt_start(thread, function, data) 启动线程、mt_exit() 退出、mt_exec(thread) 执行、mt_stop(thread) 终止。

1.4 网络服务（必考表格）

提供服务协议内容
精简的 TCP/IP 协议栈uIPTCP、UDP、ICMP、IP；将 TCP/IP 协议栈精简为必须的最小的功能集合，减少内存占用
IPv6 层的适配层服务6LowPAN数据包的分割重组、IPv6 包头压缩和 UDP 包头压缩
数据分发和收集服务RPL针对低功耗有损网络设计的 IPv6 距离矢量路由协议

RPL vs CTP（课件原文）：CTP 仅提供了多对一的通信模式；RPL 支持多种网络通信模式——一对多（数据分发）、多对一（数据收集）和一对一（点对点）。

1.5 基于 shell 的交互式编程

sky-shell 样例默认提供多种交互式命令，可登录节点执行传感数据采集（sense）、改变发送能量（txpower）、改变通信信道（rfchannel）等操作（例：sense 输出 Light 1 4 / Temperature 23.2 / Relative humidity 79 / RSSI 8 / Voltage 2.50）。支持自定义命令：如 echoT 命令用 shell_register_command() 注册、SHELL_COMMAND() 定义、在 PROCESS_THREAD 里用 shell_output() 把参数字符串输出两次。

二、RIOT

2.1 简介与特点

RIOT 是一个专门面向物联网场景的实时多线程操作系统，基于微内核实现——所有系统服务（时钟、网络协议栈、网络服务等）都通过创建独立的线程来实现。最初由柏林自由大学开发维护；2008 年启动开源社区，现已发展成拥有 293 个贡献者的社区；支持 67 种处理器型号和 237 款开发板。

开发者友好

开发流程接近传统软件开发；支持 C/C++，兼容 gcc、gdb，可在 Linux/Windows/MacOS 编译；应用开发大多与硬件无关，代码无须修改即可跨开发板运行。

资源占用低

微内核 + 模块化裁剪；每个线程占用资源极少（通常少于 25 字节）。

网络支持好

支持大量传输层、网络层、链路层协议；提供 Shell、加密原语等工具。

2.2 关键特性表（课件原表）

特性描述
编程模型原生支持多线程编程，大量系统服务基于多线程实现；模块化设计可裁剪
任务调度支持基于优先级的线程调度，可按线程分配优先级满足实时性
内存分配支持动态分配
软件更新支持模块化软件更新
网络服务完善网络协议栈：向下支持大量无线通信协议，向上支持 TCP、UDP 等
AI 支持官方支持，兼容 TensorFlow Lite 库
其他SAUL：统一接口读写传感器和执行器

2.3 多线程编程（代码填空高发）

uint8_t thread_stack[1024]; // 栈内存 int main(void){ kernel_pid_t pid = thread_create( thread_stack, // 栈内存 1024, // 栈内存大小 8, // 优先级(0-15)，值越高优先级越低 THREAD_CREATE_STACKTEST,// flag 字段 thread_func, // 线程函数 NULL, // 输入至函数的参数 "thread name"); // 线程名 } Flag 三选一： THREAD_CREATE_SLEEPING 创建后立刻进入休眠状态 THREAD_CREATE_WOUT_YIELD 创建后可能不会立即执行，等待系统调度 THREAD_CREATE_STACKTEST 创建后将立即执行并测试内存占用量

2.4 模块化系统设计与 GNRC 协议栈

模块在代码目录中表现为文件夹；几乎所有的硬件设备同样被抽象成模块（CPU、外设等）——移植到新开发板时仅需开发相应的 CPU 模块。用法：USEMODULE += dht（温湿度传感器）、USEMODULE += xtimer（计时器）。

GNRC（Generic network stack）：最底层的 gnrc_netdev 是对下层各类网络协议的抽象——通过该层抽象，GNRC 可以兼容大量链路层协议而无需修改代码；GNRC 完全实现了 6LowPAN 协议，向上提供 IPv6、UDP、TCP 支持；应用层可用 socket API 访问。GNRC 基于 RIOT 多线程机制：每一层分配一个独立线程，底层协议线程优先级普遍高于高层——MAC 层线程优先级最高、应用层最低。

课件思考题 3（前四问）与课后习题（本课相关）

问 1：Contiki OS 的 protothreads 跟传统的多线程有什么区别？

点开看参考答案

protothreads 基于协作式调度模式、使用单个堆栈实现、不能使用局部变量（课件原文三大特点）；传统多线程每个线程有独立堆栈，可被抢占。Contiki 若需要多堆栈、支持抢占，可改用 mt_thread 多线程库。

问 2：Contiki OS 中的 RPL 协议与 CTP 协议有什么区别？

点开看参考答案

课件：CTP 仅提供多对一通信模式；RPL 支持一对多（数据分发）、多对一（数据收集）和一对一（点对点）。课后习题答案补充细节：RPL 不仅提供多对一通信的接口 dao_output，还提供一对多的通信接口 dio_output；且 dao_output 指定的目的地址不仅可以是汇聚节点，还可以是网络中其他节点（即点对点模式）。

问 3：RIOT GNRC 中哪一层实现了对下层各类网络协议的抽象，使 GNRC 可兼容大量链路层协议而无需修改代码？

点开看参考答案

最底层的 gnrc_netdev 层（课件原文）。

问 4：RIOT 中一个外围设备对应 SAUL 中哪个数据结构？传感器数据和控制执行器的参数存在哪个数据结构中？

点开看参考答案

外围设备对应 saul_reg_t 结构（内含 saul_driver_t 驱动，以链表存储）；数据存在统一的 phydat_t 类型中（课件原文）。
