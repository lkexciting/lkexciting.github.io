IFTTT 与规则引擎：冲突检测与解耦

一句话：这节讲用 If-Then 表达物联网联动逻辑，重点掌握规则冲突的两个判定条件与 SAT/SMT 求解思路，以及规则引擎如何解耦。

本课依据

考试内容以 PPT（课件）为准。本课对应课件《第六章-2026》6.2 主要功能之"IFTTT 与规则引擎"节【教材 PPT 补充单独标注】。原始课件：D:\学习文件\大三上\物联网技术基础与应用开发\第六章-2026.pdf

一、IFTTT 定义、特点与四大问题

IFTTT: If This Then That——一种简单的基于条件语句的程序逻辑。课件两例：IF soil_moisture <= threshold THEN start irrigation；IF temp >= threshold1 && humidity <= threshold2 THEN start alert。

特点（三条）：可用简单条件语句表达多种应用逻辑；一般在云端执行，可以解耦设备端代码和应用逻辑；支持多设备联动。

四大问题（必背）：规则冲突、实时性 vs 能耗、公平性问题、应用逻辑与执行操作的耦合性。

二、规则冲突判定（两个条件 + SAT/SMT）

规则冲突的两个条件（课件原文）： ① IF 条件能够同时成立 ② THEN 控制同一设备，且动作冲突 课件四组判断（.light 同一盏灯）： 组1：light>10000lux→turnOff 与 light<500lux→turnOn → 条件不能同时成立，无冲突 组2：light>10000lux→turnOff 与 light<20000lux→turnOn → light∈(10000,20000) 可同时成立且动作相反 → 冲突 组3：light>10000lux→turnOff 与 light<20000lux→turnOff → 同一设备但动作相同 → 无冲突 组4：light>10000lux→turnOff 与 time∈[19:00,24:00]→turnOn → 条件可同时成立且动作冲突 → 冲突

条件判定转为可满足性问题：引入 xᵢ 表示第 i 个条件是否成立，判断如 x₁ && (x₂ || x₃) 是否可为 1（候选 (1,1,1)、(1,1,0)、(1,0,1)），再检查同一传感器的约束——cond1 与 cond3 或 !cond3 是否有交集，排除不可能的赋值后再判断冲突。课件实例：R1 temp>30→fan=ON 与 R2 temp>=28→fan=OFF，共享条件可同时成立（取 temp=31），动作相反、同一风机 → 冲突。

名词解释（课件原文）

SAT（布尔可满足性）：给定布尔表达式，是否存在一组变量赋值使结果为真。SMT（可满足性模理论）：SAT 的推广，涉及非布尔变量，例如实数、整数、数组等。Z3：微软研究院开发的优秀 SMT Solver，能检查表达式的可满足性。

三、实时性 vs 能耗、公平性

查询频率高 → 实时性高但能耗过大；查询频率低 → 能耗小但实时性低（如关窗响应不及时可能导致雨水淋进房间）。解决方法：自适应调整查询间隔——传感数据可预测接近阈值时缩小查询间隔，反之扩大。增强的 IFTTT 语法：

IF humidity > 75% and light < 1000lux THEN window.close WITH time < 60 and missratio < 0.01 （出处：Heo 等，RT-IFTTT，IEEE RTSS 2017）

公平性问题：某应用设置多条规则或单条规则执行频率过高，可能导致其余规则无法及时执行；解决方法：通过优先级、配额与公平调度约束执行频率。耦合性问题：用规则引擎解决。

四、规则引擎与控灯案例

规则引擎解耦应用逻辑与执行操作：规则引擎筛选消息，其他服务执行操作。按 Topic 与条件筛选提取目标消息，转发给云服务——时序数据库（存储）、函数计算（处理）、推送服务（通知用户）、机器学习服务（预测）。输入是消息对象而非裸数值：先校验字段与类型（如 temp 需为 number 且 −40≤t≤125），字段、单位与质量检查在业务阈值之前完成。

案例：智能手机控制智能灯泡：① 手机 App 获取灯泡 deviceName，经 MQTT 向 Topic1 发布消息；② 规则引擎配置规则从 Topic1（/pk1/controlApp/update/）筛选消息，转发到 Topic2（/pk2/bulb/get）；③ 灯泡订阅 Topic2，接收消息修改状态。

边界推演（有效范围 −40～125℃，端点包含；>30℃ 产生过热告警）： 输入 −40 → 范围校验通过，不过热 输入 30 → 通过，不过热（30 不严格大于 30） 输入 30.1 → 通过，过热 输入 125 → 通过，过热 输入 126 → 不通过，不判断 先确定闭区间端点；再区分 > 与 ≥；缺失值不作正常值处理。

Topic 为什么要分成两个（必背三条）：① 安全：限制物联网设备订阅特定 Topic，避免设备被攻击后获取敏感信息；② 降低耦合：不同 Topic 隔离不同设备，不同命令发至不同 Topic，管理更方便；③ 可扩展性：控制端不必为新设备发送格式不同的命令，由规则引擎变更消息格式并转发到目标 Topic。排查消息链路时用 event_id 贯穿输入、节点日志与告警结果，区分未到达、被过滤与输出失败。

课件思考题（本课相关）

思考题（教材 PPT 第 59 页）：以下两条规则有无冲突？IF (time∈[07:00,17:00]) || (light>10000lux) THEN light.turnOff；IF (light<1000lux) || (sound>55dB) THEN light.turnOn。

点开看参考答案

（教材 PPT 第 59 页原解）有冲突。反例：IF light = 999lux at 07:01 —— 此时 07:01∈[07:00,17:00] 使第一条规则触发（turnOff），同时 light=999lux<1000lux 使第二条规则触发（turnOn），两条件同时成立、同一盏灯、动作相反 → 冲突。

思考（课件 53–54 页四组）：逐组判断有没有冲突。

点开看参考答案

按"IF 条件能同时成立 + THEN 同一设备且动作冲突"两个条件：
① light>10000→Off 与 light<500→On：条件区间不相交，无冲突；
② light>10000→Off 与 light<20000→On：light∈(10000,20000) 可同时成立、动作相反，有冲突；
③ light>10000→Off 与 light<20000→Off：条件可同时成立但动作相同，无冲突；
④ light>10000→Off 与 time∈[19:00,24:00]→On：晚上 19 点后若强光仍大于 10000lux，两条件同时成立、动作相反，有冲突。
