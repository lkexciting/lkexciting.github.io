IoT Studio 物模型与服务编排

一句话：阿里云平台的两把刀——物模型（属性/事件/服务三类 + JSON 定义 + Topic 使用）与流式服务编排（节点拖拽 + 钉钉告警案例），空气盒子物模型思考题在本节落地。

本课依据

考试内容以 PPT（课件）为准。本课对应课件《第七章》第 3 节【典型平台：IoT Studio（物模型 + 服务编排）】。原始课件：D:\学习文件\大三上\物联网技术基础与应用开发\第七章.pdf

一、IoT Studio 概况与四大工作台

发展史（时间线必背）：2018 年 3 月阿里巴巴宣布进军物联网领域，推出 Link Develop 1.0，涵盖物联网应用全链路开发流程；2018 年 6 月推出 Link Develop 2.0；2019 年 1 月 Link Develop 正式更名为 IoT Studio；2021 年 3 月发布 IoT Studio 3.0，提供 Web 可视化开发、移动可视化开发、业务逻辑开发与物联网数据分析等工具。

  • Bone 框架：阿里巴巴推出的 Web 应用/移动应用开发框架，集成常用的物联网应用 UI 组件。
  • IoT 应用市场：包含从硬件到解决方案一系列产品，开发者可将自己开发的产品放到应用市场，实现在线商业化。
  • 关键特性：设备开发——基于物模型的设备抽象；服务开发——支持流式服务编排，可与应用无缝集成。
工作台要点（课件原文）
设备开发工作台用于设备端应用的代码编写、应用调试；提供嵌入式 C 开发、嵌入式 JavaScript 开发、基于 AliOS Things 的开发以及基于 SDK 的开发等；同时支持本地编译、云端编译及基于解释型语言的开发
业务逻辑开发工作台用于云端服务的开发，支持可视化的服务编排（界面含：服务管理、节点、编辑区、节点配置区）
Web 应用开发工作台基于可视化拖拽的 Web 应用开发；基于 Bone 框架的 Web 应用开发
移动应用开发工作台基于可视化拖拽的移动应用开发；基于 Bone 框架的移动应用开发

二、物模型：属性、事件、服务（全章最重考点）

物模型由设备开发者和服务开发者共同定义，使用 JSON 语言描述一类设备所具有的功能，将设备功能划分为三类：

功能类型功能说明举例
属性（Property）设备运行时的状态环境监测设备测量的温度、湿度等环境数据
服务（Service）设备可被外部调用的方法设备向外部提供的打开风扇方法，分为同步调用服务和异步调用服务
事件（Event）设备运行时的事件，包含需要被外部感知和处理的通知信息任务完成的信息、设备发生故障的信息

物模型定义骨架：schema（物的 TSL 描述 schema，由云平台自动生成）、link（云端系统级 uri，用来调用服务/订阅事件，由云平台自动生成）、profile（含 productKey）、properties / events / services 三个数组。

  • 属性字段：identifier（产品下唯一）、name、accessMode（只读 r / 读写 rw）、required、dataType——type 可为 int、float、double、text、bool、array（支持 int/double/float/text）；specs 含 min/max（int、float、double 特有）、unit、unitName、size（数组特有，默认最大 128）、item（数组元素类型）。
  • 事件字段：identifier、name、desc、type（info、alert、error 三种）、required、outputData（输出参数数组）、method（事件对应的方法名称，根据 identifier 生成）。
  • 服务字段：identifier、name、desc、required、callType（sync 同步调用 / async 异步调用）、inputData、outputData、method（根据 identifier 生成）。
  • 同步调用：MQTT 协议提供基于 PUB/SUB 的异步通信，不适用于服务端同步控制设备端返回结果的场景；RRPC：基于 MQTT 协议定制的请求和响应的同步机制。

智能空调示例：属性 temp（float，-40～50，单位℃，step 0.1，accessMode "r"）；事件 TemperatureAlarm（输出 AlarmType 为 enum：0 恢复正常、1 高温报警（温度>30℃），type "alert"，method thing.event.TemperatureAlarm.post）；服务 open（返回 bool：0 失败 / 1 成功，无入参，callType "sync"，method thing.service.open）。

物模型的使用（三个 Topic + 数据格式，必背）：

属性上报 Topic：/sys/{ProductKey}/{deviceName}/thing/event/property/post 数据格式：{ "id":"123", "version":"1.0", "params":{"temp":30}, "method":"thing.event.property.post" } 事件上报 Topic：/sys/{ProductKey}/{deviceName}/thing/event/{dsl.event.identifer}/post 数据格式：{ "id":"123", "version":"1.0", "params":{"AlarmType":0}, "method":"thing.event.TemperatureAlarm.post" } 服务调用 Topic：/sys/{ProductKey}/{deviceName}/thing/service/{dsl.service.identifer} 数据格式：{ "id":"123", "version":"1.0", "params":{}, "method":"thing.service.open" }

三、服务编排：节点类型与钉钉告警案例

业务逻辑：IoT Studio 提供物联网业务逻辑的开发工具，支持通过编排服务节点的方式快速完成简单的物联网业务逻辑设计——拖拽不同功能的节点并按应用逻辑连接，即可实现设备属性查询、数据转储、信息推送等服务；还可以通过自定义脚本节点实现数据处理和服务调用，实现较复杂的应用逻辑。

案例：开发设备触发服务——当温度大于 30℃，将信息通过钉钉机器人发送到钉钉群。步骤一：选 4 种节点（设备触发节点、NodeJS 脚本节点、路径选择节点、钉钉机器人节点）；步骤二：按应用逻辑连接并配置——设备触发节点指定产品、设备及触发条件；NodeJS 脚本节点编写代码 let temp = payload.props.temperature.value; 获取温度并返回给下一节点；路径选择节点按"温度 ≥ 30℃"路由到钉钉机器人节点，否则结束；钉钉机器人节点配置 access_token；步骤三：部署应用，验证服务逻辑是否正确。

IoT Studio 提供的服务节点（按类别记）：触发——空间触发、设备触发（设备上报的读写型属性/事件数据/状态变更作为服务输入）、定时触发、HTTP 请求（API 服务开始节点，必须以 HTTP 返回节点终止）、MQTT 订阅；输出——HTTP 返回；功能——路径选择（一入多出实现 if-else，最多 10 个分支）、Python 脚本（支持 v2.7.9）、条件判断、数值计算、Node.js 脚本（支持 Node.js 6.10）；人工智能——人脸识别、OCR、图像识别（调用云市场购买的 API）；消息——短信（支持批量）、钉钉机器人（支持钉钉群信息推送，不支持返回消息处理）、移动应用推送、MQTT 发布；API 调用——自定义 API、云市场 API、项目内 API；数据——变量设置、表格存储、云数据库 MySQL、键值对存储、数据分析；设备——产品结点（下发设置属性/调用服务指令、查询属性快照值或历史值）。

思考题（本课相关：课件思考题 + 教材习题 4、5）

课件思考题 / 习题 4：为空气盒子定义物模型——属性：温度 Temp（float，-40～50，单位℃，步长 0.1，可读）、湿度 Humi（float，0%～100%，单位 %，步长 0.1，可读）；事件：属性数据上报事件（PropPost），输出参数含上述两个属性，方法名称 "thing.event.prop.post"。

点开看参考答案

JSON 结构要点：顶层含 schema、profile（productKey）、properties、events。properties 数组两项：{"identifier":"Temp","dataType":{"specs":{"unit":"°C","min":"-40","max":"50","step":"0.1"},"type":"float"},"name":"温度","accessMode":"r","required":false}；Humi 同理（unit "%RH"，min "0"，max "100"，step "0.1"）。events 数组一项：outputData 包含 Temp、Humi 两个参数（各带 dataType），"identifier":"post"，"method":"thing.event.property.post"，"name":"post"，"type":"info"，"required":true，"desc":"属性上报"。（出处：教材课后习题答案第 4 题，含完整 JSON，可照抄背诵结构）

习题 5：用 IoT Studio 服务编排开发智能电灯云服务——当房间没有人并且电灯打开时关闭电灯（人有无用摄像头判断、耗时长；灯是否开用光照强度判断、耗时短）；否则不处理。列出节点并编排。

点开看参考答案

需要节点："设备触发"、"脚本"、"条件"、"自定义 API"、"产品"节点。编排与各节点作用：设备触发——服务流起始节点；第一个脚本——处理设备上传数据，根据光照强度判断电灯是否打开，结果传给条件节点；第一个条件——灯开则继续，否则服务结束（耗时短的条件先判断）；第二个脚本——获取设备上传的图像数据传给自定义 API；自定义 API——根据摄像头图片判断房间内是否有人，结果传给第二个条件；第二个条件——无人则继续，否则结束；产品——调用设备服务，关闭电灯。（出处：教材课后习题答案第 5 题）
