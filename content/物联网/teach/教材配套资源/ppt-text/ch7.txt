三端应用集成简化 命名机制 物联网场景中，内容检索和命令推送是两个基本功能 例如，“查询现在的室内光线强度” , “打开客厅的灯” 命名机制是支持这两种操作的基础 需要通过名字找到对应的数据或设备 传统基于 TCP/IP 的命名机制 为设备分配 IP 地址，建立从设备到 IP ，再到应用层名称等多层映射关系 问题 关注于建立设备之间的连接，需要实现复杂的协议栈，通过多层映射建立设备之间的连接 当用户需要操作多个设备时，需要和多个设备分别建立连接

总结 物联网云 - 端一体开发平台涵盖了设备开发、云服务开发、 Web 应用 / 移动应用开发等物联网应用开发的全链路流程 本章涉及三个主流的物联网云平台， TinyLink 、 IoT Studio 和 Tuya IoT 平台，三个平台的比较如下 平台名称 设备开发 服务开发 Web 应用 / 移动应用开发 特点 TinyLink 采用硬件无关的 TinyLink 语言，支持云端编译 支持基于 IFTTT 规则的服务开发 基于设备端代码，自动生成 Web 应用 / 移动应用框架，开发难度最低 开发简单，适合物联网技术的初学者 Link Develop 提供基于 SDK 、基于 AliOS -Things 、基于解释型语言多种设备端开发方式 提供基于可视化服务编排的服务开发方式 提供可视化搭建的 Web 应用 / 移动应用开发方式，适合初学者 支持多种开发方式，开发更为灵活 Tuya IoT 平台 提供零代码开发方式和基于 SDK 的低代码 / 多代码开发 支持基于脚本语言的规则开发 提供可视化搭建的 Web 应用 / 移动应用开发方式，也提供基于 SDK 的开发方式 开发简单，解决方案成熟，对工业界支持较多
