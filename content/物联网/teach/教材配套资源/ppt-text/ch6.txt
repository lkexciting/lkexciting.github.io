CoAP CoAP （ Constrained Application Protocol ） 定义： CoAP 是一种 M2M （ machine-to-machine ）数据传输协议，主要用于物联网中资源受限的节点和网络应用。 非确认式请求 - 响应消息传输模型 确认式请求 - 响应消息传输模型 23 Request 和 Response 只发送一次，没有 ACK 确认 Request 和 Response 中任何一个丢失都会导致 数据传输失败 Request 和 Response 任何一个丢失都会导致 重传 ACK 和数据作为 Response 同时到达请求端

CoAP 特点 轻量级 ：数据包头部长度短，相比于 HTTP 消息长度减少很多 没有中间代理 ：节点之间可以直接通信，无需通过中间服务器进行消息转发 类似 HTTP ：具有类似 HTTP Header 的控制字段，可实现 GET 、 POST 、 DELETE 等方法 灵活 ：消息传输方式（ GET 、 POST ， Confirmable 、 Non-confirmable ）多，每种传输方式代价不同，可基于不同的应用场景灵活选择 主动请求 ：数据从 A 传输到 B ，则 B 必须先主动发送 Request 请求到 A 29

MQTT 报文类型 报文类型 值 数据流向 描述 Reserved 0/15 无 保留 CONNECT 1 Client → Server Client 向 Server 发起的连接请求 CONNACK 2 Server → Client Server 对连接请求返回的 ACK PUBLISH 3 Client ↔ Server 向话题发布的消息 PUBACK 4 Client ↔ Server 发布消息后返回的 ACK SUBSCRIBE 8 Client → Server Client 订阅话题的请求 SUBACK 9 Server → Client Server 对订阅话题请求返回的 ACK DISCONNECT 14 Client → Server Client 向 Server 发起断开连接的请求 33

MQTT 报文标志位 报文 Flag （仅允许设置 PUBLISH 类型报文的 Flag ） - Bit3(DUP Flag) ： 1 代表重传， 0 代表该数据包是第一次发送 - Bit1~2(QoS Flag) ： 0~2 代表三种 QoS ，值越大 QoS 越高 - Bit0(RETAIN Flag) ： 1 代表 MQTT 代理保留消息， 0 代表 MQTT 不保留消息 34
