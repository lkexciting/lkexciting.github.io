5. 直接管理和设备影子有什么不同？请举一个具体的例子说明。
答：
设备影子与直接管理的区别：
由于设备影子具有存储设备状态信息的功能，在设备离线状况下云平台发布的指令可以在设备上线后执行。直接管理遵循请求-响应模式，类似于会立即成功或失败的HTTP调用，适用于需要立即确认其结果的交互，因此，其在设备离线时的所有操作都是无效的，必须考虑设备是否在线；
设备影子可以保证基于调用指令的排序。这是因为从应用程序发出的指令到达设备影子的时间是严格按照指令发出顺序排序的。而直接管理方法无法保证基于调用指令的排序，并且无法支持任何并发语义；
举例：
对一盏灯先后调用开红色光和开蓝色光指令，当使用设备影子方法时，这盏灯最后的状态一定是开蓝色光；而使用直接管理时，若第二个指令先传输到设备，则设备最终打开的是红色光。
6. 不同于传统的关系型数据库基于B+树实现，时序数据库选择LSM树以实现高性能的写入操作，请调研并回答以下问题：
1. 简述LSM树和B+树最显著的区别。
2. 解释LSM树读取性能不佳的原因并提出一种优化的方法。
答：
LSM树和B+树最主要的区别在于他们的结构和如何利用硬件，特别是磁盘。
B+树的特点决定了能够对主键进行高效的查找和删除，B+树能够提供高效的的范围扫描功能得益于相互连接且按主键有序，扫描时避免了耗时的遍历操作。 
LSM树在查找时先查找内存的存储，如果在内存中未命中就去磁盘文件中查找文件，找到key之后返回最新的版本。
原因：由于LSM树数据存放的位置不确定，导致查找时需要一层一层地遍历，增加了时间的消耗。例如当需要读取指定key的数据时，先在内存中的 MemTable 和 Immutable MemTable 中查找，如果没有找到，则继续从 Level 0 层开始，找不到就从更高层的 SSTable 文件中查找，如果查找失败，说明整个 LSM Tree 中都不存在这个 key 的数据。
优化：在内存中放入一个记录文件，用来记录每个数据的Level层、文件名、最小key值、最大key值等，可以帮助快速定位到要查询的SSTable文件，避免频繁读取。
7. 对于问题“快速找出1 – 100 （无重复）中缺失的2个数”，除了利用流计算思想一次遍历计算得到，还有其它算法可以实现？请再提出一种算法，并通过实际编程测试，给出两种算法的运行时长的比值。
解：
算法：运用桶排序的思想，输入每个数，就令下标为该数的数组值为1，最后遍历该数组，当第二个值为0的数出现时，跳出循环，最后值为0的两个数即为所求值。

8. 请根据描述和样例输入输出设计一个体现流计算的算法：
描述：直线上有n个等距的村庄，每个村庄要么买酒（ai>0），要么卖酒（ai<0）,所有村庄供需平衡，即所有ai之和等于0.把k个单位的酒从一个村庄运到相邻村庄需要k个单元的劳动力。计算最少需要多少劳动力可以满足所有村庄的需求，要求最多只能扫描一次数组。
样例输入：首先输入n代表村庄个数，然后分别输入n个买酒/卖酒的数量
5
5 -4 1 -3 1
6
-1000 -1000 -1000 1000 1000 1000
样例输出：输出最少需要的劳动力个数
9
9000
解：
算法思想：由于最后所有的村庄酒的数目都是0，因此我们可以从第1个村庄遍历到倒数第2个村庄，对于每个村庄i，需要的劳动力为当前酒的数目的绝对值，因为这些酒不管是买还是卖，都需要劳动力，我们假设是从后面的那个村庄来买或卖，因此第i+1个村庄的酒的数目加上第i个村庄的酒的数目，最后算出来的值即为需要的劳动力数目。
代码：
#include <stdio.h>  
#include <math.h>  
#include <time.h>  
  
const int N=500050;  
int a[N];  
int main(){  
  
    int n;  // 村庄的数目  
    scanf("%d",&n);  
    for(int i=0;i<n;i++)  
    {  
        scanf("%d",a+i); //输入每个村的情况  
    }  
    int need=0;  // 需要的劳动力数目  
    for(int i=0;i<n-1;i++)  
    {  
        need+=fabs(a[i]);  
        a[i+1]+=a[i];  
    }  
    printf("需要的劳动力数目为: %d\n",need);  
  
    return 0;  
}  


9. 结合基于对称密钥和非对称密钥的设备认证方法的优缺点，讨论分别在什么样的物联网场景下，适合使用基于对称密钥的设备认证和非对称密钥的设备认证？
答：
对称密钥
对称密钥加密，又称私钥加密，即信息的发送方和接收方用一个密钥去加密和解密数据。它的最大优势是加/解密速度快，适合于对大数据量进行加密，对称加密的一大缺点是密钥的管理与分配，换句话说，如何把密钥发送到需要解密你的消息的人的手里是一个问题。由于需要将密钥在网络传输，密钥有很大的风险会被黑客们拦截并解密，所以只适合用在一些安全性不高的场景。
非对称密钥
非对称密钥加密系统，又称公钥密钥加密。非对称加密为数据的加密与解密提供了一个非常安全的方法，它使用了一对密钥，即公钥（public key）和私钥（private key）。私钥由一方安全保管，不能外泄，而公钥则可以发给任何请求它的人。非对称加密使用这对密钥中的一个进行加密，而解密则需要另一个密钥。公钥机制灵活，但加密和解密速度却比对称密钥加密慢得多，不适合数据传输频繁的场景下，适合于数据安全性较高的情景中，如国家安全、军队通信方面。

11. 为物联网边缘计算场景设计一个寻找计算下沉锚点的算法（使用C语言实现），并求其计算复杂度（提示：边缘节点只知道自身的父节点（也即路由信息））
解：
该寻找计算下沉锚点的算法即为寻找两个点最近公共祖先算法。
算法思想：
对于两个结点u和v，假设它们的最近公共祖先为lca(u, v)，用depth[x]表示x这个结点的深度，pre[x]表示x的父结点。那么很显然，有depth[ lca(u, v) ] <= min{depth[u], depth[v]}，通过这样一个性质，我们可以很容易得出一个算法：
1) 当depth[u] < depth[v]时，lca(u, v) = lca(u, pre[v]);
2) 当depth[u] > depth[v]时，lca(u, v) = lca(pre[u], v);
利用以上两个条件，可以将u和v不断向根进行步进，递归求解，直到u == v时，这里的u或v就是原先要求的(u, v)的最近公共祖先。

{  
    int xxx=x,yyy=y;  
    if(depth[x]<depth[y])  
        swap(x,y);
