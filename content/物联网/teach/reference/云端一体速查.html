1. 核心概念（必背）

云-端一体开发平台各大厂商（三星 SmartThings、阿里云 IoT Studio、涂鸦智能 Tuya IoT）推出的、涵盖物联网应用整个开发流程的平台，解决应用开发碎片化、标准不统一、技术栈复杂问题；背景＝物联网技术栈涉及嵌入式、网络协议、云平台、Web、移动开发多个领域
理想四大功能①设备端开发 ②云服务开发 ③Web 应用/移动应用开发 ④三端集成开发流程简化
设备端三方式本地编译（SDK＝API 函数/帮助文档/开发工具的集合，屏蔽底层硬件；物联网 OS＝统一接口 + 任务调度/资源管理/软件更新）｜云端编译（云端编译、免本地环境、资源动态分配、速度快成本低）｜解释型语言（JavaScript/MicroPython 免编译、装解释器、跨平台可移植强）
云服务三内容设备接入（设备发现→控制认证→设备注册[分配 ID+对接属性和控制接口]）｜IFTTT 规则（简单云服务，OneNet 温度告警；接收方式邮箱/URL）｜服务编排（服务节点＝基础 API；组合节点配置实现功能）
应用端三方式应用框架自动生成（基于设备端代码；TinyLink、中移 OneNet）｜可视化拖拽（IoT Studio 温度展示）｜插件（HTML/CSS/JS/JSON 定义设备 UI 和行为，官方 app 按需加载，SmartThings）
三端集成简化设备模型＝设备的抽象描述，规定设备与云端数据交互规范，解耦设备与云服务开发；命名机制＝物理设备与虚拟 ID 的映射

3. 设备模型与命名机制

SmartThings 设备档案JSON 描述；设备>组件>功能>（属性，命令）；功能必须是平台已有的（capability 官方提供共 73 种）
IoT Studio 物模型JSON 描述；功能分属性/事件/服务三类；可用标准功能也可自行定义
开发流程（智能灯泡）步骤 1 定义设备模型（开/关功能 + 光照/声音强度属性 + 属性上报事件）→ 步骤 2 并行开发：硬件人员写设备端代码，软件人员用虚拟设备模拟开发应用
TCP/IP 命名机制分配 IP、多层映射；问题：复杂协议栈、操作多设备需分别建立连接
NDNName Data Networking，以数据为中心、与位置无关；兴趣包 Interest（请求数据名/操作）+数据包 Data（内容或 ACK）；分层命名 /location/fixture-namespace/command/timestamp；新设备经兴趣包向配置管理器注册 ID、名称前缀、功能集合

4. TinyLink（浙大 EmNets）

版本线2017.3 TinyLink 1.0（软硬件一体快速开发）→ 2017.12 TinyLink 2.0（+Web 端/手机端＝一体化）
开发模式自顶向下：应用需求分析→节点软件编程→分析用户代码→硬件平台搭建（对比传统自底向上：选硬件→写代码→交叉编译→烧录→调试）
使用流程五步①编写程序代码（TL_ API，setup/loop）②上传到云端 ③得到输出（硬件配置文件 + 二进制程序）④组装物联网平台 ⑤USB 连电脑一键烧写
特点自顶向下｜自动（自动生成硬件配置和二进制代码、自动接入 IBM Watson IoT/OneNet、可优化价格/功耗）｜简单（Arduino setup/loop + 云编译）；客户端 69MB vs Arduino IDE+LinkIt One 420MB / 树莓派链 266MB / BBB 链 302MB
推荐系统推荐同功能不同硬件平台：LinkIt One 例推荐 34 种可行方案，可支持编译 8 种
硬件生成系统分析代码 + 硬件数据库（组件×ID×成本×提供/占用接口×功能）→ 约束求解：用户约束（如 WiFi 模块总量>1）+ 接口约束（每类接口提供 Port ≥ 消耗 Port，类型含 Analog/UART/I2C/SPI/USB）→ 价格最小化，通常 210 条约束，线性规划 + lp_solver
软件生成系统硬件配置头文件衔接：硬件无关（用户代码）+ 硬件相关（硬件配置 + 驱动库）；116 个公开项目提取 225 个 API、实现 24 类；调试：#REQUIRE DBGPrint（额外 UART 打印）/ #REQUIRE DBG（交互式，树莓派/BBB 用 gdb，提供源码）
2.0 三端与特性设备（高层 API 封装 1.0、支持 LoRa/并发）；云服务（规则转 JSON→后缀表达式；规则引擎触发器分事件/时间；三线程 Redis FIFO 队列：消息/规则/命令）；移动端（@Client 微应用→WebView，AST→JS，HTML/JS 混合模板）；特性：微应用模型、隐式交互、云定义节点行为（类 IFTTT）、虚拟传感器（多源数据推理）

5. IoT Studio（阿里云）

版本线2018.3 Link Develop 1.0 → 2018.6 2.0 → 2019.1 更名 IoT Studio → 2021.3 3.0（Web/移动可视化、业务逻辑、物联网数据分析）
配套Bone 框架（Web/移动开发框架，集成物联网 UI 组件）；IoT 应用市场（硬件到解决方案，在线商业化）；四大工作台：设备开发（嵌入式 C/JS、AliOS Things、SDK；本地+云端编译）、业务逻辑（可视化服务编排）、Web 应用、移动应用
物模型三类属性 Property＝运行时状态（温度湿度）；服务 Service＝可被外部调用的方法（开风扇；sync/async）；事件 Event＝需外部感知处理的通知（任务完成/故障；type：info/alert/error）
物模型字段顶层：schema/link（云平台自动生成）+ profile(productKey) + properties/events/services；属性：identifier/name/accessMode(r,rw)/required/dataType(type:int,float,double,text,bool,array；specs:min,max,unit,unitName,size≤128,item)；服务：callType(sync,async)+inputData/outputData/method
同步调用MQTT PUB/SUB 异步不适合同步返回；RRPC＝基于 MQTT 定制的请求响应同步机制
物模型使用 Topic属性上报 /sys/{ProductKey}/{deviceName}/thing/event/property/post（method thing.event.property.post）；事件上报 .../thing/event/{dsl.event.identifer}/post；服务调用 .../thing/service/{dsl.service.identifer}（method thing.service.open）
服务节点分类触发（空间/设备/定时/HTTP 请求/MQTT 订阅）、输出（HTTP 返回）、功能（路径选择≤10 分支、Python 2.7.9、条件判断、数值计算、Node.js 6.10）、AI（人脸/OCR/图像识别）、消息（短信/钉钉机器人/移动推送/MQTT 发布）、API（自定义/云市场/项目内）、数据（变量/表格存储/MySQL/键值对/数据分析）、设备（产品结点）
编排案例温度>30℃ 推钉钉：设备触发→NodeJS 脚本（payload.props.temperature.value）→路径选择（≥30℃）→钉钉机器人（access_token）；智能灯习题：设备触发→脚本→条件→脚本→自定义 API→条件→产品结点

6. Tuya IoT 与联合开发

Tuya 简介涂鸦智能 2016 年推出；接入 Alexa/Google Assistant/HomeKit/SmartThings 生态；截至 2021.7 有 37.4 万开发者、覆盖 200+ 国家和地区
设备端三档零代码（标准电工照明传感，可视化 UI+选模组→自动生成固件）｜低代码（有 MCU 产品，MCU SDK）｜多代码（网关/摄像头，设备 SDK）
面板控制智能产品的界面程序，基于 React Native；嵌入方式：公版 App / OEM App（零代码）/ SDK 本地开发
平台特性成熟硬件解决方案｜边缘计算网关（Docker 镜像安装、支持主流协议+私有协议驱动）｜SaaS 开发框架（前后端开源，用户登录/角色权限）｜全球公有云
联合开发TinyLink 管设备端，IoT Studio 管云服务+Web/移动应用；关键点＝TinyLink 实现基于物模型的设备接入。IoT Studio 设备端不足：硬件种类少、仍自底向上
MQTT 接入参数serverName＝${productKey}.iot-as-mqtt.cn-shanghai.aliyuncs.com；port＝1883；clientName＝clientId|securemode=x,signmethod=xxx,timestamp=xxx|（securemode：2 TLS/3 TCP；signmethod：hmacSha1/hmacSha256/hmacMd5）；userName＝deviceName&productKey；passWord＝sign_hmac(deviceSecret,(productKey,deviceName,timestamp,clientId))

7. 三平台总结表（简答收尾必背）

平台设备开发服务开发应用开发特点
TinyLink硬件无关 TinyLink 语言，云端编译IFTTT 规则框架自动生成，难度最低开发简单，适合初学者
Link DevelopSDK/AliOS-Things/解释型语言多种方式可视化服务编排可视化搭建，适合初学者多种开发方式，更灵活
Tuya IoT零代码 + SDK 低/多代码基于脚本语言的规则开发可视化搭建 + SDK 开发开发简单、方案成熟、工业界支持多

8. 易错辨析（考前最后过一遍）

易混点一句话区分（均出自课件）
IFTTT vs 服务编排IFTTT＝工作台设规则、做简单云服务（TinyLink/Tuya/OneNet）；编排＝组合服务节点（每个＝基础 API）实现特定功能（IoT Studio/LinkDevelop）
设备模型 vs 命名机制设备模型＝抽象描述+数据交互规范（解耦开发）；命名机制＝物理设备与虚拟 ID 映射（找数据/设备）
自顶向下 vs 自底向上自顶向下＝先写应用代码由系统反推硬件（TinyLink）；自底向上＝先选硬件再写代码适配（传统开发，IoT Studio 设备端仍是这种方式）
属性 vs 事件 vs 服务属性＝状态（上报）；事件＝通知（上报，info/alert/error）；服务＝方法（被调用，sync/async 用 RRPC 同步）
MCU SDK vs 设备 SDKTuya 低代码＝MCU SDK（有 MCU 产品）；多代码＝设备 SDK（网关/摄像头等复杂设备）
