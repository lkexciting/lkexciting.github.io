操作系统速查

《物联网技术基础与应用开发》第 3 章全部高频考点一页压缩，全部出自课件《第三章-dw(3)》。小课：0301–0306。

1. 概述必背

  • 定义：支撑物联网大规模发展的核心软件；屏蔽硬件差异性、提供统一编程接口、提供运行时环境、降低开发成本和时间；硬件抽象是核心功能之一；现状"数量众多、百家争鸣"。
  • 与传统 OS 三区别：①存储占用小（一般只有几十 KB）；②内存管理（有 MMU vs 无 MMU，MMU 提供地址翻译和内存保护）；③特权模式（很多物联网芯片无 CPU 特权模式 → 有 Bug 的程序可不受控占用 CPU 周期）。
  • 系统构成：嵌入式 OS 组件（任务调度：事件驱动/多线程；动态加载；存储管理 RAM+Flash；资源抽象：专用/虚拟化/共享；传感器接口）+ 无线网络组件（网络协议栈）+ AI 组件（TinyML：TensorFlowLite、Split Computing）。
  • Library OS：OS 功能作为库运行，应用直接调用服务，减少用户态/内核态上下文切换。微内核：只留任务/线程管理、内存管理、IPC，其余为用户态进程经消息传递通信（模块化、灵活）；宏内核：功能集成在一个内核态大进程，如 Linux。

2. 七大关键特性

特性必背点
1 编程模型程序结构：非模块化 / 模块化（编码层=TinyOS 组件化；二进制层=SOS 模块化）。TinyOS 编译后单二进制映像不留组件信息；SOS 编译后保留模块信息、可动态加载。执行逻辑：事件驱动（实时响应、实时性响应性好）/ 多线程（一线程一任务，减少代码分片）
2 调度方式抢占式（高优先级抢占）/ 非抢占式（执行至完成或阻塞）/ 协作式（主动 yield()）/ 时间片轮转（片完让出 CPU）。原子操作：非抢占式 {x++; Yield(); write(x);} 错、协作式 {x++; write(x); Yield();} 对、抢占/轮转需 mutex
3 I/O 方式阻塞式（完成才返回、易编程）/ 分阶段（调用与完成分离、代码冗长但高响应、更好控制并发）
4 内存分配静态（TinyOS；编译时定；.bss+.data；优：高效无碎片 / 劣：不能按需）vs 动态（SOS；运行时 malloc/free；优：按需 / 劣：碎片+安全隐患）
5 软件更新有线（串口/以太网）/ 无线 OTA（WiFi）。Bootloader=加电后第一段代码，初始化后装载 OS/应用并跳转。四步：查升级文件→擦 Flash 旧文件→写入→校验（可回滚）。三法：整个镜像 / 模块化 / 差分。差分指令：COPY 5B；ADD 3+m B。影响因素：差分算法、相似性保持。算法：bsdiff、xdelta3、HDiffPatch、MDiffPatch（INFOCOM 2024）
6 网络服务传感网：多跳自组织、IEEE 802.15.4、数据收集/分发/时间同步协议；物联网：BLE、ZigBee、WiFi HaLow、LoRaWAN、NB-IoT；学术：干扰共存、异构互联。TinyNet：2.5 层 uniMAC 接口，关键模块=邻居发现、通信调度
7 AI 支持框架：TFLite→嵌入式 Linux（树莓派）；TFLite for Micro→MCU（ESP32）；PyTorch Mobile→Android/iOS。TinyML=把模型部署到微控制器和低功耗边缘设备的 ML 分支；特点：低延迟、保护隐私、低功耗、高可靠、精度稍低、内存小。优化：剪枝/量化（32/64bit 浮点→8bit 定点）/知识蒸馏（教师→学生）/高效架构（MobileNetV2）/硬件加速（DSP）

5. Contiki 必背

  • 2002 Adam Dunkels（瑞典计算机科学研究所）提出；2004 v2.0 加 Cooja 模拟器 + Rime 协议栈；2011 加 Contiki RPL + Contiki MAC；2012 起 Thingsquare 维护；2015.8 v3.0。
  • protothreads（2006，瑞士计算机学院）：协作式、单堆栈、不能用局部变量；五宏：PROCESS / AUTOSTART_PROCESSES / PROCESS_THREAD / PROCESS_BEGIN / PROCESS_END；实现=switch(lc) 状态机。mt_thread：多堆栈，支持协作式+抢占式；API：mt_init/start/exec/stop/exit。
  • 网络：uIP（精简 TCP/IP 最小功能集；TCP/UDP/ICMP/IP）、6LowPAN（分包重组+IPv6/UDP 包头压缩）、RPL（低功耗有损网络 IPv6 距离矢量路由）。RPL vs CTP：CTP 仅多对一；RPL 支持一对多/多对一/一对一。
  • shell：sense（采数据）、txpower（发送能量）、rfchannel（信道）；自定义命令 shell_register_command + SHELL_COMMAND。

6. RIOT 必背

  • 实时多线程 OS；微内核（所有系统服务=独立线程）；柏林自由大学；2008 开源社区，293 贡献者；67 种处理器、237 款开发板。三特征：开发者友好 / 资源占用低（线程通常 <25 字节）/ 网络支持好。
  • thread_create(栈, 栈大小, 优先级 0–15（值越高优先级越低）, flag, 函数, 参数, 名字)；flag：SLEEPING 创建即休眠 / WOUT_YIELD 等调度 / STACKTEST 立即执行并测内存。
  • 模块化：模块=文件夹；USEMODULE += dht / xtimer；移植新板仅需开发 CPU 模块。
  • GNRC：最底层 gnrc_netdev 抽象下层协议 → 兼容大量链路层协议；完全实现 6LowPAN → 上层 IPv6/UDP/TCP；应用层 socket API；每层一个线程，MAC 层优先级最高、应用层最低。
  • SAUL：设备=saul_reg_t（链表）；驱动=saul_driver_t（read/write/type）；数据=phydat_t；saul_reg_read + phydat_dump 遍历读取。

7. AliOS Things 必背

  • 阿里云轻量级 IoT OS；智能家居/智慧城市；C + JavaScript；内核 ROM <2KB；FOTA、多 bin/差分/乒乓升级。
  • Rhino 内核：小内存块分配器（静态+动态、固定+可变块）；空闲 CPU 模式（C0 活跃，C1～Cn 睡眠；ARM WFI / IA32 HLT）；抢占式+循环调度、首选最高优先级。
  • 网络：uMesh（自组织、自我修复、多跳）、SAL（套接字抽象层）、LwIP（IPv4/IPv6、TCP/UDP、ICMP、ARP）、LoRaWAN Class A/C。安全：LinkTEE、Link ID²（不可篡改、不可伪造、全球唯一、一芯一密）。工具：AliOS Cube、AliOS Studio、WebIDE(Theia)。

8. HarmonyOS 必背

  • 华为全场景分布式 OS；1+8+N：手机 + 车机/音箱/耳机/手表手环/平板/大屏/PC/AR-VR + 泛 IoT 设备。
  • 四层：内核/系统服务/框架/应用。多内核：手机=Linux；IoT=LiteOS-A（标准设备 ≥128MB、有 MMU、虚拟内存映射、HDF）/ LiteOS-M（微设备 ≥1MB、迷你 ≥128KB、无 MMU、HAL；Cortex-M3/M4/M7、RISC-V）。
  • 分布式软总线：无形总线，自发现、自组网、高带宽、低时延；四大能力：分布式数据管理、分布式任务调度、分布式设备虚拟化（超级虚拟终端）、跨设备业务（多屏协同、文件分享）。网络：星闪 NearLink。AI：TFLite + MindSpore Lite。

9. 案例 AntiTheft 与研究前沿

  • AntiTheft：每 1s、100Hz 采加速度，方差阈值 4（var > 4×ACCEL_SAMPLES）→ 红灯。Contiki 版：TelosB+mts300，etimer，ACCEL_INTERVAL=CLOCK_SECOND/100；make TARGET=sky + MOTES=/dev/ttyUSB0 upload。RIOT 版：ESP32+mts300，ztimer，ACCEL_INTERVAL=US_PER_MS*10，两线程各 1024B 栈、优先级 8、STACKTEST；make BOARD=esp32-wroom-32 flash。
  • 前沿四方向：低代码（LLM as an OS）；高安全性（Tock，Rust 内核，SOSP17，64kB 计算机）；高拓展性（FireStorm，Cortex M4+Lua，IPSN16；课题组 WAIT、TinyNet）；环境自适应性（Intermittent Computing：断电前存状态到非易失内存；InK，SenSys18）。
