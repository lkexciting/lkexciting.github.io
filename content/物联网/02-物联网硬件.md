# 第二章 物联网硬件

> 从处理器、内存、接口和供电约束出发进行设备选型。硬件参数只用于明确型号或给定算例，不同型号与开发板不能直接套用同一组数值。

## 1. 硬件选型先看任务，后看参数

硬件平台是程序运行和物理交互的基础，包括处理器、存储、供电、传感、通信及扩展接口。本节按能力把设备划分为 Things、Smart Things、类 PC 嵌入式设备。这是面向应用的分类，不是不可变化的芯片等级。

- **Things**：资源有限、强调低功耗与低成本，例如传统传感节点、典型 MCU 板。
- **Smart Things**：具有更强算力与完整软件环境，例如树莓派、Jetson。
- **类 PC 设备**：可运行更复杂系统与应用，成本、体积、功耗通常也更高。

![硬件选型决策流程](%E7%89%A9%E8%81%94%E7%BD%91/pictures/02-%E7%89%A9%E8%81%94%E7%BD%91%E7%A1%AC%E4%BB%B6/%E7%A1%AC%E4%BB%B6%E9%80%89%E5%9E%8B.webp)

**选型顺序**：明确传感和控制需求 → 计算 RAM/Flash 预算 → 确认接口与通信 → 评估实时性和推理算力 → 估算整板能耗 → 考虑成本、尺寸与开发生态。

### 1.1 CPU、MCU、MPU

| 名称 | 含义 | 核心理解 |
|---|---|---|
| CPU | 中央处理器 | 执行指令的运算和控制核心 |
| MCU | 微控制器 | 把 CPU、RAM、Flash、外设等集成进芯片，适合控制与低功耗任务 |
| MPU | 微处理器 | 偏重复杂计算，常配外部内存并运行完整 OS |
| SoC | 片上系统（讲解补充） | 可集成 CPU、GPU、NPU、通信等多个子系统 |

别把“开发板”和“处理器芯片”混为一谈：板上还可能有电源转换、USB 转串口、指示灯等，它们也耗电。

## 2. 四类关键指标

### 2.1 成本与微型化

节点越便宜、越小，越有利于大规模高密度部署；但还要算传感器、外壳、安装、维护、通信与更换电池的总成本。价格表明确是历史参考，不能当作当前报价。

### 2.2 功率与能量

P=VI, E=Σ_i P_iΔt_i=Σ_i V_i I_iΔt_i

**功率 P 用 W，能量 E 用 J；电流 I 用 A。** 有时把电流称作“能耗”，计算时必须恢复正确物理量。

原题：5 V；工作 0.5 s、电流 0.2 mA；睡眠 0.5 s、电流 0.1 μA。

E=5×(0.2×10^(-3)×0.5+0.1×10^(-6)×0.5)
=0.00050025J=0.50025mJ

总时长为 1 s，所以平均功率数值为 0.50025 mW。**总能量和平均功率可以有相关数值，但单位与含义不同。**

低功耗模式要同时比较：进入/退出开销、唤醒时间、RAM 是否保留、哪些外设能工作、哪些事件可以唤醒。睡得最深不一定让整个任务最省电。

### 2.3 运算速度与存储

主频是每秒时钟周期数，不等于每秒指令数。在固定每条指令耗费 k 周期的简化模型下：

R_inst=f/k

16 MHz、每条指令 20 周期，得到 0.8×10⁶ 条/秒。跨不同架构比较性能不能只看 MHz。

讲解补充：动态功率常用 P_dyn∝αC V² f 近似。降电压对动态功率影响显著，但系统还存在静态功耗，且频率、电压和任务运行时间相互制约。

| 存储 | 易失性 | 用途 | 常见约束 |
|---|---|---|---|
| RAM | 断电丢失 | 栈、堆、变量、缓冲区、激活张量 | 容量小，必须留运行余量 |
| Flash | 断电保留 | 程序、常量、固件镜像 | 擦写粒度与寿命，写入较慢 |
| ROM | 断电保留 | 固化代码或启动例程 | 通常不能按普通 RAM 修改 |

**“程序大小能放进 Flash”只是必要条件之一。** 运行时 RAM 还要容纳 OS、栈、全局变量和中断上下文。

### 2.4 接口与扩展能力

| 接口 | 典型线/信号 | 同步性与特点 | 典型用途 |
|---|---|---|---|
| Analog | 模拟电压 | 经 ADC 采样后才成为数字量 | 模拟传感器 |
| Digital/GPIO | 高低电平 | 通用输入/输出 | 按键、LED、数字状态 |
| PWM | 周期脉冲 | 调占空比改变平均作用量 | 电机、灯光控制 |
| UART | TX、RX、GND | 异步串行，通常全双工 | 串口调试、通信模块 |
| I²C | SDA、SCL、GND | 同步、按地址共享总线 | 多个低速传感器 |
| SPI | SCLK、MOSI、MISO、CS | 同步、通常全双工，常由片选区分外设 | 显示、存储、高速外设 |

I²C 通常需要上拉；SPI 多个外设常需要不同片选；GPIO 电压兼容性、引脚复用和电流能力都要检查。接口“总数多”不等于“所有接口可同时用”。Grove 是便捷连接方式，不能据此认为各端口的电气和协议完全相同。

## 3. 选型与预算计算题：完整作答

### 3.1 10240 字节数组该选哪块 MCU？

![MCU RAM 与工作睡眠电流题](%E7%89%A9%E8%81%94%E7%BD%91/pictures/02-%E7%89%A9%E8%81%94%E7%BD%91%E7%A1%AC%E4%BB%B6/%E8%AF%BE%E4%BB%B6-p012.webp)

给定参数：MSP430F2618 RAM 为 8 KB，MSP430F5437 RAM 为 16 KB。数组需要 10240 B，即 10 KiB，所以前者不够，后者才有可能运行；还要为其他数据和栈留余量。

表内工作电流分别为 0.5 mA、0.28 mA；睡眠电流分别为 1.1 μA、1.7 μA。题设电压均为 3 V、总时长 10 s。

| 占空比 | F2618 平均电流 | F5437 平均电流 | 10 s 能量：前者 / 后者 | 更省电 |
|---|---:|---:|---:|---|
| 80% | 0.40022 mA | 0.22434 mA | 12.0066 / 6.7302 mJ | F5437 |
| 0.1% | 0.0015989 mA | 0.0019783 mA | 0.047967 / 0.059349 mJ | F2618 |

结论：**高占空比重视工作电流，低占空比重视睡眠电流。** 不能用“哪块 MCU 永远更省电”概括。

### 3.2 UART 接收缓存

题设每帧 11 bit，其中 8 bit 数据。波特率 B；最长不能及时处理接收的时间为 t 秒；只缓存数据字节：

N≥⌈Bt/11⌉ 字节

9600、1 ms：⌈9600×0.001/11⌉=1 B。

9600、2 ms：⌈9600×0.002/11⌉=2 B。

这是示例的简化缓存预算：把处理时间视作无法及时排空缓冲的窗口。真实持续接收还要求平均处理速度足够；若“处理一位需要 1 ms”被理解为持续消费速率，长期积压就不能靠这一个字节解决。UART 常见的其他帧格式位数也不同，必须按题设 11 bit 计算。

## 4. 常见硬件平台

| 平台 | 主要定位 | 典型优点 | 主要限制 | 适合的任务 |
|---|---|---|---|---|
| MicaZ / TelosB | 传统无线传感节点 | 低功耗，感知通信集成 | RAM 很小 | 传感网实验、周期采样 |
| STM32 | MCU 控制平台 | 外设丰富、实时控制、型号广 | 需按具体型号选型 | 工业采样、控制、电池节点 |
| ESP32 | 带无线功能的 MCU | 典型型号集成 Wi-Fi/Bluetooth | RF 共用和功耗管理需考虑 | 智能家居、联网原型 |
| Arduino | 开源原型开发生态 | 编程简单，库和盾板多 | UNO 等经典板资源有限 | 教学、快速验证 |
| 树莓派 | 单板计算机 | Linux 与高级语言、接口丰富 | 较高功耗，通常无板载通用 ADC | 网关、边缘应用 |
| Jetson | 嵌入式 AI 计算 | GPU、并行计算、AI 工具链 | 功耗和成本较高 | 视觉、机器人、复杂推理 |

### 4.1 传感节点

表中的 MicaZ RAM 为 4 KB。假定常见的 1 KB=1024 B，则 4 KB=4096 B，4100 B 的 RAM 数据已经放不下，何况还有系统运行开销。若题目说的是存于 Flash 的只读数据，需要按具体存储放置方法另行分析。

TelosB 的典型 MCU 属于 16 位 MSP430；不同板卡版本的主频和存储容量需要分别核对，不能混成一套“唯一规格”。记住低功耗、资源有限和面向无线传感网这一定位，并按题目给定数值计算。

### 4.2 STM32：三种典型低功耗模式（以 F103 本节模型为例）

| 模式 | 主要行为 | 权衡 |
|---|---|---|
| Sleep 睡眠 | CPU 停止，部分外设继续运行 | 唤醒快，适合等中断 |
| Stop 停机 | 停止主要时钟，通常保留 RAM 状态 | 更省电，恢复时钟需要开销 |
| Standby 待机 | 关闭更多供电域 | 功耗最低，但状态保留和唤醒限制更大 |

不同 STM32 系列的模式、唤醒源和电流并不完全相同。的微安数值是例子，不应视作整板固定电流。

### 4.3 ESP32：无线共存与分级睡眠

本节以经典 ESP32 为例，介绍 Xtensa LX6、最高 240 MHz、520 KB SRAM 等。**这些参数不能覆盖所有 ESP32 系列型号。**

Wi-Fi 与蓝牙可在系统层面共存，但共享射频资源时通过时间分配协调，不代表同一射频在同一时刻发两种无线信号。

![ESP32 Wi-Fi 与蓝牙共用射频](%E7%89%A9%E8%81%94%E7%BD%91/pictures/02-%E7%89%A9%E8%81%94%E7%BD%91%E7%A1%AC%E4%BB%B6/%E8%AF%BE%E4%BB%B6-p035.webp)

| 模式 | CPU / 射频的主要变化 | 直观理解 |
|---|---|---|
| Active | 射频工作 | 正常通信 |
| Modem-sleep | CPU 可运行，射频基带按模式关闭 | 算而少传 |
| Light-sleep | CPU 暂停，保留部分状态 | 浅睡，可较快恢复 |
| Deep-sleep | CPU 与大部分外设断电 | 深睡，需处理恢复流程 |
| Hibernation | 进一步关闭保留模块 | 进一步降低静态消耗 |

### 4.4 Arduino 与树莓派

经典 UNO 使用 ATmega328 系列，AVR 是 RISC 架构，采用程序与数据空间分离的哈佛结构。不要把“Arduino 生态”直接等同于“只能用 AVR”：自己也列举了不同 MCU 的 Arduino 板。

**盾板（Shield/HAT）**扩展通信、传感或接口能力。树莓派的 GrovePi+ 可以通过 I²C 与主板通信，借助扩展板接入模拟传感器；“扩展板能读模拟量”不等于树莓派原生 GPIO 就具备 ADC。

### 4.5 Jetson 与算力单位

- 1GFLOPS=10⁹ 次浮点运算/秒。
- 1TFLOPS=10^(12) 次浮点运算/秒。
- 1TOPS=10^(12) 次操作/秒；必须注明 INT8 等数值类型与统计口径。
- 1.3 TFLOPS 表示在约定精度和条件下每秒约 1.3×10^(12) 次浮点运算，不表示真实应用必然达到该速度。

FP16 TFLOPS、FP32 TFLOPS、INT8 TOPS 不能脱离精度直接横向比较；模型还受访存、算子、驱动、批量等因素影响。

## 5. 开发案例：3 秒温湿度监测

### 5.1 标准开发流程

选择传感器及电压 → 核对连接与引脚 → 准备开发环境和库 → 编程 → 编译 → 烧写/运行 → 串口或终端验证。

Arduino 案例用 DHT11，`setup()` 初始化一次，`loop()` 不断执行。下面是**教学伪代码**，具体 DHT 库接口依库而定：

```cpp
void setup() {
    Serial.begin(9600);
    sensor.begin();
}
void loop() {
    float t = sensor.readTemperature();
    float h = sensor.readHumidity();
    if (isfinite(t) && isfinite(h)) {
        print_reading(t, h); // 输出温度、湿度与单位
    } else {
        report_read_error();
    }
    delay(3000);
}
```

`delay(3000)` 表示本轮读取和打印之后等待 3 秒，所以实际开始到开始的间隔约为“本轮处理时间+3 秒”；严格周期任务宜用定时器或绝对时刻调度。

树莓派案例：Linux → Python → GrovePi 库 → I²C 扩展板 → DHT11。要处理无效数值、I/O 异常和失败重试，而非只验证“程序能启动”。

### 5.2 常见故障定位

| 现象 | 优先检查 |
|---|---|
| 串口乱码 | 两侧波特率、帧格式是否一致 |
| 无传感器数据 | 供电、共地、引脚号、模块型号、库 |
| 板子重启 | 供电能力、射频峰值电流、程序异常 |
| 睡眠后无法醒来 | 唤醒源、对应引脚、模式是否支持 |
| 功耗远大于芯片手册 | USB 芯片、LED、稳压器、外设是否仍通电 |

## 6. 学术趋势与自测

高性能：边缘 AI 需要更强算力与更高能效。模块化：供电、存储、通信、传感等模块通过标准接口连接，便于替换、定制与复用。

1. Flash 足够，程序为何仍不能运行？——RAM、栈、外设及架构要求可能不满足。
2. 哪种 STM32 模式最低功耗？——F103 本节模型中的 Standby，但要付出状态丢失与唤醒限制。
3. ESP32 两个协议能共存是否代表射频同时工作？——不是，典型共存依赖共享射频调度。
4. 低占空比选型看什么？——睡眠电流与整板漏电特别重要。
5. 何时选 Jetson？——需要高性能视觉或并行推理，且功耗、体积、成本预算允许。
