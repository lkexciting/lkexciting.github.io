## 2. 共性指标：功耗、距离、频带、数据率、安全

### 2.1 无线电不仅发送耗电

无线模块常有发送、接收、空闲侦听、睡眠等状态。对传感器节点，接收和空闲侦听也可能占据很大能耗。仅仅“少发数据”未必足够，关键是让无线电大部分时间真正休眠。

能源浪费来源：空闲侦听、碰撞后重传、串音/过听、控制包开销、过度发送、干扰导致错误唤醒。MAC 的省电策略往往是在能耗、等待延迟、吞吐量和同步成本之间权衡。

### 2.2 路径损耗与链路预算

本节采用对数距离模型：

PL(d)=PL(d_0)+10nlog₁₀(d/d_0)

n 为环境相关路径损耗指数。简化接收功率：

P_r=P_t+G_t+G_r-PL-L_other

使用 dBm/dB 形式时可以相加减；接收功率需高于灵敏度并留出裕量。环境遮挡、天线和干扰都会影响距离，不能把某协议的宣传距离当作任何场景保证值。

**dBm 是相对 1 mW 的绝对功率；dB 是比值。**

P_dBm=10log₁₀(P_mW), P_mW=10^P_dBm/10

0 dBm=1 mW；10 dBm=10 mW；20 dBm=100 mW。两个 dBm 功率之差可形成 dB 比值；但求物理平均功率时先转线性单位，不能直接把 dBm 算术平均当成真实平均功率。

### 2.3 数据率与安全

最大 PHY 速率不等于应用吞吐：前导、头部、ACK、信道侦听、退避、重传、周期休眠都占时间。2.4 GHz 经典 802.15.4 的 250 kb/s 是该 PHY 场景参数，不代表所有版本/频段速率都一样。

授权频段需频谱授权；ISM 等非授权使用也必须符合当地频谱规定。“非授权”不代表无限功率、任意频段或无限占用。

AES 等加密、完整性校验、身份鉴别、访问控制要分清；CRC 用于检测传输差错，本身不是抵御攻击者篡改的认证机制。

## 3. IEEE 802.15.4 物理层

### 3.1 4 bit → 32 chips → I/Q 调制

.4 GHz DSSS/O-QPSK 链路：

1. 每 4 bit 数据查表映射为 32 个 chip。
2. 偶数位置 chip c_0,c_2,… 送 I 支路。
3. 奇数位置 chip c_1,c_3,… 送 Q 支路。
4. Q 相对 I 延迟一个 chip，即 0.5 μs；做半正弦脉冲成形并调制。

总 chip rate=2 Mchip/s。每 32 chip 携带 4 bit，所以数据率=2M×4/32=250 kbit/s。每支路 1 Mchip/s，每个支路 chip 持续 1 μs；不要把总 chip 周期与支路周期混淆。

![DSSS 查表与码片序列](%E7%89%A9%E8%81%94%E7%BD%91/pictures/05-%E4%BD%8E%E5%8A%9F%E8%80%97%E6%97%A0%E7%BA%BF%E5%8D%8F%E8%AE%AE/%E8%AF%BE%E4%BB%B6-p031.webp)

### 3.2 原题：10111110 的 I/Q 码片序列

**按本节约定直接给出的流顺序与表的 b0 b1 b2 b3 约定**，分成 `1011`、`1110`，不要额外把这 8 bit 当作某个十六进制字节后再隐式倒序。

| 数据组 | 查得的 32-chip 序列 | I：偶数下标 | Q：奇数下标 |
|---|---|---|---|
| 1011 | 01100000011101111011100011001001 | 0100010111101010 | 1000111101001001 |
| 1110 | 10011100001101010010001011101101 | 1010010001011110 | 0110011100001011 |

拼接：

```text
I = 0100010111101010 1010010001011110
Q = 1000111101001001 0110011100001011
```

这给出的是支路码片值；若画时间波形，还要画出 Q 的 0.5 μs 偏移与脉冲成形。若题目明确采用字节值和最低有效位先传，则应先按该约定生成比特流再查表。

### 3.3 帧结构

```text
PPDU = Preamble(4 B) + SFD(1 B) + PHR(1 B) + PSDU(0~127 B)
PSDU 通常承载 MAC 帧：MAC头 + 载荷 + FCS
```

术语辨析：SHR 通常包含前导和 SFD，共 5 B；4 B 只是这里的前导长度，不是整个同步头。最大 127 B 指该这里讨论的经典 PHY 的 PSDU，不是应用净载荷。

## 4. 低功耗 MAC：三类机制对比

![同步与异步 MAC 时序](%E7%89%A9%E8%81%94%E7%BD%91/pictures/05-%E4%BD%8E%E5%8A%9F%E8%80%97%E6%97%A0%E7%BA%BF%E5%8D%8F%E8%AE%AE/MAC%E6%97%B6%E5%BA%8F.webp)

### 4.1 S-MAC：同步醒、同步睡

邻居同步活动与休眠周期，在活动窗口内竞争信道，配合 RTS/CTS、虚拟载波侦听等机制减少冲突与过听。

优点：避免持续开机；局限：需要同步，活动窗口仍有空闲侦听，多跳包可能等待下一周期。

物理载波侦听看信道状态；虚拟载波侦听通过帧中的占用时间设置 NAV，预约一段时间。

### 4.2 LPL：发送方发起、接收方周期检查

接收节点短暂唤醒做信道检查，平时休眠；发送方用足够长的前导/重复探测包覆盖对方唤醒时刻。

- 单播：接收方确认后可提前停止重复发送。
- 广播：多个邻居唤醒不同步，往往需要更长发送覆盖。
- 接收完成后额外保持一段监听，可利于后续突发数据。
- 干扰可能触发 CCA，造成错误唤醒并浪费能量。

发送成本可能较高，特别是接收方检查间隔较长时。CCA 与载波侦听的具体判据依无线芯片与配置，不能只用名字判断。

### 4.3 RI-MAC：接收方先说“我醒了”

接收方周期性发送 beacon；有数据的发送方侦听 beacon，然后发数据。多个发送者同时响应可能碰撞，需要退避与竞争协调。

| 机制 | 发起方 | 主要代价 |
|---|---|---|
| S-MAC | 共享时间表 | 同步与活动窗口空闲侦听 |
| LPL | 发送方 | 长前导/重复包占信道 |
| RI-MAC | 接收方 | 发送方等待 beacon，多个发送者竞争 |

### 4.4 探测包间隔题：先写清平均模型

已知包长 2 ms，CCA 窗长 11 ms，400 次采样；信号 -56 dBm，噪声 -100 dBm，平均值必须**超过** -77 dBm。

若题目按“采样的 dBm 数值算术平均”，信号样本比例 f 需满足：

-56f-100(1-f)>-77⇒f>23/44≈0.5227

长期平均近似，设包间空隙 g：

2/(2+g)>23/44⇒g<42/23≈1.826ms

但这是长期占比，不保证任意相位的有限 11 ms 窗口都达标。若要求连续时间均匀采样近似下的最差相位保证，在临界附近令周期 P=2+g，11 ms 最低有效信号时长为 17-3P ms，要求：

17-3P>11×23/44=5.75⇒g<1.75ms

推导方法：窗口包含两个完整周期和余段 r=11-2P；最差余段先覆盖空隙，信号时长最少 4+max(0,r-g)。临界附近整理为 17-3P。

**这些答案依赖模型**：400 个离散样本还受采样端点、相位影响；若平均的是线性功率再转 dBm，结果又不同。因此解题应说明老师采用的是长期近似还是有限窗口保证；不要无条件把 dBm 当线性物理功率平均。

## 5. 链路质量估计

| 指标 | 含义 | 优点 | 局限 |
|---|---|---|---|
| RSSI | 接收信号强度指示 | 获取方便 | 干扰也可能使能量大，不保证解码好 |
| SNR | 信号/噪声功率比 | 考虑噪声环境 | 测量与估计依实现 |
| LQI | 接收质量指示 | 与解调质量相关 | 芯片定义不同，不是通用绝对值 |
| PRR | 成功接收包数/发送包数 | 直接反映包接收结果 | 需样本，随时间、包长变化 |
| ETX | 期望成功传递一次的发送次数 | 可用于路由成本 | 依赖数据与 ACK 成功模型 |

同带宽下用 dBm 表示时，SNR(dB) 近似为信号 dBm 减噪声 dBm。信号 -80、噪声 -100，则约 20 dB。RSSI 某阈值对应高 PRR 的结论属于特定测量环境，不能把 的 -87 dBm 当作所有无线的通用分界线。

EWMA 平滑：

p_new=αp_current+(1-α)p_old

α 大则响应快、波动大；α 小则平滑但滞后。例：旧值 0.67，新窗口 1，α=0.9，更新为 0.967。

若数据包成功率为 d_f、ACK 成功率为 d_r，并采用独立重试近似：

ETX≈1/d_fd_r

例：0.8 与 0.9，ETX≈1.389。ACK 计数能反映往返成功；ACK 丢失也可能导致“数据实际已到达但发送方不知道”。

4-bit 估计器融合物理层 White bit、链路层 Ack bit、网络层 Pin/Compare bit，说明跨层信息可以改善链路选择。

## 6. 6LoWPAN：为什么 IPv6 需要适配？

IPv6 要求链路能够承载至少 1280 B 的包，而经典 802.15.4 PSDU 最多 127 B，扣除 MAC/安全头后可用更少。IPv6 基本头又有 40 B，UDP 头 8 B，对短包负担很重。

两大功能：**分片重组、头部压缩**。利用可推导的链路地址和共享上下文省略部分 IPv6 字段，而非随便丢弃协议头。

分片头字段：

- datagram_size：分片前整个 IP 包大小，不是当前片大小。
- datagram_tag：标识同一数据报的分片。
- datagram_offset：相对原始数据报位置，以 8 B 为单位，首片省略。

> [!warning] 纠偏
> 该页把 Size 解释为“每一个分段的大小”。按 [RFC 4944](https://www.rfc-editor.org/rfc/inline-errata/rfc4944.html)，datagram_size 表示整个 IP 包的大小；复习应采用这个区分。

分片越多，重组成功依赖的链路传输越多，丢一片就可能使整个包无法交付，所以适配能力不等于分片没有代价。

## 7. CTP 与 RPL：路由的核心是选下一跳

### 7.1 CTP：向汇聚点收集

节点选择到汇聚点路径成本较小的父节点，邻居 beacon 传播当前路径成本。采用 ETX 可按如下比较：

Cost(u→sink via v)=ETX(u,v)+Cost(v)

教学例：走 A 链路 ETX=1.2、A 到根为 2，总计 3.2；走 B 为 1+2.5=3.5，所以优先 A。跳数更少的路径未必 ETX 更小。

维护要点：周期 beacon 更新，发现不一致时加速广播；网络稳定时扩大间隔，节约控制开销。数据向根转发时路径成本应合理下降，异常可提示环路或陈旧路由，但判断受度量与状态约定影响。

### 7.2 RPL：面向低功耗有损网络的 IPv6 路由

DODAG 是以一个目的根为导向的有向无环图。目标函数综合 ETX、跳数、时延等指标与约束选择父节点。

| 术语 | 作用 |
|---|---|
| Rank | 表示相对根的位置并支持无环组织，不简单等同于跳数 |
| DIO | 传播 DODAG 信息，帮助建立上行关系 |
| DAO | 传播可达目的信息，支持下行路由 |
| MP2P | 多对一收集 |
| P2MP | 一对多分发 |
| P2P | 点对点，可结合上下行路径实现 |

CTP 主要是收集型路由；RPL 属于 IPv6 路由并支持更多通信模式。6LoWPAN 和 RPL 各司其职，前者不能替代后者。

## 8. Thread 与 Matter

Thread 以 802.15.4 和 IPv6 为基础组织低功耗 Mesh。路由器转发；端设备依附父路由器；Sleepy End Device 通过睡眠省电，父节点承担缓存等职责。设备分类 FTD 包含 Router、REED、FED；MTD 包含 MED、SED。

Matter 解决应用层的统一设备模型、控制与互操作，可运行在 Thread、Wi-Fi、以太网等 IP 网络上。Thread 边界路由器把 Thread 网络接到其他 IP 网络；它不一定承担全部应用逻辑。

**BLE 在 Matter 中主要用于发现、入网配置等流程，不能简单说正常 Matter 应用数据都经 BLE 传输。** 参考 [Matter 官方设备入网示例](https://project-chip.github.io/connectedhomeip-doc/examples/all-clusters-minimal-app/nrfconnect/README.html)。

单一网络与星状多网络连接是部署拓扑；协议层次仍要分别分析，不能把所有设备画在同一个图里就认为无线 PHY 相同。

## 9. BLE：广播、连接与属性访问

### 9.1 PHY 与信道

BLE 在 2.4 GHz 使用 40 个、间隔 2 MHz 的信道；传统主广播信道是 37、38、39，其余 37 个用于数据，扩展广播可以利用辅助信道。调制采用 GFSK，以高斯滤波平滑频率变化。

后续标准又引入 LE 2M、LE Coded 等扩展，参数需按对应 PHY 比较；不能把“蓝牙 5.x”当作单一固定速率。

### 9.2 从广播到建立连接

广播者发广播 → 扫描者发现 → 发起者请求连接 → 双方依据连接参数在数据频道进行连接事件通信。

链路状态：Standby、Advertising、Scanning、Initiating、Connection。本节采用 master/slave 名称，可对应理解为 central/peripheral；ATT/GATT 客户端服务器角色与它们不是同一维度。

连接间隔在这里讨论的经典连接模型中为 7.5 ms–4 s、1.25 ms 的倍数；较长间隔通常省电，但增加等待与下行响应延迟。实际还要结合从机延迟和监督超时等约束。

链路层使用 CRC 检错，SN/NESN 等机制确认顺序与重传；跳频提高对部分窄带干扰的适应能力，不代表干扰完全消失。

### 9.3 L2CAP、ATT、GATT

| 层 | 做什么 | 复习关键词 |
|---|---|---|
| L2CAP | 上层复用与必要的分段重组 | Length、Channel ID |
| ATT | 以属性方式存储与读写 | handle、type UUID、value、permission |
| GATT | 把属性组织为服务与特征 | service、characteristic、descriptor |

![GATT 属性表](%E7%89%A9%E8%81%94%E7%BD%91/pictures/05-%E4%BD%8E%E5%8A%9F%E8%80%97%E6%97%A0%E7%BA%BF%E5%8D%8F%E8%AE%AE/%E8%AF%BE%E4%BB%B6-p123.webp)

**句柄和 UUID 不同**：handle 在某设备属性表中定位属性；UUID 说明服务/特征的类型。多个设备可以有相同服务 UUID，但各自属性句柄不同。

温度服务示例：客户端先发现服务，再找到温度特征及 value 句柄，根据权限读取值；支持通知时可配置相关描述符后订阅。不是“看到 UUID 就能绕过权限读取”。

### 9.4 BLE Mesh

Mesh 使用转发、TTL、缓存等支持多跳通信。基础受管泛洪模式下，不能当成 RPL 一样逐跳计算最短父节点树。

| 角色 | 作用 |
|---|---|
| Relay | 转发允许转发的 Mesh 消息 |
| Low Power Node | 经常睡眠，与 Friend 协作 |
| Friend | 缓存发往低功耗节点的消息，按轮询交付 |
| Proxy | 通过 GATT 等让非 Mesh 接口设备接入 |

TTL 控制转发范围，Friend 不必就是 Relay，不能把两个能力合并。转发分析必须明确连线、Relay 能力和 Friend 配对。

![BLE Mesh 原题拓扑](%E7%89%A9%E8%81%94%E7%BD%91/pictures/05-%E4%BD%8E%E5%8A%9F%E8%80%97%E6%97%A0%E7%BA%BF%E5%8D%8F%E8%AE%AE/%E8%AF%BE%E4%BB%B6-p128.webp)

本例规定链路为 E—R—O，另有 E—Q—R 支路；L 是经常睡眠的低功耗节点，O 是 L 的 Friend 且未开启 Relay。可按 **E 广播（TTL=3）→ R 接收并转发（TTL=2）→ O 收到并为 L 缓存 → L 唤醒后轮询 O，O 交付缓存消息** 理解。E 也可到 Q，Q 再到 R，形成另一传播支路；重复消息由缓存等机制抑制。O 未开启 Relay 时不为其他普通节点继续泛洪，但仍能向自己的低功耗朋友 L 交付缓存。答题要区分朋友缓存交付与普通 Relay 转发，不能把所有节点都当作可持续转发节点。

### 9.5 蓝牙 5.x 的扩展

LE 2M 改善速率；LE Coded 用冗余编码换取覆盖能力，常见编码速率为 500/125 kb/s；扩展广播把更多广播内容移到辅助信道；方向探测配合天线阵列等条件支持定位。定位精度并不是只由蓝牙版本号决定。

## 10. 为什么需要 LPWAN？

短距离多跳覆盖城市，会遇到链路不可靠、维护复杂与靠近根节点的能量黑洞。LPWAN 通过长距离、低数据率、低占空比，适合远程表计、城市设施和低频环境上报。

| 维度 | 短距离低功耗 | LPWAN |
|---|---|---|
| 覆盖方式 | 近距离单跳或 Mesh 多跳 | 广域单跳接入网关/基站较常见 |
| 典型任务 | 家居、穿戴、局部传感 | 表计、城市设施、低频小报文 |
| 代价 | 多跳维护、邻居协同 | 较低速率、较大延迟、下行约束 |

### 10.1 增大覆盖的四种办法

1. 提高功率谱密度：相同总功率集中到更窄带宽。
2. 重复发送并合并：用更多时间/能量提高解码成功率。
3. 多接收天线：获得分集/合并增益。
4. 扩频：以时间、带宽或冗余换取低信噪比工作能力。

理想合并 N 次的增益近似 10log₁₀N dB；128 次约 21.07 dB。实际增益受非理想因素影响，示例中的覆盖预算只是特定设计估计。多天线 m 路理想合并近似 10log₁₀m，两路约 3.01 dB。

### 10.2 NB-IoT 与 LoRaWAN 总比较

| 维度 | NB-IoT | LoRaWAN |
|---|---|---|
| 接入 | 蜂窝网络 | LoRa 网关到网络服务器 |
| 频段 | 授权频段 | 多采用区域规定的非授权频段 |
| 部署 | 运营商网络为典型 | 可建设私网，也有公网服务 |
| 覆盖手段 | 窄带 PSD、重复与接收增益 | CSS 扩频等 |
| 省电机制 | PSM、eDRX | Class A/B 等接收时序 |
| 下行响应 | 与寻呼/睡眠配置相关 | 与 A/B/C 类别有关 |
| 主要权衡 | 网络服务、资费、覆盖与配置 | 自建维护、干扰、空口容量与地区限制 |

“NB-IoT 闭源、LoRaWAN 开源”过于简化。应区分公开标准、芯片技术授权、具体软件实现和网络运营模式；LoRa 与 LoRaWAN 也分别涉及不同层次。

## 11. NB-IoT 省电与部署

### 11.1 PSM 与 eDRX

| 机制 | 终端如何省电 | 下行可达性 |
|---|---|---|
| PSM | 深度睡眠，保留相关注册上下文 | 睡眠期间通常不可被即时寻呼；等待主动唤醒等 |
| eDRX | 延长非连续接收周期，按协商窗口监听 | 可在监听窗口接收，延迟随周期增大 |

“设备注册在网络”不等于“网络任何时刻都能把包交给设备”。长寿命示例高度依赖上报频率、信号、重传、监听、模组与电池，不能承诺固定十年。

### 11.2 三种部署方式

- 独立部署：利用独立的窄带频谱资源，可复用合适的 GSM 频谱资源。
- 保护带部署：利用 LTE 保护带。
- 带内部署：占用 LTE 中合适 PRB 资源，存在频点和资源约束。

区分 200 kHz 频谱栅格/配置背景与 180 kHz 有效传输带宽，不能把它们当作两种互相矛盾的答案。

## 12. NB-IoT 物理层、编码与随机接入

### 12.1 架构与物理资源

UE → 基站 eNB/BS → 核心网 → 物联网平台 → 业务应用。

下行 180 kHz，由 12 个 15 kHz 子载波组成，使用 OFDM；上行支持 15 kHz 或 3.75 kHz 子载波间隔，本节按 SC-FDMA 描述，single-tone 与 multi-tone 的资源配置不同。

| 信号/信道 | 主要作用 |
|---|---|
| NPSS | 时间、频率同步 |
| NSSS | 小区标识等同步信息 |
| NRS | 下行信道估计 |
| NPBCH | 主系统信息 MIB-NB |
| NPDCCH | 下行控制信息 DCI、资源分配 |
| NPDSCH | 下行数据、部分系统/寻呼/接入响应 |
| DMRS | 上行解调参考 |
| NPRACH | 随机接入前导 |
| NPUSCH | 上行数据与相关控制 |

同步信号帮助终端找到时间、频率与小区；参考信号帮助估计信道；控制信道说明资源分配；业务数据经共享信道传输。不能把这些不同职责合并成“都在传数据”。例如这里的 NPSS 每 10 ms 发送，NSSS 每 20 ms 发送，不能把二者周期混用。

### 12.2 卷积码与 Viterbi

卷积码输出不仅与当前输入有关，还与之前状态有关。码率 R=k/n；本例每输入 1 bit 输出 2 bit，所以 R=1/2。

令两级寄存器状态 s=(m_1,m_2)：

y_1=u⊕m_1⊕m_2, y_2=u⊕m_2, s'=(u,m_1)

两个记忆单元对应 4 个状态；若约束长度 K 定义为“当前输入加记忆长度”，则 K=3。记忆长度为 2，而此定义下的约束长度为 3，使用符号前先说明定义。

| 当前状态 | 输入 0：输出/下一状态 | 输入 1：输出/下一状态 |
|---|---|---|
| 00 | 00 / 00 | 11 / 10 |
| 01 | 11 / 00 | 00 / 10 |
| 10 | 10 / 01 | 01 / 11 |
| 11 | 01 / 01 | 10 / 11 |

初态 00，输入 0110，编码为 `00 11 01 01`，可逐位验证。

Viterbi 的过程：每个时刻枚举分支 → 将输出与接收码做汉明距离 → 累加路径度量 → 对同一终态保留代价最小的幸存路径 → 最后回溯。不是看到某一组有错就独立修改该组，因为编码有记忆。

**原题接收 `00 10 01 01`**，初态 00、没有额外末态限定时：

| 接收后时刻 | 状态 00 最小代价 | 01 | 10 | 11 |
|---|---:|---:|---:|---:|
| 初始 | 0 | ∞ | ∞ | ∞ |
| 第 1 组 00 | 0 | ∞ | 2 | ∞ |
| 第 2 组 10 | 1 | 2 | 1 | 4 |
| 第 3 组 01 | 2 | 3 | 2 | 1 |
| 第 4 组 01 | 3 | 1 | 3 | 2 |

最优终态 01、累计距离 1；回溯原始输入 **0110**，对应编码 **00 11 01 01**。第二组接收 10 与真实 11 相差 1 bit。

TBCC 用尾咬方式处理边界，使起止状态满足约束，减少专门尾部开销；Turbo 码通过交织和多个分量编码器提高纠错性能。编码增益以额外冗余、处理和时延为代价。

### 12.3 四步竞争随机接入

![NB-IoT 四步随机接入](%E7%89%A9%E8%81%94%E7%BD%91/pictures/05-%E4%BD%8E%E5%8A%9F%E8%80%97%E6%97%A0%E7%BA%BF%E5%8D%8F%E8%AE%AE/%E9%9A%8F%E6%9C%BA%E6%8E%A5%E5%85%A5.webp)

| 步骤 | 方向 | 内容 |
|---|---|---|
| Msg1 | UE→基站 | 随机接入前导 NPRACH |
| Msg2 | 基站→UE | RAR：时序调整、资源授权等 |
| Msg3 | UE→基站 | 按授权资源在 NPUSCH 发 RRC 连接请求等 |
| Msg4 | 基站→UE | 竞争解决 |

> [!warning] 的上下行笔误
> 该页先写 Msg3“在 NPDSCH 上发送”，同一句后面又正确写在 NPUSCH 上。Msg3 为上行，复习应写 **NPUSCH**。

多个 UE 可能选到相同前导，因此收到 Msg2 不等于竞争已经完全解决。覆盖增强等级按无线条件等选择，更多重复可增强可靠性但降低有效速率。

### 12.4 从应用报文到空口

应用字节 → UDP/IP 等协议头 → 无线协议层分段 → 信道编码与速率匹配 → 映射到分配的资源 → 基站解码重组。网络资源单位 RU、无线编码块和应用消息不是同一概念；AT 命令只是模组控制接口，不能代替对空口协议分层的理解。

## 13. LoRa 与 LoRaWAN

### 13.1 CSS 与扩频因子 SF

Chirp 的瞬时频率随时间变化；信息可用不同循环移位/起始相位对应的符号表示。解调的直观步骤是 dechirp，再 FFT 寻找对应峰值。

常用关系：

T_sym=(2^(SF))/BW, R_sym=BW/(2^(SF))

忽略额外帧开销时，按编码率 CR=4/(4+r) 的一种记法：

R_b≈SF BW/(2^(SF))4/(4+r)

SF 增大通常让符号更长、速率更低、空口占用更久，换来更强低信噪比接收能力。不同 SF 具有近似可分离特性，但不是任何功率差、干扰和实现条件下都完全正交、互不影响。

**教学例**：SF=8、BW=125 kHz，T_sym=256/125000=2.048 ms；SF=12 时为 32.768 ms。同样的包可能占用更多空口时间，影响电量与容量。

### 13.2 网络结构

终端广播上行，可能被多个网关接收；网关通过 IP 网络转发到 Network Server，后者进行去重、网络管理与下行调度等，再连接应用服务。典型 LoRaWAN 是星中之星结构，不要求终端为其他终端逐跳转发。

一个 CN470 信道规划示例使用 96 个上行和 48 个下行信道。信道数量必须与给定频率规划一致，不能把不同配置中的数字混用。地区参数、版本和法律使用要求可能变化，不能据此直接安排真实发射配置。

### 13.3 OTAA 与 ABP

| 方式 | 如何获得运行身份与密钥 | 权衡 |
|---|---|---|
| OTAA | 空中 Join-request / Join-accept，派生会话上下文 | 需要入网流程，便于管理与更新会话 |
| ABP | 预置地址及会话相关参数 | 启动简单，但密钥、计数器和生命周期管理需谨慎 |

本节采用 AppKey、NwkSKey、AppSKey 等记法，具体密钥体系需按 LoRaWAN 版本区分。**网关主要转发，入网认证与会话管理由相应服务器承担，不能把它都写成网关独立完成。**

把入网后的确认交互继续画入流程；复习应区分核心 OTAA 的 Join-request/Join-accept 与后续数据/确认交换，不要背成所有版本统一四次握手。参考 [LoRa Alliance 入门指南](https://lora-alliance.org/wp-content/uploads/2019/12/Documentation_20190215_10.pdf)。

### 13.4 Class A / B / C

![LoRaWAN 三类接收窗口](%E7%89%A9%E8%81%94%E7%BD%91/pictures/05-%E4%BD%8E%E5%8A%9F%E8%80%97%E6%97%A0%E7%BA%BF%E5%8D%8F%E8%AE%AE/LoRaWAN%E6%8E%A5%E6%94%B6%E7%AA%97%E5%8F%A3.webp)

| 类别 | 接收时机 | 能耗 | 下行等待 | 适合 |
|---|---|---|---|---|
| A | 每次上行后 RX1、RX2 | 最低 | 需等下一次合适上行后窗口 | 电池传感器、表计 |
| B | A 的窗口 + beacon 同步的 ping slot | 中等 | 有计划的额外机会 | 需要周期下行控制 |
| C | 除发送等时段外尽量持续接收 | 较高 | 较低 | 常供电执行器 |

A 是所有设备必须支持的基础类别。RX1 成功接收后通常无需再开 RX2。RX1/RX2 延迟、频率、速率依区域/配置；不是任何时候服务器都能叫醒 Class A。

Class B 用 beacon 保持额外接收时序；Friend 缓存是 BLE Mesh 机制，不能移植到 Class B 的术语中。

### 13.5 占空比、碰撞与确认

发送时长 T_on，占空比 D 限制下：

T_period≥T_on/D, T_off≥T_on(1/D-1)

例：0.5 s、1% → 总周期至少 50 s，等待至少 **49.5 s**。50 s 是含发送的周期，不是单独等待时间。1% 是题设示例，不能当作所有地区 LoRa 的统一限制。

LoRaWAN 基础上行常按 ALOHA 竞争理解，碰撞、确认、重传及下行占用都影响容量。确认包并非越多越好：ACK 也占有限下行资源；网关半双工实现发送时可能无法接收其他上行。

## 14. 研究进展怎么复习？

无需把每个论文题目当成协议定义。按“问题—手段—目标”理解：

| 类别 | 例题 | 想解决的问题 |
|---|---|---|
| 跨技术通信 | WEBee、WiRa、LigBee | 不同无线技术之间如何交换信息 |
| BLE 调度与安全 | RT-BLE、位置跟踪攻击研究 | 多连接实时性与隐私 |
| 低信噪比接收 | NELoRa | 弱信号下如何提高解码能力 |
| 并发与碰撞处理 | CoLoRa、LMAC | 提升空口容量与接入效率 |
| 定位与感知 | Seirios、LoRa 穿墙活动识别 | 把通信信号用于位置/活动感知 |
| 编码优化 | ChirpTransformer | 用计算方法改进无线信号处理 |

论文中的实验提升不是协议标准保证；边缘 AI 也可能成为改善无线解码、调度和感知的工具，形成第四、五章之间的联系。

## 15. 典型综合题：怎样选协议？

**场景 A：手机读取手环数据。** 优先分析 BLE：手机支持、短距离、低功耗、GATT 数据模型。说明广播发现、连接间隔、通知与电量权衡。

**场景 B：大楼电池传感器互联与智能家居控制。** 分析 Thread/Matter 或其他 Mesh：覆盖、供电路由节点、休眠端设备、边界路由、应用互操作；不能让所有电池节点持续转发而忽略能耗。

**场景 C：城市水表每天小量上报。** 比较 NB-IoT 和 LoRaWAN：既有网络覆盖、公私网、费用、地下信号、上报时延和下行需求。写“适合 NB-IoT”后还应说明 PSM 与上报周期。

**场景 D：摄像头实时高清视频。** 本章低速低功耗协议通常不适合承载主视频流，应结合更高带宽链路与本地分析；只传告警事件或识别结果则可以重新评估低速链路。
