# Computer Networks — Final Review（期末复习精讲）

> 复习以“认清所在层→识别题型→写条件→列式→画图→检查单位”为主线。英文术语与短答句用于适应English exam，中文解释帮助推导，最后用综合自测检查掌握程度。网络安全作为补充复习单独列出。

## 1. Introduction：协议、服务与分层

### 1.1 Network Model 与硬件分类

Client–server中client请求常驻server服务；P2P中节点可兼任请求者与资源提供者。P2P不意味着没有任何集中协调，C/S也不意味着数据永远只在两台机器之间流动。

Transmission technology：broadcast network共享信道，point-to-point network由成对链路连接。规模可分PAN、LAN、MAN、WAN；WAN可抽象为hosts加subnet，subnet包含transmission lines与switching elements。Internet互连多种网络，不等同于WWW。

### 1.2 Protocol / Service / Interface

| 词 | 对象 | 一句话定义 |
|---|---|---|
| Protocol | 同层peer entities | 规定交换消息的格式和含义 |
| Service | 下层向上层 | 提供什么能力和操作 |
| Interface | 相邻层之间 | 如何调用这些服务 |
| Network architecture | 一套分层与协议 | 规定层次和通信安排 |
| Protocol stack | 某系统实际使用的组合 | 各层选用的具体协议 |

同层逻辑通信是virtual，实际数据要沿本端协议栈下行，经物理介质再在对端上行。Protocol改变但service保持，应用可能不需重写；不能把两者完全等同。

### 1.3 OSI、TCP/IP、Five-layer Model

| OSI | 五层复习模型 | 主要功能/例子 |
|---|---|---|
| Application、Presentation、Session | Application | DNS、SMTP、HTTP、表示与会话相关应用功能 |
| Transport | Transport | TCP/UDP、process-to-process |
| Network | Network | IP、routing、host-to-host |
| Data Link | Data Link | frame、MAC、CRC、相邻节点 |
| Physical | Physical | bit、signal、medium |

OSI七层；常见TCP/IP参考模型四层，把link/network access作为一层；教学混合模型把link再拆成data link与physical，共五层。OSI先建模再安排协议，TCP/IP从已有协议经验概括；OSI更明确区分service/interface/protocol。

![OSI reference model](计算机网络/pictures/NetworkReview/osi-model.png)
![Five-layer reference model](计算机网络/pictures/NetworkReview/five-layer-model.png)

标准组织识读：ITU、ISO（International Organization for Standardization）、IEEE、IETF、IRTF、IAB。RFC是文档系列，不是每篇RFC都是Internet Standard。Internet历史中ARPANET是重要源头；无线LAN常见IEEE802.11。

> A protocol defines communication between peer entities, while a service describes what a layer provides to the layer above.

## 2. 基础计算：先区分Transmission、Propagation、RTT

$$T_{tx}=L/R,\qquad T_{prop}=D/v$$

发送时间由packet size与bit rate决定；传播时间由distance与signal speed决定。RTT是完整来回时间，可含传播、处理和排队；题目说two-way propagation delay时可能只计纯往返传播，不能擅自加倍。

| 单位 | 含义 |
|---|---|
| b / bit | 比特 |
| B / byte | 8bit |
| Mbps / Gbps | $10^6/10^9$bit/s |
| kB / MB | 通常十进制字节，需看题意 |
| KiB / MiB | $2^{10}/2^{20}$B |
| μs / ms | $10^{-6}/10^{-3}$s |

Bandwidth-delay product：单程$R\tau$是在途bit数量；端到端发送窗口常用$R\cdot RTT$，两者要说明延迟定义。

例：1000B、100Mbps→80μs；100km、$2\times10^8$m/s→500μs。增加速率只缩短80μs，不会自动缩短500μs。

## 3. Physical Layer：速率、噪声、调制

### 3.1 Symbol Rate vs. Data Rate

Baud rate是symbol/s，不是必然等于bit/s。无额外编码且$M$个可区分symbol每个代表$\log_2M$bit：

$$R_b=R_s\log_2M$$

8电平→3bit/symbol，2400baud→7200bps；QPSK4点→2bit/symbol，16QAM→4bit/symbol，64QAM→6bit/symbol。

曼彻斯特若以半bit电平区间计signal elements，每个数据bit用两个区间，电平区间率为数据率2倍；不能与M进制独立symbol映射公式不加条件地混用。

### 3.2 Nyquist与Shannon两道上限

Noiseless、bandwidth $H$Hz、$M$离散级：

$$R_{Nyquist}\le2H\log_2M$$

Noisy channel、linear signal-to-noise ratio $S/N$：

$$R_{Shannon}\le H\log_2(1+S/N)$$
$$SNR_{dB}=10\log_{10}(S/N),\quad S/N=10^{SNR_{dB}/10}$$

**解题步骤：**列H→把dB转linear→分别算两个上限→若两种条件同时约束，取较小值。

例：H=3000Hz、SNR=30dB、M=16。

1. linear S/N=$10^3=1000$。
2. Nyquist=$2(3000)\log_2(16)=24000$bps。
3. Shannon=$3000\log_2(1001)\approx29902$bps。
4. 该指定16级方案受24kbps上限限制。

反求：希望在H=3kHz下R=24kbps，无噪声级数至少$M\ge2^{R/(2H)}=16$；噪声条件至少$S/N\ge2^{R/H}-1=255$，对应约24.07dB。两项都要满足，并不代表实际编码就一定达到理论极限。

### 3.3 Transmission Media

Guided：magnetic media、twisted pair、coaxial cable、power lines、fiber。Unguided：radio、microwave、infrared/millimeter wave、free-space light等。

Twisted pair便宜易布线，光纤带宽大且不受普通电磁干扰；无线受共享、遮挡、干扰和移动影响。选介质要同时考虑distance、capacity、attenuation、interference、cost，不是只看标称速率。

### 3.4 Baseband Encoding：按bit边界画

| Encoding | 常见约定 | 画图方法 |
|---|---|---|
| NRZ-L | 1高、0低（以题目为准） | 每bit固定一个电平 |
| NRZI | 1在边界翻转、0不翻转（以题目为准） | 声明初始电平，逐bit判断是否翻转 |
| Manchester | 1高→低、0低→高 | 每bit拆两半，中点必跳 |
| Differential Manchester | 起点跳变=0、不跳=1 | 先判起点，再固定中点跳变 |
| AMI | 0为零电平，连续出现的1交替正负 | 记录上一个1使用的极性 |

![Line encoding comparison](计算机网络/pictures/NetworkReview/line-encoding.png)

例：数据10010，Manchester半bit电平`HL | LH | LH | HL | LH`；AMI若第一个1为正，则`+ 0 0 - 0`。连续0不让AMI极性轮换，因为轮换只针对非零mark。

### 3.5 Passband Modulation与Constellation

ASK改变amplitude，FSK改变frequency，PSK改变phase；QAM联合振幅和相位。星座图横轴I、纵轴Q；每点为一个symbol，离原点距离对应幅度，角度对应相位。

![QPSK, 16-QAM and 64-QAM constellations](计算机网络/pictures/NetworkReview/constellations.png)

画QPSK：画两正交轴、4等距相位点，按题设标bit；画16QAM：I/Q各4电平形成4×4网格。Gray labeling让近邻点常仅差1bit，但具体标签必须按题给约定，不能只数16个点就臆造唯一bit顺序。

### 3.6 FDM / TDM / WDM / CDMA

FDM分频，TDM分时，WDM在光纤用不同波长，本质是光频域复用；CDMA用不同chip sequence区分同时叠加信号。

理想CDMA要求同步、近似正交、信道可线性叠加。每站长度$m$的chip vector $s_i$，$s_i\cdot s_i=m$、不同站内积0。发1发送$s_i$，发0发送$-s_i$，静默发0向量。接收叠加$x=\sum b_is_i$后：

$$\hat b_i=\frac{x\cdot s_i}{m}$$

结果+1→1，-1→0，0→未发（理想模型）。**数据bit0不等于静默。**

![CDMA chip vectors and correlation decoding](计算机网络/pictures/NetworkReview/cdma-example.png)

图中C=`(-1,+1,-1,+1,+1,+1,-1,-1)`，若B/C都发1，叠加$x=(-2,0,0,0,2,2,0,-2)$。与C内积$2+0+0+0+2+2+0+2=8$，除8得1，所以C发1。其他站因正交项消失。实际功率不均、不同步与多径会破坏理想解码条件。

## 4. PSTN、ADSL、PCM与T1

PSTN三部分：local loop（用户到交换局）、trunk（局间长距离干线）、switching office（交换局）。Modem在传输信道上实现调制/解调；ADSL利用比语音更宽的本地环路频谱，Discrete Multitone把频带分成多个子载波，上下行配置不对称。

![ADSL and discrete multitone channels](计算机网络/pictures/NetworkReview/adsl.png)

语音PCM常用8000samples/s，每样本8bit→64kbps；采样率与量化位数分开。T1每帧24×8+1=193bit，每125μs一帧即8000帧/s：

$$R_{T1}=193\times8000=1.544\text{ Mbps}$$

总时隙载荷24×64kbps=1.536Mbps，framing8kbps。某些传统语音信令方案借用部分bit作signaling，所以用户净数据可低于完整64kbps/channel；不应一律把T1任意场景解释成固定7bit有效数据。

![T1 multiplexed frame](计算机网络/pictures/NetworkReview/t1-frame.png)

Circuit switching先建立资源/路径，适合持续业务但空闲可能浪费；packet switching统计复用突发业务，利用率更灵活但有queueing、竞争与变时延。Connection-oriented packet network也不是物理独占circuit。

## 5. Data Link Layer：成帧、差错、流控

三类服务：unacknowledged connectionless、acknowledged connectionless、acknowledged connection-oriented。ACK与connection是两个独立维度，不是无连接就必然无确认。

### 5.1 Framing与Stuffing

Byte count用长度找边界，长度坏可能失同步；flag bytes用特殊字节标界并byte stuffing；flag bits常用`01111110`标界并bit stuffing；encoding violation利用合法数据不会出现的物理模式。

**Bit stuffing：**发送端在**数据**中每连续5个1后插0，接收端删除这些插入0。例：原数据`01111110`→`011111010`，再由外部flags包围。边界flag本身不执行同样插零，否则无法识别flag。

**Byte stuffing：**数据中的FLAG、ESC需按题设转义。概念规则`A FLAG ESC`→`A ESC FLAG ESC ESC`，外面另加FLAG。实际PPP的具体转义变换要按其定义，不能把所有协议都当同一个规则。

### 5.2 Hamming Distance（海明距离）

两个bit串不同位置数；code的$d_{min}$是任意两合法codeword距离的最小值。

$$\text{Guaranteed detection of }s\text{ errors: }d_{min}\ge s+1$$
$$\text{Guaranteed correction of }t\text{ errors: }d_{min}\ge2t+1$$

例：$d_{min}=5$→可保证检测4bit差错，或纠正2bit差错。说检测与纠正能力时要说明decoder策略，不等于“纠正2bit同时无条件识别其他所有错”。

### 5.3 Hamming Code 手工构造

数据$m$bit、单错纠正parity位$r$，需$2^r\ge m+r+1$。对m=4，r=3，使用(7,4) code。位置1、2、4放parity；3、5、6、7放data。

data=`1011`，even parity，按位置从1到7写：`p1 p2 1 p4 0 1 1`。

- p1覆盖1、3、5、7：$p1\oplus1\oplus0\oplus1=0$→p1=0。
- p2覆盖2、3、6、7：$p2\oplus1\oplus1\oplus1=0$→p2=1。
- p4覆盖4、5、6、7：$p4\oplus0\oplus1\oplus1=0$→p4=0。

codeword=`0110011`。若第6位翻转，syndrome各分量s1=0、s2=1、s4=1，按$s4s2s1=110_2=6$定位翻回。位号方向必须事先声明，不能和“二进制数最左为高位”的显示方式混淆。

### 5.4 Internet Checksum：回卷进位后再取反

16bit one’s-complement sum：每个16bit字相加，超过16bit的carry加回低16bit，最终按位取反。验证时包括checksum的总和应为0xFFFF。

例：`0xE666 + 0xD555 = 0x1BBBB`，低16位BBBB再加carry1→BBBC，checksum=`0x4443`。

![One's-complement checksum and end-around carry](计算机网络/pictures/NetworkReview/checksum-example.png)

补充校验：$0xBBBC+0x4443=0xFFFF$。不要丢弃最高carry；CRC的XOR除法则完全不做进位，二者是不同运算。

### 5.5 CRC（Cyclic Redundancy Check）逐步算

bit串对应GF(2)多项式；addition/subtraction都用XOR，无carry/borrow。Generator $G$最高次为$r$：

1. 数据$M$后补$r$个0，相当于乘$x^r$。
2. 用G做模2长除，求rbit余数R。
3. 用余数替换补零位置，发$T=Mx^r\oplus R$。
4. Receiver用G除T，零余数表示通过该检验；并不证明绝无错误。

例：M=`1101011011`，G=`10011`，r=4；被除数`11010110110000`，余数`1110`，发送`11010110111110`。

![CRC modulo-2 long division](计算机网络/pictures/NetworkReview/crc-example.png)

手工除法每次把generator首1对齐当前余串最高1，逐位XOR，再下移；高位为0则商位0并继续，不做普通十进制借位。若误差多项式E恰可被G整除，则可能未检测到；合理r次generator可保证检测长度不超过r的burst等性质，但不能说任何generator都一样强。

## 6. Stop-and-wait / GBN / SR：算效率并画丢包图

### 6.1 Stop-and-wait Utilization

不计ACK发送及处理时：

$$U=\frac{T_f}{T_f+2\tau}=\frac1{1+2a},\quad a=\tau/T_f$$

若算有效payload比例，需把分子改成payload发送时间：

$$U_{effective}=\frac{L_{payload}/R}{(L_{payload}+H)/R+2\tau+L_{ACK}/R}$$

例：payload100B、header40B、ACK60B、R100Mbps、单程传播12μs。

- 数据帧发送=$140\times8/10^8=11.2$μs。
- ACK发送=$60\times8/10^8=4.8$μs。
- 周期=$11.2+24+4.8=40$μs。
- 有效发送=$100\times8/10^8=8$μs。
- 有效利用率=$8/40=20\%$；若分子用整帧则是28%，不是同一指标。

### 6.2 Window / Pipelining

窗口W、等长帧、无损且ACK时间忽略：

$$U\approx\min\left(1,\frac{W}{1+2a}\right)$$

填满链路需$W\ge\lceil1+2a\rceil$。若ACK时间不能忽略，使用完整cycle长度重新推导。例：$T_f=1$ms、$\tau=5$ms，需要W≥11；W=4时利用率约4/11=36.36%。

### 6.3 GBN vs. SR与序号空间

| Feature | Go-Back-N | Selective Repeat |
|---|---|---|
| Receiver window | 1（基本模型） | 多帧 |
| Out-of-order frames | 一般丢弃 | 可缓存 |
| Retransmission | 从缺失处及其后的未确认帧重传 | 仅重传需要的帧 |
| ACK | 累计确认 | 选择性确认/单独记录，依模型 |
| mbit序号最大W | $2^m-1$ | 对称窗口常$2^{m-1}$ |

更一般SR约束是$W_s+W_r\le2^m$；相等时才得到半个序号空间。目的是防止旧帧被误认为新窗口帧。

**画丢包图：**左右sender/receiver两时间轴，标data Seq与ACK语义；画丢失叉号、timer起止、重传虚线；GBN让丢失后乱序帧被丢，SR把它们画进buffer。题目若ACK表示“最后收到序号”或“下个期望号”不同，必须统一后再算。

### 6.4 PPP

PPP（Point-to-Point Protocol）提供framing、error detection、LCP（Link Control Protocol）建立/测试/协商/释放链路，以及NCP（Network Control Protocol）协商网络层协议选项。PPP可用于不同链路，不表示它自动提供所有可靠重传与拥塞控制。

## 7. MAC Sublayer：共享信道计算与画图

### 7.1 ALOHA核心推导

$G$=每帧时间内所有尝试均值，含重传；$S$=成功发送均值。Pure ALOHA脆弱期2帧，Slotted ALOHA脆弱期1帧：

$$S_{pure}=Ge^{-2G},\quad S_{slotted}=Ge^{-G}$$
$$S_{pure,max}=1/(2e)\approx0.184\ (G=0.5)$$
$$S_{slotted,max}=1/e\approx0.368\ (G=1)$$

画曲线时标轴Offered load G、Throughput S、两个峰值，重载段下降。低负载Pure可立即发，Slotted平均多等半槽，最大吞吐量与低载延迟不能混为一谈。

56kbps信道、每站每100s一帧1000bit：每站10bps，$N\le56000/(2e\cdot10)$，最大整数1030。

### 7.2 CSMA与CSMA/CD

1-persistent：空闲立刻发，忙则持续听；nonpersistent：忙就随机等后再听；p-persistent：分槽空闲时以p发送，1-p推迟。一直空闲、首次立即判断时平均推迟$(1-p)t/p$。

Carrier sense不能消除传播窗口：信号未到远端，远端仍会误判空闲。CSMA/CD边发边检测碰撞，最坏需要2τ：

$$L_{min}\ge2\tau R=2(D/v)R$$

例：1Gbps、1km、$v=200000$km/s→τ5μs→10000bit=1250B，指题设理想共享网络。经典以太网64B最小MAC帧、46B最小数据+填充；全双工交换以太网不使用CSMA/CD。

Binary exponential backoff：第i次碰撞后$k=\min(i,10)$，从0…$2^k-1$均匀选槽数。10Mbps经典slot=51.2μs，达到失败限制后报告。窗口M相同的两站再次同号概率1/M；窗口不同需枚举组合，条件事件需重新归一化。

### 7.3 Collision-free与Limited Contention

Bit-map：Nbit预留后按编号发送，轻载效率$d/(N+d)$，重载$d/(d+1)$。Token passing由令牌给permission，空闲站转交；binary countdown高位先比较，0被1覆盖就退出，最大地址胜出，仲裁约$\lceil\log_2N\rceil$bit。

Adaptive tree walk把站放叶子，碰撞才展开左右子树，空闲/成功立即终止该组。16站素数2、3、5、7、11、13同时就绪，从根深度优先搜索访问组：

```text
1–16, 1–8, 1–4, 1–2, 3–4, 5–8,
5–6, 7–8, 9–16, 9–12, 13–16
```

共11槽，访问编号0…10。不能把所有16个叶子都无条件计一槽。

### 7.4 Ethernet Frame与无线

普通无标签Ethernet MAC frame：DA6+SA6+Type/Length2+Data/Pad46…1500+FCS4→64…1518B；Preamble/SFD8B和IFG12B等效时间不含在这个MAC frame长度中。Type/Length≤1500按length，≥1536按type，中间保留范围不要误读。

Hidden terminal：A/C互相听不到却都干扰B；exposed terminal：因听到别人的发送而过度避让，本来另一个接收端可安全接收。画图必须标coverage与receiver，不只看sender是否相邻。

MACA先RTS/CTS再DATA，让听到CTS的站保护接收端；RTS仍会冲突。802.11 DCF的CSMA/CA使用侦听、随机backoff、ACK和可选RTS/CTS，忙时冻结倒计数；NAV是虚拟预约计时。SIFS<PIFS<DIFS<EIFS，短间隔保护响应和连续交换。

802.11架构有infrastructure（AP）与ad-hoc。历史PHY：802.11a为5GHz OFDM/54Mbps，b为11Mbps HR-DSSS，g为2.4GHz OFDM/54Mbps，n采用MIMO-OFDM。GHz是频率，Mbps是速率，二者不能相互替换。

### 7.5 Learning Bridges、STP、Domains

网桥先学source MAC→入端口，再查destination；已知异口forward，已知同口filter，未知flood到同VLAN中除入口以外的可转发口。不同桥独立学习，不会自动共享全部表项。

STP先选最小Bridge ID为root，再比较root path cost选root port和每段designated port，冗余端口阻塞；不要把物理冗余线误删成真的不存在。二层环路可产生broadcast storm、重复帧、MAC表振荡。

Hub共享碰撞段；switch分隔传统collision domains；full-duplex段没有实际碰撞。VLAN与router边界分隔broadcast domains。Repeater/Hub主要L1，Bridge/Switch主要L2，Router主要L3，应用gateway可以做更高层协议转换。

## 8. Network Layer：路由、地址、分片

### 8.1 Datagram / Virtual Circuit与Routing算法

Datagram无预先连接，各包按目的地址查表；VC先setup，按入口/label映射到出口/新label。Routing算路径，forwarding应用转发规则。

DV：$D_x(y)=\min_v[c(x,v)+D_v(y)]$。LS：发现邻居、测cost、构造带sequence/age的LSP、泛洪、运行Dijkstra。DV主要听邻居距离，LS拥有相应范围内拓扑；count-to-infinity是DV典型问题，poisoned reverse不能保证排除多节点循环。

**计算DV例：**R到X/Y cost为2/5，X到目的D报告7，Y报告1，则via X=9，via Y=6，选Y与cost6。不能只比较邻居报告的7与1而忘记本地cost。

Dijkstra每轮取最小未定标签，更新邻居，保存predecessor。Hierarchical routing用区域汇总减小表，可能牺牲最短路径。Flooding复制包，RPF只接受来自到source的正常反向路径；multicast修剪无组成员分支；anycast交给组内优选的一个。

### 8.2 Internetworking与SDN

路由器逐跳更换frame，在普通非NAT路径上保留IP源/目的但减少TTL；tunnel增加outer header使原包跨越另一种网络，封装不自动加密。

SDN分data plane/control plane，controller维护全网视图并安装match+action规则。Northbound对应用，southbound对设备；logical centralization可由多个物理控制器实现。OpenFlow表按rule priority等规则处理，不一概等于IP longest-prefix表。

### 8.3 IPv4 Header关键字段

Version4bit；IHL4bit以4B为单位；Total Length16bit；ID16bit；Flags3bit；Offset13bit以8B为单位；TTL8bit；Protocol8bit；Checksum16bit仅保护IP首部；Source/Destination各32bit。

`45 00 00 38`→IPv4、首部20B、总长56B。若后面TCP Data Offset=5，应用payload=$56-20-20=16$B。Protocol=6表示TCP，17表示UDP，1表示ICMP。

### 8.4 子网、聚合与最长前缀

`IP/p`：host bits=32-p，块大小$2^{32-p}$，普通host count减2。Network=IP AND mask，broadcast=主机位全1。

例：172.16.9.201/27：mask255.255.255.224，最后字节块跨度32，落在192–223；network=.192，broadcast=.223，可用.193–.222，30个。

VLSM先求容纳需求的最小2幂，再找正确对齐空闲块。1024个addresses需/22；1024个usable hosts需/21，因为/22只有1022普通主机位。

CIDR聚合需连续、对齐、数量合适且转发策略兼容。57.6.96.0/21、104/21、112/21、120/21→57.6.96.0/19。若大聚合中少量地址转其他出口，可加更具体条目，LPM使其优先。

**LPM练习：**10.0.0.0/8→A，10.2.0.0/16→B，10.2.3.0/24→C，default→D。10.2.3.4同时命中前三条，选择C，不以最早出现/最小metric代替prefix length比较。

### 8.5 IPv4分片

无选项等首部教学模型：

$$D=L-H,\quad F=8\lfloor(MTU-H)/8\rfloor$$

总1500B、H20B、MTU800→数据1480，首片776B、末片704B；IP总长796/724B；offset0/97；MF1/0。每片复制自己的IP首部，offset相对原payload。DF=1则不能直接路由器分片，要检查题设。

IPv6固定首部40B、地址128bit，payload length不含固定首部，Next Header串接扩展或上层协议，Hop Limit限制寿命，无IPv4式首部checksum；路由器不执行IPv4式中间分片。地址8组16bit，组内可去前导0，`::`最多一次。

### 8.6 NAT、ICMP、ARP、DHCP、OSPF/BGP

- NAT/NAPT：去程改source IP/port，回程按映射还原destination；private地址10/8、172.16/12、192.168/16。
- ICMP：错误报告与诊断；traceroute利用逐步TTL到期，知道初值才能精确算hop count。
- ARP：本地IPv4 next-hop→MAC，跨网解析gateway MAC而不是远端MAC。
- DHCP：Discover→Offer→Request→ACK，动态获取IP、mask、gateway、DNS、lease。
- OSPF：intra-AS LS，Dijkstra、area与backbone；直接在IP上传送，区分ABR/ASBR。
- RIP：DV，hop metric，15跳可达上限、16不可达。
- BGP：path vector，AS-PATH/NEXT-HOP/local preference等，policy可优先于性能，使用TCP。

## 9. Transport Layer：TCP计算总整理

### 9.1 UDP与TCP

UDP首部8B，保留datagram边界，有port与checksum，不自行保证重传、顺序和交付。TCP首部通常20–60B，提供可靠有序全双工byte stream，不保留应用消息边界。

Server sockets：socket→bind→listen→accept→send/recv；client：socket→connect→send/recv。应用重复read直到满足自己的消息长度或EOF，而不是假设一个read就是一个完整send。

### 9.2 TCP首部、Seq/Ack、握手与关闭

source/destination port各16bit，Seq/Ack各32bit，Data Offset以4B计首部，Window原字段16bit，Checksum含TCP与pseudo-header。

SYN、FIN各消耗一个序号，纯ACK不消耗。ACK=next expected byte；两个方向的Seq空间相互独立。

```text
SYN Seq100  →
           ← SYN+ACK Seq500 Ack101
ACK Seq101 Ack501 →
DATA Seq101 Len20 →
           ← ACK121
```

若第二数据段Seq121先到而101–120缺失，继续ACK101。不能因“最后收到某高序号包”就把累计ACK越过缺口。

FIN只关闭本端发送方向，另一方可继续传。正常关闭可能四段，也可能FIN/ACK合并；LAST-ACK等本端FIN的ACK，TIME-WAIT用于最后ACK重发及旧包消失，通常2MSL。

### 9.3 Window与吞吐

$$Allowed=\min(cwnd,rwnd),\quad NewData=\max(0,Allowed-FlightSize)$$

例：cwnd6000B、rwnd4100B、已发未确认1000B→新发最多3100B。Window字段是**发这个报文的一方通告给对方的接收窗口**，方向不要倒过来。

理想window-limited rate≈$W/RTT$；若W用B则结果B/s。100Mbps、RTT40ms→需要约500000B在途才填满链路。MSS=MTU−IP header−TCP header；1500−20−20=1460B。

Nagle减少sender tinygrams，Clark减少receiver tiny window updates；persist timer探测zero window，避免更新丢失死锁。

### 9.4 RTT与RTO递推

$$S' = \alpha S+(1-\alpha)R$$
$$V'=\tfrac34V+\tfrac14|S_{old}-R|,\quad RTO\approx S'+4V'$$

初S30ms、α0.9，26/32/24ms三个样本→29.6→29.84→29.256ms。计算variation时要使用相应公式要求的old SRTT，不要先覆盖变量再算偏差。实际RTO还受粒度、下限和超时backoff影响。

### 9.5 TCP Reno / Tahoe画图

考试常用初cwnd1MSS：SS每RTT翻倍；到ssthresh转CA每RTT+1MSS。Reno的3dupACK简化为减半后CA；timeout回1后SS。Tahoe遇3dupACK也回1。

| Round | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| cwnd，ssthresh=8 | 1 | 2 | 4 | 8 | 9 | 10 | 11 | 12 |

若round8后3dupACK，阈值6，Reno恢复后round9约6，随后7、8……；若timeout则round9=1，随后2、4、再达到阈值后线性。真实fast recovery还包含暂时+3MSS膨胀，画简化轮次图时明确这一点。

![Reno and Tahoe response to duplicate ACKs](计算机网络/pictures/NetworkReview/tcp-reno-example.png)

Reno锯齿窗口从W/2至W，连续近似平均3W/4，平均吞吐约$0.75W/RTT$。每RTT增1MSS，恢复半个窗口需约$W/(2MSS)$个RTT。三个dupACK与timeout的处理区别要在图上明确。

### 9.6 QUIC与BBR速记

QUIC是UDP之上的安全可靠多流传输，HTTP/3基于它；不同stream独立排序降低跨stream HOL，但共享拥塞且同stream仍有顺序。BBR估计BtlBw与RTprop、BDP=BtlBw×RTprop，通过pacing和inflight控制减少不必要排队；不是HTTP/3必须绑定的算法。

## 10. Application Layer：DNS、Email、HTTP

### 10.1 DNS

分层命名与分布式数据库；RR五元组Name/TTL/Class/Type/Value。A=IPv4，AAAA=IPv6，MX=mail exchanger，NS=nameserver，CNAME=canonical name，PTR=reverse lookup，SOA=zone管理数据。

Host通常recursive问resolver，resolver再iterative问root/TLD/authoritative。Zone是委派后的管理范围，不能与domain完全等同；13个根标识不等于13台物理设备。可UDP/TCP53。

### 10.2 Email / MIME / Base64

MUA经SMTP提交给MTA，再SMTP传到收件服务器；收件人用POP3/IMAP/Webmail取用。Envelope的MAIL FROM/RCPT TO不等于message可见From/To；Bcc可投递但不必显示在To。

MIME描述Content-Type、charset、transfer encoding与multipart boundary。Base64每3B变4字符：

$$L=4\lceil n/3\rceil$$

`Man`的bit串`010011010110000101101110`→6bit索引19/22/5/46→`TWFu`。4560B编码6080B，按题设每110字符及末尾加CRLF，共56行→6192B。Base64不是encryption。

### 10.3 WWW与HTTP

URL含scheme、host、可选port、path、query、fragment；HTTP request不发送普通fragment给server。HTML结构、CSS样式、JS行为；server-side程序生成内容，client-side脚本响应交互。AJAX让异步请求返回后局部更新DOM，数据不必是XML。

Cookie通过Set-Cookie设置、Cookie发回，借identifier关联session。Secure不等于加密cookie存储，HttpOnly限制脚本，SameSite参与跨站携带控制；网站仍可用第三方关联与device fingerprinting追踪。

HTTP方法GET/HEAD/POST/PUT/DELETE/OPTIONS/TRACE/CONNECT；状态1xx信息、2xx成功、3xx重定向/验证、4xx请求方相关错误、5xx服务器错误。Content-Type帮助解释body；no-cache要求验证，no-store禁止相关存储，304配合缓存body。

### 10.4 HTTP延迟速算

设DNS总$D$、服务器RTT=$r$，小对象、忽略传输/TLS等：

| 场景 | 耗时 |
|---|---|
| 1个HTML、需新建TCP | D+2r |
| HTML+3对象，每次新连接且顺序 | D+8r |
| HTML+3对象，持久顺序 | D+5r |
| HTML+3对象，持久pipeline | D+3r |
| HTML后3对象并行新连接 | D+4r |

HTML要先到达才能发现对象，不能把它和引用资源全部从t0并行请求。HTTP/2二进制frame多路复用、HPACK，但TCP仍有传输层HOL；HTTP/3用QUIC、QPACK，改善跨stream交付阻塞。

## 11. Network Security补充复习

CIA=Confidentiality/Integrity/Availability；Authentication判断身份，Nonrepudiation处理可验证的行为证据，Freshness防重放。Encryption、hash、MAC、signature各有职责。

| 运算 | 核心公式/规则 |
|---|---|
| Caesar | c=(p+k) mod26 |
| OTP | C=P XOR K，同key不可复用 |
| RSA | n=pq，φ=(p−1)(q−1)，ed≡1 modφ，C=M^e modn |
| DH | A=g^a modp，B=g^b modp，共享g^(ab) modp |
| Hash birthday bound | nbit摘要找collision约2^(n/2)工作量 |
| SHA类padding例 | 加1、补0至448 mod512，再加64bit长度（SHA-1模型） |
| Signature | signer private key生成，public key验证 |
| HMAC | 规范化key与ipad/opad嵌套hash，不是简单H(M+K) |

RSA例：p3、q11→n33、φ20，e3、d7；M4→C31→解密4。DH例：p23、g5、a6、b15，A8、B19，共享2。小数值仅用于运算演示。

AES block128bit，key128/192/256bit对应10/12/14轮；DES有效key56bit是历史知识。CBC/CTR等单独提供confidentiality不等于自动authentication；nonce/IV有相应使用条件。DH未认证会受MITM，certificate将identity与public key绑定，验证需同时检查chain、名称、有效性等。

TLS负责握手认证/密钥建立与连接保护；旧RSA premaster握手不能当成TLS1.3完整流程。PGP式hybrid流程：hash/sign→compress→session-key encrypt→recipient public-key包裹session key，接收方逆序恢复并验签。

### 12.1 英文计算答案四句话

1. **Given / Assume ...** 明确单位与忽略项。
2. **The relevant constraint is ...** 写模型或公式。
3. **Substituting the values gives ...** 保留代入和必要中间结果。
4. **Therefore, ...** 结果带单位、取整和适用条件。

例：

> The one-way propagation delay is 5 microseconds. A worst-case collision takes approximately 10 microseconds to return to the sender. Therefore, the minimum frame size is 10000 bits, or 1250 bytes, under the stated CSMA/CD model.

### 13.1 最后检查五种高频错误

- **单位错：**byte没乘8、dB直接代Shannon、ms当s。
- **范围错：**frame/packet/payload计数混淆、IPv4 IHL当byte、offset没除8。
- **方向错：**ARP问远端MAC、ACK确认错方向、Window把发送者与接收者倒置。
- **条件错：**忽略DF、把所有丢包归拥塞、把平均窗口当整数段硬数。
- **语义错：**UDP没重传≠没checksum，Base64≠加密，signature≠保密，persistent≠pipeline。
